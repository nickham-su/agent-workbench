# 失败矩阵、日志与安全

## 总体失败原则

- 私有 state 错投递、身份冲突、顺序冲突或协议终态不完整时，宁可失败也不得完成 Assistant。
- “可重试”只代表 Runner 可以考虑发起一个全新 Attempt；不保证一定重试。
- 任何 Attempt 的失败状态、临时 item 映射和未确认 metadata 均不得跨 Attempt 复用。
- 只有成功 `completeAssistant` 的 completed Assistant 才能在后续 PromptContext 中成为 state source。
- OpenAI Phase A 对损坏 state 保持既有安全跳过；DeepSeek experimental 对 scope 内、Assistant protocol snapshot 明确匹配的必需 state 损坏必须请求前失败关闭，具体见 [03-接口数据与不变量.md](./03-接口数据与不变量.md) 与 [08-PhaseC协议快照与完整性闭环.md](./08-PhaseC协议快照与完整性闭环.md)。

## 错误分类

| 分类 | 典型来源 | retry | replacement | 成功提交 |
|---|---|---:|---:|---:|
| Configuration | 非法 npm/protocolAdapter 组合、Factory/Adapter 选择失败、DeepSeek scope 内 state diagnostics、topP 范围错误 | 否；只能修复配置/数据后重新发起 | 否，请求前不应有输出 | 否 |
| Invariant | `assert...Compatible`、Part 类型/顺序冲突、identity/tool-call ID 不一致 | 否 | 否；不得用 replacement 掩盖矛盾 | 否 |
| TransientProtocol | 普通 Provider 网络/transport 错误及当前 Runner 已判可重试的请求失败 | 可以，由 Runner 既有策略决定 | 已 flush 输出时必须先成功 replacement | 否，该 Attempt 不可完成 |
| TerminalProtocol | OpenAI 缺 completed、failed/incomplete、unknown finish；Adapter finalize 拒绝 | Phase A 保持当前 Runner 既有策略，不得在重构中改变 | Runner 若重试且已有输出则必须 replacement | 否，该 Attempt 不可完成 |

## 失败与边界矩阵

| 场景 | 分类 | 必须行为 | 可重试 | 允许成功提交 |
|---|---|---|---:|---:|
| Provider ID / 模型 / 协议合法但不匹配 | 无 | 正常跳过该历史 state，不删除 | 不适用 | 可以，使用普通 transcript |
| 非默认 `protocolAdapter` 无 Registry 条目 | Configuration | 发请求前失败关闭，给出无敏感信息诊断 | 否 | 否 |
| Factory npm/协议非法组合或初始化失败 | Configuration | 不创建 Assistant，不发送模型请求 | 否 | 否 |
| Adapter `prepareInvocation` 失败 | Configuration 或 Invariant | 不创建 Assistant，不发送模型请求；Phase A 不触发工具发现 | 否 | 否 |
| OpenAI 损坏/未知 Envelope | 无 | 保持当前私有 read-side 安全跳过，不回显原文 | 不适用 | 可以 |
| 无法识别协议归属的损坏 JSON | 无 | 安全跳过，不猜测为 DeepSeek | 不适用 | 可以 |
| snapshot 匹配 DeepSeek 的 reasoning Part 整体缺 Envelope | Configuration | 诊断为 `missing-required-metadata`；请求前失败关闭 | 否 | 否 |
| 可识别且匹配 DeepSeek scope 的 schema/版本/metadata 损坏 | Configuration | 请求前失败关闭，不发送模型请求 | 否 | 否 |
| 匹配 DeepSeek state 缺 `completion: "complete-v1"`、缺/空/不完整 reasoning Part.text | Configuration | 请求前失败关闭 | 否 | 否 |
| 写入非法 Envelope | Invariant | 严格拒绝写入 | 否 | 否 |
| metadata-only update | 无 | 允许附着既有正确目标，强制 flush | 不适用 | flush 成功后才可 |
| metadata 目标不存在/类型不符 | Invariant | 抛不变量错误 | 否 | 否 |
| 原生 item identity 冲突 | Invariant | 抛不变量错误 | 否 | 否 |
| tool-call ID 与 metadata 不一致 | Invariant | 抛不变量错误 | 否 | 否 |
| 旧 stream Part 乱序追加 delta | Invariant | 抛不变量错误，不重排 | 否 | 否 |
| OpenAI 无 `response.completed` | TerminalProtocol | 当前 Attempt 校验失败；保持既有 Runner retry/replacement 路径 | 依当前 Runner | 否 |
| OpenAI `failed`/`incomplete` | TerminalProtocol | 当前 Attempt 校验失败；保持既有 Runner retry/replacement 路径 | 依当前 Runner | 否 |
| OpenAI `unknown` finish reason | TerminalProtocol | 当前 Attempt 校验失败；保持既有 Runner retry/replacement 路径 | 依当前 Runner | 否 |
| DeepSeek reasoning-end | 无 | 继续等待 response finish；不得写 completion metadata | 不适用 | 不适用 |
| DeepSeek `stop` / `tool-calls` finish | 无 | 为本 Attempt reasoning Parts 写 `complete-v1` metadata，强制 flush 后才 finalize | 不适用 | 仅 flush 成功后 |
| DeepSeek EOF 无 finish / unknown / length / content-filter | TerminalProtocol | 不写 `complete-v1`，当前 Attempt 不完成 | 否 | 否 |
| DeepSeek stream error / abort / timeout / 取消 | TerminalProtocol | 不写 `complete-v1`，部分 reasoning 不成为 source | 否 | 否 |
| 流 `error` | TransientProtocol 或既有错误类别 | 终止 Attempt，Runner 按既有策略处理 | 可能 | 否 |
| 流 `abort` 或外部 abort | 无 | 不提交，按取消语义结束 | 否 | 否 |
| idle/total timeout | TransientProtocol 或既有超时语义 | abort 当前 Attempt，禁止该 Attempt 提交 | 依当前 Runner | 否 |
| flush 失败 | TransientProtocol 或本地写入错误 | 不得 finalize/complete；仅 Runner 决定是否 replacement/retry | 依当前 Runner | 否 |
| completeAssistant 失败 | 本地控制面错误 | Run 失败或按既有控制面语义处理；不得假定完成 | 否 | 否 |
| replacement 失败 | 本地控制面错误 | 终止 Run，不得继续旧 Assistant | 否 | 否 |
| 失败 Attempt 已输出 | Transient/Terminal | replacement 成功后清空全部 Attempt/output state，再发新请求 | 可能 | 仅新 Attempt 成功后 |
| recovery 恢复 | 无 | 从已持久化有效历史重建，不复用网络 Attempt 内存 state | 依既有恢复规则 | 仅最终完整成功后 |
| 目标 schema 下 Assistant snapshot 缺失/损坏/冲突 | Invariant | 不推断或补写 snapshot，不认领续跑，不发送 Provider HTTP；走 fenced failure/convergence 使 Run 与 Message 离开 running | 否 | 否 |
| superseded/failed/cancelled Assistant | 无 | 不进入 state source | 不适用 | 不适用 |
| compaction 后 resolver 外旧 state | 无 | 不读取、不补回；retained tail 中的兼容 state 按正常规则处理 | 不适用 | 可以 |
| single-call / messages-context | 无 | 不取得、不透传私有 state，也不启用 DeepSeek 特化 | 不适用 | 可以 |
| DeepSeek `toolsDisposition: "omitted"` | 无 | 不注入 DeepSeek reasoning；空 toolSet 必须为 omitted | 不适用 | 可以 |
| DeepSeek `present-non-empty` | 无 | 仅回放最后 User 后、scope 内全部兼容且诊断完好的 reasoning | 不适用 | 可以 |

## Debug 日志独立方案

### 要解决的问题

当前 Assistant debug dump 记录的是：

```ts
request: { ...requestBase, messages: context.messages }
```

而实际 `streamText()` 使用已 replay 注入、再附件物化的 `materializedMessages`。因此旧日志不能证明最终 AI SDK 是否收到了 reasoning state。

日志改造是 Phase B 的独立行为变更，不属于 OpenAI 等价重构。

### 目标语义

Phase B 的投影对象不是孤立的 `request`，而是完整的 **Assistant Debug Record**。建议由唯一入口 `projectAssistantDebugRecord()`（最终名称可按项目风格调整）在 running、completed、failed 三种写入路径生成同一受限结构。

该函数必须覆盖并统一处理：

- `request`：脱敏后的最终 AI SDK 入参投影；
- `response`：普通 response text、reasoning 摘要、finish/status 与受限 metadata；
- `toolCalls`：工具名、ID 存在性、工具 input 与 result 的受限投影；
- `error`：`Error.message`、cause、字符串化 JSON 与其他错误字段的安全摘要；
- record 级状态、计数和固定诊断字段。

其中 `request` 应表示：

> 脱敏后的最终 AI SDK 入参投影。

它不是：

- 注入前普通 transcript；
- JavaScript 对象的完整 dump；
- SDK 编码后的最终 HTTP JSON body；
- 原始 SSE、Provider 原始响应或未脱敏错误对象。

若保留 source 信息，名称必须明确为 `sourceMessages`，并仅表示 replay 注入前的 Provider-neutral transcript。默认不记录该字段，避免重复、体积膨胀和使用者误判。`request.messages` 必须只表示最终入参投影。

### 必须实现专用安全投影

禁止机械地将 `messages: context.messages` 改为 `messages: materializedMessages`，原因是后者可能包含文件内容、图像/base64、可见 DeepSeek reasoning 和 Provider metadata。

投影至少满足：

| 数据 | 日志行为 |
|---|---|
| OpenAI `encryptedContent` / `reasoningEncryptedContent` | 固定 `"***"`，记录 `present`；绝无文本预览 |
| DeepSeek 可见 reasoning | 不记录任何文本预览；仅记录 `present`、Unicode code point 长度及 `truncated`/`omittedReason` |
| API key、Authorization、Cookie、Token、Secret、Password | 固定 `"***"` |
| Provider replay envelope | 不写原文；仅协议、是否存在、可选数量摘要 |
| 附件二进制、data URL、base64 | 不写内容；仅 Part 类型、media type、受限 filename、byteLength、`hasHash` |
| request 中普通 user/assistant 文本、response.text | 单字段最多 4 KiB UTF-8；超过时按完整 Unicode code point 截断，并标记原 `byteLength` |
| toolCalls 的 input / result | 先递归清理敏感键、附件/base64/data URL，再对每个可输出字符串字段应用 4 KiB UTF-8 限制；不得因为来自 tool 而获得更大配额 |
| `Error.message`、cause、错误字符串、字符串化 JSON | 先按敏感键递归清理，再对每个输出字符串字段应用 4 KiB UTF-8 限制；不得借 Error 或预先 stringify 的 JSON 旁路 |
| response.reasoningText（DeepSeek） | 不记录正文或预览；仅 `present`、Unicode code point 长度、`omittedReason:"reasoning-no-preview"` |
| 原始 SSE / HTTP body | 不记录，除非未来另立受控诊断设计 |

建议 reasoning 投影形态：

```json
{
  "type": "reasoning",
  "providerProtocol": "openai-responses",
  "hasItemId": true,
  "hasReplay": true,
  "reasoningEncryptedContent": "***"
}
```

DeepSeek：

```json
{
  "type": "reasoning",
  "providerProtocol": "deepseek-chat-thinking",
  "present": true,
  "unicodeCodePointLength": 123,
  "truncated": true,
  "omittedReason": "reasoning-no-preview"
}
```

数值仅为结构示例。OpenAI 密文和 DeepSeek reasoning 均无文本预览；DeepSeek 在 UI 可见不意味着 debug 有权复制它。

### 固定投影限额与确定性截断

以下数值是 Phase B 的强制规范，不得由环境变量或调用方任意放宽：

| 范围 | 限额 | 确定性规则 |
|---|---:|---|
| 普通 user/assistant/response 文本、任一 tool input/result 或错误字符串字段 | 4 KiB（4096 UTF-8 bytes） | 清理敏感键后，从开头按 Unicode code point 逐个累加 UTF-8 byteLength；下一个 code point 超限即停止。输出 `truncated:true` 和原始 `byteLength`。不按 UTF-16 code unit 截断，不产生半个 surrogate pair。 |
| DeepSeek reasoning | 0 文本 bytes | 固定省略正文；输出 `present`、Unicode code point 数、`truncated:true`、`omittedReason:"reasoning-no-preview"`。空文本为 `present:false`、长度 0。 |
| OpenAI 密文 | 0 文本 bytes | 固定 `"***"` 和 `present`；不记录长度、hash 或预览。 |
| 附件 filename | 最多 256 Unicode code points | 保留前 256 个 code points；超出时 `filenameTruncated:true` 和原 code point 数；正文/data URL/base64 始终省略。 |
| 整份 Assistant Debug Record | 256 KiB（262144 UTF-8 serialized bytes） | 对完整 record 的 canonical JSON 投影序列化后测量；超过时按下述固定优先级降级。request 不能单独占满记录配额。 |

完整 Assistant Debug Record 的超限降级顺序固定为：

- 首先移除 request/response 中全部普通文本与 tool input/result 的已截断正文，保留 `byteLength`、`truncated`、角色、Part 类型、工具名、toolCallId 是否存在、output 类型和计数；DeepSeek reasoning 与 OpenAI 密文继续保留其无正文存在性摘要；
- 仍超限时移除 request 的 system、assistant/user 文本内容以及 response.text，保留每条消息角色、Part 类型、附件摘要、replay 是否存在和 response/finish 计数；
- 仍超限时移除 tool input/result 的结构详情和 error 的非必要诊断字段，保留 tool name、toolCallId 是否存在、错误类别/名称、是否有 message/cause 及计数；
- 若仍超过 256 KiB，只输出结构摘要：record status、provider protocol、request message/role/part/tool/replay 计数、response/tool/error 存在性和计数、各敏感字段存在性，以及 `projectionOmittedReason:"assistant-debug-record-limit"`。

投影必须以稳定字段顺序和稳定遍历顺序构建，同一输入必得同一输出；不得通过随机 hash、对象枚举偶然顺序或“尽量保留”策略改变结果。

### 日志写入时机

- running、completed、failed 三次写入必须调用同一个 `projectAssistantDebugRecord()`，避免 request、response、toolCalls 或 error 的任一路径绕过安全投影。
- request 子对象在最终消息准备与附件物化完成后投影；失败发生在该阶段前时，record 必须记录安全错误摘要和 request 缺失原因，而非伪造 request。
- completed/failed record 的 response、toolCalls、error 均必须由同一函数在写入时投影；不得先把未处理对象写入日志再事后清理。
- debug 写入失败只能记录安全摘要 warning，不能影响正常模型执行。

### 必测 sentinel

- 构造只会在 `request`、`response.reasoningText`、tool input、tool result、`Error.message` 和字符串化 JSON 中出现的不同 sentinel；每个最终 Debug Record 均不得包含任何一个 sentinel。
- 对 response.text、tool input/result、错误字符串分别验证 4 KiB UTF-8 完整 code point 截断与敏感键清理；对 DeepSeek `response.reasoningText` 验证只输出 `present`、Unicode code point 长度与 `omittedReason`。
- 构造超过 256 KiB 的 running、completed、failed record，逐级断言固定降级顺序、稳定序列化结果和最终结构摘要；不得仅测试 request 子对象。

## 公开面与安全验收边界

以下目标中不得出现**私有 Provider state、OpenAI 密文或其可恢复原文**：

- 前端 API、Timeline、公开 Message 映射中的私有 metadata；
- Archive、搜索索引、messages-context；
- compaction prompt、shared single-call；
- 普通日志、错误消息、debug dump；
- 数据库以外的非专用导出或缓存。

DeepSeek 第一版可见 reasoning Part.`text` 是明确例外：它可按既有消息 UI/read-side 语义出现；这不授权 Provider replay metadata 或完整 debug 复制出现。

允许持有私有 state 的边界仅包括：

- `agent_message_part.provider_replay_json` 的受控存储；
- 私有 read-side 到 PromptContext 的内部传输；
- Worker 内 Adapter 物化的短暂内存；
- 经专用安全投影后的 debug 元信息。

任何新增路径若需要访问 state，代码审查必须明确说明其必要性、最小数据字段、输出面和脱敏测试。

## 维护 CLI 操作边界

```bash
npm run maintenance:git-lease -- --help
npm run maintenance:git-lease -- inspect --data-dir <physical-data-root>
```

- CLI 不加载 `.env.local`。配置顺序为显式 `--data-dir`、当前进程 `AWB_DATA_DIR`、`.data`；须使用与部署一致的物理数据根和 OS 身份。inspect 仅打开安全元数据，不启动服务；inspect 本身不能证明可释放。
- release 只允许单个合法 lease ID、完整 `expectedOwner` 与 `expectedState`；正常 meta 需要四字段 owner，坏 meta 只能 `unreadable`/`null`，且禁用 `known_scope`。
- 操作者先建立适用维护窗口、停止主服务/调度/Worker 及覆盖范围内启动源、禁用自动拉起，保持独占到 CLI 退出。使用 `--window`、安全记录 ID `--evidence-ref`、四项确认 flag；known_scope 另提供可信当前范围的 `--known-pids`/`--known-pgids`。CLI 只做 signal 0 检查，不杀进程、不发现全局 supervisor。
- 必须在 stdin 精确输入 `RELEASE <leaseId>`。CLI 与正常 release/janitor 复用同一 v2 服务/锁/固定 fd 删除算法；在锁内重新核对 expectation，合法 meta 先持久化 stopped 再删除，坏 meta 不合成替代 stopped 文件。失败保持相应 hold/stopped，而不执行 Git、不重试命令。
- 定点删除后检查目标不存在、其他 hold 保持；退出 CLI 后才能按部署程序恢复服务。主 API 启动时 guard 必须先于 pending 删除恢复。实际部署证据见下节，尚未执行的窗口不能以 fixture 确认冒充。

## M1/M2 修复与关闭证据

- **M1（Fix）**：v2 唯一 `readMeta()` 的 open flags 增加 `O_NONBLOCK`，保留 `O_NOFOLLOW`、fd fstat 的普通文件/nlink/0600/64KiB 检查、有界 read 和 finally close。没有增加运行时超时框架。真实 Linux `mkfifo` 没有 writer，inspect 返回 unreadable；batch inspect、普通 release、Workspace guard、janitor 和缺适用维护证据的调用均在隔离 child 的 5 秒测试边界内结束并保持保护。生产路径没有这层测试超时机制。

- 完整维护窗口没有被笼统禁用：`unreadable/null` 的普通损坏 meta 在两个完整窗口声明下仍可定点释放并保留其他 lease。FIFO 本身仍受原有共享 flat-regular-artifact 删除规则拒绝；不为修复读阻塞放宽特殊文件删除边界，不伪造 stopped meta。fixture 确认不证明真实部署窗口。

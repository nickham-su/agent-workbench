## 本次改造的闭环

```text
每轮读取当前 Workspace 登记仓库名
  → 动态加入 git 工具描述
  → 模型调用 git(repo, args, timeout)
  → API 校验运行归属、登记仓库并准备仓库认证租约
  → Worker 在选定仓库直接启动 git，原样传递 argv
  → 所有退出共享同组收尾/确认停止/脱敏；确认后释放，否则持有保护并运维恢复

同时：删除 Bash 的 Git 命令识别和项目主动凭证注入
```

## 固定范围

- 新增可配置内置工具 `git`；不是 `action` 枚举，也不是任意 Shell 执行接口。
- `repo` 只允许当前 Workspace 的登记 `dirName`；显式选择，即使只有一个仓库也不自动补齐。
- `args` 原生透传，不维护 Git 子命令或危险参数名单；不自动补 `git`、`-u`、`--ff-only` 或仓库地址。
- 有效仓库名每轮刷新，执行时重新校验；仓库不可用时，只有经过共享严格 response schema 校验的 `REPO_NOT_AVAILABLE` 才将最新安全登记名作为完整 JSON 数组写入模型错误，空数组显式显示，不截断 100 项、不自动纠正或重试；额外诊断不复制名单。首版不依赖动态 schema enum。
- 同次删除 Bash 识别、prepare/cleanup 消费者和仅为它服务的协议，不保留兼容 fallback。
- 保留 API Git、交互式终端、终端凭证开关以及可复用的认证和租约清理能力。
- 凭证选择以登记仓库配置为准，复用既有 Git 认证权威实现；不使用 `terminalCredentialId`。
- Git 子进程不继承 Worker 内部 `AWB_*`；不顺手修改 Bash 的整个环境继承策略。
- 不自动给已有或新建 Agent 启用 `git`；用户显式开启后生效。
- Git timeout默认120秒、最大3600秒；有效stopped常规残留最长65分钟到期，正常清扫最多再等5分钟；未确认不靠TTL解锁，prepare/release故障也可能需要维护。
- 正常父退出同样收尾同组后代；只有受管范围停止被确认，才允许租约回收和项目删除保护解除。
- 新Git停止确认发布基线为Linux/POSIX；无经验证等价能力的平台明确拒绝新工具，不顺手改变Bash。
- 仅prepare/release两个新增RPC；元数据状态unconfirmed/stopped，正常release与janitor复用进程内短临界区，单调确认且不复活已删目录。
- 普通child/数值PGID监督不是强OS身份；首次ESRCH后不再向同号发信号，观测间重用竞态仍在，未知/zombie-only未消失均保守持有。
- 同机维护CLI直接调用同一租约服务，凭既有OS权限/受信根/停机窗口，不启动HTTP、临时token、Agent/fallback/调度/删除恢复；正常Worker RPC仍内部鉴权。
- helper不自动证明完整宿主静止或外部supervisor已关闭。坏meta/范围信息不齐只能用已验证覆盖全部执行的受管环境全停或重启后服务未启动维护窗口，证据不足保持hold，无安全现场恢复保证。

## 审查和验收使用规则

- 参数、上下文、凭证、取消、租约、迁移等权威规则分别集中在 `RULE-*` 小节，其他文档通过链接引用，不另维护不同版本。
- 验收项使用稳定的 `AC-*` 标识，实施任务使用 `TASK-*` 标识；不得只用测试文件名表示已验收。
- 全部验收项都必须有测试或人工证据；故障注入只能使用测试仓库和伪造凭证。
- 设计承认原生 Git 的能力边界。不能把“`repo` 已校验”表述为“所有 Git 子进程均被限制在该仓库”；不能把“没有 Shell 拼接”表述为“Git hooks/alias 不会运行程序”。
- 工作区和内部控制面的既定安全保护仍需遵守。通用执行隔离不是本次新增能力，不能用工具描述或参数名单冒充隔离。
- 发生超时、取消、输出超限或结果写回失败时，不承诺 Git 副作用回滚，也不得自动重复命令。

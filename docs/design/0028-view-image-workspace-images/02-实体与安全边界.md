# 实体、存储、路径与安全边界

## 路径与图片元数据

- **Workspace 根**由已授权的 `workspaceId` 查得，不由工具提供；当前默认是 `<dataDir>/workspaces/<dirName>`，仓库通常位于其子目录：`apps/api/src/infra/fs/paths.ts` 的 `workspaceRoot()`、`workspaceRepoDirPath()`。新上传图片最终在该根的 `.awb/agent/attachments/`，不是 `dataDir/agent/attachments/by_workspace/`，也不是某个仓库内部。
- 新上传图片使用不可由原始上传文件名决定的安全文件名：`att_<安全ID>.<png|jpg|webp>`（JPEG 统一 `jpg`）；使用检测出的 MIME 选择后缀。历史占位路径是 `.awb/agent/attachments/<storage_key>`，`storage_key` 必须经服务器规则校验，且 attachment.workspace_id 与当前 Workspace 一致。`filename` 仍是供下载／显示的清洗后原名，**不是**路径权威。单图片字节 1–10 MiB，PNG/JPEG/WebP 签名校验。
- 任意截图可在 Workspace 内其他目录（如 `repo/screenshots/page.png`）；其 `view_image` 结果路径记录为经规范化的 Workspace 相对路径，**不搬入** `.awb`。不得使用绝对路径、`..`、空路径、NUL、换行、不可显示的控制字符、路径别名或者目录本身；推荐只接受正常文件路径且拒绝任何路径分量软链，不因为软链最终仍在 Workspace 内就放宽。统一使用 `/` 展示分隔符，安全转换为宿主 OS 路径时重新校验。
- 图像类型以实际已读取的字节签名决定，并核验其允许的扩展名与 MIME 一致（`jpg/jpeg` 对应 JPEG）；伪装后缀、GIF/PDF、空文件、非规则文件明确失败。信任边界是**文件句柄及其数据**，不是字符串／客户端声明的 MIME。单次工具读取及模型发送前重读都做大小和签名校验。

## 上传提交、读取与删除

- `apps/api/src/modules/agent/routes/agent-public.routes.ts` 的 `parseAgentMessageMultipart()` 在 dataDir temp 接收最多 4 张、单张 10 MiB、合计 20 MiB；`apps/api/src/modules/agent/attachments/agent-attachment-storage.ts` 的 `stageAgentImageUpload()` 检测签名。上传文件先异步暂存、预校验，尚未由事务判定业务状态前不发布到 Workspace；暂存清理尽力进行。
- `sqlite-run-lifecycle-persistence.ts` 的 `activateUserRun()` 使用 SQLite **IMMEDIATE 事务**，在读取幂等、Session 运行状态、标题与 fork 状态前取得写锁；权威判定通过后，才在事务内同步、排他 hardlink 发布到当前已授权 Workspace 的 `.awb/agent/attachments/`，随后写入附件、用户消息和 Run，成功后入队 Worker。两个 SQLite 连接争用时，失败／重复请求不得在判定前发布 final；不复制图片字节以延长写事务。`validateUserRunImages()` 对新记录严格核验 `storageKey` 的 ID 与 MIME 后缀，确保 DB key 对应安全发布的文件；事务回滚不能留下半完成的消息或 Run。
- Workspace 目录可由同一用户的工具并发修改：目录创建和发布绑定安全目录身份／文件 inode，排他 hardlink 不覆盖已有目标，路径层级被替换或软链劫持时拒绝；**已发布的 final 不能靠“检查 inode 后按路径 unlink”安全删除**，即使把文件移动到 Workspace 中的临时删除槽也仍有竞争窗口。普通幂等／Session／标题／fork 冲突在发布前终止，不产生孤儿；发布成功后若后续 SQL、磁盘操作或进程异常，SQLite 回滚可能留下无 DB 关联文件，禁止盲目删除或覆盖，保留有限、脱敏诊断供人工核查（进程崩溃时不能保证即时日志）。不新建孤儿数据库、配额或定时清扫；遇到跨设备硬链接不可用等情况安全失败，尽力清理 dataDir 暂存，不做不受控复制。Workspace 删除路径（`apps/api/src/modules/workspaces/workspace.service.ts`）应覆盖新 `.awb` 目标；旧 data 根附件依既有清理处理，不引入越界清理。
- Web 受控预览由 `apps/api/src/modules/agent/agent.composition.ts` 的附件归属查询、`resolveSafeAgentAttachmentContentPath()` 和 `apps/api/src/modules/agent/routes/agent-public.routes.ts` 的 `GET .../attachments/:attachmentId/content` 共同实现。**实施前基线（设计时）**：`agent.composition.ts` 当时要求 `storageKey === attachmentId` 且传 `dataDir` 找旧文件；现已实现按**可信新 key = ID + MIME 后缀**取 Workspace 相对 path 并验证**session 可见消息 → image part → attachment.workspace_id → 正确 Workspace 实文件**，返回经安全打开的同一 inode。旧 key 不具新规范时受控失败即可；不要用工具的图片路径替代这套 Web 鉴权，不要开放 `.awb` 静态预览。`apps/api/src/modules/preview/preview-file.service.ts` 拒绝 `.awb` 段，保持这一限制。

- **实施前基线（设计时）**：API read-side 的 `ModelContextResolver.resolve()` 已有 message parts、独立 `agent_attachment` 和工具执行查询，但其 `ResolvedContextBlock.attachments` 当时只含附件 ID/MIME/filename。现已补齐**按本 Workspace 成批查询 `agent_attachment` 的 join**、严格验证真实 attachment 记录／ID／MIME 后给该 block 的上传图片附上 `relativePath: string | null`。新格式值成为**唯一**普通历史占位、压缩占位及当前 `attachment_ref.path` 的生成依据；如触发 Run 缺 path 则明确本地失败，旧历史无 path 仍可读。工具结果的 `image_ref.path` 使用独立的已校验 ToolExecution 字段，不与此映射混淆。
- **实施前基线（设计时）**：Worker 的 `apps/agent-worker/src/runtime/agentAttachmentStorage.ts` 当时按 dataDir 的 `by_workspace/<workspaceId>/<attachmentId>` 打开附件。现使用内部 `attachment_ref.path` 与可信当前 Run 的 `workspacePath/workspaceId` 读取：预期必须匹配 `.awb/agent/attachments/<storage_key>` 且该 key 的附件 ID、后缀、MIME 与引用一致；在真实 Workspace 根内基于安全目录／句柄校验并重验字节，拒绝路径穿越及软链；不得重新从 dataDir 拼路径或信任客户端 filename。Worker 不直接访问 DB，依赖 API 已授权的 ID+path 配对以及自身再次校验。

## `view_image` 的安全读取与持久化

- 仅在现有 Worker tool registry 授权、Run 的 Workspace 上下文中执行：输入 schema 为唯一必填 `path`（非空 Workspace 相对路径），禁止自由 URL、`file://`、data 目录路径、`attachmentId`、数组 `paths`。工具可调用多个独立 `view_image` 实现多图，不将多路径封进单次调用。
- 将 Workspace 根和逐级路径绑定到安全的已打开目录／文件句柄：检查规范化相对路径及根目录实路径边界；通过 `O_NOFOLLOW` 和文件／祖先 inode 校验拒绝软链与路径置换；`fstat` 确认为规则文件且 `1..10 MiB` 后从**该句柄**有界读取；读取后复核大小及字节签名。**实施前基线（设计时）**：旧 `apps/agent-worker/src/runtime/tools/providers/builtin.ts` 的 `resolveVisualInputFile()` 用 `realpath → stat → readFile(path)`，后两步之间仍可换文件，不应误认为当前 `view_image` 的读取方式。
- 成功仅返回 `{type:"image_ref",path:"<经过校验的相对路径>"}`，若未来确需文字可用 `[text,image_ref]`，不得返回 Uint8Array/Base64 给通用 runner。`apps/agent-worker/src/runtime/runner.ts` 的工具返回值可进入 `buildToolSuccessText`、`structuredResult`、`writeItemLog`、失败诊断；须将“有图”与“图片字节”严格分离：**结构化结果仅含路径**、preview／日志仅含必要路径元数据且不能记录文件内容、调试请求日志不能 dump 转换后的媒体。API 的工具完成写回必须验证 ToolExecution 属于该 Workspace/Session/Run 且 status/fence 合法、工具名为 `view_image`，图片引用只有此工具的 completed 状态可写；验证失败不可仅丢弃 structuredResult 然后标记成功。
- **每次模型请求尝试**（首发和自动重试）都复用同一安全读取器**重新打开**用户图和工具图；不因为 ToolExecution 存了 path 就免检，不允许复用上一 attempt 的 Uint8Array/Base64。图片被覆盖、删除、MIME 不符时按当前内容安全失败或读取变化后的有效图片（与原图不同被产品接受）；**无快照、无内容哈希一致性承诺**。从用户上传 ID 到 Workspace 路径属于 API 可信映射；从工具 path 到模型媒体必须检查执行的 `originRunId === 当前Run.runId`、Workspace/Session 匹配及该结果的调用 part 归属，而不仅仅检查路径看起来存在。

## 使用限制与风险

- Workspace 默认根通常不在各子仓库内，但用户可能以不同 Git 布局工作；repo 自身 `.gitignore` 并无通用 `.awb/` 规则，不自动修改用户仓库 `.gitignore`／`.git/info/exclude`。文档明确提醒可能被 Git 收录；以安全的 Workspace 根作为默认上传位置。
- 此处无需新建 ToolExecution 图片附件表，也不借用 dataDir 作为 `view_image` 的持久化快照目录。保留 `agent_attachment` 给上传图片的 UI 权限及元数据，不把原本属于图片上传的受控 Web 内容接口泛化成“任意 Workspace 文件下载”。

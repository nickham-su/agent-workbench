# 验收标准、负例与代码审查清单

此文件是**必须实际验证**的行为清单，而非“原则上应该安全”。测试建议以已有 API 集成测试、Worker 单元／runner 集成测试、shared schema 测试为主；能在模型适配前构造测试替身就不调用真实收费 Provider。用可识别的**测试字节序列**断言不得出现在 DB、日志、preview 和调试 artifact 中；不要使用真实凭证或私人图片。

| 验收场景 | 可观察断言 | 测试切入 |
| --- | --- | --- |

## 工具读取、持久化与恢复

| 验收场景 | 可观察断言 |
| --- | --- |
| 合法文件与单项结果 | `view_image({path:"repo/screenshots/page.png"})` 成功，ToolExecution `completed` 的结构化结果**恰好** `{type:"image_ref",path:"repo/screenshots/page.png"}`，允许只有 image_ref；工具执行过程中不触发单独视觉模型调用。上传目录下的文件同样可读 |
| 路径安全负例 | 空 path、绝对路径、`../`、越界解析、软链（含父目录）、路径换 inode、目录／非规则文件、NUL／换行／控制字符及拒绝的扩展名均失败；目录本身或 dataDir 图片存放地址不可越过 Workspace 根。拒绝后的工具不能提供图片结果或读取边界外字节 |
| 字节限制与真实 MIME | 测试单图 1 字节／>10 MiB、PNG 扩展名但 JPEG 字节、GIF／PDF 及**签名无效／截断到不足签名长度**的 PNG/JPEG/WebP；只认允许的字节签名且与后缀匹配，不承诺完整图片解码校验。工具阶段错误仅为该 callId 的 `error-text` |
| 持久化权威与授权 | resultPreview 故意截断或构造误导性图片路径时模型仍从合法 `structured_result_json` 取原路径；伪造结构化结果、别的 toolName、别的 Workspace／Run、缺少 originRunId、failed／unknown 工具执行不能触发图片读取；坏数据 fail closed 并保持历史可诊断 |
| 可变源与恢复 | 工具成功后原图仍在，本 Run 后续步骤与以新 Runner＋真实 API PromptContext 模拟的 Worker 恢复按路径重读；删除后出现**本地请求前失败**，不发送缺图请求；合法覆盖后可读到新内容，不承诺原字节；图片字节不持久化到任何表、preview、structured JSON、artifact／日志；此测试不等同于进程级重启 E2E |

## Run 隔离、并发与协议

| 验收场景 | OpenAI Responses／Anthropic | OpenAI-compatible／Moonshot／DeepSeek |
| --- | --- | --- |
| 当前 Run 单图（无成功提示文本） | 原 `toolCallId` 的工具结果 `output.type=content` 且唯一媒体项，SDK 实际序列化图片，无强制文本 | 相同 callId 的纯文本 tool 应答后恰好一条 user 消息，含 path/callId 标签及 file part；tool 文本绝无 Base64 |
| 同轮两图并发，B 先完成 | 两个媒体结果分别绑定 A/B callId，仍按**模型调用位置 A、B**发出 | 先发 A、B 的全部文本 tool 结果，再一条 user 消息，依次 `label(A),file(A),label(B),file(B)`；不能夹在两条 tool 回复中 |
| 同轮 view_image 成功 A、失败 B、普通 read 成功 C | A 发图，B 错误文本，C 原样文本；每个 callId 恰好回复一次 | 文本 tool 应答 A/B/C 全部到齐，仅 A 追加图片；B/C 不凭位置误配 A 图 |
| 两个 view_image 都失败 | 两个错误 tool 输出，不附图 | 仅两条 tool 错误输出，**不追加空 user 消息** |
| 图片预算 | 一张 10 MiB 合法；多次 view_image 调用数量不限，**一次模型请求**中混合上传图与工具图之和 >20 MiB，本地明确失败，无“丢弃第三张图但成功回复” | 相同；聚合检查在向 SDK 传递之前，不能在两条完整 tool 文本应答之后只发部分成功图 |
| 后续 Run 与无 Run 消息阅读 | view_image 历史仅 path 文本 tool 结果，不含媒体；用户历史仅原文字／上传图路径 | 同左；不追加媒体 user 消息，消息的 toolCallId 及原 call/tool 顺序不变 |
| reasoning 回传 | 不破坏现有 Responses 私有重放边界 | Moonshot/DeepSeek 先恢复 reasoning 原有可见序号，再插入图片 user 消息；验证 DeepSeek last-user 位置和两 Provider 连续兼容 reasoning 回传，不能因图片导致已授权 reasoning 重复或错位 |
| 首轮 Provider 出错后的文件删除 | 分别测试**工具图片**和**上传用户图片**：首轮请求已有可识别的图片字节，远端异常进入 backoff，期间删图；下一 attempt 必须在 Provider 调用前本地失败，Provider 调用次数不增加，终态为可诊断的一般本地失败 | 相同；不能重发上一 attempt 的 bytes，也不能走模型报错重试分支继续背压 |
| 首轮 Provider 出错后的有效覆盖 | 分别测试**工具图片**和**上传用户图片**：在退避期替换为**同格式的不同图片字节**；第二 attempt 安全重读并用新 bytes 构造新 requestBase（含所有预算复核），断言首次字节不会重发或残留；reasoning 不重复处理 | 相同；Chat 仍先全部 tool 应答，再一条新鲜的 user 多图消息 |

- 每一种 Provider 均至少做一次**进入所安装 SDK 序列化器的离线测试**，断言 OpenAI `function_call_output.output[]` 含 `input_image`、Anthropic `tool_result.content[]` 含 `image`、三种 Chat 只有 user `image_url` 而 tool content 没有 Base64／`JSON.stringify` 媒体对象。Provider 无法识别图片时报模型请求错误，按原有 Runner 重试次数和终态处理；单独验证在**模型请求之前**读取失败不算“Provider 不支持视觉”、不进入该自动重试策略。
- 提供典型两工具完成顺序互换的并发测试，断言相同的稳定 transcript，不仅检查输出数量。人工审查每组 assistant.tool_calls 是否全部被相同 toolCallId 的 tool 结果回答后才出现 synthetic user。

## 压缩、旧记录与配置

- 压缩 API source 窄 schema、API resolver、Worker materializer/planner、summary 输入以及普通 PromptContext 对**相同路径和 Run**投影一致：工具图不在 retained tail 时使用 callId+path 文字占位进入 prefix 摘要（无需图片字节）；确需媒体的同 Run retained tail 安全读图。tool-only 图片超保留尾部预算仍可继续路径文本摘要且**不触发 `media_requires_resend`、不将工具块填入 `triggerMessageId`**；用户触发图超预算继续沿原专用 `media_requires_resend` 逻辑。保留工具图所需源文件删除或合法性无法维持时为一般本地失败，不静默丢媒体、也不要求用户重发工具图片。
- 测试包含“一个只含工具图片的超大源块进入摘要前缀、一个可合法保留的后续消息作尾部”，断言 planner 正常生成计划、摘要模型仅收到工具结果路径文字；“当前 Run 工具图片在 retained tail”按原文件成功携图、文件删除后本地失败；“用户触发图片不适合保留”仍返回原用户图 `media_requires_resend(triggerMessageId=原用户消息ID)`，工具图片绝不影响该 ID。
- 用户历史图片（新图、无有效新路径旧图）在普通投影与压缩路径占位一致；构造数据库中已持久化的 `visual_analyze` tool-call／结果，经 AgentMessage schema／内部 RPC／前端读取历史均合法且不执行旧工具；旧含 `visionModel` 的 settings JSON 可读取但旧配置不重新启用旧路径，新工具可用列表、执行 Profile、Web UI、RPC 的**新调用面**不暴露 `visual_analyze`、`vision`、`visionModel`。回归工具禁用／权限快照与配置归一化，不因收窄新可配置 union 使历史崩溃。
- 前端不因为新路径而直接向 `.awb` 发 HTTP 静态请求；面向附件的授权接口与 MIME、安全策略不退化。

## 不泄漏与审查否决项

- 拒绝任何图片 bytes/Base64 进入 `agent_tool_execution.structured_result_json`、resultPreview／result artifact、工具日志、Assistant debug artifact、错误栈或 Worker RPC 文本；没有必要在业务错误中回显绝对文件路径、用户凭证或文件内容。
- 审查代码是否在任何媒体授权前**核验 ToolExecution originRunId**，并且对旧 tool 结果、preview 伪路径、compaction source 缺少 Run ID 都 fail closed。并发路径的工具结果顺序不得跟着任务完成时间漂移。
- 审查 IMMEDIATE 事务内的发布时机及双连接争用：普通去重／冲突不发布 final，发布后异常不按 Workspace 路径删除用户可能替换的文件；文件读取是否以**验证后的同一个文件句柄**读 bytes（不能只靠 `realpath()` 再 `readFile(path)`）；symlink／路径穿越与 Workspace ID 不能突破隔离。

- 审查没有残留独立视觉模型调用、`visionModel` 重新启用配置及 GIF/PDF 支持承诺；不自动写用户的 Git 忽略配置，不放开 `.awb` 静态访问。

## 定向自检命令

在仓库根目录依变更执行，失败项记录成具体可重现的测试名，不能只报“已通过测试”：

```bash
npm run build -w packages/shared
npm run typecheck -w apps/agent-worker
npm run typecheck -w apps/api
npm run typecheck -w apps/web
# 执行受影响 workspace 的图片上传、安全读写、PromptContext、压缩、Provider 投影与设置相关定向测试
```

若修改跨全部 workspaces 的共享契约，最终加跑 `npm run typecheck`；不需要真实 Provider API Key 即可完成协议与安全验收。

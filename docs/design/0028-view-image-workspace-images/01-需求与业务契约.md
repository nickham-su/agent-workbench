# 需求、业务流程与可见性契约

## 使用流程

- 用户从 Web 上传一至四张图片。API 在 dataDir 流式暂存并异步预校验图片；确认 Workspace 后，SQLite `activateUserRun` 使用 IMMEDIATE 事务取得写锁，先权威判定幂等、Session／标题／fork 冲突，再以同步、排他 hardlink 发布新附件至 Workspace 根 `.awb/agent/attachments/`，写入附件、消息与 Run 记录，成功后入队 Worker。普通冲突不会发布最终文件；暂存清理尽力进行。前端图片展示仍通过已授权的 `sessionId + attachmentId` 内容接口获取，不使用公共静态路径。
- 本次用户 Run：API 依据该 Workspace 的可信 `agent_attachment.storage_key` 构造内部 user `attachment_ref.path`，Worker 安全重读原文件，把原文字与真实图片发给主模型；首次尝试、每次自动重试以及该 Run 后续 step 均如此。后续 Run 的相同历史 user message：原文字 + **由同一可信附件记录**按原消息 part 顺序生成的每图相对路径占位；**不附图、不生成内容描述**。旧 DB 图片若无新规范路径则按旧无路径占位处理，不会让历史读取崩溃。

- 模型可在可用工具清单中调用 `view_image({path:"repo/screenshots/page.png"})` 或 `.awb/agent/attachments/att_...png`。工具仅读取 Workspace 中文件并识别真实 PNG、JPEG、WebP；无第二个视觉模型请求。成功的原路径随 ToolExecution 持久化；随后主模型的请求附带图像，工具本身可仅返回图片，无需额外成功文本。失败为工具错误文本，不得“失败但附图”。
- 图片工具结果的后续历史保留同一安全路径的文字占位；下一 Run 如需重新看图，再次调用工具。模型**从未被告知已看过**那些未作为多模态字节发送的图片。

## 推荐占位文本

- 新上传图片的**历史** user message（路径按 image part 顺序）示例：

```text
<用户原有文字；如果没有原文字则省略本行>

[Image 1: .awb/agent/attachments/att_a.png]
[Image 2: .awb/agent/attachments/att_b.webp]
[Image contents are not included in this run. Call view_image with a path above if needed.]
```

- `view_image` 在**其他 Run**中的历史 tool result，应保持相同 `toolCallId` 对应关系，输出仅为文本；不能在这一轮追加图片 user message：

```text
[Image viewed in an earlier run: repo/screenshots/page.png]
[Image contents are not included in this run. Call view_image with this path if needed.]
```

- 不可提供经验证的可用新路径的旧用户附件，只写“历史消息含图片、本 Run 未提供图片字节”，不编造 `.awb` 地址。旧 `visual_analyze` 的历史调用按原有文字结果可读，不进入新工具图片规则。
- 路径来自系统持久化且经过校验的相对路径／附件元数据，不从旧 resultPreview 或用户原文件名逆向构造；持久路径可以在之后失效，因此占位表示**曾经的可尝试路径**而非保证可读。对包含换行、控制字符等不能安全展示的文件路径，在工具入口就拒绝，不得让路径文本变成伪造消息指令。

## 状态与边界矩阵

| 场景 | 工具／持久状态 | 本 Run 向模型发送 | 后续 Run 向模型发送 | 失败或边界 |
| --- | --- | --- | --- | --- |
| 新用户上传单图／多图 | Workspace 内新附件，DB user image parts 关联附件 ID | 触发 Run：原文字 + 原图 `file` parts（单请求总图字节受预算约束） | 原文字 + **每图路径**占位 | 图片后来删改则新的读取遵循当前文件状态；无旧图自动迁移 |
| 旧用户上传记录 | 原有 data 目录及旧 DB 元数据保留 | 不保证切换存储后仍能读取旧图片；保留消息可读 | 原文字 + 无路径历史提示，不能崩溃 | 不要求旧图片可再次查看；Web 请求无法安全读取时维持受控 404 |
| `view_image` 单图成功 | ToolExecution `completed` + 安全相对路径，**无文件副本** | 所属 Run 中：tool-call 配对 + 图片；只有图像项也合法 | 与原 toolCallId 配对的文字路径占位 | 文件在模型请求前消失或损坏：本地重建失败，不静默降级 |
| 多次并发查看且都成功 | 每个独立 ToolExecution 保存各自路径 | 每个 callId 正确配对；Chat 系在**全部工具文本应答后**一次发全部图片 | 按调用位置保留各自文字路径 | 完成先后不改变调用／图片顺序；合计超预算时请求前明确失败 |
| 部分工具查看失败或混有别的工具 | 失败项仅 `error-text`，成功图片项有独立 path | 所有 callId 都有 tool 应答；仅成功的 view_image 在 Chat 附图 | 成功项路径占位，失败项错误文本 | 均失败则不追加 user 图像消息；不能把 A 图错配给 B |
| tool 执行时图片格式／大小／路径非法 | ToolExecution failed | 保留该 callId 的错误文本，不发送图 | 该错误文本 | 同批其他独立执行继续，不用其成功掩盖此失败 |
| 同 Run 中首次模型尝试已报错，在自动重试前图片被删改（包括用户上传图） | ToolExecution 的原路径／用户附件记录不变 | **每个 attempt 重新安全打开全部图片**；删除即本地失败、不会发起该次重试；合法覆盖后第二次发送新字节，绝不复用首次 attempt 的图片 buffer | 仅路径文字，不尝试自动附图 | **本地请求前错误**不同于已发送 Provider 请求失败；不能承诺原字节恢复 |
| Worker 中断恢复 | DB 仍存 path、originRunId | 仅原 Run、文件仍安全可读时再物化；不信任旧内存结果 | 与普通历史相同 | 无快照，无“恢复时字节一致”保证 |
| 压缩上下文 | 源块中的路径和 originRunId 经过窄契约投影 | 工具图不在保留尾部时在 prefix 变成明确路径文字、摘要可继续；保留尾部确需工具媒体时仅在同 Run 重读；用户触发原图保留既有规划策略 | 历史只用文本路径 | 工具图溢出**不触发要求用户重发图片**；需要媒体却读不到文件或无法安全保留状态时按一般本地失败，不静默丢图 |
| 模型不支持图片 | 工具成功后可能在模型请求阶段报错 | 同当前 Provider 适配路径尝试发图 | 下个 Run 仅有路径占位 | 不建图片错误码表；已进入模型请求的错误按现有自动重试与终态处理 |

## 明确区分的两类失败

- **读取阶段**：工具执行时安全校验失败是该工具的 `error-text`；若工具已成功，但首次请求或某次自动重试**重新物化**时用户图／工具图不可读、MIME 失配、合计超 20 MiB 或授权不匹配，是本地请求前失败，立刻终止该尝试且不进入模型错误的后续自动重试。不得发送上一 attempt 的旧图片字节、发送不完整图片集合、捏造已看图或记为“模型拒绝图片”。错误仅报告安全、可诊断的相对路径和原因类别，避免绝对路径及内部诊断泄漏。
- **模型阶段**：图片已物化并进入模型请求后，由实际 Provider／型号返回的不支持、网络／模型错误走现有模型请求重试上限与终态规则；不增加视觉专属错误分类。

## 实施前基线（设计时）与保留的边界

- **实施前基线（设计时，缺口已实现）**：`apps/api/src/modules/agent/read-side/runtime-transcript-projector.ts` 的 `safeUserText()` 当时只给图片数量、`projectToolExecutionResult()` 只给 preview/error；`apps/agent-worker/src/runtime/compaction/primary-materializer.ts` 当时有独立图片数量占位。两处应一致地使用可信新路径与 Run 作用域。
- **保留的限额**：上传限制来自 `apps/api/src/modules/agent/attachments/agent-attachment-limits.ts`（4 张、每张 10 MiB、合计 20 MiB），新工具**不限制一轮调用次数**，但每张及所有将进入**一次模型请求**的图片依本设计执行 10/20 MiB 硬上限；无论来源是上传图、工具图或混合，都计入同一预算。
- **保留的授权边界**：`apps/api/src/modules/agent/read-side/messages-context-projector.ts` 的 `getMessagesContext()` 传 `triggerMessageId: null`；不能把这个无 Run 授权的入口当作发图通道。仅显式目标 Run 有媒体、其他阅读模式一律纯文字。

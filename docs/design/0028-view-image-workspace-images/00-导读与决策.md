## 背景与目标

- **实施前基线（设计时）**：用户上传图片持久化到 `AWB_DATA_DIR/agent/attachments/by_workspace/<workspaceId>/`；只有其触发的 Run 收到图片字节，后续 Run 的历史消息只给图片数量提示，既无路径也不能通过模型工具再次查看。Worker 的 `visual_analyze` 接受 Workspace 文件路径，却使用单独的视觉模型；Playwright 等生成的截图要走另一套模型理解路径。
- 目标是让**当前主模型**自行理解 Workspace 中的图片：上传图片和截图都变成可供 `view_image(path)` 显式再次读取的相对路径；跨 Run 只继承路径文本、不继承图片字节。个人自托管场景接受源文件被删改的后果，不为工具结果制作副本。
- 本次不增加多租户、账号、遥测、图片模型能力表或视觉专用 Provider 错误码。不为其他会话形态建立特别授权或传播通道。

## 固定决策与取舍

| 问题 | 决策 | 取舍与理由 |
| --- | --- | --- |
| 新上传图片最终存储 | Workspace 根 `.awb/agent/attachments/`；dataDir 暂存并异步预校验；SQLite `activateUserRun` 的 IMMEDIATE 事务先判定幂等、Session、标题及 fork 冲突，再同步排他 hardlink 发布文件、写入 DB，成功后入队 Worker | 普通冲突在发布前结束，不产生 final；Workspace 目录项可由同用户工具并发替换，发布后不能依靠路径安全删除。发布后 SQL／进程／磁盘异常可能留下无 DB 关联文件，保留有限脱敏诊断并由人工核查，不为避免罕见孤儿冒险误删用户文件，也不引入孤儿数据库、配额或定时清扫 |
| 新上传图片的当前 Run 闭环 | API 从 `agent_attachment.storage_key` 按 Workspace 归属生成、校验相对路径，并**在当前 Run 的内部 PromptContext `attachment_ref` 显式传 path**；Worker 仅据此在当前 Workspace 安全重读 | 实施前基线（设计时）：Worker 从旧 dataDir 按 attachmentId 猜位置；只改上传保存位置会导致触发 Run 看不到图。用户历史占位复用同一个可信路径来源 |

| 旧数据 | 不迁移、不保证旧图片可再次查看；历史消息、旧配置必须能被安全读取 | 单人使用，不以破坏已有消息解析为代价强制兼容旧图片；绝不猜造一个实际上不存在的新路径 |
| 新工具 | `view_image(path)` 只校验／读取 Workspace 内 PNG、JPEG、WebP，让主模型看图；彻底删除 `visual_analyze` 新调用及独立视觉模型 | 避免第二次模型调用、避免 GIF/PDF 旧能力被无意承诺 |
| 工具图片表示 | `{ type: "image_ref", path: "<Workspace 相对路径>" }`；也允许现有 text、error-text；成功可只有一张图 | 路径是可信读写边界，指向**原输入**，并非附件 ID 或另建快照；工具结果不持久化字节／Base64 |
| 工具执行关联 | 当前 ToolExecution 的结构化字段存放安全、简短的路径引用，`origin_run_id` 决定图片重放资格；preview 只展示文字 | 现有 preview 可截断，不能作为路径唯一权威；不新建无必要的通用媒体框架 |
| 图片可见范围 | 用户上传的原图只在触发 Run 自动发送；`view_image` 的图片仅在其 ToolExecution 所属 Run 中多模态重放；其他 Run 只见可再次调用工具的路径 | 与现有“当前 Run 原图，历史 Run 占位”的规则一致；路径不等于自动附图 |
| 源文件变更和重试 | 不复制、不制作快照；**首次尝试及每次自动重试前**分别重开用户图／工具图、重验并重建本次请求 | 实施前基线（设计时）：媒体物化在重试循环外，须改造。两次 Provider 尝试间源文件删改，下一尝试不复用旧字节；本地重读失败不能进入 Provider 请求错误自动重试 |
| Provider | OpenAI Responses／Anthropic 使用原生媒体工具结果；OpenAI-compatible／Moonshot／DeepSeek 使用全量文本工具回复后的一条带图 user 消息 | Chat tool 消息不原生承载图片，现有 SDK 对媒体 tool output 会 JSON.stringify；处理在进入 SDK **之前**完成 |
| 不支持视觉的模型 | 不预检、不识别专用错误码；已进入模型请求的报错沿用现有重试／终态 | SDK 能序列化图片不代表远端型号一定支持；本地读取失败发生在请求之前，不伪称会走模型请求自动重试 |
| 并发预算 | 单图最多 10 MiB；**每次模型请求**中所有待附图片总计最多 20 MiB；不限制工具调用次数 | 防止并发及累计历史图片无界占用内存；超过总量则明确请求前失败，不能丢弃部分图片声称调用成功 |
| 工具图片与压缩 | 被总结的工具图以路径文本进入 prefix；只有同 Run 的保留尾部确实携图时才重读媒体；用户触发图的 `media_requires_resend` 不用于工具图 | 工具源文件可按路径重试，不能误要求用户重发；无法保留必要状态时报告一般本地失败 |

## 非目标与显式失效模式

- 不支持自动生成视觉摘要；“路径占位”只陈述原文字、图片文件路径及本 Run 未包含字节。
- 不将 `.awb` 开放为静态公共目录；Web 预览沿用受控的附件内容 API。不能修改用户 Git 忽略配置来掩盖图片可能进入 Git 的风险。
- 不保证工具成功后源文件永久存在、不保证 Worker 恢复后字节相同，也不为没有有效新路径的旧图片伪造地址。
- 不保留旧 `visual_analyze` 的 GIF、PDF 识别；不允许把旧 tool 的历史持久化记录当作新工具执行。

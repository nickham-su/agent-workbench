# 实施计划与代码审查清单

## 实施原则

- 不修改不属于本功能的文件；已有未提交改动视为用户工作，不得重置、格式化或顺带处理。
- 先确认 SDK mock 的实际序列化行为，再合入 Provider 生产路径；官方端点联调仅用于具体模型兼容性声明。不能以手工构造“理想 replay JSON”替代 SDK 转换证据。
- 每个阶段可独立构建、审查和回滚。OpenAI 回归失败时先修公共抽象，不得放宽 OpenAI 校验掩盖问题。
- 新 Provider 不设模型白名单；保留原有 provenance、recovery 与工具安全边界，由 SDK/服务端报告具体模型的不兼容。

## 阶段任务与完成定义

| 阶段 | 改动范围 | 完成定义 |
|---|---|---|
| SDK Spike | 官方工厂、mock HTTP/SSE、模型分支、URL 记录 | 锁定 SDK 序列化证据；不伪称官方端点已验收 |
| 固定策略与模型 ID | shared Provider 固定 options、Worker/shared single-call | 自定义 ID 可进入 SDK；`providerModelId` 非空 trim 优先，否则本地 ID；不维护准入表 |
| Settings/options/工厂 | sanitizer、fixed-last merge、API/Web 清理、两个官方工厂 | reserved/危险键清除、合法选项保留、namespace 只包装一次 |
| replay 契约与生命周期 | shared union、API provenance、Adapter/Runner | 连续兼容段、endpointDigest、原子工具完成、recovery fence 不回归 |
| 测试与兼容声明 | SDK mock、Worker/API 闭环、官方端点联调记录 | 自定义 ID 测试通过；只对有真实证据的模型声明相应兼容性 |

## Provider discovery 与固定策略步骤

- 记录 SDK/`ai`/transitive provider 锁定版本；用 mock HTTP 验证工厂、namespace、URL、实际模型 ID 序列化分支；Web 可手工配置模型。模型列表查询另按官方文档通过 Bearer 接入；API 失败回退已配置模型，两家 Web 失败静默清空候选。
- shared `reasoningProviderFixedOptions(providerNpm)` 仅按 Provider 返回固定 thinking（Moonshot 还固定 preserved history），Agent Adapter 与 shared single-call 使用同一 shared sanitizer/fixed-last merge。
- 任何实际模型 ID 都允许进入 SDK；SDK 自身模型前缀分支不是本地准入。SDK 可对旧非思考模型 warning 并省略不支持字段后继续请求；SDK/API 真报错时如实走受控失败路径，不改写 `reasoning_content`、不自动关闭 thinking 重试。
- endpoint 摘要与实际模型 ID 均进入 provenance/连续兼容段；切换配置时不恢复旧 reasoning。官方端点仅在授权环境联调，不记录凭证或正文。

## Settings、Web 与工厂步骤

### 共享/API/Web

- 扩展 `AgentProviderNpmSchema`、`SingleCallProviderNpm` 及全部穷尽分支。
- 在 shared package 增加唯一 plain-object sanitizer、reserved-key 常量和 fixed-last merge 纯函数；顶层 key 仅以 `trim → 去 '_'/'-' → lowercase` 匹配 reserved，危险键至少处理 `__proto__`、`prototype`、`constructor`。
- sanitizer 递归只保留 JSON plain-object/array/primitive 数据，清理嵌套危险键；不递归删除普通嵌套 option 的 reserved 同名键。
- API 保存、Worker invocation、Web UX 都复用这个 shared 函数；API/Worker 是权威。禁止三份自定义 matcher。
- 对新 Provider model options，在 API 保存路径剥离 reserved 等价键；Worker 读取历史 options 时同样清理；下次保存清理，不报配置冲突。
- Web 不增加 thinking 控件；generic JSON/Options 的帮助、校验、提交清理禁止 reserved keys，并测试无法绕过 API/Worker 固定策略。
- 增加 shared 单测：合法非 reserved 保留、nested thinking 整对象清除、fixed 不被改写、危险键与非 plain object 被过滤、Agent/single-call 同 payload。
- 测试 Moonshot `/v1/models`、DeepSeek `/models` 的本地 mock 路径与 Bearer 鉴权、`data[].id` 和实际 `providerModelId` 合并、缓存/刷新及 API 异常回退；Web 测试两家失败/缓存失败/未知警告/抛错不显示选项与提示、编辑值和手动输入可保存，其它 Provider 不变。不能让在线模型发现成为调用门槛，真实账号候选仍需单独验证。

### Worker/shared factory

- 在 `runner.ts`、`single-call.ts` 以官方工厂创建 Moonshot/DeepSeek chat model；实际模型计算必须统一使用 `providerModelId` 优先规则。
- 固定职责顺序为：`reasoningProviderFixedOptions(providerNpm)` 生成 fixedOptions → shared `mergeReasoningProviderOptions(rawNamespacePayload, fixedOptions)` 清理并 fixed-last 浅合并 → Agent Adapter 在 `prepareInvocation()` 中调用/使用该逻辑、完整保留 prepared payload，同时处理 replay/context → Runner 只按 `providerOptionsKeyByNpm()` 原样包装一次 namespace。
- shared single-call 自行按 Provider 固定 fixedOptions → 同一 shared merge → namespace 包装的顺序执行；不接受调用方 structural policy，不丢弃合法非 reserved option，也不得实现第二套清理/合并规则。
- 为 unsupported npm 保持显式错误；不回退 OpenAI、Anthropic 或 Compatible。
- Single-call 固定向 SDK 请求开启思考（SDK 可省略旧非思考模型的不支持字段），但不读取/写入 history replay；适用于 compaction 等一次性调用。

## 契约、API 与 Runner 步骤

### replay union 和 read-side

- 将 `agent-provider-replay.ts` 改为 strict discriminated union；保留 OpenAI `version: 1` JSON，不增加字段，只在 provenance 投影映射 protocolVersion 1。
- 新 Provider Part item 使用 `text`/`reasoning`/`tool_call`；所有持久化 Part（含空 text）有 metadata。
- API 以整条 Assistant 所有 replay-capable Part 推导 provenance；任一缺失/冲突/unknown/legacy 生成 null 硬边界。
- 有原始 reasoning 但无 visible content 的 completed Assistant 始终有 protected 空占位/source；source null 仍必须保留。
- `assistantOrdinal` 继续表示 provider-neutral messages index；保持名称，不以计数器实现。
- 新 Provider primary projection descriptor 显式 `undefined`/不兼容；不新增 retained-tail Assistant anchor。

### Adapter/Runner

- 所有 Adapter（含 OpenAI）返回 mandatory readonly attemptContext；Runner 只有有 Adapter 时调用 `createAttempt(context)`。
- 增加 part materialization hook，在创建 text/reasoning 与 push tool_call 后调用；`text-start` 无 delta 同样写 metadata。
- `finalizeAttempt()` 的成功值提供 `allowsReplayOnlyAssistant`；Runner 用协议能力、非空 reasoning、identity 一致、final flush 成功共同决定 reasoning-only 完成。
- Adapter 在恢复后删除无法恢复的 API 边界空 Assistant；最终 SDK request 不得有 `content: []` 或空 text。
- Runner 完整保留 prepared payload 中合法 non-reserved 与 fixed options（例如 `{ parallelToolCalls: true, thinking: ..., reasoningHistory: ... }`），不重新合并、不修改、不丢弃，只按 npm namespace 包装一次；增加双 namespace 反断言。
- 以严格顺序实现 `finalize → final flush → 构造 queued inputs → API 原子 complete+create queued → 后续执行工具`。
- 为 recovery continuation 增加同 Run/same identity fence、已有 Part 加载和 identical metadata 核验；existing Part 的缺失/损坏/identity、position、Part ID 冲突 fail closed。不能证明续接时用安全 replacement；replacement 不能隔离旧 Part 时 fail closed。
- hook/invariant 本地异常在 flush/complete 前中止、不重试；provider stream/API 错误沿既有 retry classifier。

## 代码审查清单

### 产品、配置、payload 与身份

- 是否只用官方 SDK，任意自定义实际模型 ID 经生产 Registry/Runner 与 shared single-call 可发请求？非空 `providerModelId.trim()` 是否优先，否则本地 ID？
- shared Provider 策略是否为 fixedOptions 唯一来源，Agent/single-call 是否复用 sanitizer/fixed-last merge，不接受用户 thinking/reasoningHistory/reasoningEffort 覆盖？
- API/Web 保存与 Worker 读取是否清理 reserved/危险键，保留合法非 reserved 选项？
- Runner 是否只包装一次 namespace，Adapter 的 mandatory context、retry、工具子轮是否不泄漏 mutable context？
- 模型/Provider/endpoint 变化是否截断 replay；是否不把 SDK 前缀判断当成白名单，且未验收 ID 不被宣称官方兼容？

### 数据、回放和空消息

- envelope 是否严格、无正文/凭证/baseURL/tool 参数；OpenAI JSON 是否保持兼容？
- text/reasoning/tool_call（含空 text）是否都带 provenance，并在 Assistant 粒度统一核验？
- legacy/损坏/冲突数据是否形成 null 硬边界？
- reasoning-only legacy/损坏 Assistant 是否有 API 边界占位、却不被发送给 Provider？
- 连续段是否按 messages index/Part.position 稳定恢复，且不跨 identity 边界？
- primary projection 是否明确不支持新 Provider Assistant anchor？

### 事务、失败与安全

- `finalize`/final flush 失败是否绝不调用原子完成、绝不创建 queued ToolExecution？
- 成功路径是否在一个 API 事务中完成 Assistant 和创建 queued execution，工具仅在之后执行？
- hook 异常是否在提交前终止且不 retry；网络/SDK 错误是否沿现有 classifier？
- recovery 是否只允许同 Run/same identity；已有 Part metadata identical 是否幂等，缺失/损坏/冲突/position/Part ID 冲突是否 fail closed？
- recovery/replacement 失败后是否无 completed Assistant、无 ToolExecution、无 PromptContext replay history，且没有猜测续接？
- 是否不存在失败 Attempt replay、metadata 失败后模型重发、400 自动降级或数据库回捞？
- debug/error/log 是否没有 reasoning、body、tool output、replay JSON 或凭证泄露？

## 回滚与条件升级

- 对已知不兼容模型更新具体兼容性说明；不得以关闭 thinking 的普通调用作自动降级。
- 公共 union 导致 OpenAI 回归时，优先恢复 OpenAI parser/normalizer/update 语义，不能放宽 schema。
- 官方端点拒绝异构历史时，收紧该模型的兼容性声明；不做自动角色转译。
- 若 Spike 证明标准事件不能表达必要状态，停止本期常规实现，单独提交最小数据需求、迁移/隐私影响和替代方案的条件升级设计。

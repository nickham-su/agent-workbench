# 需求背景、业务逻辑与产品方案

## 现状与问题

当前 `GET /api/agent/sessions?workspaceId=...` 查询该工作区全部主会话和子任务，按 `updated_at DESC` 返回裸数组，没有 LIMIT 或分页。列表是元数据，不携带消息正文，因此流量主要随会话数量增长。

Agent 初始化、Agent 刷新和定时任务关联会话校验共三处直接调用。继续会话弹窗从已加载列表过滤，本身不发请求。单目标操作明明知道 ID，仍刷新全部会话；Fork 已返回完整新记录，却只沿事件链传 ID 后再刷新。

初始化得到的集合还承担了“所有真实会话”的隐式角色：Tab 可见性控制器、状态 store 会根据列表缺失清理状态。只加 SQL 筛选、不调整此假设，会丢失隐藏会话的状态与提醒。

## 目标与不做事项

### 目标

- 单目标操作的会话查询成本与工作区历史数量解耦。
- 初始化不传输已关闭主会话和未打开子任务的完整元数据。
- 候选列表的资格判定与分页在后端完成，首屏最多传输 50 条候选。
- 不改变用户可继续哪些会话、默认恢复哪些 Tab 的业务规则。
- 失败可重试，过期响应不写当前UI；已发PUT仍可能在服务端提交，不承诺旧后端无变化。已有数据无需重建、无需清空localStorage。
- 为代码审查提供禁止调用清单，为验收提供状态断言和网络请求预算。

### 不做事项

- 不自动关闭历史主会话，不设置恢复 Tab 数量上限，不修改主/子会话默认可见性。
- 不引入实时订阅、ETag、通用增量同步、数据库元数据新版本号或后台全量对账。
- 不改变中文默认标题“新会话”的候选排除规则，不把 head 非空改为消息数量判断。
- 不增加纯存在性 HEAD/布尔校验接口；单会话元数据 GET 同时承担存在性与打开所需数据查询。
- 不保留旧列表契约，不支持前后端版本混用；也不实施破坏性数据迁移。

## 初始化与 Tab 恢复

| 会话情况 | 恢复行为 |
|---|---|
| primary 无关闭覆盖 | 恢复，默认可见 |
| primary 有关闭覆盖 | 不作为可见 record 返回；Tab 状态仍保留关闭覆盖 |
| subtask 无打开覆盖 | 不恢复，默认隐藏 |
| subtask 有打开覆盖 | 恢复 |
| 当前客户端有较新的 pending / 已成功可见性意图 | 使用本地较新意图，不被较早 snapshot 覆盖 |
| PUT在snapshot前已发起、期间完成/失败且pending清空 | 以confirmationEpoch和发起时未决集合保护本地确认/回滚；成功open保留，close排除，失败不伪造成功 |
| 返回零个可见会话 | 初始化成功后才创建一个本地草稿；不据此删除历史 |
| 初始化失败 | 展示专用失败态和重试，不显示普通空态，不创建替代草稿 |

阶段二只需一个关键 `scope=tabs` GET 完成 records 与 Tab 覆盖的初始化。可选 Agent 配置失败不得遮蔽已成功的关键 snapshot。正常 KeepAlive 再激活不隐式重取；错误态再激活或显式重试才发新的初始化尝试。

最终 Tab 展示仍按现有 Tab 编号升序，编号相同按 `createdAt`；后端按更新时间排序不等于 Tab 的展示排序。新增 ID 次级排序只确定并列更新时间的输入顺序，已有编号不重排。

## 单目标打开

### 入口

- 定时任务最新执行、执行历史中的“查看 Session”。
- 定时任务来源的“查看上下文”。
- 子任务打开父会话、主会话打开子任务。
- 继续会话弹窗选中目标，以及其他外部 `openSessionRequest`。

### 行为

- 定时任务只发送打开意图，不再拉全量列表校验。
- Agent 统一按 `workspaceId + sessionId` 查询、核实、upsert，再请求可见、激活、标记已读。
- 已知本地目标可以先乐观激活，但仍只做单目标核实。该乐观行为不允许提前关闭来源 Tab 或替换来源草稿。
- 打开父会话需要关闭来源子任务时，必须等目标 GET 成功、该打开意图的目标可见性已明确确认且当前意图仍有效，才发出来源关闭意图。目标 Tab PUT 失败同样保留来源。
- 同一 UI 中连续打开 A、B：只有最后有效意图 B 能最终激活；A 的迟到成功、失败、404 均不能跳转或告警。
- 加载/核实中提供目标级反馈，不把整个 Agent 界面切回初始化 loading。
- 查询失败不会发全量刷新兜底；保留来源，允许重新操作。401 走统一认证提示，网络/5xx 提示“加载失败，可重试”，真实目标 404 提示“会话已不可用”。
- 窄target/tabs/候选GET每次15秒；Tab可见性PUT每次15秒；UI等某次可见性确认从登记起最多30秒，含队列等待。UI超时保留来源，不声称后端未提交，不任意清实际PUT队列。
- 较新同向或反向Tab意图都取代旧确认订阅；旧父会话来源关闭/旧草稿替换终止，不迁移等待到新意图。快速no-op确认也要检查最后意图后才提交。

定时任务执行按钮继续由 `sessionAvailable && sessionId` 门禁控制。该字段验证 request→Run→Session 归属，不能以单 GET 成功替代。来源上下文按钮不需要执行门禁，查询目标时照常校验工作区归属。

## 创建、Fork 和标题

- 创建、手动标题和 Fork 成功使用接口返回的完整 record 局部更新，不触发列表查询。
- Fork 事件必须包含完整 record，相关父子组件和单元测试同步调整；只传 ID 后补全量刷新不合格；Fork发起后用户已有较新切换/打开意图时，成功record仍可局部加入，但不抢回activeTab，旧workspace/pane结果静默。
- timeline实际发起时取得父级统一readOrder和mutation代次，携token上送title-only事件；保护record清除后读/mutation水位仍保留。旧标题拒绝不丢弃有效timeline正文，也不触发无意义补查。
- 自动标题完成补查只查询目标，遵守 `04-client-state-and-concurrency.md` 的单飞、mutation 保护、dirty 补查和失败停止规则。
- 本次不改变手动标题接管语义；用户成功设置的标题不被迟到查询回滚。

## 继续会话弹窗

### 候选资格

后端先筛选再分页，沿用现有规则：

- `kind === 'primary'`。
- `headMessageId !== null`。
- JS `String.trim()` 后标题非空。
- trim 后标题不等于中文“新会话”。
- 包括已关闭主会话；当前来源是本地草稿，天然不在服务端候选集合中。

head 非空表达当前会话 head 有上下文，不代表存在本会话原生用户消息：Fork 可以引用来源消息；revert 可以把 head 置 null 而保留历史。手动命名为“新会话”的会话仍被排除，这是沿用现状，不是标题非法。

### 交互状态

| 状态/动作 | 明确行为 |
|---|---|
| 草稿空对话页面 | 可打开弹窗；按钮不依赖本地可见 records 中是否有其他 primary |
| 首次打开/显式刷新 | 清空旧页，发首屏 GET；刷新从无 cursor 开始 |
| 首屏 loading | 显示加载，不显示“无候选” |
| 首屏成功为空 | 显示“暂无可继续的会话”，保留关闭入口 |
| 首屏失败 | 显示失败和重试；不当作空结果 |
| 有 nextCursor | 显示“加载更多”；滚动容器不自动等于分页 |
| 加载更多中/重复点击 | 保留已有候选，禁用重复加载，仅一个该页请求在途 |
| 后续页失败 | 保留已有候选及当前 cursor，允许重试同一页 |
| nextCursor 为 null | 不再发下一页请求 |
| 页面数据重复 | 按 ID 去重，后到记录可更新对应行，但不制造重复项 |
| cursor 非法 | 不无限重试同一 cursor；显示列表已失效及重新加载入口 |
| 选中候选 | 仅实际接受的完整target GET record可判资格；最多一次自动新鲜补查、合计最多2次真实GET，30秒核实。受保护cache不能当成功，只有有效证明合格才PUT；再独立最多30秒确认后替换/激活 |
| 选中期间 | 禁止重复选中重置次数/时限；展示核实/确认loading并保留取消。protected二次未收敛、失败/核实超时保持原草稿、候选及选择，提供显式“重试该选择” |
| 目标 404 或已不符合资格 | 不替换草稿；移除该行，提示不可继续，仍可刷新或选择其他目标 |
| 目标网络/5xx/401失败 | 不移除为“已删除”；保留草稿和候选，按错误类型提示 |
| 关闭弹窗 | 失效读/选择并释放订阅，先保留来源；已有PUT不保证撤销，同workspace符合最后意图且目标原本隐藏才队列补偿 |
| 来源草稿切走、开始创建被替换、隐藏/销毁 | 关闭并使弹窗代次失效；不得把稍后响应作用于新的草稿 |
| 补偿成功 | 明确恢复隐藏；正常成功选择关闭弹窗不触发补偿 |
| 补偿失败/超时 | 不宣称撤销；目标可能仍可见，保留来源，当前workspace一次非阻塞提示，用户可显式关闭或核实，不自动无限重试 |
| 补偿被新意图取代 | 不宣称恢复旧状态；按最新用户意图执行，旧选择不激活/替换、不弹过期补偿失败告警 |
| 工作区切换、组件卸载 | 清理弹窗内存/订阅，不发旧补偿、不弹旧告警；旧PUT可能提交，重新进入用真实snapshot |
| 目标原本可见/有新用户意图 | 不因旧选择取消而隐藏目标或撤销新意图 |

单目标核实后再次校验资格是防止列表查询与点击间的 revert/标题变化，不是把全列表过滤移回前端。资格校验和成功激活之间仍可能发生其他进程更新；本次不引入锁定会话或 snapshot 级浏览保证。

核实采用同一次实际通过保护检查的完整record，不拿新title拼旧head。本地mutationEpoch变化或实际接受的kind/head/JS trimmed title资格字段在等待可见性确认期间相对证明改变，停止来源替换并按取消规则处理；相同标题读取只推进acceptedReadOrder，不使证明失效；未知外部并发不提供锁定。失败后显式重试开启新选择代次；核实＋确认总上限60秒，不含之后独立、有界的取消补偿等待。

## 活数据分页承诺

- 每次请求保证该次查询结果按资格和排序正确；静态数据中连续翻页完整、不重复。
- 不承诺跨多次请求的全程数据库快照。翻页期间更新时间、标题、head 变化可能使记录跨 cursor 移动，导致重排、漏项或再次出现。
- 前端去重解决重复展示，不解决活数据漏项；需要重新查看最新结果时显式刷新首屏。
- 弹窗不悄悄拉全量历史补偿漏项，也不定时刷新并打断用户选择。

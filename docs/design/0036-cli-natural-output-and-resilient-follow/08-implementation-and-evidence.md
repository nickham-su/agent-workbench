## 1. 实施范围与实际顺序

1. shared/API：Timeline 的最小 `headReplacement` 摘要、严格 schema、同一同步 SQLite ReadView、最多 256 边；不返回不可见正文/关系图，不引入 endpoint、表或配置。
2. follow GET retry：独立包装每个只读请求，初次 + 3 次、1/2/4 秒；原初始化、解析、续签、总时限和写操作边界不变。
3. 自然文本与 `MessageRenderer`：移除对外机器输出入口，建立正文、局部字符 pending、已显示/终态/身份发布状态及 stdout callback 边界。
4. proof 协调与两 pass `FinalDrain`：复用第 3 步权威显示和保护状态。把 renderer 放在协调前，是避免协调实现重复维护“已显示”“已发布”“作废”的第二套状态；不是改变需求或合并边界。`FollowState` 是组合设计实体，不机械要求每个文档概念独立 class。作废草稿释放正文，仅留最小身份 tombstone，不能绕过已显示保护。
5. 真实 CLI/API/SQLite 集成、help/README/历史基线说明、逐项证据和全门禁执行：开发与独立源码复审已完成。根据主会话同步的原全面审查者最新 `existing` 结论，M1～M5、D1/D2 全部关闭，无新增实质问题；逐项修复与审查事实见第 10 节。本轮仅同步文档并执行最后完整门禁，结果见第 3 节，**总体验收确认仍由主会话给出**，不能将源码复审通过或测试全绿自动等同整体交付通过。

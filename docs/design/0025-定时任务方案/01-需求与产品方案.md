# 需求与产品方案

[返回导航](00-文档导航.md)｜[业务规则与边界](02-业务规则与边界条件.md)｜[接口与前端交互](04-接口与前端交互.md)

## 背景与目标

个人开发者常有已验证、需反复执行的开发任务，例如依赖检查、日报整理或周期性代码审查。当前系统已具备 Workspace、Session、Agent Run 和 Worker，但用户需要手动启动每一次执行，且无法统一回顾周期任务结果。

首版在当前 Workspace 内增加“定时任务”工具：用户配置计划、任务 Prompt、Agent 与可选历史消息上下文；系统在计划到达时创建独立 Session 并复用现有 RunLifecycle 执行。目标是形成：

```text
配置任务 → 自动/手动触发 → 独立 Session 与 Run → 查看执行历史和 Session
```

定时任务是**执行编排层**，不是新的 Agent 引擎。它不得绕过现有 Session、RunLifecycle、Worker、取消、恢复和 Workspace deleting fence。

## 已确认产品范围

### Workspace 边界

- Task 必须属于当前 Workspace；页面、API 和数据库查询都必须以 `workspaceId` 为边界。
- 不提供跨 Workspace 任务、Agent、Session 或 Message 选择。
- 任意来源 Session/Message、关联 Session/Run 的读取与跳转必须再次验证 Workspace 归属。
- 不同任务和普通 Agent Session 可以同时写同一 Workspace；首版**不做**文件锁、冲突检测或提示文案。

### 页面信息架构

定时任务作为 Workspace Dock 的一个独立工具，采用左侧列表、右侧详情的主从布局：

| 区域 | 内容与行为 |
|---|---|
| 左侧任务列表 | 标题仅为“定时任务”，不显示总数；提供名称搜索、"全部状态 / 已启用 / 已暂停"筛选和创建按钮。 |
| 任务卡片 | 两行布局：第一行状态点、任务名、可选警告图标、启用/暂停标签；第二行计划摘要以及下次运行、无后续计划或“已运行 X 分钟”。 |
| 时间同步区 | 固定于左栏底部，显示服务端时间、设备时间、估算偏差和健康状态；均以设备本地时间格式化。 |
| 详情 | 顶部显示启用/暂停与空闲/运行中；操作为暂停/启用、立即运行、编辑、删除。含“概览”和“执行历史”Tab，标题均不显示数量；历史提供结果和触发方式筛选。 |
| 创建/编辑 | 使用右侧 Drawer。编辑复用创建字段，但不得隐式修改已声明的 execution。 |

列表排序必须是：

```text
已启用优先 → 已暂停在后 → 同组按 updated_at（配置更新时间）倒序
```

调度器推进 `next_run_at`、写 execution、同步执行状态时**不得**更新 Task 的 `updated_at`，否则列表会在运行时不断重排。

### 状态呈现

- Task 管理状态只有“已启用”和“已暂停”；“运行中”不是筛选项，也不是第三种 Task 状态。
- 活动 execution 时，列表显示 `● 已运行 X 分钟`，详情显示“运行中”。
- 任务名旁警告图标只在最近一次**自动** execution 为 `skipped` 时显示；手动执行不得清除该提示，失败执行不得占用该警告语义。
- “已跳过”在执行历史中使用状态标签。鼠标悬停或键盘聚焦时，Tooltip 显示原因，例如：`跳过原因：上一次执行在本次计划时间到达时仍未结束。`。
- 最近执行和每条带 `sessionId` 的历史记录都提供“查看 Session ↗”；不可用的逻辑引用必须禁用链接并显示确定原因，不得跳到其他 Workspace。

名称搜索仅匹配任务名称，trim 空字符串等同未搜索，最多 100 个 Unicode code points；ASCII 字母不区分大小写。执行历史结果筛选为“全部 / 已完成 / 已失败 / 已跳过”，其中“已失败”包含 `failed` 和 `failed_to_start`，不包含 `cancelled`；触发方式筛选为“全部 / 自动 / 手动”。

## 配置产品方案

### 基本信息与 Agent

任务表单必须包含：

- 名称；
- 创建后立即启用开关；
- 任务 Prompt；
- Agent。

任务名称必须由后端 `normalizeScheduledTaskName()` 规范化：先与现有 `normalizeManualSessionTitle()` 一样将连续 JavaScript `\s` 空白压缩为单个普通空格，再 trim；仅空白输入因此被拒绝。tab、LF、CR 等被 `\s` 匹配的空白会被规范化为空格而非拒绝；压缩后残留的 `U+0000..U+001F`、`U+007F..U+009F` 控制字符才被拒绝。规范化名称最多 100 个 Unicode code points。执行 Session 标题不是前端直接拼接的名称，而由后端权威函数根据该完整规范化任务名构造；详情继续展示完整任务名。

Task 只保存 `agentId`。Agent 是系统角色配置，Run 在每次触发时使用其当时的默认模型；Task **不得**配置或持久化 Provider/Model。创建和编辑仅列出当前 Workspace 中允许 `user` surface 且默认模型解析为 ready 的 Agent。若之后 Agent 被删除、禁用、默认模型、Provider 或 API Key 失效，本次 execution 记为 `failed_to_start`；Task 保留且不自动暂停。

### 执行上下文

| 模式 | 每次执行 | 表单要求 |
|---|---|---|
| `new_session` | 新建独立 primary Session，发送 Prompt，经既有 RunLifecycle 启动 Run。 | 不显示来源 ID。 |
| `fork_message` | 从保存的历史消息锚点 Fork 出独立 primary Session，再追加 Prompt 并启动 Run。 | 手填 `Session ID`、`Message ID`，点击“校验并加载”。 |

Fork 模式不得提供 Session/Message 选择器，不得在会话视图新增创建任务入口。会话视图已有 Session ID、Message ID 复制功能，表单应明确提示用户从那里复制。

“校验并加载”成功后只显示来源 Session 标题、最多 500 个 Unicode code points 的纯文本消息摘要和消息时间，不返回完整消息内容。修改任一 ID 必须立刻清空已验证摘要；未持有与当前 ID 完全匹配的验证结果，创建/保存必须禁用并返回明确错误。该验证结果只是前端交互状态；后端在创建、全量编辑和实际触发时必须重新权威校验来源。

### 调度编辑体验

只允许一个 Task 选择一种类型：

| 类型 | 本地 UI 配置 | 可读摘要示例 |
|---|---|---|
| `hourly` | 多个分钟：`00`、`15`、`30`、`45` | 每小时的 00、30 分执行 |
| `daily` | 多个完整时间：`00:00`、`06:00` | 每天的 00:00、06:00 执行 |
| `weekly` | 多个星期和多个时间 | 每周一、三、五的 09:00、18:00 执行 |

前端必须实时显示计划摘要与接下来三次运行预览。预览仅帮助配置；后端 `next_run_at` 才是触发权威。

所有设置与展示按浏览器当前本地时间进行，保存时转换为固定 UTC 规则。界面必须显示以下含义的说明：

> 时间按当前设备本地时间设置和回显，保存时转换为 UTC。切换设备时区或发生夏令时变化后，本地执行时间和星期可能产生偏移。

用户不需要理解 UTC、服务端时区或 IANA 时区；首版不显示这些概念。

## 操作语义

| 操作 | 确定行为 |
|---|---|
| 启用 | 将 Task 设为启用，并从当前服务端时刻计算第一个未来计划；不得补跑过去时点。 |
| 暂停 | 停止后续自动声明；不得停止已启动 Run；暂停后仍可手动立即运行。 |
| 全量编辑 | 后端比较规范化 UTC schedule：未变化时保留原 `next_run_at`；变化且已启用时以 PUT 事务捕获的服务端时刻重算严格未来计划并废弃旧尚未声明 slot；暂停时始终为 `null`。已声明 execution 的输入不变。 |
| 立即运行 | 空闲时创建 `manual` execution；不改变 `next_run_at`。活动 execution 存在时返回冲突且不写记录。 |
| 删除 | `starting/running` 存在时拒绝删除；其他情况删除 Task 及其 execution 历史，但不得删除已创建的 Session/Run。 |

完整调度、并发、异常、恢复与删除行为以[业务规则与边界条件](02-业务规则与边界条件.md)为准。

## 明确非目标

首版不得实现或暗中引入：

- 高级 Cron、RRULE、日历规则、多个不同周期混合；
- IANA 时区持久化、服务端时区选择或“本地固定墙钟时间”语义；
- Provider/Model 任务级覆盖；
- 自动重试、漏跑补偿、批量补跑、排队、replace、合并；
- Redis、外部队列、分布式锁、分布式调度器、重型调度框架；
- Workspace 文件锁、worktree 隔离、成本预算、通知、自动 PR、连续失败自动暂停；
- 工具调用/工具结果/reasoning 精确 Fork 或工具操作重放；
- 通用持久化工作流引擎和外部副作用 exactly-once 承诺。

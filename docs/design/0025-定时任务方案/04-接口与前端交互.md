## 契约与安全原则

- 所有公开 schema 必须定义于 `packages/shared/src/contracts/scheduled-tasks.ts`，由 `packages/shared/src/index.ts` 导出，并由 Fastify route 直接复用为 schema/OpenAPI；不得在 web/api 复制手写类型。
- 所有 request object 必须 `additionalProperties: false`。字符串必须 trim、限长；schedule 必须由服务端验证、排序、去重，不得信任客户端。
- `workspaceId` 是每个 API 的边界。Execution 未存 `workspace_id`，其查询、更新、删除、历史、Session 跳转辅助读取都必须 `join scheduled_agent_task task on task.id=execution.task_id` 并带 `task.workspace_id=:workspaceId`。
- 不存在、无权或跨 Workspace 的资源不得泄露标题、消息摘要或成员关系；来源校验统一使用安全错误。
- 响应不得返回 API Key、Provider 原始错误、服务器时区、绝对 Workspace 路径或来源消息完整正文。

## 资源表示

```ts
type ScheduledTask = {
  id: string;
  workspaceId: string;
  name: string;
  enabled: boolean;
  triggerMode: "new_session" | "fork_message";
  prompt: string;
  agentId: string;
  schedule: UtcSchedule;
  nextRunAt: number | null;
  source: null | {
    sessionId: string;
    messageId: string;
    title: string;
    messageSummary: string;      // 最多 500 Unicode code points 的纯文本
    messageCreatedAt: number;
  };
  latestExecution: ExecutionSummary | null;
  latestScheduledExecution: ExecutionSummary | null;
  createdAt: number;
  updatedAt: number;
};

type ScheduledExecution = {
  id: string;
  taskId: string;
  triggerType: "scheduled" | "manual";
  scheduledFor: number | null;
  status: "starting" | "running" | "completed" | "failed" | "cancelled" | "failed_to_start" | "skipped";
  reasonCode: string | null;
  reasonMessage: string | null;
  sessionId: string | null;
  runId: string | null;
  createdAt: number;
  startedAt: number | null;
  finishedAt: number | null;
};
```

`latestExecution` 是全部 trigger type 中按 `(createdAt DESC,id DESC)` 的最新记录，用于概览“最近执行”。`latestScheduledExecution` 是仅 `trigger_type=scheduled` 的最新记录，用于计划跳过警告：**仅当它的 status 为 `skipped` 时**，任务名称旁显示警告图标，详情显示“最近一次计划执行已跳过”及原因 Tooltip。手动 execution 不得清除或改变该语义；失败 execution 只在概览/历史按普通状态展示，不得扩大警告图标含义。

## REST API

基础路径：`/api/workspaces/:workspaceId/scheduled-tasks`。`limit` 均为 `1..100`，默认 `50`。

| 方法与路径 | 请求 | 成功响应 | 必须行为 |
|---|---|---|---|
| `GET /` | `status=all|enabled|paused`、`q?`、`cursor?`、`limit?` | `{items,nextCursor}` | 固定排序 `(enabled DESC,updatedAt DESC,id DESC)`；按筛选后分页。 |
| `POST /` | `CreateScheduledTaskRequest` | `201 {task}` | 后端重新验证 Agent/来源；启用时计算未来 nextRunAt。 |
| `GET /:taskId` | 无 | `{task}` | 必须按 Workspace 读取。 |
| `PUT /:taskId` | `ReplaceScheduledTaskRequest` | `{task}` | 全量替换配置；不得省略必填字段；不直接改变 enabled。 |
| `DELETE /:taskId` | 无 | `204` | 有活动 execution 时冲突；否则删 Task，execution 级联删除，Agent Session/Run 保留。 |
| `POST /:taskId/enable` | 空 object | `{task}` | 幂等；启用并从 now 计算第一个未来 slot。 |
| `POST /:taskId/pause` | 空 object | `{task}` | 幂等；暂停且 `nextRunAt=null`，不取消 Run。 |
| `POST /:taskId/run` | 空 object | `202 {execution}` | paused 也允许；不改 nextRunAt；unknown 仍返回 202。 |
| `GET /:taskId/executions` | `result=all|completed|failed|skipped`、`triggerType=all|scheduled|manual`、`cursor?`、`limit?` | `{items,nextCursor}` | 固定 `(createdAt DESC,id DESC)`，过滤后分页。 |
| `POST /validate-source` | `{sessionId,messageId}` | `{source}` | 只校验与返回安全摘要；不得创建 Task/Session/Run。 |
| `GET /server-time` | 无 | `{now,protocolVersion:1}` | 仅 UTC instant；不得返回服务器时区。 |

### 创建与全量编辑

```ts
type TaskInput = {
  name: string;                 // 服务端 normalizeScheduledTaskName() 后为 1..100 Unicode code points
  prompt: string;               // trim 后 1..20000
  agentId: string;
  schedule: UtcSchedule;
  triggerMode: "new_session" | "fork_message";
  sourceSessionId: string | null;
  sourceMessageId: string | null;
};

type CreateScheduledTaskRequest = TaskInput & { enabled: boolean };
type ReplaceScheduledTaskRequest = TaskInput;
```

- `new_session` 必须有两个 NULL 来源 ID；`fork_message` 必须有两个非空来源 ID。
- `name` 的 API 原始输入必须由服务端 `normalizeScheduledTaskName()` 规范化后持久化、返回、写入 snapshot 并展示：连续 JavaScript `\s` 压缩为普通空格再 trim，tab/LF/CR 等空白不拒绝；仅空白输入，以及压缩后残留的 NUL、退格、C1 等控制字符以验证错误拒绝。前端可为体验预览相同结果，但后端是唯一权威。
- Drawer 的“校验并加载”结果只是当前前端状态：任一 ID 修改或 Drawer 关闭必须清空结果，未校验不得提交 fork 表单。
- 创建/全量编辑请求只提交来源 ID；后端必须在 POST、PUT 和每次实际启动时重新做完整来源成员关系/锚点校验。
- `PUT` 是全量配置替换，所有字段必填；缺字段必须以契约校验错误拒绝，绝不得默认为保留或清空旧值。
- `PUT` 不得改变 Task 的 `enabled`。后端必须比较排序去重后的 UTC schedule 深度相等性：相等时保留原 `nextRunAt`；不等且当前 enabled 时，以 PUT 事务捕获的服务端 now 写入严格未来的首个新 slot，旧未声明 slot 废弃；paused 时无论是否变化均保持 `nextRunAt=null`。
- 已声明 execution 的 snapshot 不得被 PUT 修改。非 schedule PUT 先提交时，后续 Scheduler 用更新后的配置为原 nextRunAt 声明 snapshot；schedule PUT 先提交时，旧 nextRunAt 已被替换。
- 创建/PUT 都必须重新检查 Agent 是否适用于当前 Workspace 的 user surface 且默认模型 ready；客户端列表过滤不是权威边界。

### 搜索、筛选与 cursor

Task 列表 `q` 必须：trim，空字符串等同未传，最大 100 Unicode code points；仅对 Task `name` 做包含匹配，ASCII 字母不区分大小写。SQLite 实现必须显式保证 ASCII case-insensitive（例如 `instr(lower(name),lower(:q)) > 0`），不承诺非 ASCII 的大小写折叠。服务端先过滤再 cursor 分页。

Execution 历史筛选语义：

| 参数 | 值 | 映射 |
|---|---|---|
| `result` | `all` | 不过滤，`starting/running/cancelled` 仅在此可见。 |
| `result` | `completed` | 仅 `status='completed'`。 |
| `result` | `failed` | `status in ('failed','failed_to_start')`；不包含 `cancelled`。 |
| `result` | `skipped` | 仅 `status='skipped'`。 |
| `triggerType` | `all` | 不过滤。 |
| `triggerType` | `scheduled` / `manual` | 精确匹配 trigger type。 |

cursor 必须是不透明的版本化 base64url JSON（或同等编码），服务端生成、客户端原样回传：

```ts
type TaskCursor = {
  v: 1;
  filter: { status: "all"|"enabled"|"paused"; q: string | null };
  after: { enabled: 0|1; updatedAt: number; id: string };
};
type ExecutionCursor = {
  v: 1;
  filter: { result: "all"|"completed"|"failed"|"skipped"; triggerType: "all"|"scheduled"|"manual" };
  after: { createdAt: number; id: string };
};
```

游标使用与排序完全一致的严格 lexicographic “after” 条件。篡改、base64url/JSON 解码失败、`v` 不支持、字段类型不符或当前筛选指纹不匹配必须统一返回 `400 CURSOR_INVALID`；不得静默从第一页重启。

### 来源校验响应与错误

```ts
type ValidateSourceResponse = {
  source: {
    sessionId: string;
    messageId: string;
    title: string;
    messageSummary: string;     // 纯文本，按 Unicode code point 截断到 500
    messageCreatedAt: number;
  };
};
```

摘要必须移除/折叠不安全控制字符，按 Unicode code points 而非 UTF-16 code units 截断；不得返回完整消息内容、attachment、tool/reasoning 内容、API Key 或跨 Workspace 元数据。

| HTTP | 代码 | 必须语义与前端处理 |
|---|---|---|
| `400` | `SCHEDULE_INVALID` | schedule 判别、范围、空数组、重复规范化后非法；显示字段错误。 |
| `400` | `TASK_TRIGGER_MODE_INVALID` | triggerMode 与来源 ID nullability 不匹配。 |
| `400` | `SOURCE_MESSAGE_INVALID` | 非法类型/终态/锚点；提示重新校验，不泄露细节。 |
| `400` | `SOURCE_UNAVAILABLE` | 来源 Session/Message 不存在、已清理或不可读；提示重新校验，不泄露资源存在性。 |
| `404` | `SCHEDULED_TASK_NOT_FOUND` | Task 不存在或不属于 Workspace；回列表刷新。 |
| `409` | `TASK_EXECUTION_ALREADY_ACTIVE` | 手动运行遇到活动 execution；不产生记录。 |
| `409` | `TASK_DELETE_EXECUTION_ACTIVE` | 删除活动 Task；提示等待结束。 |
| `409` | `WORKSPACE_DELETING` | fence 已建立；停止写操作。 |
| `422` | `AGENT_NOT_READY` | Agent scope/enablement/default model 不可用；保留表单。 |
| `503` | `AGENT_WORKER_UNAVAILABLE` | 手动启动确定失败；error details 必须含已持久化的 `executionId`。 |

手动运行同步可确定的前置/启动失败必须先将 execution 收敛为 `failed_to_start`，再返回 4xx/503（标准安全 error details 带 `executionId`）。`AGENT_WORKER_ENQUEUE_UNKNOWN` 不是确定失败：返回 `202 {execution}`，status 保持 `starting`。

## 前端交互实现

### Workspace Dock、列表与筛选

`apps/web/src/features/workspace/types.ts` 的 `ToolId`，以及 `apps/web/src/features/workspace/views/WorkspaceLayout.vue` 的 `TOOL_IDS`、`ToolDefinition`、`toolArea` 是扩展点。实现必须增加 `scheduledTasks` ToolId、图标、i18n、view 和默认 `leftTop` 区域，并显式传入 `workspaceId`。

- 左栏标题不显示数量；搜索框绑定 `q`，仅搜索任务名称；状态筛选仅“全部状态/已启用/已暂停”。筛选变化必须清空 cursor 并从第一页请求。
- 列表排序由 API 决定。调度推进不能改变 Task `updatedAt`，前端不得自行按运行时间重排。
- 执行历史 Tab 必须提供结果筛选（全部/已完成/已失败/已跳过）和触发方式筛选（全部/自动/手动）；改变任一筛选清空 execution cursor。
- “运行中”只作为 `latestExecution` 的显示状态，卡片用 `● 已运行 X 分钟`；不是 Task 筛选项。
- 警告图标严格使用 `latestScheduledExecution.status==='skipped'`。Tooltip 和详情警告使用该 execution 的安全 reason 文案。

### local/UTC adapter

前端必须将 API UTC model 与 local editor model 分离：

```text
UTC schedule/timestamps → local editor + format → 用户编辑
→ 单次捕获 getTimezoneOffset() → UTC schedule → API
```

实现必须使用[业务规则规定的取模与 weekday 算法](02-业务规则与边界条件.md#单次提交的-local--utc-规范算法)，不得对每个未来日期取得不同 offset。weekly 不可因式分解必须进入 pair editor。摘要使用当前单一 offset；三次 preview 先算 UTC instant，再对每个 instant 调用浏览器实际时区格式化。

### Drawer、操作和 Session 跳转

- Drawer 状态至少包含 `form`、`sourceValidation`、`submitting`、`schedulePreview`。ID 输入、模式切换、关闭 Drawer 都必须清空 `sourceValidation`；fork 未校验不能保存。
- 成功校验只显示 Session 标题、最多 500 code point 摘要和消息时间；不显示“校验通过”标签。
- “立即运行”收到 `202 starting` 时显示“已提交，正在确认运行状态”；收到确定错误时从 error details 取得 executionId 后刷新历史并显示安全失败提示。
- 点击“查看 Session ↗”走既有 Agent Session 打开机制；若 Session 已不存在，显示“关联会话已不可用”。`AgentClientPane.vue` 已有 `copySessionId()`、`copyMessageId()`，不得改消息区增加创建 Task 入口。
- skipped 状态 Tooltip 必须同时支持 hover 与键盘 focus。

### 时间同步

前端固定每 30 秒请求服务端时间（实现必须可注入时钟/interval）。可见页面每秒从最近成功同步基线推进显示；不可见时可以暂停每秒渲染和请求。恢复可见时必须立即请求，成功后从该成功时刻重置 30 秒周期，失败则保持既有 30 秒节奏。每次请求记录 `t0`、`t1`、RTT、offset、成功时间，并按[业务规则的确定阈值](02-业务规则与边界条件.md#agentworkspace-与时间同步)计算状态点：成功低 RTT/低偏差为 `normal`，成功低 RTT/高偏差为 `warning`，高 RTT 或最近成功 `<120s` 的请求失败为 `uncertain`，从未成功或 `>=120s` 为 `unavailable`。失败 `<120s` 必须显示“正在重新同步”并保留最后估算。不得把估算 offset 用于触发调度。

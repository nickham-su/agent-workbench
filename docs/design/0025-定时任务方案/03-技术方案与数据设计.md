# 技术方案与数据设计

## 架构与模块边界

```text
Web ScheduledTasksTool
  → Shared TypeBox contracts
  → Fastify scheduled-tasks routes/service
  → SQLite task + execution stores
  → API 内 Scheduler（纯 next-run calculator + 定时扫描）
  → Agent SessionInteraction / 内部 HistoricalAnchorFork
  → RunLifecycleApplication
  → 既有 Agent Runtime / Worker
```

- `scheduled-tasks` 模块必须拥有 Task、Execution、计划计算、扫描、Task API 和 execution/Run 对账。
- Agent 模块必须继续拥有 Session、Message 图、Run 激活、Worker 入队、取消和 Run 恢复。
- scheduled-tasks 模块不得直接拼接 Agent 消息图 SQL、插入 `agent_session`/`agent_run` 或直接调 Worker。
- 历史锚点 Fork 与预分配 Session 创建必须位于 Agent session/message application 边界，且只提供给受信任内部应用服务。

文件组织可按现有模块结构调整，但下列职责边界必须保持：

| 位置 | 职责 |
|---|---|
| `packages/shared/src/contracts/scheduled-tasks.ts` | 公开 REST TypeBox schema、类型、稳定枚举、cursor schema。 |
| `packages/shared/src/index.ts` | 导出公开契约。 |
| `apps/api/src/modules/scheduled-tasks/` | module、routes、service、store、scheduler、calculator、reconciler 和测试。 |
| 非 Agent 基础 schema 初始化点 | 幂等创建 scheduled 两张表及索引。 |
| Agent session/message application | 预分配 ID 的 primary 创建、预分配 ID 的历史锚点 Fork、来源验证摘要。 |
| `apps/web/src/features/workspace/tools/scheduled-tasks/` | 页面、API client、Drawer、local/UTC adapter、时间同步状态和组件测试。 |

## 迁移策略：轻量隔离

`apps/api/src/infra/db/schema.ts` 中的 `AGENT_SCHEMA_VERSION`、`classifyAgentSchema()`、`rebuildAgentDomain()` 和 `clearAndDropAgentDomain()` 管理可破坏性 Agent 域重建。因此：

- `scheduled_agent_task`、`scheduled_agent_execution` **不得**进入 Agent schema 分类、`createAgentSchema()` 或 destructive rebuild。
- 首版不得提升 `AGENT_SCHEMA_VERSION` 来创建 scheduled 表。
- 首版必须在非 Agent 基础 schema 初始化路径中，以事务内 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` 幂等建表。当前 `apps/api/src/infra/db/db.ts` 的 foreign keys、`busy_timeout`、WAL 可直接复用。
- 首版不得预建通用 migration framework；首次 scheduled 表发生不兼容变化时，才增加仅覆盖 scheduled 域的轻量版本表和定向迁移。

## 数据实体与不变量

### `scheduled_agent_task`

| 字段 | 类型 / 约束 | 说明 |
|---|---|---|
| `id` | `text primary key` | Task ID。 |
| `workspace_id` | `text not null`，FK `workspaces(id)` `on delete restrict` | 唯一的 Workspace 持久化边界。 |
| `name` | `text not null`，规范化后 `1..100` Unicode code points | 不要求同 Workspace 唯一；由 `normalizeScheduledTaskName()` 压缩连续 `\s`、trim 并拒绝残留控制字符。 |
| `enabled` | `integer not null check (enabled in (0,1))` | 仅 Task 管理状态。 |
| `trigger_mode` | `text not null check (trigger_mode in ('new_session','fork_message'))` | 执行上下文。 |
| `prompt` | `text not null`，trim 后 `1..20000` | 任务追加 Prompt。 |
| `agent_id` | `text not null` | Settings 域逻辑引用；不得设 FK。 |
| `schedule_json` | `text not null` | 已规范化的 UTC schedule JSON。 |
| `next_run_at` | `integer null` | 启用时下一个未来 UTC slot；暂停时 NULL。 |
| `source_session_id` | `text null` | Fork 来源逻辑引用。 |
| `source_message_id` | `text null` | Fork 来源逻辑引用。 |
| `source_title` | `text null` | 最近一次校验展示快照；不用于授权/Fork。 |
| `source_message_summary` | `text null` | 最多 500 Unicode code points 的纯文本展示摘要。 |
| `source_message_created_at` | `integer null` | 来源消息 UTC 时间展示快照。 |
| `created_at` / `updated_at` | `integer not null` | `updated_at` 仅配置更新；调度/执行状态不得更新它。 |

Task 必须具备以下 SQL CHECK（服务层仍必须验证 JSON 结构和业务归属）：

```sql
check ((enabled = 1 and next_run_at is not null)
    or (enabled = 0 and next_run_at is null)),
check ((trigger_mode = 'new_session'
          and source_session_id is null and source_message_id is null
          and source_title is null and source_message_summary is null
          and source_message_created_at is null)
    or (trigger_mode = 'fork_message'
           and source_session_id is not null and source_message_id is not null
           and source_title is not null and source_message_summary is not null
           and source_message_created_at is not null))
```

Task 名称必须在服务层通过 `session-title.ts` 的 `normalizeScheduledTaskName()`：复用或抽取与 `normalizeManualSessionTitle()` 相同的连续 `\s` 压缩、trim 和压缩后残留控制字符校验原语，采用 100 code points 上限。tab、LF、CR 等 `\s` 空白必须归一为空格；仅空白名称、NUL、退格和残留 C1 控制字符必须拒绝。不得在 scheduled 模块另写不同语义的正则或顺序。暂停必须清空 `next_run_at`；启用必须在同一写操作中从服务端 now 写入第一个未来时点。PUT 的 schedule 相等比较与 `next_run_at` 更新事务规则以[业务规则](02-业务规则与边界条件.md#暂停编辑删除竞态)为准。Task 查询与写入必须始终以 `workspace_id` 为条件。

推荐索引：

```sql
create index if not exists idx_scheduled_task_workspace_order
  on scheduled_agent_task(workspace_id, enabled desc, updated_at desc, id desc);
create index if not exists idx_scheduled_task_due
  on scheduled_agent_task(enabled, next_run_at)
  where enabled = 1 and next_run_at is not null;
```

### `scheduled_agent_execution`

Execution **不得保存 `workspace_id`**。其 Workspace 归属只能经 `task_id → scheduled_agent_task.workspace_id` 取得；所有读取、更新、删除、历史和关联跳转查询都必须 join Task 并带 `task.workspace_id = :workspaceId` 条件。

| 字段 | 类型 / 约束 | 说明 |
|---|---|---|
| `id` | `text primary key` | Execution ID。 |
| `task_id` | `text not null`，FK Task `on delete cascade` | Task 删除时一并删除 execution 历史。 |
| `trigger_type` | `text not null` | `scheduled` 或 `manual`。 |
| `scheduled_for` | `integer null` | 自动执行的计划 UTC 时刻；手动为 NULL。 |
| `status` | `text not null` | 受枚举 CHECK 限制。 |
| `reason_code` | `text null` | 稳定、非敏感诊断码。 |
| `reason_detail` | `text null`，最大 500 | 安全短文本；不得存 Prompt、消息全文、密钥、绝对路径或原始 Provider 异常。 |
| `task_snapshot_json` | `text not null` | 声明时不可变的执行输入快照。 |
| `client_request_id` | `text not null unique` | 固定 `scheduled-execution:<executionId>`。 |
| `session_id` | `text null` | 对 Agent 域逻辑引用；除 skipped 外在声明时预分配。 |
| `run_id` | `text null` | 对 Agent Run 的逻辑引用。 |
| `created_at` / `updated_at` | `integer not null` | 声明与状态更新时间。 |
| `started_at` / `finished_at` | `integer null` | Run 开始/终态时间。 |

`source_session_id`、`source_message_id`、`session_id`、`run_id` 都不得对 Agent 域建立 FK，避免 Agent 域独立重建冲突；逻辑引用必须在服务层验证。Task 到 Workspace、Execution 到 Task 的域内 FK 必须保留。

必须以 SQL CHECK 明确以下不变量：

```sql
check (trigger_type in ('scheduled', 'manual')),
check ((trigger_type = 'scheduled' and scheduled_for is not null)
    or (trigger_type = 'manual' and scheduled_for is null)),
check (status in ('starting', 'running', 'completed', 'failed',
                  'cancelled', 'failed_to_start', 'skipped')),
check ((status = 'skipped' and session_id is null and run_id is null and started_at is null)
    or (status <> 'skipped' and session_id is not null)),
check ((status in ('starting', 'running') and finished_at is null)
    or (status in ('completed', 'failed', 'cancelled', 'failed_to_start', 'skipped')
        and finished_at is not null)),
check (status <> 'running' or started_at is not null)
```

服务层还必须保证：`skipped` 仅自动执行可写；`run_id` 一经写入不得改指向其他 Run；终态不得转回活动态；有 Run 且已进入 work 的终态必须有 `started_at`。

强制索引：

```sql
create unique index if not exists uq_scheduled_execution_auto_slot
  on scheduled_agent_execution(task_id, scheduled_for)
  where trigger_type = 'scheduled';
create unique index if not exists uq_scheduled_execution_one_active
  on scheduled_agent_execution(task_id)
  where status in ('starting', 'running');
create index if not exists idx_scheduled_execution_task_created
  on scheduled_agent_execution(task_id, created_at desc, id desc);
create index if not exists idx_scheduled_execution_run
  on scheduled_agent_execution(run_id) where run_id is not null;
```

### JSON 与快照

```ts
type UtcSchedule =
  | { kind: "hourly"; minutesUtc: number[] }
  | { kind: "daily"; minutesOfDayUtc: number[] }
  | { kind: "weekly"; slotsUtc: Array<{ weekdayUtc: 0|1|2|3|4|5|6; minuteOfDayUtc: number }> };

type ExecutionTaskSnapshot = {
  taskName: string;
  triggerMode: "new_session" | "fork_message";
  prompt: string;
  agentId: string;
  sourceSessionId: string | null;
  sourceMessageId: string | null;
};
```

服务层必须先验证、排序、去重，再序列化 `schedule_json`。snapshot 必须在声明时写入且不可修改；`taskName` 必须保存完整规范化名称，不得保存 Provider、Model、时区、来源正文或 API Key。执行 Session 标题必须以 snapshot `taskName` 调用 `buildScheduledExecutionSessionTitle()` 生成；不得由前端拼接，不得读取随后编辑的 Task 名称。

### 状态与原因码

状态迁移和 Run 分类以[业务规则](02-业务规则与边界条件.md#executionrun-与轻量恢复)为准。首版至少使用：`previous_execution_running`、`source_unavailable`、`source_anchor_invalid`、`agent_unavailable`、`agent_model_unavailable`、`worker_unavailable`、`startup_interrupted_before_run`、`workspace_deleting`、`session_id_conflict`、`run_cancelled`。原因码是稳定分类，不得等同于底层异常原文。

## Scheduler 与编排实现

Scheduler 必须具有 `starting/running` phase、可注入 Clock、可 `start()/stop()`，且 tick 不得重入。扫描事务只做声明与 `next_run_at` 推进；不得在事务内做 Worker RPC、网络请求或复杂 Fork。

事务提交后，编排器必须：

1. 复核 Workspace deleting fence；
2. 使用 execution snapshot 和预分配 ID 调 Agent 内部创建或 Fork；
3. 用稳定 clientRequestId 调既有 RunLifecycle；
4. 写入/对账 `run_id` 与状态；
5. 对 enqueue unknown 保持 `starting` 并等待持久化 Run 对账。

已声明 execution 不因 Task 暂停/PUT 编辑而取消；仅 deleting fence 可在实际启动前将其安全收敛。完整多 slot 规则、启动 phase 和重叠行为以[业务规则](02-业务规则与边界条件.md#自动调度与并发)为准。

### PUT 与 `next_run_at` 写入事务

Task replace service 必须在同一事务内按 Workspace 条件读取当前 Task、规范化请求 schedule、比较规范化结构并写入配置：

```text
schedule 深度相等 → 保留原 next_run_at
schedule 不等且 enabled=1 → now=事务内 Clock.nowMs()；next_run_at=firstFuture(newSchedule,now)
enabled=0 → 无论 schedule 是否变化，next_run_at=NULL
```

比较必须针对判别类型与排序去重后的数组/weekly slot pair 做结构深度相等，不能比较 JSON 字节串。schedule 改变替换旧尚未声明 slot；schedule 未变的非 schedule PUT 保持原相位，但 Scheduler 之后使用更新后的配置形成 execution snapshot。PUT 绝不得更新已存在 execution 的 snapshot。

## Workspace 删除

`deleteWorkspace()` 的最终数据库事务必须按此顺序：

```text
删除 scheduled_agent_task（execution 经 ON DELETE CASCADE 删除）
→ 既有 deleteWorkspaceAgentData()
→ 其他 Workspace 域数据与 Workspace 记录
```

在最终事务前，既有流程必须已建立 deleting fence、阻止 Scheduler 声明、收敛 Agent Run。Task 的 restrict FK 只防遗漏，不能替代此生命周期顺序。

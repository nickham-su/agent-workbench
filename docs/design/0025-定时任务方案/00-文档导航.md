## 术语

| 术语 | 含义 |
|---|---|
| Task / 任务 | 一个 Workspace 内保存的、可启用或暂停的周期性 Agent 配置。 |
| Execution / 执行实例 | 一次自动计划或一次手动立即运行的持久化记录；一个 execution 至多关联一个 Session 和一个 Run。 |
| 自动执行 | `trigger_type=scheduled`，由 `scheduled_for` 表示其计划 UTC 时刻。 |
| 手动执行 | `trigger_type=manual`，由用户点击“立即运行”创建，不改变任务的 `next_run_at`。 |
| 活动 execution | 状态为 `starting` 或 `running` 的 execution。 |
| UTC 规则 | 后端存储与 API 传输的结构化周期规则，不含时区名称。 |
| 本地时间 | 浏览器/设备当前时区下的显示和编辑时间；不是后端持久化语义。 |
| 历史消息锚点 | Fork 任务保存的 `sourceSessionId + sourceMessageId`；每次执行据此创建一个新 Session。 |
| 计划扫描 | API 进程周期性检查到期任务、声明 execution 或跳过记录的过程。 |

## 首版边界摘要

- 支持 `hourly`、`daily`、`weekly` 三种**单一**周期类型及周期内多值；不支持 Cron、RRULE、混合周期和 IANA 时区。
- 不补跑、重试、排队、合并或替换执行；同任务运行中时自动计划记为跳过。
- 不引入 Redis、外部队列、分布式调度器、工作区文件锁或 worktree 隔离。
- 不做 Session/Message 选择器，也不在消息操作区新增“创建定时任务”入口；用户从现有会话视图复制 ID。
- 不建设通用工作流恢复引擎；仅实现低成本的唯一声明、Run 对账与保守失败收敛。

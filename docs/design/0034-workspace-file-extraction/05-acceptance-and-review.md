# 验收与代码审查矩阵

## 使用方式与通过标准

- 验收 ID 是稳定引用标识，不表示执行先后。规则以对应权威设计为准；测试不得为通过而放宽设计。
- `U` 为纯函数/解析/发布单测，`I` 为真实路由与 FS 集成，`C` 为前端组件/操作测试，`M` 为人工浏览器/目标平台验收。
- 归档恶意样本由测试构造器生成，不读取用户真实包、凭证、真实仓库或项目外数据；使用测试专属 Workspace/数据目录。日志断言使用假数据。
- 不依赖系统解压命令生成或校验样本；允许测试构造器明确写入非法原始头/CRC，以避免“正常库不生成恶意包所以没测”。
- 非规范头/尾部样本按固定基线库公开解析结果记录；适配器不得增加完整格式扫描器来满足旧稿严格假设。接受样本仍必须满足路径/类型/配额/CRC；公开库报错必须失败。已有验收 ID 保留领域语义，修正兼容边界；新增问题使用新 ID，不复用已删除语义。
- 配额边界用可注入的测试额度和小样本覆盖，同时至少验证生产常量绑定；不要求测试实际写满 2 GiB。
- 对每个失败用例不仅断言状态码，还断言源保留、既有对象未改动、最终产物/暂存的实际状态和正确清理结果。若预期清理不完整，必须证明未误删外部对象。
- 核心自动验收全部通过且独立审查问题关闭后，才能标记代码可交付；浏览器/平台项未执行只能标记“待验收”，不能声称完整通过。

## 人工验收最小路径

- 在测试 Workspace 普通目录与仓库目录各放一个四种格式样本，右键解压，检查层级、内容、源保留与菜单中英文。
- 对含两份顶层结果的包，在其中一个名称已有目录时执行，确认整包拒绝且另一个顶层没有新增。
- 使用真实 UTF-8 中文 ZIP、标准 CP437 ZIP 与常用 TAR 验证兼容；非标准 GBK 不保证字符恢复，也不应虚构“已识别不支持编码”提示。
- 请求期间切 Workspace/隐藏工具，回到原 Workspace 后刷新确认结果，无旧消息污染。
- 浏览器断网/代理超时后确认未知结果提示，恢复网络刷新，不发生自动重复解压。
- 在目标 Node/OS/FS 上执行权限、别名、hardlink 和 no-replace 行为验证；未验证平台不能列为已支持。

## 代码审查清单

- 核实所有包内路径均经过最终有效值检查，元数据/结构性根不会跳过规则。
- 检查输入快照完整复制验证；ZIP 成功为惰性 end、文件流/尺寸/CRC、库关闭及错误收敛，不要求逐字节扫描随机访问源；TAR/gzip 需顺序输入完整消费与 gzip/Parser/写流完成，不能仅最后 entry 结束。不新增扫描器，TAR 不用 tar.x/t 或私有 Symbol。
- 检查 ignoredEntry 必失败、meta sparse 保守拒绝、Parser 前 gzip 前缀检查及完整 TAR 计量；区分 TAR 元数据库限额与 ZIP 单条有界缓冲/公开累计，不能伪造物理头计数。
- 检查源规范校验在区域选择前、schema 与服务字节限额/错误区分、NONBLOCK/NOFOLLOW/fstat 防 FIFO 阻塞。
- 检查先完整校验再发布、所有顶层预检、发布使用排他原语、没有 `rename`/检查后覆盖/递归 `mkdir` 合并旁路。
- 检查错误处理不把 IO 失败/清理失败吞成成功，commit 前后语义不同；断连与崩溃承诺真实。
- 检查文件完整版本含 mode/mtime/ctime、正常内部别名操作更新、目录不按不可变时间戳判断；每项回滚/非递归 rmdir 保留外部对象，owner 标记不能授权删除。
- 检查生命周期/区域锁作用域、源快照和父链重检；不为简化实现绕过现有边界。
- 检查前端 scope、token、防重入、消息释放与刷新异常处理；无覆盖原有编辑内容的隐藏行为。
- 检查实际依赖版本/许可/安全门禁记录、workspace 边界、无系统命令依赖；设计与实现差异须先说明。

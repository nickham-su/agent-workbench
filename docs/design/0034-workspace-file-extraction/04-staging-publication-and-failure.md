# 暂存、发布与失败边界

## 保证范围与威胁模型

- 防御不可信压缩包：路径穿越、格式欺骗、归档链接、特殊文件、资源耗尽以及覆盖既有对象。
- 沿用单 API 进程的 Workspace 生命周期与区域锁，不宣称 API 锁能约束 Agent bash、终端、其他进程或远程文件系统服务端。
- 同 UID 程序可以任意重命名父目录、改写本进程文件；纯 Node 路径 API 的 `lstat/realpath → write/unlink` 不是不可竞争的沙箱。**本方案不提供针对同 UID 恶意路径替换者的跨进程隔离保证**，不能在代码/验收说明中称“消除所有 TOCTOU”。
- 对正常外部并发：以排他创建保证叶节点不覆盖，重要步骤复核父链及已建节点身份，发现异常停止；回滚时无法确认归属就保留并报清理不完整。对有意绕过权限的外部程序，不能保证所有检测窗口内均不发生越界；若产品要求该级隔离，应单独设计基于 dirfd/openat2 等能力的受控 FS 层，本期不得用口头保证冒充实现。
- 首期部署门禁聚焦项目实际使用的 Linux 本地文件系统、Node 20/22；macOS/其他本地 FS 通过同一门禁后才能声明支持。网络 FS 未验证、不在首期支持声明内；不新增自动 FS 品类探测器。实际跨设备、权限/身份或排他原语不足时明确失败，不静默退化。

## 请求内状态

```text
admit → resolve/open → snapshot → extract/validate → preflight
      → publish → verify/commit → cleanup → respond
                    ↘ fail → stop/drain → rollback → cleanup → error
```

- `commit` 仅是请求内“所有预期产物已发布并核验”的逻辑点，不是磁盘事务或 `fsync` 持久化保证。
- 完整解压校验前没有最终产物，但会有受控暂存目录。发布开始后，其他读取者可能看到部分顶层对象或尚未填满的新目录。
- 合法空包跳过最终发布，仍完成源校验和暂存清理。

## Admission、锁与释放顺序

- schema 通过后，先完成规范源路径及 UTF-8 字节/段长校验，再同步尝试进程解压槽；已有操作立即 `ARCHIVE_BUSY`。源路径校验必须早于区域选择，不能先让 `./repo/a.zip` 等进入普通区域锁；忙碌拒绝可早于读取 Workspace 状态。
- 取得槽后进入 `workspaceLifecycleCoordinator.withMutation(workspaceId, ...)`，在 gate 内重新解析 Workspace 和仓库映射；删除 fence 生效时不得产生暂存副作用。
- 按源所属区域取得锁：Workspace 普通区域用 `withWorkspaceLock`，仓库区域用 `withWorkspaceRepoLock({ workspaceId, dirName })`。源与输出父目录属于同一区域，不跨区域解压。
- 生命周期 gate 必须覆盖目标解析、区域锁等待、源读取、暂存、解析、发布、回滚、清理。区域锁覆盖全部实际文件 IO 和清理，避免请求结束后仍在修改。
- 锁内重新验证父链和源对象；不能复用锁外的安全检查作为写入依据。
- 解压不尝试重新取得已持有的非重入区域锁，不能通过调用已有 mkdir/write API 对每个条目加锁而自锁。
- `finally` 顺序为：停止新 IO，等待已启动 IO/流结束，关闭文件句柄，完成回滚/清理结果判定，释放区域锁、生命周期 gate，最后释放解压槽。
- 正常删除必须等待此 gate 退出。长时间操作会阻塞同 Workspace 的其他生命周期 mutation，这是沿用现有语义的明确代价，不新增协调框架。

## 路径与源快照

- 源请求必须已经规范，完整规则见[源请求 path](02-format-path-and-limits.md#源请求-path必须已经规范)：不能有空段、`.`、`..`、前尾斜线或重复分隔符，不规范不修正后继续；源超限为 400。先验证字符串，再核对 Workspace 预期 DB 路径与区域映射；只对新增接口生效。
- 对可信 Workspace 根（含根本身）经区域 repo 根到源父目录的整条现存链逐组件做 `lstat`，拒绝符号链接/非目录；仅在完成整链检查后取得新鲜 `realpath` 验证 Workspace 边界，不能把 repo 的 canonical path 重新作为独立信任根。
- 记录并持有整条链的身份；后续源观察、发布、最终核验及回滚/清理的重要步骤持续检查该链、realpath 和 identity，不能只在服务入口检查一次 Workspace 根。不得直接把归档路径交给解压库的“解到目录”快捷接口。
- 先 `lstat` 源，已知目录/链接/FIFO/设备等非普通对象立即 `ARCHIVE_PATH_INVALID`，不得打开无写端 FIFO 等待写端。
- Linux 源打开固定使用 `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`，随后 `fstat` 再次确认普通文件，并与先前源身份比较。`O_NONBLOCK` 防止 lstat 后被替换成无写端 FIFO 时阻塞整个槽/锁；不能改为先 lstat 后普通阻塞 open。
- 所需标志/普通文件行为由平台门禁核验，缺失时明确不支持，不静默去掉 nonblock/no-follow。对普通文件读取仍按有界流执行，打开失败按安全 IO 分类。
- 在父目录创建随机暂存根后，将已打开源句柄以有界、背压的分块 IO 复制到 `input.archive`，实际读取量受限且须与观察的源尺寸一致；解析只使用本次私有快照，不重开源路径。实现采用 64 KiB `FileHandle.read/write` 循环，不额外创建读流；原句柄由收尾唯一负责关闭，保证后续 fstat 观察点有效。
- 复制前后比较源句柄的 `dev/ino/size/mtimeNs/ctimeNs`，复制结束及发布前还比较当前源路径身份；不一致则 `ARCHIVE_SOURCE_CHANGED`，不发布。
- 这是有明确观察点的版本检测，不是源文件不可变锁。发布前最后一次检查后的外部源修改不被承诺实时追踪；输出内容取自已校验快照。
- 原源句柄保持到源最后检查结束，然后在收尾关闭；不对源写入、chmod 或 unlink。

## 暂存布局与归属

```text
<source-parent>/
  source.zip
  .awb-extract-<random>/    # mkdir 排他创建，0700
    owner.json             # 仅随机操作标识、版本、时间等非敏感信息
    input.archive          # 0600，源快照
    payload/               # 0700，仅本次校验后的输出
```

- 使用安全随机名和非递归排他 `mkdir`；名字冲突更换随机名，不能删除已有同名前缀目录。
- 暂存与目标位于同一父目录、同一 FS，以支持文件 hardlink 发布；验证 `dev` 相同。禁止用系统 tmp 目录后依赖跨设备 rename。
- 暂存名称不作文件树全局隐藏规则；短暂可见是已知行为。不要为本功能修改所有既有列表/搜索语义。
- `owner.json` 不含源绝对/相对路径、文件内容、凭证或完整清单，仅辅助人工定位；不能凭该标记自动递归删除任意目录。
- 记录暂存根、输入快照、payload 和每个节点的身份/归属，受限权限不代表同 UID 外部进程绝对无法修改。
- 文件流写入必须排他创建；先校验路径再打开，结束后核验字节/CRC并登记完成。异步错误必须汇聚到同一失败路径，不允许未处理的 rejection 或后台流继续落盘。
- 输入快照已完整复制并验证；解析按[各格式成功门槛](02-format-path-and-limits.md#后缀与库兼容边界)：ZIP 等待惰性枚举 end、需解出文件流/尺寸/CRC 完成及库关闭/错误收敛，不要求随机访问覆盖每个原始字节；TAR/gzip 等待完整顺序输入、外层 gzip 校验、Parser 与写流完成。TAR 字节层与常量前缀检查仍先于 Parser，entry/ignoredEntry/meta 仍按格式文档处理，不新增原始格式扫描。
- 完整清单生成后，重新核验 staged 节点类型、数量、文件版本和归属；不允许外部插入的节点成为本次发布内容。失败可以提前 abort，不要求继续读完整恶意包。

## 所有权版本与本次操作基线

| 对象/操作 | 必须比较或更新的字段 | 不作的错误假设 |
|---|---|---|
| 已完成写入的本次普通文件 | 类型为普通文件，`dev/ino/size/mtimeNs/ctimeNs` 与预期一致，`mode & 0o7777` 等于当前预期受限 mode | 相同 inode、相同长度不等于内容/版本未变；不加全量 hash |
| 本次目录 | 目录类型、`dev/ino`、预期 mode、已知子项集合；未知子项不能当作本次产物 | 创建/删除子项会正常改变目录 mtime/ctime，不按不可变文件版本核验目录 |
| 内部受限 chmod | 先校验旧文件版本；仅允许预期 mode/ctime 变化，身份/尺寸/mtime 等不得异常变化；成功后更新全部存活别名的预期 | 不能把 chmod 后任意新状态无条件登记成可信基线 |
| 内部 link | 先校验旧版本；成功后核验同一 inode、尺寸/mtime/mode 不变，nlink 按本次新增一名变化、ctime 可更新；同步登记 staged/final 全部存活别名 | 两个名字共享 inode，不能只更新 final 而让 stage 留旧 ctime |
| 内部 unlink | 先校验待删对象及同 inode 别名预期；成功后移除该别名，核验剩余别名身份/尺寸/mtime/mode 不变，nlink 按本次减一、ctime 可更新，再同步新预期 | 删除 final 名后 stage 名仍可清理；删除 stage 后 final 仍有效，不能把自身 unlink 误当外部改写 |
| 内部 mkdir/rmdir/目录 chmod | 校验目录身份/mode，更新已知子项集合及本次受限 mode 变化 | 不用目录时间戳不变来证明无外部干扰 |

- `mode` 比较阶段敏感：文件可从暂存 `0600` 经已知 chmod 变为最终 `0644/0755`，目录从 `0700` 变为 `0755`。每次变化必须是本次预期动作，不能重新信任归档原始 mode。
- 本次成功操作发生前验证旧预期，发生后仅接受该操作允许的字段变化，再更新全部仍存别名基线；nlink 用于内部别名记账，不替代上述身份/版本核验。
- 发现同 inode 同长度但 mtime/ctime/mode 改变、意外 nlink 或不能归因于本次操作的状态，立即停止，不更新为可信新基线；异常节点及其共享 inode 别名保留，最终归清理不完整。
- 在“校验 → 系统调用 → 再核验”之间仍有同 UID 恶意竞态窗口；这是保守观测协议，不是无竞态文件事务。不得盲目刷新 stat 抹掉外部变化证据。

## 顶层冲突预检

- 从规范化完整清单生成不同顶层集合。所有顶层名称都必须对目标父目录 `lstat`；任何已有对象，包括悬空符号链接，均整包拒绝。
- 预检覆盖全部顶层后才开始发布，源压缩包和暂存目录本身也属于已有对象。
- 预检只能尽早报错，不提供无竞态占位。发布仍必须使用不覆盖原语。
- 当目标处于 Workspace 根时，已登记仓库目录同样是已有顶层，不合并进入仓库。没有真实目录但 DB 中保留的仓库顶层名也视为受保护冲突，避免解出伪仓库根。

## 无覆盖发布算法

### 原语选择

- 不使用普通 `fs.rename` 发布顶层目录：POSIX rename 可能替换已有空目录，不能通过“之前检查不存在”修复此问题。
- 目录使用 `mkdir(path, { recursive: false, mode: 0o700 })` 排他创建；`EEXIST` 不复用、不先删除。
- 普通文件使用同 FS 的 `link(stagedFile, finalFile)` 发布；目标存在时必须失败。这里是内部发布 hardlink，不是接受归档中的 hardlink 条目。
- 不支持 hardlink、跨设备或身份能力不足时返回 `ARCHIVE_FILESYSTEM_UNSUPPORTED`；不自动换成普通复制、覆盖 rename 或先删后写。

### 具体步骤

- 按固定字符串顺序处理顶层集合。每一步前复核目标父链及本次拥有的祖先目录身份。
- 顶层为目录：排他创建空目录，立即记录 `OwnedNode` 身份；顶层为文件：校验 staged 文件、设置受限最终 mode 后执行 hardlink，立即记录最终节点身份/版本。
- 遍历已创建顶层目录的清单：先创建父目录，再创建子目录/链接普通文件；嵌套目录同样必须排他创建。只复用本次清单中已经创建且身份一致的父节点，不复用外部目录。
- 每个成功创建操作立即登记，确保后续任意一步抛错时都能知道哪些操作已生效。若创建成功但登记/后续核验失败且身份不明，进入清理不完整，而不是猜测路径归属。
- 所有文件流已在暂存阶段写完；发布期不再解压、不复制整份数据。设置文件 mode 必须在 hardlink 之前完成，因为两个名字共享 inode。
- 生成完整输出后，按由深到浅顺序设置新目录最终 mode；更新由本次操作引起的所有权版本记录，不能把自身正常 chmod/link/mkdir 当外部修改。
- commit 前逐文件核验本节规则表全部版本字段及预期 mode，不只核验 dev/ino/size；逐目录核验身份/mode/已知子项，检查未知节点。任何异常先停止，不能继续进入逻辑 commit。
- commit 后只清理暂存 hardlink、输入快照和本次临时目录，不删除最终产物；输出文件因仍有最终 hardlink 而保留。
- 正常内部 link/unlink/chmod 引起的 ctime/nlink/mode 变化严格按规则表更新全部存活别名；commit 后清理 stage 名也必须维护 final 名预期，不能误判自身清理造成的变化。

## 失败、回滚与清理

### commit 前可控失败

- 首先停止新解析/发布，销毁有关流并等待已有 IO 收敛；不能一边回滚一边让旧写流继续写入。
- 逆序处理已发布普通文件：复核父链与规则表中的完整文件版本，确认未替换/改写才 unlink；成功后更新剩余 stage 别名的 nlink/ctime 预期，再清理 stage。异常或无法确认时保留全部不确定别名，不以原始尺寸/身份相同为由删除。
- 目录按由深到浅处理，只对身份确认的本次目录调用**非递归** `rmdir`。出现未知子项、权限变化、身份变化或 `ENOTEMPTY` 时保留，不 `rm({ recursive: true })`。
- 临时输入/payload 也按所有权清单逐项清理，不能因“随机目录由我创建”就递归清掉后来出现的未知内容。
- 若外部对象导致排他创建冲突，该对象不在本次所有权登记里，不得清理；本次之前成功创建的对象按上述规则回滚。
- 在 API 内无外部干扰且 IO 正常的失败，预期最终目录恢复到发布前状态；清理过程发生新故障或归属变化时，不承诺全回滚。

### commit 后失败

- 只处理暂存清理，不回滚已经核验完成的最终输出。清理不完整返回专用错误，提示可能已解压并需要刷新确认。
- 响应发送失败不反向撤销已完成的解压，不因浏览器消失而删掉结果。

### 清理不完整

- 不能安全删除、清理 IO 报错、拥有节点被外部改写/替换，均汇总成 `ARCHIVE_CLEANUP_INCOMPLETE`；保留未知对象，不无限重试。
- 单条安全日志记录原始错误 code、失败阶段、残留计数、请求关联标识及随机暂存 basename。随机 basename 仅用于人工定位，不记录源/目标绝对路径和包内名称。
- 所有权检查与 unlink 本身仍存在同 UID 恶意竞态窗口，前述威胁边界适用；不得将此补偿协议称作跨进程事务。

## 并发、断连和进程崩溃

| 场景 | 规定行为 |
|---|---|
| 同视图重复点击 | UI 禁用并在动作入口防重入；直接重复 API 请求由进程槽拒绝 |
| 不同 Workspace 同时解压 | 进程只允许一项，后者立即忙碌；不累计多份大暂存 |
| API 内上传/改名/删除 | 沿用生命周期/区域锁；不得绕过该边界 |
| 外部终端在预检后创建顶层对象 | 排他原语失败，绝不覆盖；回滚本次先前产物 |
| 外部终端向本次目录加入文件 | 不合并其为归档结果；发现后停止，回滚不删除该文件，目录可能保留 |
| 外部修改本次已发布文件 | 能检测到版本变化则保留并报告清理不完整，不删除外部新内容 |
| 页面切换/HTTP 断连/代理超时 | 不作为后端取消；后端继续到成功或受控失败/清理；前端结果未知不自动重试 |
| 处理超时 | 协作停止、等待 IO、回滚/清理，再释放锁；不让后台继续写 |
| 进程崩溃/主机断电 | 可能留下暂存和部分最终输出；没有自动全量回滚，也不宣称成功响应前绝对没有残留 |

- 重启不新增盲目按 `.awb-extract-*` glob 清理。人工确认进程已停止/操作已结束后，只在已确认的 Workspace 和源父目录检查具体暂存目录，确认归属再处理。
- 崩溃后最终部分输出无法仅凭目录名安全辨认；用户应对照原包与实际文件确认，不能自动删除“看起来像解压结果”的代码。
- 解压功能不恢复跨进程执行日志或任务。若未来需要崩溃自动恢复，应另行设计可靠 manifest、身份校验与恢复协议，不能在本期偷渡。

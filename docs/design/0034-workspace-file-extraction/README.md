# Workspace 文件树解压：开发、审查与验收基准

## 文档状态与适用范围

- 本目录是功能的设计与验收基线，不是实现完成报告。设计编写时没有解压接口、解压菜单或本功能测试；[实施计划与代码引用](06-implementation-and-references.md)保留编写时源码基线，当前实现、审查和逐项验收证据见[实施状态](implementation-status.md)。
- 面向现有单 API 进程、自托管 Workspace 文件工具。无需数据库迁移，不依赖系统 `unzip`、`tar` 或 `7z`。
- 用户已确认：支持 ZIP、TAR、TAR.GZ、TGZ；解压到压缩包所在目录；保留内部层级和原压缩包；不覆盖、不合并；暂存后发布；无额外配置界面和后台任务系统。
- 编码、配额、权限、源快照、单进程单解压、错误和失败处理是经负责人审查裁定的**工程默认，不是用户逐项指定**。
- **2026-10-16 状态**：设计、三个开发阶段审查与全面复审全部通过，M1～M5 全部 Resolved，无剩余 Open 项（原审查者结论，主会话转达）。作者已完成 14 项 HTTP 补测，归档定向 154/154、本轮独立根 `npm test` 3,938 项、全 workspace typecheck 及 API build 均通过；原审查者另独立重跑 200 项测试并通过类型检查，作者根门禁日志经独立核验，而非审查者重跑根测试。人工浏览器、Node20、macOS、大小写/Unicode 别名 FS 等未执行项见实施状态，不代表这些人工/平台验收已通过。
- 核心解析路线已确定：`yauzl` + `buffer-crc32` 处理 ZIP，`tar` 包公开 `Parser` 处理 TAR。不使用 tar-stream、不自研原始格式扫描器；兼容性继承公开库行为，安全规则独立强制。2026-10-16 源码基线与证据见实施文档。
- 依赖能力、文件系统原语及跨平台行为有开工验证门禁，见 [GATE](06-implementation-and-references.md#开工验证门禁)。门禁未通过不得用降低安全要求的方式继续实现。
- 当前不承诺多顶层发布原子性、断电持久性、崩溃自动全量恢复或对同 UID 恶意文件系统修改的跨进程隔离。

## 核心不变量

- **R-LOCATION**：目的地只能是源压缩包的父目录，不自动创建同名目录、不扁平化内部目录。
- **R-NO-REPLACE**：任何现有顶层对象都阻止本次发布；不覆盖、不合并、不隐式删除后重试。
- **R-VALIDATE-FIRST**：完整暂存、公开解析器/外层 gzip 成功、普通文件 CRC（ZIP）及条目校验通过后才发布；不额外承诺库未检查的原始格式约束。
- **R-BOUNDARY**：源请求必须已规范且先于区域选择验证；源用 no-follow/nonblock 打开并复核普通文件；包内路径、暂存和发布各自受控。
- **R-OWNERSHIP**：失败清理只处理本次拥有且版本可确认的对象，包含同 inode 同长度改写检测；内部 chmod/link/unlink 依法更新别名基线，不递归删除外部内容。
- **R-BOUNDED**：字节、条目、路径、元数据、耗时、并发均有界；流式处理不等于天然有界。
- **R-HONEST-RESULT**：不以 HTTP 失败推断“没有产物”，不以暂存成功声称多顶层发布原子；清理不完整和网络结果未知必须有可诊断语义。
- **R-SCOPE**：前端 Workspace 切换或卸载后不得展示旧操作的成功消息、刷新新 Workspace 或清除新操作状态。

## 明确非目标

- 普通 `.gz`、`.tar.bz2`、`.tar.xz`、RAR、7Z；加密、分卷、稀疏文件、链接及特殊对象。
- 选择目标目录、覆盖/合并确认、自动重命名、智能扁平化、递归解压、密码弹窗。
- 自研完整 ZIP/TAR/PAX 扫描器、猜测 GBK、额外严格原始头/尾部协议、精确物理扩展头计数；ZIP 标准 CP437 解码在范围内。
- 任务数据库、任务轮询、进度条、取消界面、通用归档插件框架、跨进程文件锁或重型恢复平台。
- 修改既有文件编辑器保存协议、Git 状态模型或 Workspace 文件列表响应结构。

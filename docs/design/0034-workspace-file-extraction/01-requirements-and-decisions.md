# 需求、业务与产品决策

## 需求背景

- 开发者在 Workspace 内下载或由 Agent 生成压缩包后，目前需要打开终端输入解压命令，打断文件查看与编辑流程。
- 文件工具已有右键菜单、文件类型信息、请求封装和目录刷新能力，适合小范围扩展，而不是新增独立工具。
- 用户希望实现尽量简单，同时覆盖 ZIP 和常见 TAR 系列格式。

## 目标与业务结果

- **R-MENU**：对支持格式的普通文件显示“解压”，点击即可执行，不增加目的地或参数弹窗。
- **R-FORMAT**：首期只支持 `.zip`、`.tar`、`.tar.gz`、`.tgz`；格式细则以[格式、路径与资源规则](02-format-path-and-limits.md)为准。
- **R-LOCATION**：目标是压缩包所在目录，即当前文件树中该文件的父目录；不是浏览器状态中的其他目录，也不是 API 进程的 `cwd`。
- **R-STRUCTURE**：内部层级原样保留。不额外创建压缩包同名目录，不自动去除包内顶层目录，不递归解压嵌套压缩包。
- **R-SOURCE**：原压缩包保留、不改名、不修改内容与权限。读取可能引起操作系统的访问时间变化，不将 atime 不变作为承诺。
- **R-SOURCE-PATH**：新增接口只接受已经规范的源路径，前端传真实文件树路径，不添加 `./` 或重复分隔符。源与包内路径规则不同；超限、校验顺序和错误以格式/接口文档为准，不扩大修改既有文件 API。
- **R-NO-REPLACE**：不覆盖、不合并。包内任一规范化后的顶层名称与目标父目录中的任何对象冲突，则整包拒绝。

### 位置与冲突示例

| 源压缩包 | 包内条目 | 结果 |
|---|---|---|
| `downloads/demo.zip` | `src/main.ts`、`README.md` | 新增 `downloads/src/main.ts`、`downloads/README.md` |
| `demo.tar.gz` | `demo/a.txt` | 新增 `demo/a.txt`，不是 `demo/demo/a.txt` |
| `demo.zip` | `a.zip` | `a.zip` 作为普通文件解出，不继续解压 |
| `demo.zip` | `src/a.ts`，已有 `src/` | 整包冲突，即使已有目录为空也不合并 |
| `demo.zip` | `demo.zip` | 与源压缩包自身冲突，整包拒绝 |
| `demo.zip` | `a.txt`，已有悬空符号链接 `a.txt` | 整包冲突，不跟随、不替换该链接 |

- 冲突检测覆盖目标已有文件、目录、符号链接、悬空链接及其他文件系统对象，不能只用 `access` 或跟随链接的 `stat` 判断。
- 若已有顶层目录与包内目录同名，即使内部文件没有重名也拒绝。这是有意采用的简化，不是实现缺陷。
- 包内空目录作为真实结果保留；没有有效输出节点的合法空包成功返回零计数，不创建最终产物。

## 文件树与前端状态

### 菜单显示

- 基于右键选中的节点快照判断：`kind === "file"` 且文件名命中支持后缀。
- 只对后缀做 ASCII 大小写不敏感匹配；先匹配 `.tar.gz`，再匹配其余后缀。不对整个真实路径做小写化。
- 名称以 `.zip` 结尾的目录不显示；`.gz`、`.rar`、`.7z`、`.tar.bz2` 不显示。
- 菜单只作可用性提示。后端独立校验源对象和实际内容；不能因菜单已显示就信任请求。
- 本文件工具视图已有解压请求时，所有“解压”菜单项禁用；动作函数入口也做防重入检查。

### 操作流程

- 点击时捕获 `workspaceId`、源 `path`、父目录、`scopeSeq` 和本次操作标识；后续不得重新读取可能已经变化的 `selectedNode` 来决定目的地。
- 立即设置忙碌状态，并用唯一消息 key 显示“正在解压…”，不展示伪进度。
- 请求成功且仍属当前 scope 时，刷新捕获的父目录，然后显示成功；零结果使用“压缩包为空，没有新增文件”。
- 成功但刷新失败时，显示“解压已完成，目录刷新失败，请手动刷新”，不能将成功解压误报成解压失败。
- 当前 `refreshDir` 会自行提示并吞掉异常，新增操作应调用能传播错误的 `loadDir` 或增加明确返回结果的窄刷新辅助，不能对 `refreshDir` 简单套 catch 后声称已覆盖刷新失败。
- 明确业务失败时，显示本功能错误码对应的本地化提示，并尽力刷新捕获的父目录：发布失败可能有残留或外部新对象。
- 网络断开、代理超时等无法取得业务响应时，显示“请求结果未知，解压可能已完成，请刷新目录确认”，不自动重试。
- 同一 scope 的刷新异常不能遮盖原始业务错误；失败后的刷新应单独兜底。
- 无论结果如何，都按本次操作标识释放自身忙碌状态和加载消息，不能清除后来启动操作的状态。

### Workspace 切换、工具隐藏与卸载

- 切换 Workspace 后，旧回调只清理旧消息，不弹旧成功/失败消息、不刷新新 Workspace。
- 原请求在后端继续，切换页面不是撤销操作；新 Workspace 可以独立开始操作。
- 工具仅隐藏而未卸载时，保持该 scope 忙碌状态；重新可见后沿用现有刷新机制。
- 卸载时销毁本视图加载消息、使旧操作 token 失效；当前代码只注销 refresh 命令，解压新增逻辑必须补上 scope/token 失效处理。
- 不新增编辑器通知协议：本方案不修改既有文件；文件树刷新即可。不得为复用上传逻辑而发送语义不准确的 `editor.fsUploaded` 事件。

## 关键决策与取舍

| 决策 | 原因 | 代价/边界 |
|---|---|---|
| 对齐 `unzip` 的解压位置 | 符合用户明确选择，便于直接使用包内目录结构 | 顶层多个产物发布不具备整体原子性 |
| 不覆盖、不合并 | 避免已有代码和未保存编辑被覆盖；省去确认与合并协议 | 已有同名目录时需用户自行处理后重试 |
| 完整暂存后发布 | 在格式错误或非法路径发现前不污染最终目录 | 需要额外磁盘空间和失败清理 |
| 已定的公开解析库，不依赖系统命令 | yauzl/CRC 与 node-tar Parser 各司其职，不自研格式扫描器 | 库可能容忍非规范结构；继承库兼容边界，不额外许诺全部头/尾部矛盾必拒绝 |
| ZIP 标准 UTF-8/CP437/Unicode Path 解码 | 使用库现有能力，避免另造编码检测 | 不猜 GBK、不承诺非标准 GBK 包恢复原字符；不提供编码选择界面 |
| TAR 稀疏标记保守拒绝 | 公开 meta 文本中检查标记，无需自研完整 PAX 解析 | 描述文本包含同样标记也可能被拒绝，错误提示归档条目不支持 |
| 无后台任务与进度/取消界面 | 保持小范围改动和低维护成本 | 只支持有明确上限的请求内操作；断连结果可能未知 |
| 链接和特殊条目整包拒绝 | 与当前文件工具隐藏/拒绝符号链接的方向一致，降低逃逸风险 | 部分合法源码 TAR 包会被拒绝，提示需明确 |
| 正常执行位受限保留 | 解出脚本后仍可正常使用 | 不恢复 owner、setuid/setgid、粘滞位或任意写权限；细则见格式文档 |

## 不作额外承诺

- 以上编码、额度、权限、快照、单进程单解压和失败清理属于审查收敛后的工程默认，不应称为用户逐项指定；源打开、资源计量与所有权版本核验仍必须落实为测试。
- 不承诺解压期间目录树完全不可见、不承诺外部终端无法读写最终产物。
- 不承诺进程崩溃后自动回滚；残留处理见[暂存、发布与失败边界](04-staging-publication-and-failure.md)。
- 不把“请求只返回一个成功/失败结果”等同于文件系统事务。正常可控失败尽力恢复，归属不明时宁可保留并报清理不完整，也不误删外部数据。

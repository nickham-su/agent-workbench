# 十分钟聚合与查询算法

## 目标与不变量

Analytics Fact 支持准确性、恢复和重建；UTC 十分钟聚合是查询缓存。聚合表可删除，但不得被过期结果当作权威数据。

- 只有**封闭、存在、非 Dirty、非 rebuild 不可用**的桶可以读取聚合。
- Dirty、缺失、当前开放桶、lease 未完成或 rebuild 影响的桶必须回退 Analytics Fact。
- 每个请求时间片只能选 Fact 或聚合之一；不得相加重叠来源。
- 若准确 Fact 回退超过安全预算，返回受控 `dataIncomplete`/错误，不能返回旧桶伪装为准确结果。
- 当前 queued/running Run 只查 Execution Fact，不查聚合。

## 桶、领域与归属

```text
BUCKET_MS = 600000
bucket_start(ts) = floor(ts / BUCKET_MS) * BUCKET_MS
bucket = [bucket_start, bucket_start + BUCKET_MS)
```

当前开放桶是 `bucket_start(now)`；即使已有聚合行，也必须读 Fact。所有边界半开，恰在桶结束时刻的事件属于下一桶。

| 域 | 聚合键 | 归属规则 |
| --- | --- | --- |
| 模型 | `bucket_start, provider_id, model_id` | `model_call.started_at` |
| Run 数 | `bucket_start, workspace_id, run_kind` | `run.created_at` |
| 顶层 Agent 时长 | `bucket_start, workspace_id` | 顶层 user Execution 与桶交集 |
| 工具 | `bucket_start, tool_name` | 始终 `tool.created_at` |
| 消息 | `bucket_start, workspace_id` | `message.created_at` |
| 会话 | `bucket_start, workspace_id, session_kind` | `session.created_at` |
| Git | `bucket_start, repo_id` | current generation 中 Commit 的 `committed_at` |
| Worker | `bucket_start` | `occurred_at` |

Run 数是创建 cohort，Agent 时长是区间切片，不能合并为一张表或共用错误 SQL。

## 可组合字段

### 模型桶

```text
request_count
completed_count / failed_count / timed_out_count
cancelled_count / interrupted_count / unknown_count
idle_timeout_count / total_timeout_count

input_tokens_sum / input_reported_count
output_tokens_sum / output_reported_count
total_tokens_sum / total_reported_count / total_derived_count
cache_read_tokens_sum / cache_comparable_count / cache_input_tokens_sum
cache_write_tokens_sum / cache_write_reported_count

completed_duration_sum_ms / completed_duration_count
failed_duration_sum_ms / failed_duration_count
timed_out_duration_sum_ms / timed_out_duration_count
cancelled_duration_sum_ms / cancelled_duration_count
```

```text
成功率 = completed / (completed + failed + timed_out)
超时率 = timed_out / (completed + failed + timed_out)
缓存命中率 = cache_read_tokens_sum / cache_input_tokens_sum
```

比例分母为零返回 `null`。默认“请求平均时长”只用 `completed_duration_*`；跨状态总览须明确其状态集合。

### 其他桶

| 聚合表 | 可组合字段 |
| --- | --- |
| `dashboard_run_10m` | `run_count`、completed/failed/cancelled/running/interrupted/unknown count |
| `dashboard_agent_duration_10m` | `duration_sum_ms`、`execution_slice_count` |
| `dashboard_tool_10m` | `call_count`、各状态 count、由可靠 `duration_completed_at-started_at` 得出的 completed/failed/cancelled 时长 `sum/count`；unknown 无时长 |
| `dashboard_message_10m` | `message_count` |
| `dashboard_session_10m` | `session_count` |
| `dashboard_git_10m` | `commit_count`、`non_merge_commit_count`、files/insertions/deletions sum |
| `dashboard_worker_10m` | `unexpected_exit_count`、`restart_attempted_count`、`restart_succeeded_count`、`restart_failed_count`；不含仅内部诊断的 `restart_scheduled` |

## 顶层 Agent 时长切片

只读取：

```sql
run_kind = 'user'
and parent_run_id is null
and started_at is not null
and effective_ended_at is not null
and effective_ended_at > started_at
```

对 Execution `[start,end)`：

```text
first = bucket_start(start)
last  = bucket_start(end - 1)
逐桶：
  slice_start = max(start, bucket_start)
  slice_end   = min(end, bucket_start + BUCKET_MS)
  duration += slice_end - slice_start
```

`end_time_quality='unknown'` 没有 slice。长跨度 Execution 按批标脏，不能把剩余时长塞到首尾桶。

## Dirty、lease 与聚合任务

### 可靠标脏

Fact/状态变更与以下 Dirty 必须同一事务：

| 变化 | Dirty 范围 |
| --- | --- |
| 消息、会话、Run Fact | `created_at` 桶 |
| 顶层 user Execution 的可靠时长变化 | 统一 `domain='agent_duration'`；新增/修正可靠终点标记 `[started_at,effective_ended_at)` 所有交集桶，清除终点标记变更前可靠区间，修正时取旧/新区间并集 |
| 工具创建、开始、终态 | 始终 `created_at` 桶 |
| 模型 begin/finish | `started_at` 桶 |
| Worker event / restart 结算 | `occurred_at` 桶 |
| Git current generation 切换 | 旧/新 membership 所有受影响 Committer Date 桶 |
| 聚合 SQL/口径变更 | 显式全量标脏 |

Dirty 不是 Best-effort；Fact 成功、Dirty 丢失的状态不允许存在。

`execution` 没有聚合表和 Dirty：它只提供原始 Execution 实时状态与 collection coverage。queued/running、无可靠有效区间的 ended，以及 `subtask`、`manual_compaction`、其他非顶层 user 的 Execution 迁移都不标 `agent_duration` Dirty。恢复、Agent rebuild、全量重建同样只按顶层 user 的旧/新可靠切片标记 `agent_duration`；非顶层对象只在清除已知错误历史投影时作为受控例外标记相关桶。

### 有 lease 的领取协议

`analytics_dirty_bucket` 状态：

- `pending`：可领取或有新版本等待处理。
- `claimed`：由 `claimed_by` 在 `[claimed_at,claim_expires_at)` 内处理。

每次标脏会递增 `mark_version`。领取使用短事务条件更新：仅 `pending` 或 `claim_expires_at <= now` 的行可变更为 `claimed`；写领取者、时间、有限 lease、`claimed_version=mark_version`、`attempt_count+1`。多个 API 进程竞争时只有一个成功。领取者崩溃后 lease 到期可重领。

处理者：

- 从 Fact 完整重算该 domain/bucket/dimension。
- 在一个事务内 upsert 或删除聚合行，并且仅当 `mark_version=claimed_version` 时删除同一 Dirty 主键。
- 若重算期间发生新的标脏，`mark_version>claimed_version`：投影可提交本次结果，但 Dirty 必须释放为 `pending`，不得删除；下一次必须重新计算最新版本。
- 失败不删除 Dirty；可提前释放为 pending 或等待 lease 到期。

### 调度

复用 `startGitEnvJanitor()` 的 onReady + interval + onClose + `unref()` 模式。每十分钟：

- 为当前 UTC 桶和最近 48 小时生成兜底 Dirty；这不是历史正确性的唯一机制。
- 领取有限批次，例如 500；短事务、范围索引、进程内 running guard。
- 更新**按 domain**的 `analytics_domain_state.job_status/last_job_*/last_error_code`；失败保留 Dirty 并写安全错误码。

## 可用桶与准确查询

### 可用性判定

对某 domain/bucket/dimension，聚合可用当且仅当：

- 桶已封闭：`bucket_end <= now`。
- 存在对应 `dashboard_*_10m` 行，或该桶经过成功重算并显式记录为空；实现必须能区分“合法空”与“缺失”。
- 不存在该键的 pending/claimed（未过期）Dirty；过期 claim 也视为 Dirty，直到重算。
- 相应 domain 没有 `preparing/rebuilding` 影响该桶的构建范围。

其余均回退 Fact。`freshness='ready'` 不能替代逐桶判定。

### 单个任意范围

给定 UTC `[from,to)`：

- 将范围切成若干十分钟桶交集。
- 对每个交集：若交集覆盖完整桶且该键对所需全部维度均可用，读取聚合；否则读取该精确交集的 Fact。
- 事件型 Fact 以归属时间过滤；Agent 时长按 Execution 区间与该精确交集再做交集。
- 每个交集恰好选择一个来源，所有可组合字段相加后才计算比例/平均值。

若一个聚合维度表没有目标行：

- 已有“显式空投影”且非 Dirty 可按零处理。
- 无投影/无空标记时必须回退 Fact；不能根据没有行推断零。

### 安全预算与不完整响应

Fact 回退必须有可配置安全预算，例如最多扫描 20,000 Fact 行、最多 2,000 Bucket-Fact 查询单元、最多 5 秒数据库时间。超过任一预算：

```text
HTTP 409 ANALYTICS_DATA_INCOMPLETE
{
  dataIncomplete: true,
  reason: "aggregation_unavailable",
  retryAfterMs?: number,
  affectedDomains: [...]
}
```

不得用过期聚合代替；前端显示“统计正在构建/修复，无法保证该范围准确”。

## 趋势 API 的点模型

趋势由后端按 `granularity` 计算，前端不得自行把十分钟点再分组。

### 有限枚举与默认

```text
granularity = '10m' | 'hour' | 'day' | 'week' | 'month'
```

| 请求范围 | 默认粒度 | 最大点数 |
| --- | --- | --- |
| `<= 48h` | `10m` | 288 |
| `> 48h && <= 31d` | `hour` | 744 |
| `> 31d && <= 180d` | `day` | 366 |
| `> 180d && <= 366d` | `week` | 106 |

`month` 仅在范围大于 366 天的受控维护查询或未来扩大范围时允许；本期公开 API 最大范围 366 天，因此客户端显式要求 `month` 时可接受，但仍限制最大 60 点。服务端拒绝超过范围或最大点数的请求，返回 `422 ANALYTICS_RANGE_TOO_LARGE`，不悄悄降采样。

### 点边界与计算

- `10m/hour` 点边界在 UTC；hour 是 UTC 整点，避免 IANA DST 的重复/缺失小时歧义。
- `day/week/month` 点边界在请求的 IANA timezone：day 为本地日零点，week 为本地周一零点，month 为本地月初零点；每个边界转换为 UTC。
- 每点是独立 `[pointFrom,pointTo)`，DST 本地日自然为 23/25 小时。
- 每点分别运行本章单个任意范围算法：完整且可用的十分钟交集读聚合，其余精确回退 Fact。
- 若任一趋势点触发安全预算，整个趋势响应 `dataIncomplete`；不得只填零或混入旧值。

## 全量重建

受保护维护命令：

- 标记相应 domain `rebuilding`，定义 rebuild 范围；当前 pointer/Git coverage 不变。
- 清空目标聚合后按 Fact 分批标 Dirty 或直接等价生成；不清 Fact。
- rebuild 期间所有受影响桶回退 Fact；Fact 超预算则受控 `dataIncomplete`。
- 完成后只有所有范围内 Dirty 被处理、job 成功才切回 `ready`。
- 聚合 SQL 或口径改变必须全量重建，不能混用旧投影。

## Domain freshness 与 coverage

每个响应按 domain 返回：

```text
freshness: {
  model: { status, lastSucceededAt, pendingDirtyCount, deliveryGapCount, deliveryIncidentCount, historicalLossCount, coverageDegraded },
  run: {...}, execution: { status, lastSucceededAt }, agentDuration: { status, lastSucceededAt, pendingDirtyCount }, tool: {...},
  message: {...}, session: {...}, git: {...}, worker: {...}
}
coverage: {
  model: { collectionStartedAt, backfillStatus, degraded, deliveryGapCount, deliveryIncidentCount, historicalLossCount },
  run: { collectionStartedAt, backfilledFrom, backfillBefore, backfillStatus },
  tool: { collectionStartedAt, backfilledFrom, backfillBefore, backfillStatus },
  message: { collectionStartedAt, backfilledFrom, backfillBefore, backfillStatus },
  session: { collectionStartedAt, backfilledFrom, backfillBefore, backfillStatus },
  execution: { collectionStartedAt, backfillStatus },
  agentDuration: { coverageSource: 'execution', collectionStartedAt: null, backfillStatus: 'not_applicable' },
  worker: { collectionStartedAt, backfillStatus },
  git: { repos: GitRepoCoverage[] }
}
```

非 Git domain 的 `collection_started_at`、回填状态/游标/水位、作业状态/错误和 rebuild 范围只从 `analytics_domain_state` 获取；它是这些 domain 的唯一 coverage 与 job 状态权威。字段命名统一使用 `collectionStartedAt`，不得保留废弃的 `analyticsStartedAt`。聚合 worker 处理成功后更新 `last_job_succeeded_at`，回填分批提交后推进 `backfill_cursor`，完成后写 `backfilled_from/backfill_before` 与终态。`agent_duration` 只维护聚合作业状态，coverage 明确引用 execution，不能生成重复采集起点。

模型 delivery gap 与 delivery incident 都不改变已存在 Fact 或聚合数值。`deliveryGapCount` 是**model domain 全局 unresolved gap 数**；`deliveryIncidentCount` 的唯一 SQL 口径为 `count(*) where resolved_at is null`；`historicalLossCount = count(resolution='confirmed_missing' AND loss_repaired_at IS NULL)`，由 `analytics_model_delivery_incident` 实时或轻量诊断查询得出，而非 `analytics_domain_state` 字段。三个计数均与请求 `[from,to)`、Provider、Model 和趋势粒度无关，都是采集健康诊断，不是所选范围模型指标。

```text
coverageDegraded = deliveryGapCount > 0
  OR deliveryIncidentCount > 0
  OR historicalLossCount > 0
```

任何一项为真均必须 `coverage.degraded=true` 和 `freshness.coverageDegraded=true`；不得因 incident 已被本地 quarantine、Gap 本地 ACK 清理或人工确认永久缺失就声称历史完整。reservation、Gap、incident 均不进入请求数、Token、时长、模型聚合或时间/Provider/Model 筛选。

Git 是例外：Git coverage 只从每个 Repo 的 `repo_state.current_scan_id` join current completed `analytics_git_scan` 获取，绝不读取 `analytics_domain_state` 或在 Repo State 冗余 coverage。公开 TypeBox/TS 合同必须使用下列判别联合，禁止以可选字段、`generation=0` 或 `coverageIncomplete=false` 伪造 unavailable coverage：

```ts
type GitRepoCoverage =
  | { repoId: string; status: 'ready'; currentGeneration: number;
      coveredFrom: number | null; coverageIncomplete: boolean;
      coverageReason: GitCoverageReason }
  | { repoId: string; status: 'preparing' | 'error'; currentGeneration: null;
      coveredFrom: null; coverageIncomplete: null; coverageReason: null }
```

`ready` 的 generation 必须是实际 current completed scan；`coverageReason` 使用受控 `GitCoverageReason`（完整 coverage 为 `none`）。`preparing/error` 不得读取最近 failed scan 当 current coverage。Git 指标数值仍按所有 current Repo 全局汇总，coverage 仅诊断级按 Repo 返回。

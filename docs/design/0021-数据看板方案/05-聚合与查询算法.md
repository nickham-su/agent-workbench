# 聚合与查询算法

## 单次查询与一致时间

范围型 Dashboard 由唯一 `POST /api/analytics/dashboard/query` 驱动。Analytics 子进程在一次受控查询流程中校验范围、生成 `rangeId/from/to/asOf`，并计算全部范围型资源。

- Analytics DB 相关的 Domain State、Dirty、Fact、Rollup、receipt/generation 诊断和 Git 结果尽量在**同一 `analytics.sqlite` 只读事务快照**读取。
- `asOf` 是该 Analytics 快照建立时刻，不是事实发生截止时间。
- Git heatmap 有自身 `from/to/asOf`；Domain health 有 `diagnosedAt` 与响应 `asOf`；Worker live snapshot 是独立实时读取，必须返回 `snapshotAt` 和 `asOf`，两者可能不同。
- 所有业务统计使用 `[from,to)` 的业务事件时间；监控数据量使用 Fact `collected_at`。

## 完整性、水位与已知 loss

范围不得早于 `availableFrom` 或 `retention_floor`；不得静默缩短范围。Domain 的完整认证综合 Collector 水位、Signal generation 状态、checkpoint、receipt、open Fact、永久 coverage gap 与 Git coverage。

Signal Domain 可推进 `reconciledThrough` 的必要条件：

- 每个配置 expected slot 均有新鲜、已注册 generation 的首个有效 checkpoint；
- 活跃 generation 的业务 event receipt 连续覆盖到 `lastSequence`；
- generation 没有 `droppedSinceSequence/lossEpoch`，没有早于候选水位的 Outbox backlog；
- generation 状态仅为 `registered|closing|closed|stale|abandoned`。仅 closed，或 abandoned 且同一事务已建立 coverage gap，才从活跃阻塞集合移除；stale 继续阻止推进。
- model/execution 候选值不晚于最早 open 下界：producer `earliestOpenStartedAt` 与 Analytics 当前 running Fact 最早 `started_at` 的最小值；无 open 时才按 `emittedThrough` 推进。

监督进程确认异常 exit 时，在同一 Analytics 事务标记 abandoned 并建立 `[gap_from,null)`。`gap_from` 取异常前最后已认证 `reconciledThrough`，从未认证时取 `collectionStartedAt`；不得因最后 checkpoint/receipt 连续省略该 gap。开放 gap 相交规则为 `to > gap_from`；非空 gap 按 `[gap_from,gap_to)` 半开区间判断。

替代 generation 只有认证到 `T`，且 Model/Execution 不存在 `started_at<T` 的未结束/不可靠 Fact 或跨 `T` 未知 Execution 尾段时，才能将旧开放 gap 关闭到 `T`。这允许 `T` 后范围恢复认证，但历史 `[gap_from,T)` 永久保留；旧 generation 的迟到事件或 Outbox 重投只能补 Fact，不能自动缩 gap。`agent_duration` 严格继承 execution 的状态、coverage、watermark 和 gap。该机制只认证已知链路；信号生成前崩溃仍可能漏计。

## Fact/Rollup 唯一来源规则

对 model、tool、message 的**每个 UTC 小时**，在同一只读事务快照先读取 Domain State、Dirty、Fact 与 Rollup，并且只选择一个来源：

```text
读取 Rollup，当且仅当：
- 小时已完整 closed；
- bucket_end <= rollupReadyThrough；
- hour 不在 analytics_dirty_hour；
- 该小时 coverage 已建立。

否则读取 Fact：
- 首尾部分小时；
- 当前开放小时；
- Dirty 小时；
- rollup 尚未 ready 的小时；
- coverage 未建立的小时。
```

- 同一小时绝不同时读取 Fact 和 Rollup。
- 迟到 finished 更新必须在写 Fact 的同一事务标记 Dirty；从标记到成功重算期间，该小时强制读 Fact。
- 成功重算在同一短事务替换 Rollup 并删除 Dirty。失败回滚，Dirty 留存。
- Run、Session、Execution、Agent 时长、Worker 历史、Git 直接查询 Fact/current membership；不建立十分钟九域 Rollup。
- `dashboard_collected_1h` 仅服务监控数据量，按 `collected_at` 分桶，且也遵守首尾小时单一来源防双计。

## 判别结果语义

每个卡、趋势、分布和表格使用 API 定义的 TypeBox 判别联合：

- `available` 必有非 null 值/数据、`completeness='complete'`、`dataIncomplete=false`。
- `partial` 必有非 null 已知值/数据、`completeness='partial'`、`dataIncomplete=true` 和受控 `partialReason`。
- `unavailable` 必有 null 值/数据、`dataIncomplete=true` 和受控 `unavailableReason`。

一个 Domain 异常只影响需要它的 Panel，不能令成功响应整包消失或改变其他 Panel 的范围。完整零值只有在所有 required Domain、coverage、水位、gap、Dirty 和 retention 条件均满足时可返回；否则有已知数据返回 partial，无安全数据返回 unavailable。

## 领域计算

### Run、Session、Message、Tool

- Run 次数/分布按 `analytics_run_fact.created_at` 和 `display_status`；running 不进入已结束分布。
- Session 按 `created_at`。
- Message 按 `created_at`、`message_kind`、`message_status` 聚合；manual/auto compaction 仅计 `type=compaction AND status=completed` 且来源 Run 已知的 Fact。`compaction_source_quality=unknown` 不归入任一类，且相关分类 Panel partial/unavailable。
- Tool 成功率分母为 completed + failed；完成平均时长仅使用 `completed_at-started_at` 的可靠样本。

### Execution 与 Agent 时长

```text
overlap = max(0, min(effective_ended_at,to) - max(started_at,from))
```

只累计顶层 user Run 的可靠 Execution overlap。缺可靠终点不推断、不计时长，并使 execution/agent_duration 的认证受 open Fact 水位限制。

### Model

请求数是 Attempt 数。状态分母、Token coverage、缓存可比性和 completed 时长遵循[指标口径](./02-指标口径.md)。Provider/Model 仅是系统整体响应内分组，不是筛选条件。

### 监控数据量

不可变定义 `dashboard_collected_fact_v1` 统计留存内首次插入的：

```text
run / session / message / tool / execution / model / worker / git
```

- 每个 Fact 只按首次 `collected_at` 计一次；迟到旧业务事件可在今天增加采集量，不重新开放旧业务趋势。
- 配置开关不回溯重算或移除已采集 Fact；它只前瞻性改变新 Fact 采集与健康期待。
- 后端以 `analytics_domain_config_version.effective_at` 把每个八域 Fact Domain 在 `[from,to)` 切为启用片段。只对启用片段要求 collection coverage、`reconciledThrough` 和无相交 coverage gap；整个范围从未启用的 Domain 不构成该范围完整性要求。
- 任一启用片段不可认证，监控数据量为 partial/unavailable；停用片段不被当作漏计或零值。`agent_duration` 随 execution 开关但不属于这八域 Fact Domain。
- 响应返回 `metricDefinitionVersion`、`collectionConfigVersion`、`configuredDomainsAtAsOf` 与 `configurationChangedWithinRange`。asOf 配置只作当前诊断，不能覆盖历史启用片段；配置变化字段仅用于 UI 提示，无需返回 configSegments。

### Git

Git 范围汇总仅 join current generation membership。ready Repo 贡献已知值；无 current generation、scan stale 或范围早于 coverage 时，Git 为 partial 并返回受控 `partialReason`。没有任何 ready Repo 时为 unavailable/null，绝不是零。

## Comparison

每个范围型结果总有 comparison 判别联合，绝不为 null：

- 可比较且前后范围完整时为 available，非 null `delta` 与 `kind`；数量/时长用 relative，比例用百分点 `percentage_points`。
- 90d 和 custom `>=90d` 为 `range_too_large`。
- previous 未覆盖为 `previous_not_covered`；previous 分母零为 `previous_zero`，两者 delta 为 null。
- Domain 不可用为 `domain_unavailable`；无比较意义为 `not_applicable`。

## 留存与维护

- 查询先限制 `event_time >= retention_floor`。
- Model/Tool/Message Rollup 仅在 `bucket_end <= retention_floor` 删除；`dashboard_collected_1h` 按自身 collected-at 小时桶删除。
- receipt 仅按 `committed_at` 清理。
- 普通非 Git Fact 依 `collected_at` 物理留存，但 Execution/Model open Fact 例外：未可靠结束或仍可改变可查询结果的 Fact 不得仅按 collected_at 删除；必须达到可靠终态、业务时间越过 retentionFloor 且达到物理保留期。
- Dirty 成功重算即在同一事务删除；维护仅清理不可查询边界前的异常遗留 Dirty，或随边界推进删除。

# 验收与测试

## 总体验收门槛

功能通过必须同时满足：

- 指标符合 [指标口径](./02-指标口径.md)，无前后端替代口径。
- Analytics Fact 与 Agent 域 destructive rebuild 隔离；聚合可从 Fact 重建。
- Fact/状态和 Dirty 可靠关联；聚合只读可用桶，回退不足时明确 dataIncomplete。
- 共享契约、数据库约束、API、Worker、前端类型检查及相应测试通过。
- 数据库、日志、fixture 和公开响应不含禁止采集的敏感内容。

## 指标与生命周期

| 域 | 场景 | 期望结果 |
| --- | --- | --- |
| 模型 | 单次 completed | 一条 Attempt，状态/Token/时长进入 started 桶 |
| 模型 | 失败后重试成功 | 两个 Attempt，failed+completed；成功率分母二 |
| 模型 | idle/total timeout | `timed_out`、kind 正确，进入成功率/超时率分母 |
| 模型 | cancelled | 单列，不进入成功率/超时率分母；观察到终态有 completed_at |
| 模型 | Worker unexpected exit | 未闭合 Attempt → interrupted，completed_at 可 null，不伪造时长 |
| 模型 | 无 total timeout 的长请求 | 仍活跃时不被纯 TTL 收敛 |
| 模型 | usage 缺失 / cache read 真零 | `null` 不计 coverage；已验证真零计 comparable coverage |
| 模型 | finish begin 缺失/身份冲突 | 包含 execution_id、started_at 的完整身份且 Execution/run 一致时可补建；任何字段（含 started_at）冲突 `409` 且不覆盖 |
| 模型 Outbox | Attempt admission | 同一 transaction 有 prepared begin、reserved finish、reservation 实体、Gap 槽位和 64 KiB reservation；任一失败不调用 SDK，Run 受控失败且无 payload 内容 |
| 模型 Outbox | 四槽位行配额边界 | 有效占用含 delivery、Gap、reservation 实体与未来 Gap 槽；99,996 可创建完整 Attempt 并至 100,000；99,997 / 99,998 / 99,999 / 100,000 均拒绝，不调用 SDK |
| 模型 Outbox | 字节、回收与并发 admission | `(page_count-freelist_count)*page_size + WAL + SHM + active reserved_bytes + 64KiB < 256MiB` 才准入；扣除全部 reservation 后剩余磁盘必须 `>512MiB`；并发 admission 在 owner transaction 中串行，近满额竞争仅一个可成功且总占用不超限；大量 Attempt 完成、ACK 清理、checkpoint 与 incremental vacuum 后仍可持续准入，主文件历史高水位不得永久阻断 |
| 模型 Outbox | admission 后逻辑满额 | 完整 Attempt 已准入后，即使有效占用满额，晋级、reserved→pending finish 和 gap 物化仍使用预留资源成功；仅真实 SQLite/I/O 故障可失败 |
| 模型 Outbox | pre-call crash | 遗留 prepared+reserved+reservation；新 owner 在单 transaction 物化 `prepared_expired_ambiguous` gap、清理 prepared/finish、释放 reservation后提交；不投递、不建 Fact、不增加 request_count；不用 TTL，coverage degraded 但绝不估算请求 |
| 模型 Outbox | SDK 同步 throw | 仍 provider_invoked，写同一 started_at 的 failed finish，request_count +1 |
| 模型 Outbox | promotion Gap 故障注入 | SDK 后 promotion Gap 的 insert、prepared 删除、reserved finish 删除、reservation 删除、commit 分别失败时均整体 rollback；Gap 不存在且 prepared/reserved/reservation 保留 |
| 模型 Outbox | Gap 基数与 promotion/handoff 互斥 | 每个 model_call 至多一个 Gap；promotion Gap transaction 成功后 crash：无 prepared、handoff 不得建 prepared-expired Gap；promotion transaction 回滚后 handoff 才可建 prepared-expired Gap；两个 promotion kind 同存、promotion 与 prepared-expired Gap 同存、或同 call kind/身份冲突均必须拒绝、隔离/安全停机且不 ready |
| 模型 Outbox | provider-invoked 与孤立 reservation 恢复 | `provider_invoked+reserved` 使用 reserved 行物化 `interrupted|unknown` finish 并删除 reservation；孤立 reservation 分别覆盖 prepared、已物化 finish、Gap 与身份冲突，前者按可证明状态收敛、冲突安全停机，不得永久残留 |
| 模型 Outbox | prepared 后 API 不可用 | SDK 可调用；仅 invoked begin/finish 按退避重试，API 主库 Fact+Dirty 提交后才 ACK |
| 模型 Outbox | finish 本地落盘反复失败 | 不重发 Provider；有限重试与受控 Run 收敛，后续由 Execution/Worker/Run 收敛 Attempt |
| 模型 Outbox | owner 竞争与 stale 写入 | 锁/fence 竞争只有一个 owner；未取得 owner 不得执行模型；新 fence 后旧实例 prepared/finish/ACK/gap/清理写入均失败 |
| 模型 Outbox | prepared handoff 故障注入 | Gap insert、finish reservation cleanup、prepared cleanup、reservation release、commit 任一步失败均整体 rollback；未处理完前不得 sender/ready/模型执行；身份不一致 quarantine/安全停机 |
| 模型 Outbox | reservation 生命周期 | promotion 成功释放未来 Gap 槽；finish 完整物化即删除 reservation；handoff、promotion Gap、provider-invoked 恢复均删除 reservation，不保留 released 历史行 |
| 模型 Outbox | prepared / invoked 恢复 | handoff 遗留 prepared 立即转 gap+清理，活跃 prepared 不被后台清理；invoked 才可恢复发送，且绝不自动重发 SDK |
| 模型 Outbox | begin/finish 重放、乱序、重复 ACK | 同 event 幂等；finish 可完整补建；重复 ACK 不改 Fact/Dirty |
| 模型 Outbox | DTO 缺 execution_id、Execution 不存在、run_id 不一致 | API 拒绝；delivery 进入受控 quarantine，不覆盖 Fact |
| Delivery Incident | transport 幂等与 response lost | begin/finish/gap 以同一有效 `delivery_event_id` 重试，response 丢失后返回原 incidentId，不重复 incident count |
| Delivery Incident | 有效 ID 的 body invalid | 已认证且 ID 有效但 body 无法解析时写 `model_call_id=null` incident，coverage degraded；同 ID 重放仍为同一 incident |
| Delivery Incident | 缺失/非法 transport ID | 返回协议错误、持续告警、Worker fail-closed；无 incident、无 quarantine，三类 delivery 均覆盖 |
| 模型 Outbox | `409`/`422` 与网络/5xx | API 先可靠写或重放 incident 并返回 incidentId，Worker 才 quarantine；incident 写失败/网络/5xx 退避；API/Worker 重启后恢复 pending/delivering 发送 |
| 模型 Outbox | 保留/清理与隐私审计 | 过期 acked model delivery、ACK 超过 24h 的本地 Gap 可清理；不得删 reserved/未 ACK/unresolved/quarantined 腾空间；quarantined 30d 后仍不自动删除，只能人工受控处置或修复 ACK；文件、日志、DTO 不含正文/原始 usage/error/路径/凭证 |
| Delivery Gap | 重放、基数、先后顺序与解析 | `gap_id/event_id/model_call_id` 幂等；仅同 kind 与完整身份重放返回原 Gap，不重复增加 unresolved 数；不同 kind 或身份冲突拒绝、隔离/fail-closed，绝不新增第二行；Fact 先/后 gap 均按身份一致规则 resolve |
| Delivery Gap | ACK 本地清理 | API ACK 后本地标 acked；固定 24h 后可清理，不查询主库 resolved；清理不改变主库 count 或 coverage |
| Delivery Gap | 解析与统计范围 | promotion gap 在 begin 或完整 finish Fact+Dirty transaction resolve；prepared ambiguous 仅可信 Fact resolve；主库 resolved 30d 后可清理、unresolved 永不自动清理；全局 count 不随 range/provider/model/granularity 改变且不进入指标 |
| Delivery Incident | begin/finish/gap quarantine | 三类任一 `409/422` 均先产生主库 incidentId，公开 incident count 非零且 coverage degraded；删除本地 quarantine 不 resolve |
| Delivery Incident | resolution 字段组合与回滚 | DB check/持久层拒绝 `resolution/resolved_at` 非法组合；resolution/resolved_at 的同 transaction 迁移任一步失败整体 rollback，incident 与历史损失计数均不切换 |
| Delivery Incident | resolution 幂等与计数切换 | `null→replayed`、`null→confirmed_missing` 各只一次且同值重试返回原 resolved_at；二者互相覆盖被拒绝。replayed 使 `count(*) where resolved_at is null` 减一；confirmed_missing 同时使该计数减一、historicalLossCount 加一 |
| Delivery Incident | 历史缺失修复 | 同 repair generation 重试幂等、不同 generation 冲突；部分 incident 修复后仍有未修复 confirmed-missing incident 则 `historicalLossCount>0`、coverage 继续 degraded |
| Delivery Incident | Fact 与 repair 原子性 | 可信 Fact 重建、Dirty、目标 incident repair 同 transaction；任意写入失败整体 rollback，不能部分修复或错误恢复健康 |
| Run | 顶层 user | Run、主任务、时长纳入 |
| Run | subtask | 子任务和当前 running 纳入；Agent 总时长不纳入 |
| Run | manual compaction | 可在 Run 单列；不进主/子任务和 Agent 时长 |
| Run | 父等待子任务 | 只计父 Execution，等待时间保留且不重复 |
| Run | 崩溃恢复 | 一个 Run Fact、多个 Execution；间隔不计 |
| Run | queued 后取消 | 当前 queued 清零，Execution 无时长 |
| Run | Execution start handshake | Worker start API 未确认时不调用 processRun/模型/工具；确认后才运行 |
| Run | local fallback handshake | 同进程可靠迁移失败时不生成 assistant、不完成 Run |
| Run | API/Worker 同时停机 | 启动后不残留 queued/running；不计离线时长/崩溃 |
| Run | Agent domain rebuild | 活跃 Execution unknown 闭合、Run interrupted/unknown、当前状态清零、重建后 Analytics 保留 |
| Run | rebuild transaction 回滚 | Analytics 收敛、Dirty、Agent drop/create/校验均回滚，不得部分生效 |
| 工具 | completed / failed | 成功率分母仅二者；时长仅由 `duration_completed_at-started_at` 计算 |
| 工具 | cancelled / unknown | 单列；未开始无时长；unknown 收敛的 `duration_completed_at` 必为 null |
| 工具 | 创建与开始跨桶 | 调用、状态、时长样本都只进入 created_at 桶，不迁移 |
| 用户 | message/session | 仅 user 消息、按 session kind；不读正文 |
| Worker | unexpected exit | 异常退出一次，关联 restart chain |
| Worker | normal stop | 不计 crash |
| Worker | restart ready fail + exit | 一个 restart_attempt 仅结算一次 failed，不双计 |
| Worker | initial startup fail | 可诊断 startup_failed，不计自动重启失败 |
| Worker | restart scheduled | 仅内部诊断；公开 worker API、overview、`dashboard_worker_10m` 均无该计数 |

## 聚合、Dirty 与准确查询

| 场景 | 期望结果 |
| --- | --- |
| Fact 写入成功 | 同一 transaction 存在对应 Dirty；不能仅写 Fact |
| 模型/Worker/Git Fact 变更 | Fact/状态与 Dirty 同 Analytics transaction，或有可重试持久 outbox |
| Dirty claim 并发 | 同一 key 仅一个有效 claimant；lease 过期后可重领 |
| Dirty 被重新标记且旧 claim 正在处理 | `mark_version` 增加；旧处理者不得删除新 Dirty，必须释放为 pending 再重算 |
| 聚合 worker 崩溃 | Dirty 未丢；lease 到期后重算 |
| 聚合重算成功 | 投影 upsert/删除与 Dirty 删除同一 transaction |
| 当前开放桶 | 即使已有投影，也从 Fact 计算 |
| Dirty 桶 | 从 Fact 计算，不能读取旧聚合 |
| 缺失桶 | 无显式空投影时从 Fact 计算 |
| rebuild 桶 | 从 Fact 计算；Fact 超预算返回 dataIncomplete |
| Fact 回退超预算 | `409 ANALYTICS_DATA_INCOMPLETE`，不返回伪精确旧值 |
| 事件在桶边界 | 属于新桶 |
| Execution 跨桶 | 精确切片，slice 和等于可靠时长 |
| 顶层 user 首次正常结束 | `running → ended/exact` 为完整 `[started_at,effective_ended_at)` 写 `agent_duration` Dirty，绝不写 execution Dirty |
| Execution queued/running | 原始状态可查，但不创建 execution Dirty，也不产生 Agent 时长 Dirty |
| 顶层 user 终点修正/清除 | 仅标 agent_duration；修正标旧/新区间并集，清除标旧可靠切片以删除投影 |
| subtask/manual compaction/非顶层 user | 不产生 agent_duration Dirty；仅清理已知错误历史投影时例外 |
| 非对齐范围 | 每个子交集只选 Fact 或聚合，结果等于直接 Fact 计算 |
| 对齐范围且桶可用 | 可只读聚合，结果等于 Fact |
| 延迟终态超过 48h | 精确 Dirty 修正历史桶，不依赖兜底 |
| 全量重建 | 不清 Fact；重建中不可用桶回退/超预算错误；完成结果一致 |
| 删除聚合表 | 可由 Fact 恢复 |

## 趋势、时区与 DST

| 场景 | 期望结果 |
| --- | --- |
| `<=48h` 未指定粒度 | 后端默认 `10m`，点数不超 288 |
| 7 天未指定粒度 | 后端默认 hour，点数不超 744 |
| 90 天未指定粒度 | 后端默认 day，点数不超 366 |
| 显式超最大点数/范围 | `422 ANALYTICS_RANGE_TOO_LARGE`，不静默降采样 |
| 每个趋势点 | 独立 `[from,to)`，逐点使用可用桶/Fact 算法 |
| 本地 day/week/month | IANA 边界转换 UTC；DST 23/25 小时无漏重 |
| 10m/hour | UTC 边界；前端只转换展示，不重新聚合 |
| 任一点 Fact 超预算 | 整个趋势 `dataIncomplete`，不填零或旧值 |

## Git

| 场景 | 期望结果 |
| --- | --- |
| 同 Repo 多 Workspace | 同 SHA 只计一次 |
| 未 Push / 本地分支 / detached HEAD | 从 Workspace HEAD/heads 发现 |
| Mirror 远端提交 | 从 mirror remote refs 发现 |
| source 快照任一失败 | 整个 scan failed；current generation/pointer 不变，不标 Dirty |
| scan 开始领取 generation | `next_generation` 在短 transaction 中领取并递增；并发不重复 |
| scan 失败/崩溃恢复 | 已领取 generation 不回退、不复用；current pointer 不变 |
| 完整 source 成功 | 单调新 generation 的同一 transaction 写 Fact/membership/Scan coverage/Scan completed+时间/pointer/Dirty |
| Git 切换故障注入 | 分别令 Fact、membership、coverage、status、pointer、Dirty 写入失败；整体回滚且旧 current/member/Scan 不变，随后独立标 failed |
| Merge | Commit+1，文件/行不增 |
| binary | 文件+，行不增 |
| 空 Commit、rename、特殊路径 | 机器格式安全解析，数值正确 |
| amend/rebase | 新 generation current，旧不可达 SHA 不参与 |
| initial coverage 上限 | coverageIncomplete/coveredFrom 正确，未覆盖非零假象 |
| generation 留存 | current+前二 completed 保留；failed/running 7 天；不删 current |

## 回填、重建、隐私

| 场景 | 期望结果 |
| --- | --- |
| 双写先于回填 | 新数据有 Fact/Dirty，回填只处理 watermark 前记录 |
| 回填并发写同 ID | 幂等、不重复；身份一致；较新业务状态不被旧回填覆盖 |
| 旧 running Run | 映射 unknown，不当 queued/running 或时长 |
| 无旧 Execution/Model/Worker | 标 coverage 自启用，不伪造历史 |
| Agent schema rebuild | Analytics Fact、聚合、Git generation 保留 |
| Workspace/Repo 删除 | 历史可查，未来不扫描已删 source |
| Domain State 映射 | `model|run|execution|agent_duration|tool|message|session|worker|git` 均有 State；agent_duration coverage 引用 execution，Git State 不承担历史 coverage |
| Domain State coverage | 非 Git API coverage 与回填/作业状态只来自 `analytics_domain_state` 且字段为 collectionStartedAt；Git 只经 current_scan join |
| Model Fact 索引 | 存在并使用 `analytics_model_call_fact(execution_id,status,updated_at)`，用于 Execution 收敛/诊断查询 |
| Git Repo coverage | TypeBox/OpenAPI 使用 ready 与 unavailable 的判别联合；ready 返回真实 generation/coverage，preparing/error 四个 coverage 字段均 null，不得 generation=0/false/failed scan 冒充；前端按 status 窄化 |
| API/schema/log audit | 无正文、Prompt、工具 input/result、错误原文、Commit Message、Diff、路径、凭证 |

## 必需测试类型

- SQLite schema/migration：独立 Analytics schema、enum check、索引、Agent rebuild 隔离。
- 生命周期集成：user/subtask/manual compaction/cancel/recovery/rebuild/local fallback/start handshake。
- Worker runner/Outbox：Attempt retry/timeout/usage/cache/prepared→invoked/sync-throw/finish identity/no-total-timeout、重放、pre-call 与 post-call 崩溃恢复、gap 降级。
- ProcessManager：exit/restart attempt 唯一结算/stop/initial startup。
- Analytics store/API：Fact+Dirty 原子性、lease、状态机、Outbox ACK、Execution/run 验证、可用桶和 dataIncomplete。
- Git fixture：source 快照全成功、部分失败回退、next_generation gap、切换事务 fault injection/pointer 保留、Repo coverage 状态、merge/binary/rebase。
- Query property/fixture：直接 Fact 与每点 Fact+聚合等价、DST、非对齐。
- API/前端：filter 拒绝、granularity、状态/coverage/dataIncomplete、Workbench tab、敏感字段不可见。

## 阶段自检命令

阶段实现后，以实际新增测试文件替换示例路径；至少执行：

```bash
npm run build -w packages/shared
npm run typecheck -w apps/api
npm run typecheck -w apps/web
npm run typecheck

# 示例：按新增测试文件替换，不把不存在的路径写入 CI
npm test -w apps/api -- <analytics-schema-or-service-test>
npm test -w apps/agent-worker -- <analytics-runner-test>
npm test -w apps/web -- <dashboard-component-test>
```

涉及 Worker/API 生命周期必须有真实进程或等价集成测试，不能仅 mock store。

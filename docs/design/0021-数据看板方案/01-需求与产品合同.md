# 需求与产品合同

## 需求背景

Agent Workbench 的核心闭环是“Agent 执行 → 变更审查 → 验收提交”。现有系统持久化了部分会话、Run 和工具执行数据，但缺少能回看数月、口径稳定且可解释的分析能力。

数据看板服务两个目标：

- 帮助本地使用者了解 Agent、任务、工具、会话和 Git 使用情况。
- 帮助维护者识别 Provider/Model、工具和 Worker 的可靠性问题。

本产品是单机自托管工作台。“用户”仅指当前工作台使用者；不引入用户 ID、跨设备画像、多租户或外部行为追踪。

## 产品合同

### 数据最小化

允许采集：

- ID、时间、状态、受控枚举、Provider/Model ID、工具名、Workspace/Repo ID。
- Token 数值、时长、次数、Git SHA、文件与行数统计。
- 受控失败、超时、结束原因码。

禁止采集、返回或参与聚合：

- 用户消息正文、Prompt、Assistant 回复、Reasoning、图片内容。
- 工具参数、工具结果、Artifact 内容、原始错误文本。
- 终端输入输出。
- 文件内容、Git Diff、Commit Message、文件路径、含凭证的 remote URL。
- API Key、token、密码、凭证、绝对工作区路径、Worker stdout/stderr。

### 时间与准确性

- 所有持久化时间为 UTC Unix 毫秒；所有范围为 `[from,to)`。
- 十分钟桶固定 `[bucket_start,bucket_start+600000)` UTC。
- 本地日/周/月使用 IANA timezone 转为 UTC，DST 的 23/25 小时日必须正确。
- 只有封闭、存在、非 Dirty、非 rebuild 不可用的桶能读聚合；其余读 Fact。
- Fact 回退超安全预算时返回 `dataIncomplete`，不得返回旧聚合冒充准确。
- 当前 queued/running 始终来自 Execution Fact，不读聚合。

### 可解释性

- 工具 `completed` 只代表协议层执行完成，不代表任务成功。
- Git 行数是提交变更规模，不代表质量、效率或个人产出。
- Token/缓存缺失、不可比时显示“未提供/不可比较”，绝不按零。
- 不承诺模型推理实际耗时、终端时长、Agent 实际贡献行数、生产率或时间杠杆。

## 页面与筛选

### Workbench 内入口

新增 `/dashboard` 路由，但复用现有 `WorkbenchPage/WorkbenchLayout`，以 dashboard tab/activeKey 进入；不新增无壳独立页面。Dashboard 是顶层 Workbench 面板，不嵌入单一 Workspace 工具面板。

全局支持时间范围：近 24 小时、7 天、30 天、90 天、自定义本地时间范围与 IANA timezone。趋势点和粒度由后端决定并返回。

### 分区与维度

| 分区 | 内容 | 允许筛选/分组 |
| --- | --- | --- |
| 概览 | 各域摘要、domain freshness/coverage | 时间；Workspace 仅影响 Agent/Run/消息/会话子卡片 |
| Agent 与会话 | 顶层 Agent 时长、Run、主/子任务、消息、会话、当前 queued/running | 时间、Workspace |
| 模型 | Provider/Model 请求、状态、Token、缓存、时长 | 时间、Provider、Model；不支持 Workspace |
| 工具 | 工具名调用、状态、时长 | 时间；不支持 Workspace |
| Git | 当前可达提交、文件/增删行、coverage | 时间；不支持 Workspace |
| Worker | 异常退出和自动重启 | 时间；不支持 Workspace |

模型和工具不支持 Workspace 筛选、分组、归因或比较；UI 不显示相应控件，API 传入该 filter 必须拒绝。

### 空态、新鲜度与不完整

- 从未有可用 Fact：展示空态，不把“没有数据”画成零趋势。
- Provider 未返回 usage：可展示请求/状态，Token/缓存显示未提供与 coverage。
- Git 初始回填未完成或达到上限：显示 coverage incomplete，不把未覆盖历史绘制为零。
- 模型存在交付 Gap、永久 delivery incident 或已确认的历史缺失：显示采集健康降级；全局健康计数不是所选时间范围、Provider 或模型的指标，绝不据此估算请求。
- `catching_up` 可提示仍有 Dirty，但返回的数值仍必须由可用桶或 Fact 准确计算。
- `rebuilding` 的不可用桶回退 Fact；超过预算显示 `dataIncomplete` 与缩小范围/稍后重试建议。

## 不变量

- 一个业务 Run 只计一次 Run 数，即使有多个 Execution。
- Agent 总时长只累计 `run_kind='user' AND parent_run_id IS NULL` 的可靠 Execution；子任务与 manual compaction 绝不进入。
- 每个成功越过 SDK 调用边界并完成 Outbox `provider_invoked` 晋级的 Attempt 对应一条 API 主库模型 Fact；重试不覆盖原 Attempt。SDK 调用后、晋级前的极窄 gap 例外仅降 coverage，绝不补造 Fact。
- Worker 私有 Delivery Outbox 仅为无敏感 begin/finish DTO 的可靠交付日志，不是查询权威、聚合源或公开接口数据源；API 主库 Fact 才是权威。Worker 取得独占 owner/fence、处理遗留 prepared 后才允许模型执行；begin 初始为不可投递 `prepared`，只有 SDK 调用边界之后晋级 `provider_invoked` 才能投递。
- 请求次数的 Attempt 是进入 `streamTextFn`/SDK Provider 调用边界的一次调用，不承诺网络实际送达。为避免把调用前崩溃伪造成请求，本期不提供 SDK 与本地 SQLite 的 impossible exactly-once 保证；调用后晋级失败的极窄窗口只记录安全 gap/降级 coverage，绝不补造 Fact。
- Provider 调用前必须以同一 Outbox transaction 持久化 `prepared` begin、`reserved` finish、reservation 实体、唯一 Gap 槽位和 64 KiB 字节 reservation；每 Attempt 占四个有效容量单位。promotion Gap 与 handoff `prepared_expired_ambiguous` Gap 对同 Attempt 互斥；本地 admission、磁盘或 SQLite 失败时拒绝请求并受控收敛 Run，API 短暂不可用则由 sender 异步重试。已准入 Attempt 的 finish/Gap 不因普通逻辑容量满额而失败。
- Git 同 Repo 同 SHA 只计一次；多个 Workspace 不能放大 Git 数值。
- 非 Git coverage/回填/作业状态来自 `analytics_domain_state`；Git coverage 只来自 current generation Scan，不能在 Repo State 冗余。
- Analytics Fact 不依赖、也不随 Agent 域 rebuild 删除。
- Fact/状态变更与 Dirty 标记有可靠关系；聚合失败可重试但 Dirty 不丢。
- `execution` 仅提供原始实时状态与 coverage，不创建 Dirty 或 `pendingDirtyCount`；任何顶层 user 可靠 Agent 时长切片变化均使用 `agent_duration` Dirty。
- 看板 API 只返回受控聚合，不能通过详情字段泄漏敏感内容。

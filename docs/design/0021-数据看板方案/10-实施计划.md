# 实施计划

每个阶段都保持业务路径可运行：Analytics 不可用只能使 Dashboard 降级。实施前以当前业务 schema 为准复核 SQL，不以历史设计字段替代实际字段。

## 共享合同与响应模型

- 在 shared contracts 定义请求 rangeKind/IANA 校验、`DashboardQuerySuccessResponse`、`DashboardQueryErrorResponse`、安全错误码和唯一 POST 接口。
- 用 TypeBox `Type.Union` 实现 MetricResult、PanelResult、ComparisonResult 的判别联合，禁止平面 nullable 组合。
- 固化 200 成功、400 非法输入、503 Analytics 不可用的互斥响应；单 Domain 故障保留 200 子结果。
- 固化例外块时间：Git `from/to/asOf`、Worker `snapshotAt/asOf`、health `diagnosedAt/asOf`。

验收：OpenAPI/TypeBox fixture 可拒绝非法 status/null/reason 组合，错误响应不含伪造 range 或原始文本。

## 业务 schema 复核与旁路索引迁移

- 以 `apps/api/src/infra/db/schema.ts` 实现真实字段 SQL：Run 不读 terminal_at；Tool 用 `call_part_id` 关联 `agent_message_part.id`；Message compaction 使用 `type/status/origin_run_id`；Tool 时长用 `completed_at-started_at`。
- 新增最小业务迁移：`agent_session(updated_at,id)`、`agent_run(updated_at,run_id)`、`agent_message(updated_at,id)`、`agent_tool_execution(updated_at,id)`。
- 先执行基表游标，再执行有界 Tool/Compaction 安全 join，避免 join 参与 cursor；每批按实际 ID 数生成 `IN (?, ?, ...)` 并逐项绑定，空批跳过。
- 将 cursor 行、关联、Fact 写入和 watermark 推进作为一个批次提交语义；失败不推进 watermark，由幂等 Fact 支持重试。
- 实现低 busy_timeout、小批、只读 WAL、退避与索引/计划失败时 Collector 停用。

验收：所有 SQL 参数绑定，实际批次占位符的四条 cursor、Tool part join、Compaction Run join 的 `EXPLAIN QUERY PLAN` 在目标数据量通过；业务 busy 或迁移失败不触发全表扫描。

## Analytics 存储、Fact 与留存

- 建立独立 Analytics 子进程和 `analytics.sqlite` schema；API/业务线程只 IPC，不执行 Analytics SQL。
- 建立 Fact、Domain state、Collector watermark、Dirty、Rollup、Git membership/scan、配置版本、coverage gap 表。
- Run Fact 实现首次观察权威业务终态的 Analytics `terminal_at`，以及 observed/inferred 窄化规则。
- Message Fact 保存 type/status 和 compaction 分类质量；Tool Fact 保存安全 tool_name 质量；不采集敏感列。
- 实现 receipt `committed_at` 留存，以及 Execution/Model open Fact retention exception。

验收：receipt、Fact、Dirty 和首次 collected 计数同事务；open Fact 不会仅因 collected_at 过期被错误删除。

## Generation、slot、checkpoint 与 Outbox

- 建立 expected producer slot、generation lifecycle、checkpoint、receipt generation+sequence 与永久 coverage gap 数据模型和索引。
- 监督进程为 Agent Worker、启用的 API local fallback、Worker observer 创建实际 slot/generation，并非阻塞发送 register/closing/closed。
- 生产者实现 generation 内从 1 的 sequence、非阻塞 Signal 与 checkpoint：generation、lastSequence、emittedThrough、earliestOpenStartedAt、outboxPending、oldestPendingAt、drop/loss、sentAt。
- 固化 `registered|closing|closed|stale|abandoned`；实现首 checkpoint、closed/finalSequence、backlog、loss、stale/失联和 expected slot 共同控制水位。abandoned 只能由监督进程确认异常 exit 后在同一事务连同 `[gap_from,null)` 建立。
- 实现 gap_from 非空、开放/半开 gap 相交、替代 generation 认证到 T 后的安全关闭和历史 gap 永久保留；执行/模型 open 下界及跨 T 未知尾段限制；agent_duration 严格继承 execution。
- 实现 Model 旧 Outbox 的监督进程唯一恢复者、只读/独占幂等重投与缺失/损坏降级；不重试 Provider，不因恢复自动缩 gap；不引入业务前置 prepared/reservation。

验收：checkpoint 后崩溃、receipt 无 closed、已分配未投递 sequence、有/无旧 Outbox、开放 gap 相交、替代 generation 安全关闭、历史 gap 保留、Execution 跨 T 阻止关闭均通过故障注入，且不影响 Provider/业务。

## 聚合、监控数据量与查询

- 实现每小时唯一 Fact/Rollup source rule：closed + ready + 非 Dirty + coverage 才读 Rollup；其他读 Fact。
- 实现迟到 finished 标 Dirty、重算事务替换 Rollup 并删除 Dirty。
- 固化 `dashboard_collected_fact_v1` 八 Fact Domain，配置启停只前瞻性影响采集/期待；输出 collectionConfigVersion、configuredDomainsAtAsOf、configurationChangedWithinRange。
- 使用 `analytics_domain_config_version.effective_at` 计算范围内逐 Domain 启用片段，仅认证启用片段的 coverage/watermark/gap；任一启用片段不完整即 partial/unavailable。
- 实现 retentionFloor、Rollup/collected Rollup/receipt/open Fact 的差异化清理和 gap 相交 partial 规则。
- 在一次 Analytics 只读快照中计算范围型资源与 DB 例外块，明确实时 Worker snapshot 的独立时间。

验收：迟到 terminal 重算前读 Fact、重算后读 Rollup；配置范围内变化、历史 Fact 计数、gap 与 partial 均正确。

## Git 安全身份与前端

- 首次全新 Git Analytics 启用时原子创建 installation secret，置于受控数据目录最小权限；已有 Git 数据时密钥缺失/损坏使 Git unavailable/degraded。
- 实现稳定 HMAC commit_identity、current generation、coverage 与 Git 受控 partialReason；首版不支持在线轮换。
- 前端 UI 以 [`docs/prototype/dashboard.html`](../../prototype/dashboard.html) 为页面结构、视觉层级、卡片布局、图表形态和已演示交互的开发基线。
- 在 Workbench 壳按原型实现单 POST、范围/时区校验、判别结果渲染、枚举 reason 本地化、配置变化标识、Git 下界和例外块时间显示；不得将原型演示数据写入生产逻辑。

验收：前端与原型的结构、视觉和交互一致，不接收自由错误文本、不补零或缩短范围；真实 SHA/secret 不进入 DB、IPC、日志、API、UI 或 fixture。

## 集成门槛

- 按[验收与测试](./09-验收与测试.md)运行 shared build、API/Web typecheck、迁移、查询计划、故障注入与 UI 验收。
- 复核正式文档、OpenAPI、fixture、日志和 Analytics schema 中无旧平面结果、旧 source rule、错误 receipt 留存字段、缺少 generation checkpoint、nullable gap_from、错误 lifecycle 枚举、数组单参数 IN 或自由 partialReason。
- 发布前确认没有任何场景让 Analytics 成为业务成功条件。

# 验收与测试

## 文档与构建基线

实现按改动范围运行：

```bash
npm run build -w packages/shared
npm run typecheck -w apps/api
npm run typecheck -w apps/web
npm run typecheck
```

fixture、日志断言、快照和 Mock 不得含正文、工具参数/结果、路径、真实 SHA、Commit Message、原始错误或凭证。

## API、判别联合与时间

- [ ] 唯一范围接口是 `POST /api/analytics/dashboard/query`，一次刷新只发一个 POST。
- [ ] 成功 200 为 `DashboardQuerySuccessResponse`，始终含 `rangeId/from/to/asOf/timezone/data`；非法输入为 400、Analytics 整体不可用为 503，均为 `DashboardQueryErrorResponse` 且没有 range 元数据。
- [ ] 单 Domain 异常仍为 200，只有相应资源 partial/unavailable。
- [ ] TypeBox 用 `Type.Union` 验证 Metric/Panel：available 非 null/complete/false；partial 非 null/partial/true/受控 partialReason；unavailable null/true/受控 unavailableReason；所有非法字段组合被拒绝。
- [ ] Comparison 是判别联合：available 的 delta 非 null；previous_zero、previous_not_covered、range_too_large、domain_unavailable、not_applicable 的 delta/kind 均为 null。
- [ ] Git heatmap 返回自身 `from/to/asOf`；Domain health 返回 `diagnosedAt/asOf`；Worker snapshot 返回 `snapshotAt/asOf` 并允许与 Analytics DB 快照不同。
- [ ] API 响应和错误 schema 不含 message、stack、SQL、路径、SHA、payload 或原始异常。

## rangeKind、时区与比较

- [ ] 仅接受五种 rangeKind；custom 的 UTC ms 是安全整数、`from < to` 且不超过 366 天。
- [ ] 非法 range、timezone、reportingLag anchor 均得到对应 400 受控错误。
- [ ] API 不接收本地时间字符串；客户端 DST 不存在/歧义时间不能请求；服务端 IANA 日桶覆盖 23/25 小时日。
- [ ] 24h/7d/30d 与 custom <90d 比较紧邻前期；90d/custom >=90d 为 range_too_large；比例为 pp、数量/时长为 relative。

## 真实业务 schema、Collector 与查询计划

- [ ] SQL 与 `apps/api/src/infra/db/schema.ts` 对齐：agent_run 没有 terminal_at；Tool 使用 call_part_id；Message 有 type/status/origin_run_id，完成时长取真实 completed_at-started_at。
- [ ] Run cursor 只读取真实字段；Analytics `terminal_at` 是首次观察权威业务终态时的采集时间，普通 updated_at 不漂移它。
- [ ] Tool 先按基表 `(updated_at,id)` cursor，再以 `call_part_id = agent_message_part.id` 的 LEFT JOIN 批量取得 `tool_name`，关联不影响游标行数；可靠时长为 `completed_at-started_at`。
- [ ] Compaction 仅 `type='compaction' AND status='completed'`，并以 origin_run_id 关联真实 run_kind；来源缺失时 unknown 且不计 manual/auto。
- [ ] Tool/Message 批量关联按本批 N 个 ID 生成 `IN (?, ?, ...)` 并逐项绑定；N 等于占位符数、不超过 batchSize，空列表跳过，未将 JS 数组绑定为单参数。
- [ ] cursor 行、关联、Fact 写入和 watermark 推进为一个批次提交语义；任一步失败都不推进 watermark，重试由幂等 Fact 吸收。
- [ ] 四个业务索引均已迁移：`agent_session(updated_at,id)`、`agent_run(updated_at,run_id)`、`agent_message(updated_at,id)`、`agent_tool_execution(updated_at,id)`。
- [ ] 对四条 cursor 基表查询、含实际批次占位符的 Tool part join、Compaction Run join 分别运行 `EXPLAIN QUERY PLAN`，命中 Tool/Message 主键和关联目标键，无无理由 scan 或临时排序。
- [ ] 迁移失败、索引缺失、计划退化、busy/locked 时停用 Collector/降级 Domain 并让步，业务继续运行。

## Generation、checkpoint、receipt 与水位

- [ ] identity 为 namespace/id/generation；监督进程在每次实例启动分配不可复用 generation，sequence 在 generation 内从 1 递增。
- [ ] expected slot 与 register/closing/closed 均被测试；register 丢失、首个 checkpoint 缺失均使 Domain degraded，不能认证零值。
- [ ] checkpoint 包含 generation、lastSequence、emittedThrough、earliestOpenStartedAt、outboxPending、oldestPendingAt、droppedSinceSequence/lossEpoch、sentAt；无 Outbox/open 语义时为 null。
- [ ] receipt 的唯一性/连续性使用 namespace/id/generation/sequence；控制消息不占 event sequence 的规则被验证，不存在未解释洞。
- [ ] generation 状态只接受 registered/closing/closed/stale/abandoned；stale 仍阻塞，只有 closed 或 abandoned+同事务 gap 才移出活跃阻塞集合。
- [ ] checkpoint 后立即崩溃、receipt 已入但 closed 未发、以及 sequence 已分配但未投递时，监督进程均标 abandoned 并在同一事务建立 `[gap_from,null)`；不得因 receipt 连续遗漏 gap。
- [ ] gap_from 非空且取最后已认证 reconciledThrough、从未认证时取 collectionStartedAt；开放 gap 对任意 `to > gap_from` 相交，非空 gap 按半开区间判断。
- [ ] 旧 generation 迟到 event 可幂等补 Fact 且不覆盖窄化终态；迟到 checkpoint 不能替代新 generation，也不得自动缩短 gap。
- [ ] 测试有/无旧 Model Outbox：唯一恢复者仅重投幂等 Analytics 事件、不重试 Provider；恢复可补 Fact 但不能自动删除 gap，缺失/损坏保持 degraded。
- [ ] 替代 generation 仅在认证到 T 后关闭开放 gap；历史 `[gap_from,T)` 永久保留，T 后可恢复。Execution 跨 T 的 open/未知尾段、或 Model started_at<T 仍 open 时必须阻止关闭。
- [ ] Model/Execution open Signal 或 running Fact 阻止水位越过最早 started_at；终态到达后可推进；长运行不阻断业务。
- [ ] checkpoint 只认证已知链路；Signal 生成前崩溃的漏计不得被测试伪装成现实无损。
- [ ] agent_duration 的 enabled/status/coverage/freshness/reconciledThrough 严格等于 execution 继承值。

## Fact、Rollup、留存与监控数据量

- [ ] 每个 UTC 小时在同一只读事务快照只选 Fact 或 Rollup：仅完整 closed、`bucket_end <= rollupReadyThrough`、非 Dirty、coverage 建立时读 Rollup，其余读 Fact。
- [ ] 迟到 finished 在同一事务标 Dirty；重算前强制读 Fact，成功重算后才读 Rollup；同小时不双计。
- [ ] metricDefinitionVersion 固定 `dashboard_collected_fact_v1` 和八个 Fact Domain；启停不重写留存内已采集 Fact 计数。
- [ ] 后端以 `analytics_domain_config_version.effective_at` 为每个 Fact Domain 计算范围内启用片段；仅启用片段要求 coverage/reconciledThrough/gap 完整性，整段未启用不构成要求。
- [ ] 启用→停用、停用→启用和多次切换均覆盖：任一启用片段未认证则监控数据量 partial/unavailable，停用片段不被当作漏计或零值。
- [ ] 返回 collectionConfigVersion/configuredDomainsAtAsOf/configurationChangedWithinRange；范围内启停仅标变化，不把 asOf 配置解释为完整历史，也不返回 configSegments。
- [ ] asOf disabled Domain 从健康期待排除但 health 显示 disabled；agent_duration 不能独立开关。
- [ ] receipt 按 committed_at 清理。Execution/Model open Fact 在无可靠终态或仍可改变范围结果时不得仅按 collected_at 删除；agent_duration 继承 execution。
- [ ] Rollup、collected Rollup、Dirty 和 Git 留存规则符合实体/查询合同。

## Run、Git、安全与索引矩阵

- [ ] inferred interrupted/unknown 仅由关联安全证据 `worker_generation_exited`、`agent_domain_rebuilt`、`controlled_recovery_abandoned` 产生；删除、查询不到、漏扫、暂停、drop/stale 都不推断。
- [ ] unknown 仅在 rebuilt/recovery abandoned 明确确认不再运行而原因不明时产生；observed 终态覆盖 inferred，inferred 不覆盖 observed。
- [ ] Git partialReason 只接受 `repo_not_ready`、`range_before_coverage`、`scan_stale`、`mixed_repo_coverage`；前端映射文案，无自由错误文本；无 ready Repo 为 unavailable/null。
- [ ] installation secret 在全新无 Git 数据时原子创建并长期稳定使用；已有数据时密钥缺失/损坏使 Git unavailable/degraded，不能静默重建；首版不支持在线轮换。
- [ ] `EXPLAIN QUERY PLAN` 覆盖所有 Fact 业务时间、Fact collected_at（含 Git）、Rollup/Dirty、Execution 区间/open、Model open、Worker、Git membership、receipt generation+sequence/committed_at、checkpoint domain freshness/watermark、generation/slot 及 gap 相交查询。

# 边界、安全与恢复

## 故障处理合同

| 场景 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| Session/Message/Run/Tool 业务事务 | 最小 Fact 与 Dirty 同事务；失败按业务事务失败/重试 | 业务成功而 Fact/Dirty 缺失 |
| Execution 迁移 | queued/running/ended 原始事实可靠写入；仅顶层 user 可靠时长变化标 `agent_duration` Dirty | 创建 `execution` Dirty、无 Execution 记录继续模型/工具 |
| 模型 begin 本地持久化 | 同 transaction 写 `prepared` begin、`reserved` finish、gap 行/字节 reservation；成功后才可调用 Provider，失败则受控失败 Run | 发起没有完整 reservation 的 SDK 调用、投递 prepared/reserved |
| SDK 调用边界 | 调用返回或同步 throw 后立即 prepared→provider_invoked 并写 started_at；成功前不消费 stream | 调用前升级为 invoked 制造幽灵、把 started_at 当网络送达时间 |
| 模型 begin/finish 投递 | 只重放 invoked begin/pending finish；API Fact/状态与 Dirty 同 transaction 后 ACK；API 不可用时退避 | Worker 直写主 SQLite、将 Outbox 当查询事实、用不完整身份猜补建 |
| post-call 晋级 gap | 记录无敏感 gap、coverage degraded，受控收敛 Run | 自动投递 prepared、补造 Fact 或承诺 exactly-once |
| 永久 delivery 错误 | API 先持久化主库 incident 并回 `incidentId`，Worker 才 quarantine；incident/historical loss 使 coverage degraded | 未留主库诊断就 quarantine、删本地 quarantine 后宣称完整 |
| 模型 finish 本地失败 | 已发请求不可撤销；有限重试、安全诊断，随后依据 Execution/Worker/Run 收敛 | 重发 Provider、记录原始 usage/error 补救 |
| 聚合失败 | 保留 Dirty 或等待 lease 到期，记录安全 error | 删除 Dirty、使用旧桶伪装准确 |
| Fact 回退超预算 | 返回 `ANALYTICS_DATA_INCOMPLETE` | 返回 stale 聚合却声称准确 |
| Git 任一 source 失败 | scan failed，保留 current pointer/generation | 切换部分 membership 或清空旧集合 |
| Worker unexpected exit | 记录事件、结算 restart、关闭该 instance Execution | 正常 stop 计崩溃；推断结束时长 |
| API/Worker 同时退出 | 启动恢复关闭遗留 Execution，不造 crash | 将离线时段计入 Agent 时长 |
| Agent domain rebuild | 同一 `rebuildAgentDomain()` transaction 收敛 Execution/Run/Tool、顶层时长 Dirty 与 drop/create/校验 | 直接 drop 后遗留 queued/running、创建 execution Dirty 或删 Analytics |

## 模型 Attempt 收敛

不用纯 TTL 收敛活跃模型请求。Reconciler 只依据可证明事实：

- ProcessManager 观察 Worker unexpected exit：该 instance 未闭合 Attempt → `interrupted`。
- Run/Execution 取消：关联未闭合 Attempt → `cancelled`。
- Execution 已 ended 或 Run 已终态，Attempt 仍 running：→ `unknown`。
- Worker、Execution、Run 仍活跃：保持 running，不因年龄收敛。

配置了有限 model total timeout 时，超过 timeout 加控制面宽限可作为额外异常检测；没有有限 total timeout 的 Attempt 禁止 TTL 收敛。收敛状态与模型 Dirty 必须同一事务；`interrupted/unknown` 可以没有 `completed_at`，不伪造时长。

## Agent 域重建收敛协议

`rebuildAgentDomain()` 的**同一个 SQLite transaction**中必须按以下顺序执行：

- 查找全部未结束 `analytics_run_execution`。
- 每条更新为 `state='ended'`、`ended_at=发现时间`、`effective_ended_at=null`、`end_time_quality='unknown'`、`end_reason='agent_domain_rebuilt'`。
- 对对应仍为 `running` 的 `analytics_run_fact` 更新为 `lifecycle_status='interrupted'`、`terminal_at=发现时间`；无法证明关联时可用 `unknown`，不得伪装为 completed/failed/cancelled。
- 将全部 `queued/running` `analytics_tool_fact` 更新为 `status='unknown'`、`completed_at=发现时间`、`duration_completed_at=null`；不把收敛时间作为工具时长。
- 为 Run created bucket、Tool `created_at` 桶，以及顶层 user Execution 变更前可靠时长切片的 `agent_duration` 桶标记 Dirty；无可靠终点的 Execution 不产生时长 Dirty，Execution 本身没有 Dirty。
- 然后执行 Agent 域 drop/create/校验。任一步失败则整个 transaction 回滚，Analytics 收敛、Dirty 和 Agent rebuild 均不得部分保留。

重建完成后：

- 当前 queued/running 查询不得返回重建前 Execution。
- 历史 Run 的 interrupted/unknown 单列可查，但不进入 completed/failed/cancelled 分布。
- Analytics Fact、聚合、Git Fact 不删除；受影响桶重算后仅保留可靠时长。

## 隐私与最小化

### 允许

- 时间、状态、受控原因码、计数、时长、Token 数值。
- Provider/Model ID、工具名、Workspace/Repo/Run 等稳定 ID。
- Git SHA 与非内容型变更统计。

### 禁止

| 来源 | 禁止保存、返回或日志化 |
| --- | --- |
| 消息/模型 | 用户文本、Prompt、Assistant 文本、Reasoning、图片、Provider 原始 payload |
| 工具 | input JSON、结果 JSON、结果预览、错误文本、Artifact 路径 |
| Git | Commit Message、文件路径、Diff、文件内容、remote URL 凭证 |
| 系统 | API key、internal token、环境变量、绝对路径、Worker stdout/stderr |

受控 reason/error code 不得直接复制 `Error.message`。Analytics DTO、数据库 schema、日志字段和公开 API 均必须接受隐私审查。

### Delivery Outbox 专项审查

- Outbox 路径必须由 `analyticsWorkerDeliveryOutboxPath(dataDir)` 或同一 `paths.ts` 基础设施派生，基于 `AWB_DATA_DIR`，禁止硬编码路径或客户端输入。
- 审计 `payload_json` 必须只含经过 TypeBox/内部 schema 校验的标准 DTO；抽样 SQLite 文件、retry/quarantine 日志和 API 请求，均不得出现 Prompt、回复、Reasoning、原始 usage、原始错误、工具内容、绝对路径、token 或凭证。
- Provider 调用前必须在 owner/fence transaction 同时持久化 prepared begin、reserved finish、reservation 实体、Gap 逻辑槽位和 64 KiB 字节 reservation。有效行配额为两类 delivery 的物理未清理行、reservation 实体行与未消费 Gap 槽位之和；admission 必须串行，不能依赖内存计数。admission 成功后 finish/晋级/gap 的已预留资源不得被普通逻辑阈值拒绝。
- Worker 必须先取得 Outbox 单写者独占 lock/fence；所有写入均按 owner/fence 条件执行。取得失败不得 ready 或执行模型；新 owner 取得 fence 后旧实例所有写入必须失败。
- 新 owner 在启动 sender 前逐条处理全部遗留 prepared；每条都必须在同一 owner/fence transaction 幂等物化预留的 `prepared_expired_ambiguous` gap、删除 prepared 与 reserved finish、释放 reservation 后 commit。Gap insert、finish cleanup、prepared cleanup、release 或 commit 任一步失败都整体 rollback，且 sender/ready/模型执行全部 fail-closed。身份不完全一致只可 quarantine/安全停机，不能当幂等成功。随后仅恢复 `provider_invoked/pending/delivering`（中断 delivery 重新变可投递）发送。
- SDK 已调用而 promotion 失败、且当前 owner 仍能写时，必须改在同一 transaction 物化 `post_call_promotion_failed|post_call_promotion_uncertain` Gap、删除 prepared/unused reserved、删除 reservation 并 commit。该 transaction 成功后不得留下 prepared，handoff 不得再建 prepared-expired Gap；若回滚/崩溃，promotion Gap 不存在且只可由后续 handoff 创建 prepared-expired Gap。恢复发现同 Attempt 同时有两类 Gap 是不变量损坏，隔离、安全停机且不得 ready。`provider_invoked + reserved` 恢复必须用 reserved 行物化 `interrupted|unknown` finish 并删除 reservation；孤立 reservation 只能按可证明 begin/finish/Gap 状态收敛，身份冲突安全停机。
- 固定默认阈值：有效行配额最大 100,000，单 Attempt 64 KiB，`(page_count - freelist_count) * page_size + WAL + SHM + 未消费 reservation + 新 64 KiB` 必须 **< 256 MiB**，磁盘扣除全部 reservation 和新 reservation 后必须严格大于 512 MiB。新 Attempt 固定占 4 个容量单位，当前有效占用 99,996 可准入，99,997 及以上拒绝。容量检查前仅清理过期 acked model delivery 和 ACK 超过 24h 的本地 gap delivery；admission 后 reserved finish/gap 不得被逻辑满额拒绝。
- Outbox 首次建库前设置 `PRAGMA auto_vacuum=INCREMENTAL`；清理后只在受控非请求路径执行 WAL checkpoint 与 incremental vacuum，禁止每次请求或 admission 执行 full `VACUUM`。逻辑已用空间而非主文件历史高水位决定 admission，清理回收后必须能恢复准入。
- 本地 gap delivery API ACK 后固定保留 24h 可清理，不查询主库 resolved；主库 gap resolved 留存 30 天由 API 管理，清理本地 ACKed gap 不影响 coverage。`409/422` 仅在 API 返回已持久化的 incidentId 后 quarantine，网络/5xx/DB busy 或 incident 写入失败指数退避。
- 不得删除 prepared/provider_invoked/pending/delivering/quarantined、未 ACK gap 或 unresolved gap 腾空间。quarantined 的 30d 是告警/人工诊断期限，不是自动删除期限；只有人工受控导出/确认丢弃，或修复后 ACK 才可清理。

## 事务、幂等、并发

### 事务边界

| 类别 | 要求 |
| --- | --- |
| Session/Message/Run/Tool | 业务 Fact 与 Dirty 同一业务 SQLite transaction |
| Execution queued/ended | 与 lifecycle fence、取消、恢复、终态/重建收敛同事务 |
| Execution start | Worker internal handshake 或 local fallback 可靠条件迁移；成功前不执行 |
| 模型 Outbox admission | Worker owner/fence SQLite transaction 同时写 prepared、reserved finish、Gap/字节 reservation；Provider 调用前必须提交 |
| 模型 Outbox / handoff | 已准入的 provider_invoked、reserved→pending、唯一 Gap 物化，以及 prepared handoff 的 Gap+cleanup+release 均按 owner/fence transaction；promotion Gap 也必须 Gap+prepared/reserved/reservation cleanup 原子提交；同 call 的第二种 Gap 必须拒绝并 fail-closed；handoff 未清空不得 ready |
| 模型 API 投递 | API 在 body 解析前验证认证 envelope 的 `delivery_event_id`；Fact/终态与 Dirty 同主库 Analytics transaction，永久 `409/422` 先以该 transport ID 可靠写 incident 再回 incidentId，提交成功后 ACK；ID 缺失/非法只返回协议错误，不建 incident、不 quarantine |
| Worker/Git | instance/event 或 Fact/generation/pointer 与 Dirty 同 Analytics transaction |
| 聚合 | 单 Dirty 重算投影与删除 Dirty 同 transaction |

### 幂等与冲突

| 对象 | 键 | 冲突规则 |
| --- | --- | --- |
| Session / Message / Run / Tool Fact | 对应业务 ID | 不可变身份不一致拒绝 |
| Execution | `execution_id`、`(run_id,attempt_no)` | 条件状态迁移；重复返回同结果 |
| Outbox delivery | `delivery_id`、`event_id`、`(model_call_id,phase)` | prepared 仅 begin 且不可投递；重放同 event 幂等；每 call 仅一个 begin/finish；永久投递错误仅在已获 incidentId 后 quarantine |
| Delivery incident | `delivery_event_id` | `NOT NULL UNIQUE` transport 幂等；同 ID 重放返回原 incidentId；解析 body 失败但 ID 有效可建无 model_call ID incident |
| Delivery Gap | `gap_id`、`event_id`、`model_call_id` | 每个 call 至多一个 Gap；仅 kind 与完整身份均一致的重放幂等，kind 不同或身份冲突即隔离/fail-closed，不覆盖、不增行 |
| Model Attempt | `model_call_id`、`(run_id,turn_id,attempt_no)` | `execution_id` 必填且 Execution 的 run_id 一致；begin/finish 身份和 started_at 完全一致，否则 `409` |
| Worker instance | `worker_instance_id` | 不可变 generation/配置不一致拒绝 |
| Restart attempt | `restart_attempt_id` | outcome 唯一结算，二次结算幂等或冲突 |
| Git Fact | `(repo_id,sha)` | 不可变元数据冲突诊断，不静默覆盖 |
| Git current pointer | `repo_id + generation fence` | 仅完整成功 generation 原子切换 |
| Dirty | `(domain,bucket_start,dimension_key)` | upsert 标脏、lease 条件领取 |

### Dirty lease

- `pending` 和过期 `claimed` 可领取；有效 lease 不可被其他 worker 覆盖。
- `claimed_by/claimed_at/claim_expires_at/attempt_count` 以及 `mark_version/claimed_version` 必须持久化。
- 每次事实变更标脏递增 `mark_version`；处理者只可删除其领取版本仍为最新版本的 Dirty。领取期间有新标脏时，处理完成必须释放为 pending，不能删除新版本。
- 处理崩溃后 lease 到期可重领；尝试次数用于诊断，不能因次数多而丢弃 Dirty。

## 数据质量不变量

必须有安全诊断与测试覆盖：

- 一个 Run 多个未结束 Execution。
- 非法时间：`ended_at < started_at` 或 `effective_ended_at` 越界。
- `exact`/`unknown` 与 effective end 不一致。
- 模型 Token 负数、timeout kind 与 status 不匹配、finish 身份冲突。
- `cache_comparable=1` 但缺 input/cache-read，或 cache-write 未验证却有数值。
- Model DTO 缺 `execution_id`、Execution 不存在或 `run_id` 不匹配。
- prepared 被 sender 投递、pre-call 崩溃创建 Fact、SDK 同步 throw 未计 Attempt，或 started_at 在 begin/finish 不一致。
- post-call/pre-promotion gap 未写安全诊断/coverage degraded，同一 call 的两个 promotion kind 或 promotion 与 prepared-expired Gap 同时存在，gap kind/身份冲突仍被接受、覆盖或新增第二行，或 gap 被计入 request_count/聚合/范围筛选。
- Outbox owner lock/fence 缺失、旧 owner 仍能写、未取得 owner 仍启动模型、handoff 遗留 prepared 未在单 transaction gap+finish cleanup+release，或活跃 prepared 被后台清理。
- begin prepared 没有同 transaction finish reserved / reservation 实体 / gap / 字节 reservation，admission 后 finish/gap 被普通逻辑满额拒绝，或 reservation 的崩溃恢复、正常物化删除或孤立收敛遗漏。
- Outbox transport event ID 缺失/非法仍写 incident 或 quarantine、event 重复导致 incident 重复计数、ACK 早于 Fact+Dirty 提交、begin 未落盘即调用 Provider、API 未写 incidentId 即 quarantine、quarantined 被重试/自动删除，或容量/磁盘故障仍调用 Provider。
- coverage 未同时检查 unresolved Gap、`count(*) where resolved_at is null` 的 unresolved incident 和未修复 confirmed-missing incident 查询，或本地 ACKed gap/quarantine 删除错误改变主库 coverage；incident 的 resolution/resolved_at 非法组合被持久化、resolution 被覆盖/重写 resolved_at、不同 repair generation 被接受或 Fact/Dirty/repair 未同事务。
- 缺少或未使用 `analytics_model_call_fact(execution_id,status,updated_at)`，导致按 Execution 收敛/诊断走全表扫描。
- restart attempt 被重复结算。
- `restart_scheduled` 出现在公开聚合或 API 响应。
- current Git pointer 指向不存在/未 completed generation，或 current generation source 非全部 succeeded。
- `next_generation` 回退、失败 generation 被复用，或 Git coverage 未经 current scan join 读取。
- Git 切换 transaction 部分写入 Fact/membership/scan coverage/status/pointer/Dirty，或故障后旧 current 被改变。
- 聚合读取 Dirty、开放、缺失或 rebuild 桶。

诊断只记录安全 ID、枚举、表名和计数。

## 版本、回填与删除

- Analytics schema 独立升级，不触发 Agent 域整体删除。
- 指标口径/聚合 SQL 改变必须更新设计、同步 enum/schema、全量重建相关 domain。
- 回填与双写顺序、旧 running 映射、覆盖边界见 [数据与实体设计](./03-数据与实体设计.md)；不得尝试补造旧 Execution/模型/Worker 历史。
- `analytics_domain_state` 覆盖 `model|run|execution|agent_duration|tool|message|session|worker|git`；Git State 仅 job freshness，coverage 只经 `repo_state.current_scan_id` 读取当前 completed `analytics_git_scan`。
- Workspace/Repo 业务删除不级联删除 Analytics；未来历史清理只能经独立、显式、可确认流程。

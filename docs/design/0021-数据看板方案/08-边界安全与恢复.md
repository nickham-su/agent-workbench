# 边界、安全与恢复

## 业务与存储隔离

- Dashboard 是旁路统计，不能影响业务结果、持久状态、调用顺序、Provider 请求、工具执行、Git 操作或 Run 成功条件。
- **所有 `analytics.sqlite` SQL 和业务 SQLite 旁路只读都只能由 Analytics 子进程执行。**API 主进程仅做受控 IPC 转发。
- 私有 Outbox 不属于 `analytics.sqlite`；业务线程只调用非阻塞 `tryEmit()`，不等待队列、Outbox、IPC、SQLite 或 ACK。
- Analytics 不可用、queue 满、Outbox/控制消息/checkpoint 失败、Collector busy 或 ACK 丢失可导致统计降级/已知漏计，绝不阻断业务。

Analytics 只能接收安全 DTO。禁止持久化、传输、日志输出或错误回显正文、Reasoning、工具参数/结果、终端 I/O、原始 payload/错误/堆栈、路径、真实 SHA、Commit Message、Diff、remote/ref、凭证或绝对工作区路径。

## Producer generation、checkpoint 与 loss

- 身份必须是 `producer_namespace + producer_id + producer_generation`；监督进程每次实例启动分配不可复用 generation，sequence 仅在该 generation 内从 1 递增。
- 监督进程以 best-effort register/closing/closed 控制消息发布实际 generation。配置 expected slot 是兜底权威：slot 缺少新鲜 generation/checkpoint 时 Domain degraded，不能因 register 丢失而错误健康。
- checkpoint 需含 generation、lastSequence、emittedThrough、earliestOpenStartedAt、outboxPending、oldestPendingAt、droppedSinceSequence/lossEpoch、sentAt。
- generation 状态仅为 `registered | closing | closed | stale | abandoned`。closed 需 finalSequence、连续 receipt、无未决 backlog 且 loss 已登记；stale 仅诊断且仍阻塞水位；abandoned 只能由监督进程确认异常 exit 后标记。
- 只有 closed，或 abandoned 且同一 Analytics 事务已持久 coverage gap，才可移出活跃阻塞集合。stale/失联/未关闭 generation 不得被当作健康；但安全关闭 gap 后，未来不相交范围允许恢复认证。
- 异常 exit 一律建立 `[gap_from,null)`，即使 receipt/checkpoint 连续也不能省略。gap_from 是最后已认证 reconciledThrough，从未认证则为 collectionStartedAt；开放 gap 与任意 `to > gap_from` 的查询相交。非空 gap 使用 `[gap_from,gap_to)`。
- 任一 known drop 建立历史 gap，该 generation 余生不再认证完整。替代 generation 只有认证到 T 且不存在 started_at<T 的未结束/不可靠 Model/Execution Fact 或跨 T 未知 Execution 尾段时才能关闭开放 gap 到 T；这只恢复 T 后，绝不修复历史区间。
- Model abandoned generation 的旧 Outbox 只能由监督进程指定唯一恢复者，在旧实例退出后只读/独占打开并按 generation+sequence/event_id 重投。它可补 Fact，不能自动缩 gap，不得重试 Provider；缺失/损坏则保留 gap 并降级。
- Model/Execution 的 earliest open start 同 Analytics running Fact 的最早 started_at 共同限制水位；长运行不阻断业务。agent_duration 严格继承 execution。
- checkpoint 仅认证已知采集链路；Signal 生成前崩溃仍可能漏计，禁止任何无损/绝对完整承诺。

## Receipt 冲突与控制消息

Event receipt 绑定：

```text
producer_namespace / producer_id / producer_generation / event_id / sequence
payload_version / event_type / subject_identity / fingerprint / committed_at
```

- fingerprint 对规范化安全 DTO 求稳定 hash，不含敏感字段。
- 相同 event_id 且 fingerprint 相同才幂等 durable ACK。
- 相同 event_id 不同 fingerprint，或同 generation 的 sequence 对应不同 subject/fingerprint：不 ACK、不覆盖既有 Fact、记录受控冲突码并降级 Domain。
- 业务 event receipt 连续覆盖 `1..lastSequence`。register/closing/closed/checkpoint 是不占该序列的控制消息，按 lifecycle/时间单独校验；不允许未解释的 event sequence 洞。
- 旧 generation 迟到事件可按 generation+sequence 幂等持久化，但不得覆盖较窄化终态；迟到 checkpoint 不能代替新 generation。

## Run 推断安全边界

- inferred interrupted/unknown 仅是 Analytics 展示，不写回业务 Run。
- 可接受证据仅包括关联 run_id/execution_id 的 `worker_generation_exited`，以及 `agent_domain_rebuilt`、`controlled_recovery_abandoned`；后两者也可在同一事务只窄化当时明确 running 的集合。
- 首版 interrupted 仅在证据充分时产生。unknown 仅在 domain rebuilt/recovery abandoned 明确确认“不再运行、原因不可判定”时产生；否则保持 running，并将 Panel/Domain degraded。
- 普通行/Workspace 删除、查询不到、Collector 漏扫/暂停、Analytics 故障、Signal drop、Outbox backlog、checkpoint stale 都不是推断证据。
- observed completed/failed/cancelled 永远覆盖 inferred；inferred 永不覆盖 observed。

## Git 密钥与部分数据

`commit_identity` 是唯一可持久化的 Commit 身份：

```text
HMAC-SHA-256(installation_secret, repo_id + NUL + raw_SHA)
```

raw SHA 只在受控 scan 内瞬时使用。installation secret 在全新、无 Git Analytics 数据时原子创建，存于受控数据目录并采用最小文件权限、长期稳定使用，不出现在日志/API/UI。已有 Git Analytics 数据时若密钥缺失/损坏，Git Domain unavailable/degraded，禁止静默重建。首版不支持在线轮换；未来必须显式 identity reset 并隔离/清理旧 generation。

Git 部分数据只使用受控枚举 `repo_not_ready`、`range_before_coverage`、`scan_stale`、`mixed_repo_coverage`。有 ready Repo 时可显示下界；没有 ready Repo 时 unavailable/null，绝不是零。

## 留存、Dirty 与恢复

- `retention_floor` 是业务事件时间查询边界。Model/Tool/Message Rollup 仅在 `bucket_end <= retention_floor` 删除，collected Rollup 按自身 collected-at 桶删除。
- receipt 按 `committed_at` 清理。
- 普通非 Git Fact 按 `collected_at` 物理留存，但未可靠结束的 Execution/Model 是 open Fact 例外：仅在可靠终态、业务时间越过 retentionFloor 且达到物理保留期后删除；否则保留并诊断/degraded。
- Dirty 没有 completed 状态。成功重算事务删除 Dirty；失败回滚保留；维护只清理不可查询边界前的异常遗留 Dirty。
- Analytics DB 损坏、schema 不匹配或不可打开时隔离并使 Dashboard 受控 503；不修改业务数据库，也不推断/回填旧业务历史。

## 受控诊断

对外诊断仅包含稳定错误码、Domain、时间、coverage gap、slot/generation 健康、配置版本与 Git 枚举原因。不得暴露 SQL、原始异常、文件路径、SHA、payload 或凭证。

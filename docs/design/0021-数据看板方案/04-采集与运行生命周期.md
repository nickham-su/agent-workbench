# 采集与运行生命周期

## 旁路不变量

- **所有 `analytics.sqlite` SQL 只能由 Analytics 子进程执行。**业务 SQLite 旁路只读查询也只能由它发起。
- 业务事务不写 Analytics，不等待 Analytics I/O/ACK，Analytics 返回值不参与 Run、Provider、工具或 Git 分支。
- 生产者私有 Outbox 不属于 `analytics.sqlite`。`tryEmit()` 立即返回且不向业务抛出异常。
- 队列满、Outbox 故障、checkpoint 丢失、Collector busy、Analytics 重启或查询超时只导致统计降级/漏计，不阻断、取消、失败或重试业务动作。

API 主进程只做认证、受控 IPC 转发和子进程监督；Analytics 子进程是 Analytics SQL 的唯一写者/查询者。旧子进程完全退出后才替换，避免双写。

## 业务 SQLite 旁路 Collector

### 真实业务 schema 与迁移

以当前 `apps/api/src/infra/db/schema.ts` 为准：

- `agent_session`：`id`、`kind`、`created_at`、`updated_at`。
- `agent_run`：`run_id`、`run_kind`、`parent_run_id`、`status`、`created_at`、`updated_at`；**没有 `terminal_at`**。
- `agent_message`：`id`、`type`、`status`、`origin_run_id`、`created_at`、`updated_at`。
- `agent_tool_execution`：`id`、`call_part_id`、`origin_run_id`、`status`、`created_at`、`updated_at`、`started_at`、`completed_at`。
- `agent_message_part`：`id`、`tool_name`；`agent_tool_execution.call_part_id` 是非空唯一外键，指向该表 `id`。

启用 Collector 前，业务 SQLite 必须通过正式迁移拥有：

```sql
create index if not exists idx_agent_session_updated_id
  on agent_session(updated_at, id);
create index if not exists idx_agent_run_updated_run_id
  on agent_run(updated_at, run_id);
create index if not exists idx_agent_message_updated_id
  on agent_message(updated_at, id);
create index if not exists idx_agent_tool_execution_updated_id
  on agent_tool_execution(updated_at, id);
```

索引迁移失败、索引缺失或计划退化时，Collector 必须停用并使对应 Domain degraded/unavailable；不得静默全表扫描。业务继续运行。

### 可执行游标 SQL

每个 Collector 仅用基表的 `(updated_at, stable_id)` 游标扫描，严格升序、参数绑定、小批次。这样关联查询不参与游标，不会造成重复或跳行。

```sql
-- Session
select id, kind, created_at, updated_at
from agent_session
where (updated_at > :cursorUpdatedAt)
   or (updated_at = :cursorUpdatedAt and id > :cursorId)
order by updated_at asc, id asc
limit :batchSize;

-- Run：agent_run 无 terminal_at
select run_id, run_kind, parent_run_id, status, created_at, updated_at
from agent_run
where (updated_at > :cursorUpdatedAt)
   or (updated_at = :cursorUpdatedAt and run_id > :cursorId)
order by updated_at asc, run_id asc
limit :batchSize;

-- Message：不选择正文、part 或其他敏感列
select id, type, status, origin_run_id, created_at, updated_at
from agent_message
where (updated_at > :cursorUpdatedAt)
   or (updated_at = :cursorUpdatedAt and id > :cursorId)
order by updated_at asc, id asc
limit :batchSize;

-- Tool 基表：不选择 result_preview、structured_result_json、error 或路径
select id, call_part_id, origin_run_id, status, created_at, started_at, completed_at, updated_at
from agent_tool_execution
where (updated_at > :cursorUpdatedAt)
   or (updated_at = :cursorUpdatedAt and id > :cursorId)
order by updated_at asc, id asc
limit :batchSize;
```

批次已确定后才进行安全关联，不影响 cursor：

```sql
-- Tool 名称：LEFT JOIN 保留 Tool Fact；正常 schema 下 call_part_id 的非空 FK 应命中唯一 part。
-- 示例为 N=3；实际 SQL 由本批 N 个 `?` 组成，不是单个数组参数。
select tool.id, part.tool_name
from agent_tool_execution tool
left join agent_message_part part on part.id = tool.call_part_id
where tool.id in (?, ?, ?);

-- Compaction 分类：只有 completed compaction 才分类；缺失来源 Run 保持 unknown。
-- 示例为 N=3；实际 SQL 由本批 N 个 `?` 组成。
select message.id, message.type, message.status, message.origin_run_id, run.run_kind
from agent_message message
left join agent_run run on run.run_id = message.origin_run_id
where message.id in (?, ?, ?)
  and message.type = 'compaction'
  and message.status = 'completed';
```

- 运行时从本批 ID 数 `N` 生成 `?, ?, ...` 并逐项绑定，`N` 必须严格等于占位符数且不大于 `batchSize`；空 ID 列表跳过该关联查询。不得把 JavaScript 数组绑定到单一 `IN (?)` 参数。
- 基表 cursor 行、关联结果、Analytics Fact 写入和 Analytics watermark 推进构成一个批次提交语义：任一步失败则不推进基表 watermark，后续重试依赖幂等 Fact。
- Tool 的可靠完成时长只在 `status='completed'` 且两端非空、`completed_at >= started_at` 时为 `completed_at-started_at`。无可靠两端不计时长。
- `LEFT JOIN` 是为了不因异常参照而丢失 Tool 计数；关联缺失是业务完整性诊断，`tool_name=null`，不输出路径/原始数据并降级 Tool Domain。
- Compaction 仅 `type='compaction' AND status='completed'` 进入压缩候选。关联来源 Run 且 `run_kind='manual_compaction'` 计 manual；已知其他 run_kind 计 auto；来源 null/尚未采到时标记 unknown，永不猜入 manual/auto。
- Analytics Run Fact 的 `terminal_at` 在首次观察到权威业务终态 `completed|failed|cancelled` 时写入当前采集时间。其后普通业务 `updated_at` 不得使它漂移。

### 让步、水位与查询计划

- 使用只读 WAL 连接、低 `busy_timeout`、小批和退避；业务 busy/locked 时立即结束本批，稍后从已提交游标重试。
- 成功写入 Analytics 后才推进 cursor；有限重叠扫描由 Fact upsert 幂等吸收。
- 无新记录的完整扫描才可把 Collector `reconciledThrough` 推进至本轮扫描 anchor；它只认证已知轮询链路。
- `EXPLAIN QUERY PLAN` 必须使用实际批次生成的 `IN (?, ?, ...)` 占位符与绑定数量，验证四条基表游标查询使用目标 `(updated_at, identity)` 索引且无需临时排序；Tool 查询命中 `agent_tool_execution.id` 与 `agent_message_part.id`，Compaction 查询命中 `agent_message.id` 与 `agent_run.run_id`。

不做旧业务回填、union 查询或推断历史。启用后正常更新的旧对象可由增量游标自然发现。

## Signal producer generation 闭环

### 身份、slot 与监督控制面

生产者身份是：

```text
producer_namespace + producer_id + producer_generation
```

监督进程每次实例启动分配不可复用随机 `producer_generation`；该 generation 内 sequence 从 1 单调递增。它通过非阻塞 control signal 发送 `register`、`closing`、`closed`，不要求业务热路径持久化跨 generation 的 sequence。

配置的 expected slot 是防 register 丢失的权威兜底：

| 实际运行主体 | namespace / slot | Domain |
| --- | --- | --- |
| Agent Worker 的 AgentRunner | `agent_worker / agent_runner` | model、execution |
| 启用时 API local fallback | `api_local_fallback / api_local_fallback` | model、execution |
| Worker 生命周期观察者 | `worker_observer / process_manager` | worker |

- 未挂载的运行模式不声明 slot；不假定不存在的多实例生产者。
- expected slot 没有新鲜 generation 和有效 checkpoint 时，相关 Domain 必须 degraded，不能因 register 发布失败而错误健康或认证零值。

### Signal 与 checkpoint DTO

```ts
type ProducerIdentity = {
  producerNamespace: string;
  producerId: string;
  producerGeneration: string;
};

type ProducerCheckpoint = ProducerIdentity & {
  lastSequence: number;
  emittedThrough: number;
  earliestOpenStartedAt: number | null;
  outboxPending: number | null;
  oldestPendingAt: number | null;
  droppedSinceSequence: number | null;
  lossEpoch: string | null;
  sentAt: number;
};
```

- event sequence 只分配给业务事件，receipt 必须连续覆盖 `1..lastSequence`。register/closing/closed/checkpoint 是不占 event sequence 的控制消息，分别持久化 lifecycle/checkpoint 信息；因此它们不会制造未解释 sequence 洞。
- checkpoint、控制消息与业务 Signal 均为 best-effort、非阻塞；失败不影响业务。
- Model producer 的私有 Outbox 报告 pending 数及最早 pending 时间；没有 Outbox 的生产者显式传 `null`。

### 生命周期、水位与 loss

- 新 generation 在第一个有效 checkpoint 到达前阻止它负责的 Domain 水位推进。
- generation 状态只能是 `registered | closing | closed | stale | abandoned`。`closed` 需要正常 finalSequence、连续 receipt、无未决 backlog 且 loss 已登记；`stale` 仅诊断、仍阻塞水位；`abandoned` 只能由监督进程在确认实例退出且不可能正常关闭时标记。
- 只有 `closed`，或 `abandoned` 且同一 Analytics 事务已持久建立对应 coverage gap，才可移出活跃阻塞集合。stale、失联或未收到 closed/abandoned 的旧 generation 继续阻止推进并保持 Domain degraded；监督进程确认 exit 后必须转为 abandoned，随后仅在 gap 安全关闭后的未来不相交范围才可恢复认证。
- 任一 `droppedSinceSequence` 或 lossEpoch 表示该 generation 出现已知 loss：generation 余生不能认证完整，Analytics 记录永久 coverage gap。只有关闭它并启动新 generation 后，后续业务时间才能重新认证；旧 gap 永不被新 generation 洗掉。
- 异常 exit 时，监督进程必须在同一 Analytics 事务标记 `abandoned` 并建立 `[gap_from,null)`；`gap_from` 是该 Domain 此 generation 出问题前最后一次已认证 `reconciledThrough`，从未认证时取 `collectionStartedAt`。不得因最后 checkpoint/receipt 连续省略 gap，内存中可能已有已分配但未投递/未持久化尾部。
- 开放 gap 的 `gap_to=null` 代表至正无穷。任何 `[from,to)` 满足 `to > gap_from` 都相交，不能认证完整；非空 gap 使用 `[gap_from,gap_to)` 与标准半开区间相交。
- Model 私有 Outbox 的异常 generation 由监督进程指定唯一恢复者。旧实例完全退出后，恢复者只读/独占打开旧 Outbox，按 generation+sequence/event_id 幂等重投到 Analytics；可补 Fact，但不得重试 Provider，也不得因恢复自动删除/缩短 gap。Outbox 缺失或损坏时保持 gap 并降级 Domain。
- 替代 generation 持续健康后，只有其按 checkpoint/receipt/Outbox/open-Fact 规则认证到 `T`，且不存在 `started_at<T` 的未结束或不可靠 Model/Execution Fact、也不存在跨 `T` 的未知 Execution 尾段时，才能将旧开放 gap 写为 `[gap_from,T)`。这只允许 `T` 后恢复认证，不能修复历史 gap；Worker 无 open 语义，`T` 为替代 generation 首个可认证 `emittedThrough`；agent_duration 继承 execution gap。
- 旧 generation 的迟到 event/checkpoint 可按 `(namespace,id,generation,sequence)` 幂等接收并补 Fact，但不得覆盖更窄化终态、不得自动缩短 gap；首版不提供历史 gap repair。
- 不可见的信号生成前崩溃仍可能漏计。checkpoint 只认证已知采集链路，绝不保证现实无损。

候选 `reconciledThrough` 只有全部条件满足时才推进：所有 expected slot 均有新鲜有效 generation/checkpoint、各活跃 generation receipt 连续至 `lastSequence`、无 backlog、无 loss、无相交 coverage gap，且 generation lifecycle 合法。对 model/execution，候选值还不得晚于下列最小值：

```text
min(各 generation emittedThrough,
    各 checkpoint earliestOpenStartedAt,
    Analytics 当前 running Fact 的最早 started_at)
```

没有 open Fact 时才可按 `emittedThrough` 推进。Worker 事件没有 open 语义，open 字段为 null。长时间 Model/Execution 只阻止该水位越过开始时刻，不阻断业务。`agent_duration` 无条件继承 execution 的状态、水位、coverage 和 freshness。

## Run 展示状态与模型 Outbox

可靠证据才允许 inferred 状态：`worker_generation_exited`、`agent_domain_rebuilt`、`controlled_recovery_abandoned` 必须关联 `run_id/execution_id`，或在同一 Analytics 事务仅作用于当时明确 running 的 Fact 集合。

- 首版 `interrupted` 仅用证据充分映射。
- `unknown` 仅在 `agent_domain_rebuilt` 或 `controlled_recovery_abandoned` 明确确认不再运行、但原因不可判定时产生；否则保持 running 并令相关 Panel/Domain degraded。
- 行删除、Workspace 删除、Collector 漏扫/暂停、查询不到、Signal drop 或 checkpoint stale 均不得推断 interrupted/unknown。
- observed completed/failed/cancelled 覆盖 inferred；inferred 永不覆盖 observed。

模型调用线程经有界队列和私有 Outbox 投递 invoked/finished 安全快照。持久化 ACK 只在 Analytics 事务提交 receipt + Fact + Dirty 后返回，是删除 Outbox 项目的唯一依据；流控 ACK 不可删除 Outbox。Outbox 满/损坏只导致统计降级，不得阻止或重发 Provider 调用。

## Worker snapshot

AgentRunner 发出完整 live snapshot：

```text
snapshot_at / active_count / queue_length / concurrency / last_ready_at / runner_mode
```

nested Execution 不增加 `active_count`。snapshot 过期时整组 stale；local fallback 单独显示。live snapshot 不写历史 Rollup。

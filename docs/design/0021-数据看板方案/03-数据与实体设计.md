# 数据与实体设计

## 存储与执行边界

Analytics 数据存于独立数据目录 `analytics.sqlite`，与业务 SQLite、Agent schema 和生产者私有 Outbox 隔离。

- **所有 `analytics.sqlite` SQL 只能由 Analytics 子进程执行。**业务 SQLite 的旁路只读查询同样只能由它发起。
- 生产者私有 Outbox 不属于 `analytics.sqlite`，不作为 Dashboard 查询或聚合源。
- Analytics 使用独立 `ANALYTICS_SCHEMA_VERSION`，不进入 `AGENT_DOMAIN_TABLES`，不建跨库外键，也不随 Agent domain rebuild 删除。
- 所有时间为 UTC Unix ms；枚举、质量、原因和错误码为受控值；不得保存正文、工具参数/结果、路径、真实 SHA、Commit Message、原始错误、凭证或原始 payload。

## Domain State、配置与缺口

```text
analytics_domain_state
- domain primary key
- collection_started_at nullable
- reconciled_through nullable
- rollup_ready_through nullable
- retention_floor nullable
- status: healthy | degraded | stale | unavailable | disabled
- last_succeeded_at nullable
- last_error_code nullable
- updated_at

analytics_domain_config_version
- collection_config_version primary key
- effective_at
- enabled_fact_domains_json  // run/session/message/tool/execution/model/worker/git
- changed_at

analytics_signal_coverage_gap
- gap_id primary key
- domain
- producer_namespace / producer_id / producer_generation
- gap_from integer not null
- gap_to integer nullable
- cause: known_drop | abandoned_exit
- dropped_since_sequence nullable
- recorded_at
- closed_at nullable
```

Domain 固定为：

```text
model / run / execution / agent_duration / tool / message / session / worker / git
```

- `collection_started_at` 是非 Git Domain 开始正常采集的时间，不代表历史回填。
- `reconciled_through` 是已知采集链路认证到的业务事件时间水位，不是最大 Fact 时间，也不承诺信号生成前崩溃时未漏计。
- `rollup_ready_through` 只适用于 model/tool/message。
- `retention_floor` 是业务事件时间最早可查询边界；`availableFrom=max(collection_started_at, retention_floor)`。
- `agent_duration` 不可独立启停，`enabled(agent_duration)==enabled(execution)`；其 state、coverage、freshness、`reconciled_through` 完全继承 execution。
- `gap_from` 永远非空：异常 generation 出问题前最后一次已认证的 Domain `reconciled_through`；若从未认证，取 `collection_started_at`。若两者均不可用，Domain 尚无可认证起点，保持 unavailable，不能创建模糊 gap。
- `gap_to=null` 表示开放缺口延续到正无穷；任意查询 `[from,to)` 满足 `to > gap_from` 即与之相交。非空 gap 使用 `[gap_from,gap_to)`，与查询采用标准半开区间相交判断。
- gap 相交会使所需 Panel partial/unavailable，零值不能认证。新 producer generation 不能删除或覆盖旧 gap。

## 监控数据量定义版本

```text
metric_definition_version = "dashboard_collected_fact_v1"
```

该定义不可变，首版永久统计首次插入的八个规范 Fact Domain：

```text
run / session / message / tool / execution / model / worker / git
```

- `agent_duration`、Rollup、Dirty、Signal、receipt、checkpoint、slot/generation state、watermark、membership、scan 元数据均不计。
- 配置开关只前瞻性决定是否采集新 Fact 和是否期待该 Domain 健康；不重写、移除或重新解释留存内已采集 Fact 的 `collected_at` 计数。
- 查询按 `analytics_domain_config_version.effective_at` 切出每个八域 Fact Domain 在 `[from,to)` 的启用片段。只要求每个启用片段具备 collection coverage、`reconciled_through` 与无相交 gap 的认证；整段未启用则该 Domain 不构成该范围完整性要求。
- 任一启用片段不可认证，监控数据量为 partial/unavailable；不得仅以 asOf 配置或范围末端水位代表此前片段。
- `collection_config_version` 和 asOf 时的配置仅供响应诊断，不能代表整个历史范围；范围内配置变更由查询返回 `configurationChangedWithinRange=true`，但无需返回 configSegments。

## Signal producer generation、slot 与 checkpoint

生产者实例身份固定为：

```text
producer_namespace + producer_id + producer_generation
```

- `producer_generation` 由监督进程在每次生产者实例启动时分配不可复用随机 ID；sequence 仅在 generation 内从 1 单调递增，不要求业务热路径持久化全局 sequence。
- 配置声明的 expected slot 是预期活跃集合的兜底权威；监督进程还以非阻塞 control signal 发布 register、closing、closed。register 丢失时，slot 无新鲜 generation/checkpoint 仍必须 degraded，不能认证零值。
- 本架构只声明实际挂载的 slot：`agent_worker/agent_runner` 为 Agent Worker 的 model、execution 生产者；`api_local_fallback/api_local_fallback` 为启用时 API local fallback 的 model、execution 生产者；`worker_observer/process_manager` 为 Worker observer 的 worker 事件生产者。未挂载的模式不创建 expected slot；不虚构多实例 slot。

```text
analytics_producer_slot
- domain / producer_namespace / producer_slot primary key
- expected_enabled boolean
- configured_at

analytics_producer_generation
- producer_namespace / producer_id / producer_generation primary key
- producer_slot
- domains_json
- lifecycle: registered | closing | closed | stale | abandoned
- registered_at
- closing_at nullable / closed_at nullable
- abandoned_at nullable
- final_sequence nullable
- final_emitted_through nullable
- last_control_received_at nullable

analytics_producer_checkpoint
- domain / producer_namespace / producer_id / producer_generation primary key
- last_sequence
- emitted_through
- earliest_open_started_at nullable
- outbox_pending nullable
- oldest_pending_at nullable
- dropped_since_sequence nullable
- loss_epoch nullable
- sent_at
- received_at
```

checkpoint 的所有字段来自安全 DTO：`generation`、`lastSequence`、`emittedThrough`、`earliestOpenStartedAt`、`outboxPending`、`oldestPendingAt`、`droppedSinceSequence`、`lossEpoch`、`sentAt`。Worker 无 open 语义时 `earliestOpenStartedAt=null`；无 Outbox 时 pending 字段为 null。

一个实际 producer generation 可在 `domains_json` 声明它实际输出的多个 Domain，但每个 Domain 仍有独立 checkpoint。event sequence 属于 generation 的全局安全事件流，所有 receipt 连续处理至 checkpoint 的 `lastSequence` 后，才可用于任一声明 Domain 的认证。

- generation 状态固定为 `registered | closing | closed | stale | abandoned`。`closed` 表示生产者正常给出 finalSequence，receipt 连续、无未决 backlog，且已知 loss 已登记。`stale` 仅是诊断状态，仍在活跃阻塞集合。`abandoned` 只能由监督进程标记，表示已确认实例退出且不可能正常关闭。
- 新 generation 在首个有效 checkpoint 前阻止所在 Domain 水位推进。
- 只有 `closed`，或 `abandoned` 且对应 coverage gap 在同一 Analytics 事务已持久化，generation 才能移出活跃阻塞集合。stale、失联或无 closed/abandoned 的旧 generation 持续阻止推进，不能假装健康。
- `dropped_since_sequence` 记录本 generation 尚未显式承认的最早 drop。任一 known drop 使该 generation 余生不能认证完整；记录 coverage gap，必须关闭旧 generation 并以新 generation 才可认证后续时间。不得用累计值归零“恢复”，不得宣称无损。
- 监督进程确认异常 exit 时，Analytics 在同一事务标记 generation `abandoned` 并建立 `[gap_from,null)`；即使最后 checkpoint 或 receipt 连续也不得省略，因为内存可能已有分配但未投递/未持久化的尾部。
- 对有私有 Model Outbox 的 abandoned generation，监督进程指定唯一恢复者。旧实例完全退出后，恢复者只读/独占打开旧 Outbox 并按 `(generation,sequence)`/`event_id` 幂等重投；不得重试 Provider。恢复可补 Fact，不能证明不存在内存尾部，默认不关闭或删除 gap；Outbox 缺失/损坏则保留 gap 并降级 Domain。
- 替代 generation 持续健康后，只有它依 checkpoint/receipt/Outbox/open-Fact 规则认证到候选时间 `T`，且不存在 `started_at<T` 的未结束或不可靠 Model/Execution Fact、也不存在跨越 `T` 的未知 Execution 尾段，才可把旧开放 gap 的 `gap_to` 写为 `T`。关闭只允许 `T` 之后恢复认证，不修复 `[gap_from,T)`；首版没有 repair 历史 gap 的能力。Worker 无 open Fact 语义，`T` 取替代 generation 首个可认证 `emittedThrough`。
- Analytics 将 checkpoint 的 `earliest_open_started_at` 与本地当前 running Model/Execution Fact 的最早 `started_at` 取最早值。候选 `reconciled_through` 不得晚于该 open 下界；没有 open Fact 时才可按 `emitted_through` 推进。长运行只限制统计认证，不阻断业务。
- 旧 generation 的迟到 event/checkpoint 可按 generation+sequence 幂等接收并补已知 Fact，但不得覆盖更窄化的终态、不得自动缩短 gap，且迟到 checkpoint 不能替代新 generation 的 checkpoint。

## Event receipt

```text
analytics_event_receipt
- event_id primary key
- producer_namespace / producer_id / producer_generation
- sequence nullable
- payload_version / event_type / subject_identity
- fingerprint
- received_at / committed_at
- unique(producer_namespace, producer_id, producer_generation, sequence)
```

- `fingerprint` 是规范化安全 DTO 的稳定 hash，不包含敏感内容。
- 相同 event_id 且 fingerprint 相同才幂等 ACK；同 event_id 不同 fingerprint，或同 generation sequence 指向不同 subject/fingerprint，拒绝持久化 ACK、保留既有 Fact、降级 Domain。
- 业务事件 sequence 连续性由 receipt 覆盖 `1..last_sequence`；register/closing/closed/checkpoint 是不占 event sequence 的控制消息，单独按 generation lifecycle 和 `sent_at` 校验，因此不存在未解释 sequence 洞。

## Collector watermark 与 Rollup

```text
analytics_collector_watermark
- collector primary key
- cursor_updated_at / cursor_id
- reconciled_through
- updated_at

analytics_dirty_hour
- domain: model | tool | message
- bucket_start
- primary key(domain, bucket_start)
```

只建立 `dashboard_model_1h`、`dashboard_tool_1h`、`dashboard_message_1h` 与 `dashboard_collected_1h`。前三张按业务事件时间分桶；collected Rollup 按 Fact `collected_at` 小时分桶。

Fact 首次插入或影响统计字段的更新在同一事务标记 Dirty。成功重算在同一事务替换该小时 Rollup 并删除 Dirty；没有 completed Dirty 状态。

## 索引矩阵

### 业务 SQLite 旁路索引

通过业务数据库迁移建立：

```text
agent_session(updated_at, id)
agent_run(updated_at, run_id)
agent_message(updated_at, id)
agent_tool_execution(updated_at, id)
```

缺失、迁移失败或 `EXPLAIN QUERY PLAN` 不走目标索引时，停用对应 Collector 并降级 Domain，不得退化全表扫描。

### Analytics SQLite 索引

| 查询用途 | 必需索引 |
| --- | --- |
| Run/Session/Message/Tool 业务时间 | 各 Fact 的 `(created_at, identity)`；Message 含 `(created_at, message_kind, message_status, compaction_kind)`；Tool 含 `(created_at, tool_name, status)` |
| 所有规范 Fact 留存与监控数据量 | 每张 Fact `(collected_at)`，包括 `analytics_git_commit_fact(collected_at)` |
| Execution 区间相交与 open 保护 | `analytics_execution_fact(started_at, effective_ended_at, run_kind, parent_run_id)`；`analytics_execution_fact(state, started_at)` |
| Model 业务时间与 open 保护 | `analytics_model_call_fact(started_at, provider_id, model_id, status)`；`analytics_model_call_fact(status, started_at)` |
| Worker/Git 范围查询 | `analytics_worker_event_fact(occurred_at, event_type)`；`analytics_git_commit_fact(repo_id, committed_at)` |
| Git current generation join | `analytics_git_membership(scan_id, repo_id, commit_identity)`；`analytics_git_repo_state(current_scan_id)` |
| Rollup 与 Dirty | 每张 Rollup 的完整聚合键；`analytics_dirty_hour(domain, bucket_start)` |
| receipt 幂等、连续性、清理 | 唯一 `(producer_namespace, producer_id, producer_generation, sequence)`；`analytics_event_receipt(committed_at)` |
| checkpoint 活跃/水位 | `analytics_producer_checkpoint(domain, received_at)`；`analytics_producer_checkpoint(domain, emitted_through)` |
| slot/generation 生命周期 | `analytics_producer_slot(domain, expected_enabled)`；`analytics_producer_generation(producer_slot, lifecycle, last_control_received_at)` |
| coverage gap 相交与开放 gap | `analytics_signal_coverage_gap(domain, gap_from, gap_to)` |

索引只为列出的谓词、排序、join 或清理服务；实现必须在目标数据量执行 `EXPLAIN QUERY PLAN`，不得盲目增加重复前缀索引。

## 留存

- 查询先以业务事件时间限制 `event_time >= retention_floor`。
- Model/Tool/Message Rollup 仅在 `bucket_end <= retention_floor` 删除；`dashboard_collected_1h` 按其 collected-at 小时桶删除。
- receipt **仅按 `committed_at`** 清理。
- 普通非 Git Fact 按 `collected_at` 物理保留期清理；但 open Fact 例外：Execution 只有可靠终点、`effective_ended_at <= retention_floor` 且达到物理保留期才可删除。未结束或终点不可靠的 Execution 必须保留并诊断/degraded。
- Model Attempt 同样适用 open Fact 例外：仍 running、缺可靠终态或仍可能改变可查询结果时不得仅按 `collected_at` 删除；只有终态可靠、业务时间已越过 retentionFloor 且达到物理保留期才可清理。
- `agent_duration` 继承 execution 的保留与诊断边界。
- Git current generation、membership 和必要 Commit Fact 不使用非 Git 删除规则。

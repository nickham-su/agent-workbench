# 需求、产品与关键决策

## 需求背景

工作台的 bash 工具和持久终端目前有不同的执行链，用户缺少统一的 Workspace 环境配置入口。通过命令反复 `export` 不能可靠覆盖后续独立 bash 调用；修改服务启动环境又会影响所有 Workspace 和内部控制进程。

本需求提供与 Workspace 绑定的配置，让开发者设置本地开发环境、接口地址、代理和程序凭证等变量，稳定地作用于下一次 bash 调用及新建终端。它是任务子进程配置，不是服务配置系统，也不是秘密保险箱。

业务目标：

- 配置一次，bash 和新终端共享。
- 用户操作直接保存，错误明确，不引入全局草稿状态。
- 保护其他 Workspace、API/Worker 控制环境、凭据以及已有终端运行状态。
- 按当前单用户、自托管边界实施，不建立多租户或分布式配置平台。

## 产品方案

### Workspace 工具入口（R-PRODUCT）

- 在既有工具 Dock 中新增环境变量工具，正式工具 ID 为 `environmentVariables`。
- 采用已确认原型布局：正文标题“Workspace 环境变量”，标题行右侧“新增变量”；中央变量表格，右侧“生效范围”“配置规则”和安全提醒。
- 表格列：启用、变量名、值、备注、操作；提供按名称或备注搜索、启用状态筛选和数量统计。
- 所有值直接明文展示，不提供眼睛按钮或显隐状态。空串用明确的“空字符串”标识表达，不能显示成未配置。
- 多行值应保留可读换行，动态值按文本渲染，不通过 HTML 插入。
- 不恢复重复的顶部工具标题、黄色生效提示条、重复规则句、底部显隐说明或全局保存栏。
- 老 Dock 布局恢复时补齐新工具的缺省值，保留用户原布局，不重置已有工具状态。

最终原型是工作区根目录 `.prototype/workspace-environment.html`，不在仓库内。它是交互、布局基准，不是生产契约：虚构数据、刷新重置、仅内存、请勿填写真实秘密等演示文案不得照搬为真实功能限制。

### 按操作直接保存

| 操作 | 成功行为 | 失败或取消行为 |
|---|---|---|
| 新增／编辑 | 抽屉提交单条请求；成功后关闭并更新列表 | 校验或请求失败保留输入，不能提示已保存 |
| 启用／停用 | 直接请求并在成功后显示新状态 | 恢复原状态并说明未成功，不能静默保留假状态 |
| 删除 | 确认后请求，成功后移除条目 | 失败保留条目；不关闭已有终端 |
| 未提交表单取消、×、Escape、遮罩 | 丢弃当前表单，列表不变 | 不弹草稿放弃确认，不保存可恢复草稿 |

- 临时编辑输入不是全局草稿；不存 localStorage，不出现“加入草稿”“保存到草稿”。
- 保存请求已经发出后，暂时禁用该抽屉的重复提交和关闭入口，直到结果或超时。取消请求不能被解释成撤销服务器已提交的事务。
- 网络结果不确定时按[前端请求状态](02-data-api-and-cache.md#前端请求状态)重新读取确认，不自动重试新增。
- 切换 Workspace 时清理当前展示和编辑态；旧请求不能把值、提示或成功状态写入新 Workspace。

### 明文展示与权限

明文展示是已确认的产品选择，不另加秘密变量类型或显隐功能。生产读取仍沿用现有网页鉴权，并只从环境变量专用接口返回值，响应禁止缓存。关闭网页登录时仍沿用既有自托管访问边界；这不是新增远程公开部署安全保证。

安全提醒应说明授权命令可读取、输出变量，建议避免写入日志；不能说静态加密可阻止模型或用户命令读取。

## 作用域与生效边界

### Workspace 身份（R-SCOPE）

- bash 使用 `run.workspaceId`；终端使用创建请求所属且经服务确认的 Workspace。
- 不按 cwd、仓库目录或命令内容推断 Workspace，不因绝对 `workdir` 改变配置身份。
- 沿用 bash 现有 `workdir` 校验和 Workspace 外目录执行行为，本次不追加 cwd、realpath 或命令识别限制。
- Workspace 外执行同样注入该 run 的 Workspace 覆盖，不静默跳过。
- 本功能不是 shell 沙箱，不改变文件工具或其他资源访问边界。新增配置文件必须受 dataDir 边界保护，见[终端文件安全](04-terminal-launch-and-cleanup.md#文件安全与精确清理r-cleanup)。

### 读取快照时点

“下一次调用使用新配置”的精确定义：

- bash 在本次工具执行准备阶段、spawn 之前获得 Workspace 覆盖快照；当前 bash 不创建 Git lease。
- 终端在本次创建开始、进入配置准备阶段时获得 Workspace 覆盖快照。
- 某次写操作成功返回后才开始的下一次配置读取必须获得新配置。
- 已经获得旧快照的并发调用可以按旧快照继续；写操作不反向修改其环境，也不要求重启它。
- API 返回读取结果后、真正 spawn 前发生的修改，不触发二次读取或混合两版配置。
- 读取后创建 shell 或执行命令失败，不自动退回旧配置重试。

缓存只是读快照实现的一部分，不改变上述业务时间边界。

### 不更新已有进程

- 运行中的 bash 及其子进程保持原环境。
- 已有 tmux shell、后台作业和重连保持原环境。
- 不发送 `export` 到已有终端，不修改 tmux 全局环境，不自动杀死或重建会话。
- 需要新环境时，用户显式新建终端；不能以刷新页面或重连冒充环境更新。

## 变量语义

### 原样名称和值（R-VALUE）

- 名称为 ASCII POSIX 风格并区分大小写。合法性及额度的唯一规则见[实体与约束](02-data-api-and-cache.md#实体与约束)。
- 名称、值、备注都不自动 trim；带空格的名称报错，值和备注的前后空格保留。
- 值为字面字符串，保留空格、换行和 CR；不展开 `$PATH`，不执行 `$(...)`，不解释引号或转义。
- 原样语义适用于合法Unicode文本；异常UTF-16代理项按[统一编码约束](02-data-api-and-cache.md#合法-unicode-与字节计量)明确拒绝，不静默替换或normalize。
- 空字符串是实际覆盖值，不同于省略、停用或删除。PATCH 省略 `value` 表示不修改；提交 `value: ""` 表示改为空串。
- 不提供 dotenv 解析、自动拼接 PATH 或模板展开。

### 停用和删除

停用保留条目，执行环境中不合入该条目；删除移除条目。二者都仅移除 Workspace 覆盖，恢复本次系统基础环境中的同名变量，基础环境没有该变量时才不存在。

不增加显式 unset。用户要临时 unset 时自行在命令中使用 shell 语义；工具不识别或重写。

## 优先级与保护规则

### 普通变量（R-PRIORITY）

启动注入按精确键名遵循：

```text
系统基础环境（终端另包含既有系统网络设置）
  → Workspace 已启用变量覆盖同名普通键
  → shell 初始化脚本和用户命令正常执行
```

模型需要临时覆盖时直接写命令，如 `FOO=temporary command` 或 `export FOO=temporary; command`。影响范围、继承和顺序由 shell 本身决定。公开 bash 参数继续只有既有 `command`、`workdir`、`timeout`，不新增 `env`，不建立模型参数合并层。

保证的是目标进程启动注入规则；shell profile/rc 和命令自身仍可改写环境。bash 工具的 `bash -lc` 与交互终端加载的初始化文件不同，不能承诺二者执行后最终环境绝对相同。

### 代理与系统网络

- `HTTP_PROXY`、`http_proxy` 是两个独立名称，其他大小写组合同理。
- 不同步代理别名，不纠正值，不依据哪个程序优先读取而修改配置。
- 未覆盖的基础键继续继承，具体程序读取哪个键由程序决定。
- 终端保留现有 `applyToTerminal` 自动代理／CA 行为，作为 Workspace 下方的系统层。
- 不把 API 的 network 配置额外导入普通 bash，也不扩大现有 Git 自动网络行为。

### AWB 与 Git 保留字段（R-CONTROL）

配置拒绝大小写精确的 `AWB_` 前缀及以下名称／前缀：

| 类型 | 受保护名称 |
|---|---|
| 精确键 | `GIT_TERMINAL_PROMPT`、`GIT_ASKPASS`、`GIT_ASKPASS_USERNAME`、`GIT_ASKPASS_TOKEN_FILE`、`GIT_ASKPASS_TOKEN`、`SSH_ASKPASS`、`GIT_SSH_COMMAND`、`GIT_SSH`、`GIT_CONFIG_COUNT`、`GIT_CONFIG_PARAMETERS` |
| 前缀 | `GIT_CONFIG_KEY_`、`GIT_CONFIG_VALUE_` |

- 这是系统托管鉴权／配置通道的例外，不是“系统普通值优先”。不得禁止所有 `GIT_*`；`GIT_AUTHOR_*`、`GIT_SSL_CAINFO` 等普通键可配置。
- 新接口、读缓存填充及持久数据读取共用一份权威校验规则；数据库中异常保留配置必须报错，不能静默滤掉后执行。
- 最终 bash、终端目标 shell 环境排除继承的 `AWB_*`；不修改 API、Worker 的全局 `process.env`。
- 终端既有系统 Git 注入及独立原生 Git 工具的 lease 仍可注入受保护字段，保留既有准备、用途和 finally 清理语义；bash 不恢复已移除的项目 Git 自动鉴权，原生 Git 工具也不新增 Workspace 环境覆盖。
- 不解析命令试图阻止用户自行 `export AWB_...`。用户命令是已授权执行能力；控制变量过滤不是对任意命令的安全沙箱承诺。

## 故障语义（R-FAIL）

- 无配置和全部停用是正常空覆盖。
- Workspace 不存在、删除中、读取异常、解密异常、内部接口错误不能视作空覆盖。
- 失败阻止本次新执行／创建并给出固定、可诊断错误；不退回旧缓存、不静默降级，不影响已存在终端。
- 具体协议、日志禁区及网络结果不确定处理见[错误协议](02-data-api-and-cache.md#错误协议)。

## 关键取舍

| 决策 | 选择原因 | 明确代价／边界 |
|---|---|---|
| 共享一套配置 | 满足当前工作流，减少理解和维护成本 | 不支持 bash／终端分别覆盖 |
| 按操作保存、按条目 API | 无全局草稿；避免旧整表覆盖其他条目 | 同一条目最后成功提交生效，不做 CAS |
| 明文 UI、盘上加密 | 遵循已确认交互，并复用主密钥保护数据库副本 | 浏览器和授权命令可以读取值 |
| API 实例缓存 | 高频 bash 命中不查库、不解密；失效路径单一 | 每次 bash 仍需内部 RPC，不覆盖多 API 直写 |
| 固定 launcher＋短生命周期快照 | 值不进 argv，不依赖 tmux 全局环境或新增 IPC | 临时文件需严格权限、持久定位和恢复；TTY 待手动验证 |
| 先实施、后手动终端验收 | 当前环境不适合充分验证真实终端 | 不得把 mock 通过写成运行时兼容已通过 |

## 非目标

- bash 新参数、模型环境变量工具参数层或命令识别／改写。
- cwd 安全改造、限制 Workspace 外命令、通用 shell 沙箱。
- 显隐、秘密类型、dotenv 导入、unset、配置档或 Workspace 外全局环境管理。
- MCP、插件、API、Worker 自身环境配置。
- 代理归一化、别名同步、自动 PATH 合成；让 Workspace PATH 改写 Worker 全局工具探测缓存。
- Worker 二级缓存、多实例失效协议、账户、RBAC、多租户、通用配置平台。
- 为新快照改造全部 Git artifact 类型、统一所有运行时资源或重建 Agent 数据域。

# 需求、业务与产品决策

## 背景与问题

- CLI 已能从源主会话读取时的最新消息创建 Fork，但新会话仍是普通 primary，会进入常规发现及默认 Tab 展示。
- 一次性总结、自动化任务需要独立对话上下文，但不应持续挤占正常用户的会话选择和界面。
- 定时任务目前支持新建空白会话与固定历史消息 Fork；每次执行产生独立会话，长期运行会累积可见会话。
- 现有 Tab 表采用覆盖模型：primary 默认打开，subtask 默认关闭；没有记录不等于关闭。新增 unlisted 后继续扩展默认推断，会让后端、前端和迁移共同维护规则。

## 术语与边界

| 术语 | 定义 |
| --- | --- |
| listed | 可参与既有常规发现，仍须满足各入口原有 kind、时间、标题等条件 |
| unlisted | 不参与常规发现；持有 ID 的已认证调用者可以直接读写 |
| Tab visible | 工作区中是否展示该会话；不是身份权限或会话可见性 |
| 执行父 | 发起子任务的真实父 Session，由持久化父 Run／工具调用关系校验 |
| 内容来源 | 新 Fork 使用上下文的真实 Session，可能与执行父不同 |
| 定时来源 | 任务配置的历史 Session 与固定 messageID |
| 执行会话 | 某次定时任务新建的 primary，和来源会话不是同一实体 |
| 新声明执行 | 升级后通过现有执行声明事务写入新执行快照的执行，不以实际发送时刻区分 |

- 隐藏是降低普通发现噪声，不是安全隔离。知道 ID 的其他已认证调用者仍可访问。
- Tab 状态是 Workspace 级共享，不是当前浏览器或调用者私有；一个用户显式打开后，其他客户端加载 Tab 快照可以看到它。
- 隐藏任务仍消耗模型和 Worker，也可能通过工具修改共享工作区。不引入额外只读或文件隔离承诺。
- 不自动销毁数据；调用者“用完就丢”是停止使用，不是资源回收协议。

## 产品规则

### REQ-VIS：创建与派生

- 所有真实 Session 具有不可变 `visibility`；既有 Session 为 listed。
- CLI 增加可选 `--unlisted`，不增加 messageID、title 或 follow 参数。
- 来源 listed 的普通 Fork 未指定隐藏时仍为 listed；显式隐藏或来源 unlisted 时为 unlisted。
- 子任务创建结合执行父及内容来源继承隐藏，具体事务规则见[后端设计](03-backend-and-migration.md)。不依靠 `forkedFromSessionId` 是否存在推断，因为摘要／无边界降级可能没有该指针。
- Unlisted 父不能向既有 listed subtask 发起复用；拒绝发生在新增消息、创建／激活 Run 或排队之前。listed 父可以复用已知 unlisted subtask，目标属性不变。
- 不提供转回 listed 的管理入口；请求 `listed` 不能覆盖隐藏继承。

### REQ-DISCOVER：发现与定向使用

| 入口 | unlisted 行为 |
| --- | --- |
| 选择会话／continuable | 排除 |
| CLI 活动查询、total、recent | 排除，不占分页名额 |
| 全局完成 SSE 导出 | 不导出；内部发布及完成收敛保留 |
| 按 ID 获取元信息、消息、状态、发送、取消及既有控制操作 | 保持既有鉴权和业务限制，不因 unlisted 拒绝 |
| 明确任务关联、子任务返回及来源元信息 | 允许包含关联 ID，不做全图清洗 |
| 已打开 Tab 快照 | 允许包含 unlisted，这是恢复展示而非常规发现 |
| Analytics 真实消耗 | 保留，不掩盖任务成本 |

- 既有全局 SSE 消费者（包括插件）不再收到 unlisted 运行完成事件；这是明确产品代价。
- 定向 CLI follow 和定时执行状态收敛不依赖该导出，必须继续可用。

### REQ-TAB：实际状态与普通 Tab

- 每个 Session 在同 Workspace 下恰有一条 Tab 状态。默认只在创建事务应用：listed primary 打开，unlisted primary 与所有 subtask 关闭。
- 创建之后，仅持久化 `visible` 决定开闭；修改默认策略不会追溯改变既有状态。
- 点击任务“查看 Session”沿用普通 Agent Tab，允许所有既有交互，不增加只读查看器。
- 显式打开 unlisted 后，刷新恢复；关闭后刷新不再出现；全过程保持 unlisted，选择会话列表始终排除它。
- 会话运行是否 active／idle 与 Tab 状态独立。关闭 Tab 不取消运行，打开 Tab 不创建 Run。

### REQ-SCHEDULE：默认隐藏的定时执行

- `new_session` 和 `fork_message` 对所有新声明执行固定创建 unlisted，无配置开关。
- 原任务配置无需编辑；升级后下一次声明执行采用新规则。已有执行会话不回写。
- 允许来源为 listed 或按 ID 选定的 unlisted；不增加来源隐藏禁令。
- Fork 固定历史锚点，不改为读取时最新消息。
- 查看按钮以真实 `sessionAvailable` 为准。skipped、仅预分配 ID、确认 ID 冲突不能导航；启动失败若没有真实请求到 Run 关联也不能导航。若已有真实受理关联，则沿用当前可用性判断，不因显示失败字样一概禁用。
- 执行历史按关联 runID 展示结果；用户在普通 Tab 后续发起新的 Run，不得改写旧执行结果。
- 删除定时任务仍按现有产品语义保留已有 Session／Run；隐藏不额外级联删除。不要把任务删除提示改成自动清理承诺。

### REQ-CLI：最新选点不变

- CLI 仍先 GET 源会话，再将 `headMessageId` 作为 `fromMessageId` POST；“最新”是 GET 读取时刻。
- GET 后有新消息，仍 Fork 已读边界；Revert 使边界不可用时由后端拒绝。
- 空会话、非 primary、不稳定继承历史、streaming、未结束工具和非 user／assistant 边界继续沿用既有失败，不等待、不自动回退。
- POST 不自动重试；超时可能已创建，要保留结果未知证据。

## 关键决策与取舍

| 决策 | 采用原因 | 不采用的替代方案 |
| --- | --- | --- |
| kind 与 visibility 分离 | 主会话仍可正常发送，执行角色语义不变 | 借用 subtask：混淆角色且不能直接满足 CLI 发送 |
| 每个 Session 保存实际 Tab 状态 | 默认只创建时使用，查询和更新更直接 | 覆盖模型：需要继续维护 kind＋visibility＋覆盖的多端推断 |
| 普通 Tab 显式打开 unlisted | 用户主动查看是合理展示，不是自动干扰 | 禁止打开／专用只读查看器：过强限制、重复界面能力 |
| 定时输出固定隐藏 | 降低操作和配置成本，匹配自动执行用途 | 每任务可见性开关：用户已明确不需要 |
| 创建后 visibility 不变 | 防止策略修改改变派生和发现语义 | 隐式打开即转 listed：破坏两个独立维度 |
| 不建 ACL／TTL | 当前需求是发现和展示，不是独占或清理 | 私有身份体系、自动删除：范围和状态风险明显扩大 |
| 无损专项迁移 | 保护真实开发历史与运行记录 | 利用 Agent 重建完成转换：不可接受的数据损失 |

## 业务流验收摘要

| 流程 | 预期 |
| --- | --- |
| CLI 隐藏 Fork → 发送总结 → 读取 | 普通发现无记录，指定 ID 使用成功，默认无 Tab |
| 定时执行 → 点击查看 → 刷新 → 关闭 | 普通 Tab 正常展示并持久化，关闭后不再自动出现 |
| 隐藏任务创建子任务 | 后代不可常规枚举，仍可通过返回 ID 使用 |
| 隐藏父复用 listed 子会话 | 明确业务拒绝，无新执行副作用 |
| 升级已有工作区 | 历史可读，原 Tab 开闭结果不变，旧执行可恢复 |

# Context Archive Tools v2 (Pos-based)

## 背景

agent-workbench 在长会话中会持续追加 context items. 为了避免 prompt 上下文无限增长,系统会将较旧的 context items 归档到磁盘日志,并通过工具让模型按需检索与回读.

v1 实现已经完成了:

- 归档落盘为文本日志,按 sessionId 分目录.
- 每条 context item 归档为 1 行.
- 通过工具 archive_search/archive_read/archive_tail 访问归档.

但在实际使用中发现一个关键问题: 模型要“用好”这些工具,需要理解若干实现细节(文件分片,行号,游标语义,JSON 输出结构). 这会显著降低工具可用性,并增加提示词/工具描述的复杂度.

## 目标

- 隐藏归档实现细节,让模型只需要理解一个稳定抽象: `pos`.
- 统一三类访问需求为 2 个工具:
  - 搜索: `archive_search`
  - 读取: `archive_read`
- 工具不回传 cursor,分页仅使用 `beforePos`.
- 工具输出为纯文本(非 JSON),便于模型直接阅读与复用 `pos`.
- 统一输出顺序为旧->新(类似对话列表),降低模型阅读成本.
- 通过 `maxChars` 限制单次返回体积,降低上下文被快速填满导致频繁压缩的概率.

## 非目标

- 不引入数据库 FTS/向量检索等额外索引层.
- 不改变归档的基础存储策略(仍可保持按文件分片滚动等),但这些对外不可见.
- 不保证强一致的并发写入语义(本设计会描述风险与缓解,但不强制在 v2 一次性解决).

## 核心抽象: pos

`pos` 是会话归档中的全局位置编号(工具层抽象):

- 1 基(从 1 开始).
- 单调递增(越大越新).
- 稳定: 只要归档分片规则不变,一条归档记录的 `pos` 永不变化.

实现要求(本期边界):

- 本期不改造归档写盘格式,磁盘归档行不包含 `pos=` 前缀.
- `pos` 由工具在读取/搜索结果时计算并输出.
- 对外接口与工具描述只讨论 `pos`,不讨论文件名/分片/行号.

pos 计算规则(本期选择):

- 归档按文件分片,每个归档文件固定 100 行,文件名为 8 位序号递增(例如 `00000001.log`).
- `pos = (fileSeq - 1) * 100 + lineNo`
- 其中 `fileSeq` 为文件序号(从 1 开始),`lineNo` 为该文件内 1 基行号.
- 重要约束: 为保证 `pos` 稳定,不允许修改“每文件 100 行”的分片规则.

### 为什么不回传 cursor

在 v2 中,模型可以直接从工具输出中读取 `pos`,并用 `beforePos` 分页读取更旧内容,因此无需额外的 cursor.

优点:

- 更少的状态与协议复杂度.
- 便于模型在多次调用间自我管理“翻页进度”.
- 更容易调试(用户看到 pos 就能复现查询).

## 归档行格式

归档仍保持“字段 + text 拼成一行”的日志风格(本期不变):

- `item=<id> ts=<createdAt> kind=<kind> status=<status> tool=<toolName或-> | <text>`

说明:

- 每条 context item 对应 1 行.
- `<text>` 仍使用现有转义策略(例如换行转义为 `\\n`),避免破坏 1 行 1 记录的约束.

## 工具接口(v2)

本设计将工具集合调整为 2 个:

- `archive_search`: 在归档中搜索匹配行.
- `archive_read`: 读取归档中某个位置之前的最近若干行.

工具共同约定:

- 仅访问归档,不访问 active context.
- 输出顺序: 旧->新(按 pos 升序).
- 分页方向: 使用 `beforePos` 继续向更旧获取.
- `beforePos` 语义: 仅返回 `pos < beforePos` 的结果(严格小于,避免重复).
- `maxChars` 约束: 默认 8000,范围 1000..10000.
- `beforePos` 约束: 若提供,必须为 integer 且 >= 2.

纯文本输出说明:

- 本设计强调工具输出内容本体为“纯文本行列表”(多行字符串),便于模型直接阅读与复用 `pos`.
- API 与 worker 之间的传输可继续使用 JSON 作为载体,但不影响“内容本体为纯文本”的目标.

### archive_search

用途:

- 快速定位包含关键词/模式的归档行,返回命中行以及其 `pos`.

参数:

- `query: string`
  - 描述: 要搜索的关键词或正则表达式(取决于 regex).
  - 约束: minLength=1.
- `regex?: boolean`
  - 描述: 是否将 query 视为正则表达式. 默认按普通文本匹配.
  - 默认: false.
- `beforePos?: number`
  - 描述: 仅返回 `pos < beforePos` 的更旧命中,用于翻页.
  - 约束: integer, >=2.
- `maxHits?: number`
  - 描述: 最多返回多少条命中行.
  - 默认: 10.
  - 范围: 1..100.
- `maxChars?: number`
  - 描述: 限制本次返回内容的最大字符数,超限按统一截断逻辑处理.
  - 默认/范围: 同共同约定.

输出(纯文本):

- 每行 1 条命中,格式: `pos=<n> | <归档原始行>`
- 若发生截断,在某行末尾追加截断提示标记(见“截断策略”).

匹配语义(实现选择):

- 默认大小写不敏感.

### archive_read

用途:

- 回读归档行,默认用于读取最新内容.
- 也可通过 `beforePos` 将读取范围限制到某个位置之前(用于回读更旧内容).

参数:

- `beforePos?: number`
  - 描述: 仅返回 `pos < beforePos` 的记录. 不传表示不设上界(读取最新).
  - 约束: integer, >=2.
- `lineCount: number`
  - 描述: 返回的行数(在 beforePos 限制内的最近 lineCount 行).
  - 默认: 40.
  - 范围: 1..200.
- `maxChars?: number`
  - 描述: 限制本次返回内容的最大字符数,超限按统一截断逻辑处理.
  - 默认/范围: 同共同约定.

输出(纯文本):

- 每行 1 条记录,格式: `pos=<n> | <归档原始行>`
- 旧->新输出.
- 若发生截断,在某行末尾追加截断提示标记.

## 截断策略(maxChars)

动机:

- 工具输出会直接进入后续模型调用的上下文.
- 当返回体过大时,会快速占满上下文并触发频繁压缩,干扰工作流程.
- 我们希望优先保留最新的信息,同时保持最终输出为旧->新.

统一算法:

- 对候选结果(命中行或读取行)按新->旧遍历.
- 对每条结果:
  - 将该行插入输出的第一行.
  - 累计字符数(含换行符).
- 若加入某行会超过 `maxChars`:
  - 对该行做截断(保留剩余字符预算内的内容).
  - 在该行末尾追加: `[超过最大字符数限制,从此处截断内容]`.
  - 将截断后的该行插入输出第一行.
  - 停止加入更旧结果.

该算法保证:

- 最终输出顺序为旧->新.
- 优先保留最新的若干行.
- 截断提示出现在最旧的那一行末尾,模型可以据此缩小范围重试.

实现备注:

- 可用 `push` 收集新->旧的保留行,最后 `reverse` 再输出,避免频繁 `unshift` 带来的 O(n^2).

## 关键决策与取舍

### 为什么输出不使用 JSON

- 工具输出的主要消费者是模型,而不是程序解析.
- JSON 会引入额外符号与转义开销,扩大 token/字符占用.
- 纯文本 + 稳定前缀(`pos=`)足以让模型可靠复用.

### 为什么统一旧->新

- 更贴近对话列表的阅读顺序.
- 结合“新->旧遍历 + 头插/反转输出”的策略,既能优先保留最新信息,又能最终旧->新展示.

### 为什么 maxHits 上限可以放开到 100

- 实际返回仍受 `maxChars` 截断控制.
- `maxHits` 主要用于限制“匹配条数”,而 `maxChars` 限制“上下文体积”.
- 更大的 `maxHits` 不会显著增加危害,但能减少频繁翻页.

## 业务逻辑与系统集成点

### 工具调用路径

- worker 负责将工具暴露给模型并执行.
- API 提供 internal endpoints 访问归档.
- worker 调用 API,拿到结果后将其作为 tool result 写入 context item,再进入 prompt.

### 归档与压缩关系

- 自动压缩/手动压缩会将较旧 context items 归档.
- 模型需要通过工具从归档中回读历史信息.
- v2 工具的输出体积由 `maxChars` 控制,减少对压缩触发频率的负面影响.

## 安全性与鲁棒性

- 搜索实现仍可使用 `rg`,必须在参数中使用 `--` 终止选项解析,避免 query 被当作参数.
- 输入校验:
  - `beforePos` 必须为 integer 且 >=2.
  - `maxChars` 限制在 1000..10000.
  - `maxHits` 限制在 1..100.
- 并发读写风险:
  - 工具读取归档的同时,归档可能继续追加写入. 这会导致两次调用间的“最新位置”变化,但不影响已写入行的 `pos` 稳定性.
  - 极端情况下可能读到正在写入的末行(半行). 工具实现可选择忽略“文件末尾不以换行结尾”的最后一行,以提升鲁棒性.

## 测试策略

- pos 计算:
  - 断言 `pos = (fileSeq - 1) * 100 + lineNo` 的映射正确.
  - 断言跨文件时 pos 连续且单调递增(旧->新).
- archive_read:
  - 不传 beforePos 时读取最新.
  - 传 beforePos 时只返回更旧(`pos < beforePos`).
  - 输出顺序为旧->新.
  - `maxChars` 截断时: 最旧行末尾包含截断提示,且不再包含更旧行.
- archive_search:
  - query 与 regex 开关正确.
  - beforePos 分页语义正确.
  - 输出顺序为旧->新.
  - `maxHits` 上限 100 的参数校验.

## 迁移说明

由于项目未上线,本设计允许 breaking change:

- 移除 `archive_tail` 工具.
- 移除旧 `archive_read`(基于 file/startLine/lineCount).
- 引入新的 `archive_read`(beforePos + lineCount).
- 工具输出面向模型以纯文本为主(每行带 `pos=` 前缀),不再要求模型理解 file/line/cursor 等实现细节.

注意:

- 本期不改造归档写盘格式,仅改造归档搜索/读取工具的接口与输出抽象.

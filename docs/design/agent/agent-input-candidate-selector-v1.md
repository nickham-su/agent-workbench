# 前端 AI Agent 输入框候选选择器方案（v1）

## 背景与目标

AI Agent 输入框当前已具备基础的 `/` 命令候选能力，但该能力与页面组件实现耦合较深，且尚未形成统一的触发候选体系。随着 `@file`、`@skill` 等输入增强需求增加，需要在不破坏现有输入体验的前提下，建设一套可复用、可扩展、可维护的候选选择器方案。

本方案目标：

1. 在统一输入框中同时支持 `/` 与 `@` 候选能力；
2. 明确触发优先级、检测边界与关闭条件，避免误触发；
3. 满足已确认业务规则（总数上限、排序、插入行为、合法前缀等）；
4. 为后续新增触发符（如 `#`、`:`）预留组件与 Provider 扩展点。

---

## 现状简述

当前 `/` 候选逻辑位于前端 Agent 输入组件内部（`AgentClientPane.vue`），包含：

- slash 可见性判定（基于 `draft.trimStart().startsWith("/")`）；
- slash 候选过滤与高亮选择；
- 键盘上下选择、回车确认；
- 发送前命令解析与执行。

这说明“触发检测 + 候选面板 + 选择提交”目前是与页面业务耦合实现，尚未抽象为可复用的输入候选层。引入 `@` mention/autocomplete 后，继续在页面内堆叠逻辑会增加复杂度，建议抽象为通用能力。

---

## 设计原则

1. **优先级明确**：`/` 高于 `@`，防止模式冲突。
2. **总量可控**：候选面板总显示数最多 10 项（全局上限，不按分组分别计数）。
3. **光标就近解析**：`@` 识别必须基于当前光标位置，而非全文简单匹配。
4. **低误触发**：通过“合法前缀 + 终止条件”避免邮箱等误判。
5. **一致交互**：采用业界常见 mention/autocomplete 行为（键盘、鼠标、关闭、选中插入）。
6. **数据模型统一**：不同来源（skill/file）先映射为统一候选项，再排序/截断/渲染。
7. **渐进增强**：优先复用已有文件检索能力；`@skill` 按需要补齐专用接口。

---

## `/` 触发规则与交互规则

### 触发规则

- 当输入框内容 `trimStart()` 后以 `/` 开头时，进入 slash 模式。
- slash 模式优先级高于 `@`：
  - 一旦判定为 slash 模式，本次输入不再进行 `@` 检测与候选展示。

### 推荐交互

- 展示 slash 候选列表（按已有命令定义过滤）。
- 键盘 `ArrowUp/ArrowDown` 切换激活项，`Enter` 选中。
- 鼠标点击可直接选中。
- 当输入内容已是完整可执行命令（如 `/clear`），可隐藏提示面板。
- `Escape` 关闭候选面板（不清空输入内容）。

---

## `@` 触发检测逻辑

`@` 检测采用“基于光标位置 + 最近合法 `@`”原则。

### 1) 基础流程

设输入为 `text`，光标为 `caretIndex`（选择区时取 `selectionStart`）：

1. 若当前为 slash 模式，直接返回“不触发 @”；
2. 取 `left = text.slice(0, caretIndex)`；
3. 从 `left` 末尾向前查找最近 `@`；
4. 对该 `@` 进行合法性判定（前缀、终止符、query）；
5. 若合法，进入 `@` 候选请求与展示；否则不展示。

### 2) 合法前缀规则（避免邮箱误触发）

`@` 前一个字符（若存在）必须属于“可触发边界”，推荐：

- 行首；
- 空白字符；
- 左括号/左方括号/左花括号；
- 引号或中文标点后的分词边界。

不合法示例：

- `name@example.com` 中的 `@`（前面是字母/数字/邮箱局部串）；
- `foo@bar`（连续词中间 `@`）。

### 3) query 提取

- `query = text.slice(atIndex + 1, caretIndex)`。
- query 允许为空（刚输入 `@` 时可展示默认候选）。
- query 至少支持中文匹配；建议同时支持：英文、数字、`_`、`-`、`.`、`/`。

### 4) 终止条件

当 `@` 到光标之间出现以下字符/状态，应终止当前 mention：

- 空白换行（若产品希望 mention 不跨词）；
- 明确分隔符（如 `,`、`;`、`:`、`)`、`]`、`}` 等）；
- 光标移到该 `@` 之前；
- 输入框失焦且未在候选面板交互。

### 5) 多 `@` 支持

- 一次输入允许出现多个 `@`。
- 永远只解析“光标左侧最近且合法的 `@`”。
- 在同一段文本中可重复插入同一候选（允许重复，不去重拦截）。

---

## `@` 候选源与展示规则

## 候选源

- `skill` 候选源（优先级高）；
- `file` 候选源（次优先级）。

## 排序与数量

1. 先按来源优先级排序：`skill` > `file`；
2. 同来源内再按匹配分数（前缀命中 > 子串命中 > 其他）与稳定字段（如字典序/最近使用）排序；
3. 合并后统一截断：**最多 10 项**。

> 注意：10 项是总上限，不是“每组 10 项”。

## 展示要求（新增规则已纳入）

### `@file` 候选项

- 主显示内容：**文件路径本身**（例如 `apps/web/src/.../AgentClientPane.vue`）；
- 不展示额外描述文本（副标题留空）。

### `@skill` 候选项

- 主显示内容：**`skill:<skill_id>`**；
- 描述文本：**`skill名称 + skill描述`**（例如 `代码评审助手 · 用于审查变更风险`）。

---

## 推荐交互细则（mention/autocomplete）

### 键盘

- `ArrowDown/ArrowUp`：移动激活项（循环或边界停留，二选一，建议循环）；
- `Enter`：选中激活项；
- `Tab`：可选，作为“选中激活项”的快捷键；
- `Escape`：关闭面板，保留输入；
- `Shift+Enter`：保持换行语义，不触发选中。

### 鼠标

- 悬停高亮；
- 单击选中；
- 候选区域 `mousedown` 阻止输入框失焦抖动。

### 空态

- 无候选时显示空态提示（如“无匹配项”）；
- 空态不阻塞继续输入。

### 关闭条件

- slash 模式激活；
- 当前 mention 失效（不再有合法 `@`）；
- 手动 `Escape`；
- 成功选中后关闭。

### 选中后的行为

- 将候选“展示文本”替换 `@query` 片段；
- 自动补一个空格；
- 光标落在空格之后；
- 允许重复插入同一候选。

---

## 组件抽象建议

建议拆分为两层：

1. **通用触发候选层（UI + 交互引擎）**
   - 职责：触发符检测、光标定位、候选面板渲染、键鼠交互、插入替换。
   - 不关心业务数据来源。

2. **业务 Provider 层（数据提供）**
   - `slashProvider`：返回 `/` 命令候选；
   - `mentionProvider`：返回 `@skill` + `@file` 候选；
   - 负责查询、评分、限流、防抖、错误兜底。

该结构可复用于其他输入场景，降低 `AgentClientPane` 复杂度。

---

## 数据结构建议

可定义统一候选模型（接口草案）：

```ts
interface InputCandidateItem {
  id: string;                     // 稳定唯一ID，例如 file:path 或 skill:id
  trigger: "/" | "@";
  kind: "slash" | "file" | "skill";

  // 展示
  label: string;                  // 主显示文本
  description?: string;           // 描述文本（@file 为空，@skill=名称+描述）

  // 插入
  insertText: string;             // 选中后插入文本（会由组件自动补空格）

  // 匹配与排序
  score?: number;
  groupPriority?: number;         // skill=0, file=1

  // 业务透传
  meta?: {
    filePath?: string;
    skillId?: string;
    skillName?: string;
    skillDescription?: string;
  };
}
```

映射约定：

- `@file`：
  - `label = filePath`
  - `description = undefined`
  - `insertText = filePath`
- `@skill`：
  - `label = "skill:" + skillId`
  - `description = skillName + " " + skillDescription`
  - `insertText = "skill:" + skillId`

## 可行性与前后端影响

## 前端

- 现有 `/` 逻辑可迁移为 `slashProvider`，行为不变；
- 新增 `mentionController`：
  - 基于光标位置检测最近合法 `@`；
  - 触发并发查询（skill/file）并合并排序；
  - 统一限制总数 10。

## 后端与接口复用

### `@file`

- 可优先复用现有 workspace 文件搜索接口（`/api/workspaces/:workspaceId/files/search`）。
- 该接口当前本质是内容搜索（rg），若用于路径候选存在语义偏差：
  - 可作为短期可用方案（query 与路径命中相关时可返回路径）；
  - 中长期建议补充“按路径名/文件名检索”的轻量接口，降低噪音与耗时。

### `@skill`

- 当前已有 external skill roots 探测/设置接口，但缺少“面向输入候选的 skill 列表检索接口”。
- 建议新增 `@skill` 专用查询接口（可按 workspace 生效范围聚合 builtin + enabled external roots）。

结论：

- `@file`：可先复用现有能力落地 MVP；
- `@skill`：大概率需要补接口，或在现有后端能力上新增聚合查询端点。

---

## 风险点与验证建议

### 主要风险

1. **误触发风险**：合法前缀规则过宽会误伤邮箱；过严会漏触发。
2. **性能风险**：每次输入都查两类候选，可能产生频繁请求。
3. **排序一致性**：skill/file 融合排序后可能与用户预期不一致。
4. **插入偏移风险**：替换范围计算错误会破坏文本。

### 验证建议

- 单元测试：
  - slash 与 @ 优先级；
  - 合法/非法 `@` 前缀；
  - 多 `@` + 光标移动场景；
  - 中文 query 匹配；
  - 选中后“替换 + 自动空格 + 光标位置”。
- 交互测试：
  - 键盘全路径（上下、回车、Esc、Tab）；
  - 鼠标点击与失焦行为；
  - 空态与加载态。
- 性能测试：
  - 输入节流/防抖（建议 100~180ms）；
  - 慢网降级与请求取消（AbortController）。

---

## 推荐实施阶段

### 阶段 1：抽象与无损迁移

- 抽离当前 `/` 逻辑为通用候选层 + slashProvider；
- 保证现有 `/compact`、`/clear` 交互不回归。

### 阶段 2：接入 `@file`（MVP）

- 完成 `@` 检测器（合法前缀、最近 `@`、终止条件、多 `@`）；
- 接入 `@file` 候选并按新展示规则渲染。

### 阶段 3：接入 `@skill`

- 增加 skill 候选源（必要时补后端接口）；
- 与 file 合并排序（skill 优先），统一上限 10。

### 阶段 4：体验与稳定性优化

- 打磨排序权重、空态文案、缓存策略；
- 完成回归测试与性能压测；
- 沉淀组件文档与复用示例。

---

## 附：规则对照清单（本方案已覆盖）

- 候选面板总数最多 10 项；
- `/`：`trimStart` 后以 `/` 开头触发；`/` 优先级高于 `@`；slash 模式不处理 `@`；
- `@`：支持持续输入筛选；一次输入支持多个 `@`；基于光标位置识别最近合法 `@`；
- 合法前缀规则避免邮箱误触发；
- query 至少支持中文，建议支持英文/数字/`_`/`-`/`.`/`/`；
- 排序：skill 优先、文件其次，总数上限 10；
- 选中后插入展示文本并自动补空格；允许重复插入；
- 展示要求：
  - `@file` 主显示=文件路径，**无描述文本**；
  - `@skill` 主显示=`skill:<skill_id>`，描述=`skill名称 + skill描述`。

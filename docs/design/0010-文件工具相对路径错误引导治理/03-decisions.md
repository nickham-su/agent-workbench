# 关键决策与取舍

返回 [README](./README.md)。本文件记录已经确认的方案和不采用替代方案的理由，后续实现不得将其重新留作开放问题。

## 决策：问题定义为错误引导一致性，不是安全脱敏

**选择：** 评价错误文本的核心标准是“路径能否直接用于下一轮合法工具调用”。

**理由：** `<workspace>/src/a.ts`、`[workspace]/src/a.ts` 等脱敏文本虽然不暴露真实目录，但仍不是合法 `filePath`，依然可能误导模型。正确结果应为 `src/a.ts`，或不返回路径。

**影响：** 测试必须断言相对路径存在和可用，而不仅是断言某个绝对前缀被替换。

## 决策：首期只在工具内部处理

**选择：** `read` 在 `fileTools.ts` 内规范化，`apply_patch` 在 `applyPatch.ts` / `applyPatchUpdate.ts` 的工具私有实现内规范化；`runner.ts` 不新增路径处理。

**理由：**

- 工具最清楚用户输入路径与内部执行路径的对应关系；
- move、rename 和中间父组件错误无法由 Runner 仅凭字符串可靠判定该显示源还是目标；
- Runner 文本后处理会引入跨工具隐式规则，增加误替换和维护成本；
- 当前 Runner 原样写回错误的职责简单且可预测。

**不采用：** Runner 全局 sanitizer、`buildToolErrorText` 中替换 workspace 前缀、所有工具共享正则清洗层。

## 决策：首期采用高收益覆盖，不追求零遗漏

**选择：** 完整覆盖 `read` 的高频缺失根错误、`apply_patch` 的主问题显式路径错误，并将中间父组件相对化作为工具内补强覆盖项；允许低频未分类底层异常继续透传。

**理由：**

- `read` 问题集中，可低成本完整覆盖主路径；
- `apply_patch` 已显式构造的错误可通过现有相对字段准确修复；
- 对所有 Node 文件系统错误做跨平台、保 cause 的统一包装，成本和回归风险明显高于首期收益；
- 产品目标是显著减少模型无效重试，不是建立通用错误脱敏框架。

**验收含义：** 搜索仍可发现执行用 `fullPath`，甚至保留少量 `throw err`；这不等于验收失败。验收检查的是列明的对外错误构造点和测试场景。

## 决策：read 重建已知根错误，不做字符串替换

**选择：** 对 `ENOENT`、`ENOTDIR` 根据错误码生成稳定、含 `safePath` 的新消息，再与 repo hint 拼接。

**理由：**

- Node 原始错误格式随 syscall、平台和版本可能变化；
- 替换绝对路径需要匹配引号、分隔符和 realpath 结果，脆弱且难测；
- 已知错误码和 `safePath` 足以形成清晰、可重试文案。

**保留：** repo probe 仍只由错误对象 `code` 触发，不根据重建后的字符串触发。

## 决策：read 只规范化 ENOENT / ENOTDIR

**选择：** `EACCES`、`EPERM`、`EIO` 等非缺失根错误继续原样抛出。

**理由：**

- 它们不触发 repo hint，现有行为明确；
- 权限、设备和平台错误可能包含有价值的系统细节，首期不定义如何等价保留；
- 这类错误频率和模型复制路径重试的收益低于缺失错误。

**后续条件：** 只有出现可复现、高频的错误引导案例，才在 `read` 内按错误码逐项扩展，不做通用字符串清洗。

## 决策：apply_patch 优先传递相对字段，而非事后裁剪 fullPath

**选择：** 修改 helper 签名和调用参数，让展示函数直接接收 `relativePath`、`path`、`fromPath`、`toPath`。

**理由：**

- `ResolvedOperation`、snapshot、hunk 流程已经保留相对字段；
- `path.relative(workspacePath, fullPath)` 无法表达 move 错误应显示源还是目标的语义；
- realpath / symlink 情况下事后反推可能与原工具输入不同；
- 类型参数可以迫使调用方显式选择展示路径，降低未来误用。

## 决策：snapshot mismatch 删除 Path 行

**选择：** 保留 `Failed file: <relative>`，删除 `Path: <fullPath>`，并从 `buildSnapshotMismatchMessage` 参数中移除 `fullPath`。

**理由：** 两行表达同一文件；相对路径已经足以重试，绝对路径既冗余又误导。参数级移除比只不输出更能防止回归。

## 决策：context mismatch 使用源相对路径标签

**选择：** 调用 `deriveNewContentFromChunks` 时传入源相对路径。

**理由：** 该函数的 `filePath` 只参与错误文案，不用于 I/O；当前传 `fullPath` 没有执行需求。rename + modify 的 hunk 匹配源文件内容，应提示源路径供模型重读。

**影响：** `extractFailedFilesFromMessage` 和格式化结果无需新逻辑，即可自然得到相对路径。

**边界：** formatter / classifier 不负责路径改写；源错误必须先在生成点相对化。

## 决策：父组件错误由工具 helper 显式携带展示上下文

**选择：** `ensureParentDirectorySafe` 等会遍历中间组件的 helper 必须获得足够上下文，将当前失败组件表示为 workspace 相对路径。该项属于首期“工具内补强覆盖”，不是最终 `fullPath` 错误文案的直接翻转。

**理由：** 该分支的失败路径是遍历过程中临时派生的 `currentPath`。仅传最终 `fullPath` 时，helper 内只能输出绝对 `currentPath`；让 helper 使用已有 workspace 上下文生成展示标签，可在工具内部补齐覆盖，又不混淆主问题中已有相对字段的直接替换规则。

**约束：** 相对化只用于文案；containment 仍使用既有 absolute / realpath 逻辑，不因展示路径计算改变安全判断。

## 决策：write 首期不改错误处理

**选择：** 不新增 `write` 的 fs 错误包装 helper。

**理由：**

- 目标缺失会创建成功，主问题不存在；
- 成功输出已正确使用相对路径；
- 没有已知高频显式 `fullPath` 文案；
- 为罕见底层异常增加包装会扩大范围，且需决定错误码、cause、平台文案兼容。

**取舍：** 接受少量底层异常仍可能带绝对路径。通过文档和验收明确这不是首期失败，不让实现者自行扩范围。首期若新增 `runWriteTool` catch、错误重写或包装 helper，应直接判定为超范围，除非先完成设计变更审批。

## 决策：不新增公共错误实体或协议

**选择：** 仅新增或调整文件内私有 helper / 参数类型，不创建共享包、IPC 字段、数据库实体或 tool result 字段。

**理由：** 当前问题可在错误生成源头解决；公共协议会放大兼容和迁移成本，且没有机器消费需求。

## 决策：测试模型可见最终文本，但不把 Runner 变为实现层

**选择：** 工具单测验证源错误，Runner 输出测试验证错误确实原样进入模型上下文且不含 workspace 绝对路径。

**理由：** Runner 不改代码仍需回归，防止测试只覆盖 helper 而漏掉格式化/持久化后的重复路径。

## 取舍汇总

| 方案 | 决策 | 主要原因 |
|---|---|---|
| 工具内按语义使用相对路径 | 采用 | 准确、局部、可审查 |
| Runner 统一替换 | 不采用 | 语义不足、跨层魔法 |
| 字符串替换 workspace 前缀 | 不采用 | 脆弱，且不总能得到可重试路径 |
| 全部 fs 错误统一包装 | 首期不采用 | 成本高、收益递减 |
| read 仅治理缺失错误 | 采用 | 主路径集中，兼容边界清晰 |
| apply_patch 治理显式路径错误 | 采用 | 已有相对字段，可系统修复 |
| write 首期新增包装 | 不采用 | 无主场景，低频异常收益低 |

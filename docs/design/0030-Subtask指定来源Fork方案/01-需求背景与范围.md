# 需求背景与范围

[返回导航](README.md)｜[业务规则与边界](02-业务规则与边界.md)

## 业务背景

- 每晚由定时任务启动一个日报 Session。
- 日报 Session 查询当前 Workspace 最近二十四小时活跃的 Session。
- 为每个被选 Session 创建独立上下文分支，请分支总结执行事项、结果、问题与经验。
- 日报 Session 收集这些总结，统一编写工作报告和经验文档。
- 被总结的 Session 可能仍在执行任务；总结不应向源会话追加提示、占用其会话执行锁或改变其后续对话。

上述是需求背景，不是本阶段全部开发范围。

## 实施前阻碍与基线

下表描述方案制定时的基线，不代表指定来源功能仍未实现；当前实现和实际验收证据见 [实施与验收记录](09-实施与验收记录.md)。

| 能力 | 实施前事实 | 对本场景的限制 |
|---|---|---|
| `new` | 创建空 `subtask` Session | 不继承被总结 Session 的历史 |
| `fork` | 从调用者 Session 选取工具 Assistant 之前的边界；高上下文占用时可能使用调用者 prefork 摘要 | 不能指定另一个 Session 为历史来源 |
| `existing` | 在指定 Session 继续执行；只允许同 Workspace 的 `subtask` Session，目标必须 idle | 会改变目标上下文；普通 `primary` 不适用，运行中也不适用 |
| 普通底层 Fork | 新建 Session，引用现有消息图，不深拷贝消息及工具结果 | 当前入口受来源状态和 head/revision 等条件限制，不能直接作为任意运行中来源的稳定快照入口 |
| 定时任务历史 Fork | 已有不依赖源当前 head/revision/idle 的受信任历史锚点入口 | 限制 `primary` 来源/目标，允许已回滚历史锚点；与本次“当前分支、自动最新边界、subtask 目标”不是同一权限语义 |

代码定位见 [代码依据与影响面](05-代码依据与影响面.md)。

## 本阶段目标

- 扩展 `session.mode=fork`，新增可选 `sourceSessionId`。
- 显式来源支持 `primary` 和 `subtask`，严格限定在调用者 Workspace。
- 即使源正在运行，也可从最新稳定有效上下文创建新 `kind=subtask` Session。
- 新 Session 的模型调用、消息追加和 Run 状态独立，执行父任务仍是调用者。
- 服务端自动解析稳定边界并写入内部 Session 分支字段；对外仅提供可选来源 Session ID，不暴露实际消息边界或排除标记。
- 调用时的新增来源语义绑定不可变父工具输入，不能靠 Session 字段猜；正常工具结果沿用原有 structuredResult 与 preview/error，不增加强制长期来源展示保证。
- 无来源参数时，保留现有 Fork 全部合法行为，包括 prefork、嵌套 Fork、空边界回退和既有输出格式。
- 保持公共手动 Fork、定时任务历史 Fork 的原有入口、授权、边界和输出不变。

## 非目标

- 不新增活跃 Session 查询，也不定义“活跃”的时间统计口径。
- 不实现日报定时任务模板、自动遍历、报告去重、总结重试编排或报告文件组织。
- 不新增只读工具能力、权限模型、文件系统沙箱或 Workspace 副本。
- 不复制源 Run、流式状态、pending 工具、终端进程、插件连接或远端状态。
- 不将全部压缩前原文自动放入新模型窗口，不建立新的摘要或跨 Provider 回放基础设施。
- 不提供模型可选的消息锚点、强制等待来源结束、半条消息保留或人工 pending 策略参数。
- 不借此修复与本功能无关的会话查询或前端按需加载问题。

## 推荐业务使用方式

- 为总结任务配置适当的 Agent；如果要求不改文件，应通过实际工具配置限制写入和执行能力。
- 传入明确的总结 prompt，要求只总结来源历史，不接着执行历史中尚未完成的工作。
- 由日报 Session 统一写文档，避免多个分支同时写同一报告。
- 总结统一注明只覆盖所继承的稳定有效上下文，不保证包含进行中内容；可保留可选来源 ID，但不要求模型报告精确消息边界或排除事实。
- 选择上下文窗口足够的总结 Agent；新副本 lastResponseTotalTokens 初始 null，runner.shouldAutoCompact 此时为 false，首次请求超子模型窗口没有自动压缩兜底保证。实际超限按旧失败语义处理，本次不新增预估摘要功能。
- 源历史里出现的指令属于背景，不自动成为本次任务；Fork 防护提示应保留。模型指令防护不能替代工具权限或文件隔离。

## 完整上下文的产品定义

- 本方案承诺的是“截至实际边界的有效模型上下文”，包括现有压缩摘要与保留尾部语义。
- 物理历史共享链可以支持既有 Timeline/Archive 的祖先读取，但能读到的内容仍受现有接口、索引、附件文件和存储保留策略限制。
- 工具输出可能已经被截断；普通回放主要使用结果预览，并不自动重新读结果 artifact。
- 跨 Run 的历史图片并不保证自动进入视觉输入，Provider 私有 reasoning 回放也受现有适配和身份匹配条件限制。
- 这些限制不是新增 Fork 的失败，也不得被宣传为“复制了源模型的完整瞬时记忆”。

## 兼容性与成功定义

- 兼容性同时覆盖模型工具 schema、Worker 参数解析与调用、内部 API schema、业务材料化、Child Run 激活、结果投影、错误与失败补偿。
- 新字段的原始 HTTP 校验、调用一致性、内部边界记录、可选来源展示与回放兼容、正式 test gate 和真实协同升级操作均属于完成标准；不扩展为全局验证/drain 框架。
- API 返回 `sessionId/runId` 只能证明新分支已成功激活，不证明总结已成功；Worker 仍执行现有子 Run 终态流程。
- 显式来源无合法稳定上下文时必须拒绝，不能悄悄变为 `new`。
- 功能实现应是局部扩展；当前 Session 字段承载内部来源和实际边界，对外只增加可选来源 ID，不新增工具结果专属保留规则、消息类型、DB 表或 Agent schema 版本。现有共享图/归档保护继续，无需另存父/Child来源证明链用于回放。任何结构变更需求必须重新评审，不能触发破坏性重建。

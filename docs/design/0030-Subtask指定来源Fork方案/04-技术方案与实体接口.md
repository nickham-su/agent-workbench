# 技术方案与实体接口

[返回导航](README.md)｜[代码依据](05-代码依据与影响面.md)｜[验收](07-测试验收与审查标准.md)

## 架构与职责

```text
模型工具 session.sourceSessionId
  → Worker parseSubtaskArgs / BuiltinToolsProvider
  → Shared subtask contracts / AgentApiClient
  → start 路由原始 preValidation / SubtaskApplication
  → 父锚点及不可变 input 来源绑定
  → 复用已有 Child，或 SessionInteraction 稳定来源材料化
  → 既有 Child 激活、Nested Run、structuredResult 与 preview/error
```

| 层 | 本次职责 | 不承担 |
|---|---|---|
| 工具 schema / Shared / start 路由 | 可选来源请求与顶层响应、原始新增字段校验 | 新 mode、公开消息边界、全局 AJV 修改 |
| Worker | 保留来源、显式跳过 caller prefork、可选短展示 | 自选消息边界、强制长期来源回放 |
| SubtaskApplication / lineage | 首次/重试/winner input 绑定、Child Session 来源核对 | 全调用指纹、回放时重新验证证明链 |
| SessionInteraction / message store | 同事务当前稳定来源解析、Session 分支创建、内部锚点 | 放宽手动/历史 Fork、复制源 active Run |
| Lifecycle / maintenance | 原有父 fence、唯一 Child、取消及安全补偿 | 来源专用激活载荷或 JSON 保留写入 |
| Resolver / transcript / ToolExecution 写回 | 保持既有结果回放、闭合与可信附件防护 | 新来源跨实体回放校验、来源专属合并/防篡改/终态写回 |

## 外部请求契约

```json
{
  "description": "总结来源会话任务与经验",
  "prompt": "只总结继承的稳定历史，不继续源任务；不保证包含进行中内容。",
  "agentId": "summary-agent",
  "session": {
    "mode": "fork",
    "sourceSessionId": "source-session-id"
  }
}
```

- AgentApiSubtaskSessionSchema 的 fork 分支拟增 sourceSessionId?: string，原始值为字符串且 trim 后非空；缺失走旧路径。
- new/existing 不增加来源属性，其出现即拒绝，不能依赖 schema 对未知字段的删除行为。
- 模型工具只增加这一可选参数；不接受模型挑消息锚点，不增加等待策略、返回边界、排除事实或查询接口。
- 内部 start 请求顶层形状、父 IDs、既有 sessionId 规则不变，通过 session 扩展；显式请求禁止出现 preforkSummaryText/preforkMeta。
- getSubtaskPreforkPlan 不新增来源参数，显式不调用；既有隐式阈值、摘要失败回退、空历史和 nested fork 保持。
- 原父权限、工具归属、Workspace enablement、Agent/profile、prompt 与深度限制不被新来源绕过。

### schema 前原始校验

- 仅 start 路由增加原始 body preValidation。Fastify 默认 AJV 可能转换类型/删字段，handler 内检查太晚。
- 有原始 source 字段时先执行既有内部认证，再按 [唯一错误优先级](02-业务规则与边界.md) 检查 mode、source 原始类型/trim、prefork 字段存在性。
- 无 source 立即不做新增全对象校验，保持原 schema/handler 及认证顺序，不改全局 coerceTypes/removeAdditional。
- 合法 source 带任意 prefork 值，包括空/null/类型错误，一律专用 PREFORK_NOT_ALLOWED，不能先被 prefork schema 抢错。
- Worker/应用直调共享纯新增字段规范化逻辑；不以全请求 Value.Check 替代前置检查。用真实 createApp/route Fastify inject 验收。

## 外部响应与可选展示

拟议响应仅新增一个顶层字段：

```ts
type AgentApiSubtaskStartResponse = {
  sessionId: string;
  runId: string;
  workspacePath: string;
  agentName: string;
  reused: boolean;
  sourceSessionId?: string;
};
```

显式首次成功示例：

```json
{
  "sessionId": "child-session-id",
  "runId": "child-run-id",
  "workspacePath": "workspace-path",
  "agentName": "总结 Agent",
  "reused": false,
  "sourceSessionId": "source-session-id"
}
```

- 显式复用成功仍是同一 sessionId/runId，reused=true，来源取已核对的 Child Session.forked_from_session_id；不是重新查实时 source 得出的结果。
- 旧 new/implicit fork/existing 完全不增加该字段，不输出 null 占位。不返回消息边界或排除布尔，不增加包装对象或专用事实类型。
- Worker 实际 running/final structuredResult 可增加同名 sourceSessionId，与现有 subtaskSessionId/subtaskAgentId/subtaskAgentName/resultText 并存，按原有结果写回流程保存。
- 正常显式成功投影可以在既有状态/结果文本中简短显示来源；成功 start 后失败如已有来源，沿现有 error carrier 小字段传递并在旧错误投影显示，不把失败描述为成功。
- 来源显示可采用“来源 Session：JSON 编码的 ID”等安全短文本，不增加 shared 规范格式或头部去重框架；正文不能被用来反推权威来源。
- 未成功 start 不伪造成功来源说明；服务器直接 unknown/cancelled、Worker 没来得及更新或 error 优先时，不保证历史结果必有来源头。

## 内部实体与对外协议的区别

| 内部实体/字段 | 必须保留的用途 | 是否新增对外输出 |
|---|---|---|
| agent_session.id/kind | 独立 subtask 身份 | 原 sessionId |
| forked_from_session_id | 固定历史来源，复用调用时核对 | 仅显式成功顶层可选 sourceSessionId |
| forked_from_message_id | 实际稳定边界 sourceMessageId，固定内部锚点 | 否 |
| head_message_id | 创建时等于稳定边界，之后随副本自身追加变化 | 否 |
| context_root_message_id | 本次有效根；compaction 为边界时 root=self | 否 |
| session_run_state | idle、active Run null、pending 空，独立激活；lastResponseTotalTokens 初始 null | 否 |
| agent_run.parent_run_id/parent_tool_execution_id/depth | caller 执行链、唯一 Child 与取消 | 原 runId，不改变父关系 |
| agent_tool_execution.structured_result_json | 既有 Worker 结果，可选普通来源说明 | 不增加服务器专属来源保留键 |
| Message/Part/ToolExecution/Attachment/replay | 共享稳定历史，原有闭合和可信内容保护 | 不扩展历史结果保证 |

- 内部 sourceMessageId 变量、锚点验证、Session 字段不能因简化响应被删除。root 并非总等于边界，应按有效上下文保存。
- 不保存排除布尔，不新增表/列/AGENT_SCHEMA_VERSION，不触发 schema 重建。
- forked_from_* 是逻辑来源记录，不独自构成来源 Session 的强引用保护；现有 head/root/previous 链与归档引用保护继续。
- 不为元数据回放另存父/Child来源证明链，不改变既有消息保留策略。

## 内部稳定来源入口与事务

建议拟议入口如下；返回的是内部 Session，不是 API 响应：

```ts
// 拟议能力；最终命名可遵循项目习惯。
forkStableSourceSession(input: {
  id: string;
  workspaceId: string;
  sourceSessionId: string;
  title: string;
  createdAt: number;
}): AgentSessionRecord;
```

- 目标固定 kind=subtask。Session 自身已有来源与实际边界，材料化端口可继续携带 createdSessionId 等补偿身份，不返回额外对外事实对象。
- db.transaction(...).immediate() 内先取得写预约，再读取当前来源、物理图、有效 root、原始候选、Parts/工具并验证、选边界、插入 Session 与 idle run state。
- 无模型请求/文件 IO/await；不以事务外 source head/revision 授权或反复制造 revision 冲突，同连接嵌套 savepoint 可用，不能事务外读取后另事务创建。
- Session 创建与 Child 激活保留两阶段：第一事务确定分支，第二事务按原父/目标 fence 追加提示/任务、创建并激活 Run。两阶段之间不重新挑来源边界，不新增来源 JSON 写入。
- source 后续流式变化不令已选 Session 锚点漂移；预分配 ID 不削弱父工具唯一 Child 约束。

### 稳定解析算法

- 加载来源当前物理链，检查缺失/循环/跨 Workspace/上限，允许来源已 Fork 的共享祖先；验证当前 context root 位于链上。
- 依既有有效根、compaction、retained 定义构建原始候选。保留 streaming 与未闭合工具位置，不能先用 normalized 过滤再找截断点。
- 验证必要根和原始 retained 整体闭合。普通进行中 root 无前缀为 NO_STABLE；非法普通 root、未完成/坏 compaction、必要 retained 进行中或残留 pending 为 CONTEXT_INVALID。
- 根后按有效顺序扫描；遇第一个 streaming 普通消息或 completed Assistant 的 queued/running 工具，停止于此前稳定边界，不拆该 Assistant，不跨到后续 completed 消息。
- failed/cancelled/superseded Message 与 runtime 按旧规则不回放；completed Assistant 的 failed/cancelled/unknown 工具是可闭合终态，按原结果语义纳入。
- 可纳入内容仍验证 Parts、调用/执行归属、结果配对和现有 Provider replay 兼容性。损坏不是正常 pending，不伪造/跳过；可识别旧 replay 降级不收紧。
- System/Compaction 可作新内部合法边界。compaction 为边界时 head=compaction、root=compaction，必要 retained 保留，不退旧窗口。
- 无稳定内容拒绝，不退 new。插入 Session 的 forked_from_session_id=source、forked_from_message_id=head=实际边界、root=实际有效根；不更改源 state/revision/head。
- 压缩前非 retained 原文不进入新模型窗口；共享物理祖先仍受原图/归档保护。

## 首次、内部重试与并发 winner

### 调用阶段顺序

- 原始新增字段校验后，以既有父锚点确认父 Session/Run/工具/Workspace，读取不可变持久 tool-call input。
- input 缺失、坏 JSON、非对象或其 source 非法：ANCHOR_INVALID；合法无 source 即旧语义，不增加完整 mode/agent/prompt 指纹。
- 规范化 input 与传输来源，只比较显式存在性及规范 ID。切换显式/隐式或换来源报 MISMATCH，先于实时来源解析，不能猜 caller 字段。
- 查询既有 Child。无 Child 才校验当前来源同 Workspace/类型/稳定边界并材料化；有 Child 保留既有父权限与 lineage 检查，核对目标 Session 的 Workspace/kind 及已绑定来源关系。
- 匹配显式 Child 的 forked_from_session_id 与绑定 ID 不符报 MISMATCH；已有实体/父锚点异常仍走既有相应错误，不增加来源说明损坏类错误。
- 显式复用从 Child Session 取得来源 ID，不读实时 source，不重新选稳定边界；旧路径依既有复用规则不返回来源字段。

### 并发与补偿

- 同一父工具只允许一个成功 Child。激活 unique constraint 竞争失败后，重新读取可信 input 与 winner Session，执行同样调用一致性检查后才返回 reused。
- 两次材料化可能选到不同合法边界，winner 保留自己的边界；loser 不覆盖它，不为响应查询实时源。
- loser 或激活前失败仅补偿自己的新 Session，传本次创建 ID、预期来源与内部边界；不要求来源等于 parent。
- 所有已有安全条件继续：目标闲置、无 Run/自有消息/工具/后代/override 等，本次共享 head/root 与创建事实一致；删除 Session 壳，不删共享内容。
- 激活后失败或 existing 失败不删除会话。创建后激活前崩溃空壳仍用原保守孤儿策略，不扩大清理能力。

## 历史回放保持原有机制

- Resolver/transcript 不为来源关联父工具、input、Child、fork 字段或实时 source head/状态。普通 subtask 仍走既有 resultPreview/error/status 投影。
- 可选来源说明缺失或损坏不导致整个历史回放失败，不从请求、正文或 Session 猜测补来源。若实现选择读取简单展示字段，仅做类型/格式检查，非法省略。
- 不新增来源专属工具结果写回合并、防篡改或终态 replay 规则；原 structuredResult 替换/一致重放/错误优先行为不变。
- 不承诺服务器直接收敛后的每条历史结果有来源说明。原有 messages/tools 闭合、可信 imageRef/附件等底层防护继续执行。

## Profile、窗口与生命周期

- Agent/profile/model 依请求解析，源身份、权限和 model override 不继承；源 active Run/pending/运行连接不复制。
- 新副本 lastResponseTotalTokens=null，runner.shouldAutoCompact 此时 false。首次超子模型窗口没有自动压缩兜底保证，选窗口足够的总结 Agent；实际超限按旧失败语义，不增加预估摘要。
- Child 执行父为 caller；父取消按原链取消，非 caller 来源自行取消不影响 Child。source=caller 时不豁免父取消。
- 文件、终端、远端资源不复制或冻结，图片/reasoning/工具预览限制沿用现有机制。
- 同版本部署与完整正式测试 gate 不因删回放改造而缩减，操作与验收见后续文档。

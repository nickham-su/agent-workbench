## 最新裁决与旧版保证的边界

- 本轮 A–H 裁决覆盖旧版冲突内容。简化文档已独立审查通过；指定来源 Fork 本地实现、阶段一至五独立代码审查和最终独立全面审查及复审通过；完整正式 Shared/API/Worker gate 2034 项通过；生产发布未执行。 L2 已修复并复审 Resolved；L1 为 Open 既有非阻断维护项，接受本次 WontFix，不扩大旧 Fork 变更范围。主助理接受的 D1/D2/D3 及 API client 合理差异、最终证据见 [09](09-实施与验收记录.md)。
- 用户需要的是“指定来源、只继承稳定上下文、独立执行总结”，不是提供永久可验证的快照事实服务。
- 简化对外来源说明与历史回放，不等于放松调用参数、父权限、内部图边界或 messages/tools 闭合校验。

## 扩展 fork，不新增 snapshot mode

- 选择：仅 fork 增加可选 sourceSessionId；不传时完全保留旧隐式路径。
- 原因：本质仍是创建继承历史的新 Session，新 mode 会重复工具 schema、解析、材料化和兼容矩阵。
- 显式 source=caller 仍按新增稳定入口执行，不能混同旧工具 Assistant previous 锚点/prefork。
- new/existing 带 source 拒绝，sessionId 不成为 source 别名。

## 服务端最新稳定上下文，保留内部实际边界

- 选择：同一 immediate 事务读取当前来源、验证有效图、选连续稳定前缀、创建 subtask Session；第一个进行中截断规则不变。
- 不由模型指定 sourceMessageId，不开放指定历史、等待源终态或 pending 保留参数。
- 内部实际消息边界仍记录在 forked_from_message_id/head/root，保证共享图可定位、重试可幂等、安全补偿可检查。
- 只删除对外边界与排除事实保证，不删锚点变量、压缩 root/retained 闭合、System/Compaction 内部锚点。
- 源 running 不是拒绝理由；损坏与正常 pending 区分，必要 retained 不能删减，公共手动/定时历史 Fork 权限不放宽。

## 元数据简化与删除过度保证

| 旧版设计 | 当前取舍 | 降低的成本 |
|---|---|---|
| forkSource 包装三字段，含 sourceMessageId/excludedInProgress | 不再使用包装或输出边界/排除布尔，只在 start 顶层增加可选 sourceSessionId | 减少契约类型、输出字段、布尔取样与跨层传递 |
| subtaskForkSource 服务器 JSON 保留键，与 Child 激活同步写入 | 不再增加保留键或激活来源写入；既有 Session 字段足够存内部分支 | 删除激活载荷、JSON 合并、服务器专属写入、防篡改和终态写回改造 |
| Resolver/transcript 严格回放来源证明 | 不再关联父工具 input、Child 与 fork 字段验证来源；按原有 preview/error 回放 | 删除跨实体查询、证明链保留要求和来源损坏导致历史整体失败的耦合 |
| shared 来源规范块与精确去重 formatter | 不再增加规范块/去重框架；Worker 在现有成功/错误投影中简短展示可选 ID | 删除服务器/Worker 字节格式同步、头部去重及全终态展示矩阵 |
| MetadataInvalid / METADATA_INVALID 类来源说明错误 | 不再新增该类错误；可选说明非法省略，不猜补 | 删除说明缺失/坏格式专用错误、恢复逻辑及相关验收 |

- 旧强化保证有安全意图，但超出本功能需要：unknown 可由服务器直接收敛且没有 Worker preview，错误文本可能优先于预览；保证每条历史结果都有权威来源会迫使写回、激活、Resolver、transcript 一起改造。
- 当前产品明确接受可选来源说明缺失：成功 start 时来源明确，正常 Worker 可携带/展示；不承诺服务器直接 unknown/cancelled 后的所有结果必有头。
- 历史不读实时来源 head/状态，也不反向补来源；如简单展示读取字段，仅做类型/格式检查，非法省略。现有消息/工具闭合、可信附件、共享图与归档防护继续。
- 不新增 DB 表/列/版本，不需要为元数据回放单独保留“父/Child来源证明链”。本方案不改变既有数据保留与共享图引用保护。

## 调用时不可变 input 仍是权威

- 只保留首次/重试/并发 winner 的 source 存在性与规范 ID 比较，不扩成 mode/agent/prompt 指纹，不搬入历史回放。
- 持久 input 缺失/坏 JSON/非法 source 为 ANCHOR_INVALID；传输切换显式/隐式或更换来源为 MISMATCH。
- 已有 Child 的 sourceSessionId 取其 Session.forked_from_session_id，按合法 input 核对；source=caller 时不能靠 Session 字段猜最初是否显式。
- 因为持久 input 已能区分首次语义，不需要旧 JSON 保留键或“缺元数据”分支来证明隐式/显式。

## 内部重试复用，新的模型调用重新捕获

- 同一父工具内部重试仍是同一 Child，复用 Session 已存锚点。来源后来前进、回滚或不可查都不再重新选边界，不额外要求实时可查。
- 另一父工具调用是新的副本，重新从来源当前稳定上下文创建；对外没有重现某次历史快照的公共参数。
- 并发 loser 必须重新匹配 input 与 winner 来源才能复用，自己的未激活空副本按精确 ID/来源/内部边界安全补偿。
- 不暴露消息边界不影响服务端幂等，因为边界与 lineage 已在内部记录。

## 共享历史与执行父关系分离

- 选择：共享稳定图，不深拷贝消息/工具结果；独立 Session/Run。source 后续追加/压缩/回滚不移动副本边界。
- Session fork 来源指向被总结会话，Child Run parent 指向 caller；父取消不应取消无执行父关系的来源。
- cleanup 不再要求 source=caller，但本次创建身份、预期来源/边界、无 Run/自有消息/工具/后代/override 等条件保持。
- 外部文件、终端、远端资源不复制；不新增只读权限 UI、文件沙箱或日报/活跃查询。

## 不继承 Agent/profile，明确首次窗口限制

- 新 Run 使用请求 agentId 和现有 profile 解析，不继承源 Agent、权限、model override 或运行连接。
- 新副本 lastResponseTotalTokens 初始 null，runner.shouldAutoCompact 依上次 token 数判断，null 时 false；首次请求超子模型窗口没有自动压缩兜底保证。
- 推荐使用窗口足够的总结 Agent；实际超限按既有失败语义，不拿 caller 摘要代替 source，不新增预估摘要功能。
- 图片、工具预览、Provider 私有 replay 和附件保留仍受原有适配与存储条件限制，稳定分支不意味着复制完整瞬时记忆。

## 同版本协同部署与完整 gate 保留

- 旧 Worker 可能删 source 后执行 caller Fork，不能与公布新 schema 的 API 混跑；不增加动态能力协商。
- 用已有部署访问控制/上游暂停阻断根任务、暂停计划与手动绕行入口，保留在途内部 API。持久 Run/工具/计划 execution 和所有 Worker 新鲜队列证据收敛后整体升级。
- 无项目全局 drain 开关不伪造；无可靠队列证据、无法隔离入口或超时未收敛即中止，或经授权受控取消后重新检查。
- 回滚前新版显式 pending input 必须收敛，不因没有来源说明就降级 Worker；无 DB schema 变化，不需要元数据迁移或数据库回滚。
- 正式 API 验收保留 npm test -w apps/api 或 npm run test:all -w apps/api，分类 runner 不替代 verify-test-gate。

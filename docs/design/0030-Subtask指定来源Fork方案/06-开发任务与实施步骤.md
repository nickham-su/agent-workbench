## 契约与原始验证

### 任务

- 收集 new/existing/implicit fork、nested、prefork 成功/失败/空边界的既有基线。
- fork 请求仅增可选 sourceSessionId；start response 仅增顶层 sourceSessionId?: string，原五字段不变，旧模式不增加字段。
- 同步工具 JSON Schema、Shared、Worker parse、API serializer/decoder；不新增公开消息锚点参数或包装对象。
- 增加 02 定义的参数/来源/稳定上下文/MISMATCH 错误，沿用 ANCHOR_INVALID/PREFORK_NOT_ALLOWED。
- start 路由增 schema 前 raw preValidation；新增来源的模式、类型/trim、prefork 存在性按唯一顺序校验，保留认证、不改全局 AJV、不严格重验无 source 旧请求。
- Worker/应用直调复用纯新增字段检查，用真实 Fastify inject 验证数字/布尔/数组/object/null、非法 mode、其他 mode 带 source、prefork 空/null/类型错误及混合错误优先级。

### 完成标准

- 旧响应与新显式首次/复用响应均通过契约；规范 ID 未被重建对象或序列化丢弃。
- 非法原始字段不能被 AJV 转换/删除后接受，不产生材料化副作用。工具说明统一解释只继承稳定有效上下文。

## 内部稳定来源材料化

### 任务

- SessionInteraction/message store 新增窄的稳定来源入口，内部返回 Session，可保留创建身份供补偿，不返回对外事实对象。
- immediate 事务内同 Workspace primary/subtask 验证、当前物理链/有效 root/原始 retained/Parts/工具解析、连续稳定边界选择、Session/run state 插入。
- 保留第一个进行中截断点，不先 normalized 过滤；Assistant 整条排除，终态失败工具按原语义闭合。
- 保存内部 sourceMessageId 至 forked_from_message_id 与创建 head，保存实际有效 root；compaction 边界 root=self，必要 retained 完整，不保存排除布尔。
- root/retained 按 02 唯一错误矩阵，物理链、工具身份、Parts/现有 replay 防护不变，不改源 state/head/revision。
- 不复制 active Run/pending/身份/override/token 统计，不放宽公共手动/定时历史 Fork。

### 完成标准

- 新入口无模型/文件 IO/await，不要求源 idle，不使用事务外 head/revision 授权。
- 真实 SQLite 覆盖 streaming、多工具、空源、坏根/retained/图、继承祖先、回滚分支、System/Compaction 边界以及两连接一致性。
- 实际边界在内部可断言，对外只有来源 ID；源后续追加/压缩/回滚不影响已选副本。

## 调用一致性、幂等与补偿

### 任务

- 可信父锚点读取不可变 tool-call input，检查坏 JSON/非对象/非法 source 为 ANCHOR_INVALID。
- 首次、重试、并发 winner 只比较 source 存在性与规范 ID；显式/隐式切换或 source 不同为 MISMATCH，不增加 mode/agent/prompt 完整指纹。
- 显式分派先于 caller boundary/prefork/空历史回退。无 Child 才校验当前 source/稳定边界并新建；已有 Child 核对其 Session Workspace/kind、绑定来源及原父权限，按既有 lineage 复用。
- 显式成功来源取 Child Session.forked_from_session_id，source=caller 是否返回字段由合法绑定 input 决定，不猜 Session 字段。
- 复用沿用已存锚点，不再查实时 source；来源前进/回滚/不可查仍可合法重试。
- Child 激活沿用既有父/目标 fence、Run/消息事务和唯一约束，不增加来源专属激活载荷/JSON 写入。
- 并发 loser 再验 input 与 winner 来源后才复用，安全清理自己本次空副本；新工具调用独立材料化重新捕获。
- cleanup 移除 source=caller 假设，保留本次 ID/来源/内部边界和无 Run/自有消息/工具/后代/override 等安全条件，不删共享图。
- 取消遵循执行父链；激活前 profile/prompt/Workspace/parent 失败安全补偿，激活后失败保留会话，崩溃空壳沿原保守孤儿策略。

### 完成标准

- SQLite unique constraint 与两连接竞态证明同父最多一成功 Child，不同父工具可独立副本。
- 真实 input 驱动首次/重试/winner，同 source=caller、来源后来不可查、旧 implicit 均有测试，不依赖工具结果来源说明。
- source 不同于 caller 时失败可清理空壳，但共享历史和已拥有工作目标保持不变。

## Worker 与普通可选展示

### 任务

- 显式调用不访问 caller prefork plan/messages-context/摘要；其他模式保持旧调用序列。
- 消费 start 顶层可选 sourceSessionId，实际 running/final structuredResult 可携带同名字段，原业务字段与普通写回不变。
- 既有成功/错误投影简短显示合法来源；成功 start 后失败如已有 ID，通过既有 error carrier 传递，未成功 start 不伪造。
- 不增加 shared 来源格式/去重框架，不要求服务器所有终态添加头，不增加 ToolExecution 结果保留、合并、防篡改或终态规范化规则。
- 回放兼容测试证明可选说明缺失/坏格式不阻塞，原 preview/error/status 与可信附件机制不变；如简单展示读取非法则省略，不查关联实体或补来源。
- 明确新副本 lastResponseTotalTokens=null、shouldAutoCompact=false，首请求窗口超限不保证自动压缩；不新增预估摘要。

### 完成标准

- 正常显式成功/可携带的错误短展示正确，旧模式无新字段。直接 unknown/cancelled 无来源说明是允许结果。
- 删除旧长期回放保证后的兼容测试独立于元数据写入，不以“每条历史都有头”作为完成标准。

## 缩小后的依赖

| 任务域 | 必要依赖 |
|---|---|
| 原始验证/契约 | 旧模式基线与现有认证/schema |
| 内部稳定材料化 | 现有图/root/retained/工具闭合能力及 Session 字段 |
| start/重试/winner | 来源规范化、可信父 input、材料化、原 lineage/激活/补偿 |
| Worker 可选展示 | 新单字段响应与既有成功/错误 carrier |
| 集成验收/发布 | 上述能力及正式 gate、同版本收敛证据 |

- Worker 展示不依赖新增服务器回放字段，Child 激活不依赖来源 JSON 保留写入，lineage 不依赖历史 Resolver。
- 仍不得只改 schema 就交付；消息稳定、安全补偿和部署兼容是不可删除的主链约束。

## 同版本协同升级与回滚

### 维护前准备与阻断根入口

- 使用现有部署制品与运维权限确认 API/全部 Worker 范围、fallback 是否启用、根生产者、Workspace 计划；不在记录中写凭据或任务内容。
- 记录原启用计划，用现有 pause 逐个暂停；原暂停不误恢复。阻断 manual run、enable、create/replace 等可绕过暂停入口。
- 用已有反向代理/部署访问控制阻断根消息 JSON/multipart、手动公开/内部 compact、插件/Webhook/CLI internal trigger、外部根 Worker enqueue 等实际入口；不能仅停前端。
- 对直连绕行生产者用已有运维入口暂停或部署级路径控制，不能停止在途工具需要的插件/MCP 服务。无法隔离则中止发布，不发明项目全局开关。
- Scheduler 在 API 内 claim/execute，不经过代理；pause 阻止后续 claim，已 claim 的 starting/running execution 计入在途。
- 保持旧版本 API/Worker 和排队消费。保留在途 messages/context、工具写回、subtask start/result/status、压缩、terminal intent/convergence 等内部 API，不能一刀切封 internal 路由。

### 等待真实收敛

- 使用已有只读状态/运维观测覆盖全部 Workspace 与 Run kind：无 running 或非 terminal execution_phase Run，包括 work_pending 排队与 terminal_intent_persisted 待收敛，Session 状态释放。
- 无 queued/running ToolExecution，无待激活/starting/running scheduled execution；不能只看 Session idle 或单 Worker activeCount。
- 每个实际 Worker 用已有受认证 /_internal/analytics-snapshot 新鲜快照证明 queueLength=0、activeCount=0，交叉核对持久 Run/工具。Nested Run 不计普通 activeCount，不能省持久检查。
- fallback 如启用，使用其已有可靠队列/进程观测加持久状态；本次无新增全局 queue 查询，无法取得队列证据即不满足发布。
- 入口保持阻断、计划保持暂停，至少两次独立新鲜观测均满足，中间留正常对账机会；旧快照或 Worker 失联不算零，再确认无新 claim/入队。
- 超时仍有工作：中止发布保留旧版并按记录恢复，或经明确授权用现有 cancel 受控取消，等待真正终态收敛后重复检查。不能杀 Worker、直接停 API 或 SQL 改状态。

### 协同升级与恢复

- 完成收敛后继续阻断/暂停，协同停止旧 API/Worker，包含管理型与独立部署实例及自动重启；部署同版本 shared/API/全部 Worker。
- 启动后等待既有 runtime-ready/recovery barrier，用制品版本/摘要确认一致，health=ok 不是版本证明，不宣称新增版本查询端点。
- 验证新 schema、Worker source 解析及单字段响应、旧回放兼容，恢复对账无遗留待执行。经授权 smoke 需完整新版链路并等待其工具/Run 收敛。
- 满足全部证据后仅恢复原启用计划，其 next-run 依旧调度规则，不补跑所有错过时段；再恢复根生产者和访问控制。
- 无法完成版本一致、入口阻断或队列证据就继续阻断，不开放新 schema 给旧 Worker。

### 回滚

- 同样先阻断根入口、暂停计划、保留新版在途内部链路，核对显式 source 的不可变 pending input、工具/Run/计划 execution 和真实队列。
- 有新版显式输入仍可能执行/恢复时禁止降级 Worker，即使来源说明未写，因为旧 parser 可能删参数执行 caller Fork。
- 让新版完成或经授权受控取消后完整收敛；超时维持新版/中止回滚，不强制降级。
- 达到同样收敛条件后整体回滚 API/shared/全部 Worker，验版本/旧功能后恢复原计划与入口；没有 DB schema 或来源元数据迁移回滚操作。

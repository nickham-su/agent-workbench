## 跨层实证与实现差异

### 真正执行的链路

新增跨层文件通过真实 `app.listen` + `AgentApiClient` HTTP 与 schema decoder，由实际 Runner 的安全工具入口调用 Builtin 参数解析、生产 composition start、SQLite 稳定 Fork、生产 Nested Run、终态写回、结果/status，再由原 Resolver/transcript 回放。唯一模型替身是 Runner `streamText`；没有模拟 Session/Child/补偿事务结果。

- caller/noncaller 显式来源：首次与同父复用为同一 Session/Run，只有可选来源 ID；caller prefork plan/messages-context/summary 调用均为 0。
- running 非 caller 来源含未完成工具 Assistant：实际锚点在其前一 User，整条 Assistant 不进入子模型请求，源 Session 保持原值。
- new/existing/nested implicit：沿旧路径完成真实 Nested Run，旧响应和结果没有来源字段。
- 模拟 Provider 首次上下文超限：新副本 token 数为 null，未调用 compaction、caller prefork 或新摘要，Child/工具按原失败语义收敛，已激活会话保留。该测试不等于实际模型 token 计数或真实 Provider 窗口测量。
- 服务器直接收敛 queued→cancelled、running→unknown：没有 Worker preview/error/structuredResult，原状态回放正常，无强制来源说明。
- 普通来源说明缺失、null、数字、对象、空白、与 input 不同且没有可关联 Child：原历史仍回放，error 优先于 preview，不反向补来源。
- 新 streaming Part 测试使用生产 `flushStreamingParts` 的合法累积文本续写，证明 Fork 后进行中 Assistant 的文本继续变化不会进入已继承上下文。

### 窄调整/保留的既有行为

1. API client 生产方法无需改动：既有透明请求与 Shared decoder 已支持单字段，通过实际 HTTP 和客户端回归验证，不为文件清单机械增加生产改动。
2. 稳定解析窄复用现有 Resolver；普通 hydration 对未知 Part 类型补明确不变量错误，合法历史不变，不新增来源回放证明链。
3. cleanup 在原保护上增加精确 head/root、初始 revision 和空 pending 身份校验；仍只清本次未激活空壳，不删共享图。
4. 来源 reader 仅读取 own data property，accessor/代理异常省略；非 subtask 错误路径不读取来源。该调整修复实际复现问题，不扩大为 formatter 或恢复框架。
5. **旧 prefork 的真实 messages-context fallback**：当前通用 messages-context 对本 fixture 中进行中的 ToolCall 保留闭合防护，会拒绝其整条 Assistant；旧 Builtin 捕获上下文读取失败并安全退回旧 Fork。跨层用例诚实验证这一既有 fallback，不冒称 one-shot Provider 摘要已执行。摘要成功/Provider 失败逻辑分别由既有 Worker prefork 单测和真实 API 摘要 seed 集成测试覆盖。本阶段未放宽原回放闭合规则，未借新功能改造旧 prefork；若未来要优化它，应另行评估 caller 摘要边界。

以上不改变当前产品范围。主要约束仍是单字段对外、内部实际锚点、调用时绑定、稳定连续前缀、原历史回放；不新增 DB 表/列/版本、UI、活跃查询、日报、权限或文件隔离。

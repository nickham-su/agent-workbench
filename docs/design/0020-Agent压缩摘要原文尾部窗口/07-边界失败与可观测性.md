# 边界情况、失败语义与可观测性

## 边界决策表

| 场景 | 唯一结论 |
|---|---|
| 空 Session/head null | `/compact` 同步 HTTP 400，不创建Run |
| 只有旧摘要、无新非空原文 | proactive/manual no_prefix |
| 旧摘要很大、新原文全可保留 | 有意no_prefix |
| 最新非空块>20k | proactive跳过；manual `compaction_oversized_tail` |
| trigger媒体块或强制后缀>20k | proactive跳过；manual媒体blocked |
| Assistant为20k首块 | adapter显式支持才允许；否则向前扩User/System |
| 扩展后>20k | 标准窗口不可用 |
| 主profile投影为空 | 成本0、不计进展、不可retainedFrom |
| pending tools | manual `compaction_pending_tools`；proactive走既有pending流程 |
| retained区间穿旧摘要 | 跳过，不递归 |
| fork/subtask共享祖先 | 按Workspace+当前lineage合法，不要求originSession相同 |
| 摘要调用错误（包括容量、鉴权、网络错误） | 使用选定模型，对完整旧前缀按配置退避重试 |
| 摘要重试耗尽或工作 deadline | 手动压缩失败；自动压缩所属对话 Run 失败 |
| caller 取消 | 立即中止重试，Run 取消 |
| CAS conflict | 按模式有限重规划，当前deadline不重置 |
| profileFingerprint变化 | proactive跳过；manual `compaction_conflict` |
| 主模型 Provider 错误（含疑似context-limit） | 按`modelRequestMaxRetries`普通指数退避；不压缩恢复 |

## Work与terminal-control预算

权威值：

- proactive/manual：source前启动，使用 Web 设置下发的`modelTotalTimeoutMs`；`0`关闭deadline；
- 手动/主动摘要每轮规划最多初次调用加 `modelRequestMaxRetries` 次额外重试，摘要没有独立总请求预算；
- 所有RPC、Provider请求和退避绑定剩余deadline；
- CAS重规划不重置非零deadline。

terminal-control 独立于上述 work deadline：

- 无产物结果固定10秒，先persistTerminalIntent，后convergence；
- intent最多3个真实HTTP请求；intent成功后convergence在剩余预算内最多3个；总计最多6个但总时长不超过10秒；
- 两阶段API Client均maxRetries:0，Runner/专用terminal loop是唯一重试层；
- 每次timeout裁剪剩余预算，额外请求前固定250ms短退避；
- 同阶段提交相同status/code/detail，依赖幂等helper；
- 无ToolCall/ToolExecution的终态Assistant与manual成功compaction在work transaction内原子写产物+intent，成功后不写独立intent，首次convergence前新建10秒budget、最多3次；原子请求响应丢失时以完全相同产物和intent重放；
- proactive内部skip不单独写结果；manual/user/subtask必须终态；
- 原子产物+intent或独立intent成功后崩溃，startup只converge；独立intent完全失败则phase仍work_in_progress，startup按安全恢复规则继续或写startup failure intent；convergence持续失败保留原intent供后续startup继续收敛，不改码。

主模型的所有 Provider 错误统一按 Web 设置下发的 `modelRequestMaxRetries` 普通指数退避；`0` 不重试，也不因疑似 context-limit 启动恢复压缩。摘要调用亦不作 context-limit 分类：选定模型处理完整旧前缀，所有抛错按相同配置重试，不回退模型或递归分片。

`context_limit_media_requires_resend` 与 `context_limit_recovery_exhausted` 保留给历史 Run 的读侧和i18n展示，新运行不再生成。

## 非终态与工具完整性

- pending Assistant及之后不发送，也不进入B；
- manual写`compaction_pending_tools`；
- proactive先执行既有pending tool流程；
- 缺失execution是data invariant failure；
- Assistant块包含全部ToolCall及终态结果，不得拆分。

## Provider replay与多Provider摘要

- API只读取resolver有效块的原始envelope；
- B按主profile兼容物化，只有实际进入主请求的replay参与Estimator；
- Estimator先将真实ModelMessage映射为专用canonical schema；
- 仅白名单OpenAI Responses text/reasoning/tool-call replay从真实part.providerOptions提取；其他和未知providerOptions完全排除；
- reasoning密文替换为`<encrypted>`并按真实密文UTF-8长度另计成本；
- A生成SummaryInputBlock时移除encrypted replay和providerOptions；
- replay-only且无可见内容固定写`[Prior assistant replay state omitted from summary input]`；
- 选定摘要模型消费相同provider-neutral语义，不因摘要错误换模型；
- public Run状态、timeline等接口不返回私有replay。

## 图片与附件

- trigger带图片/附件的User块必须留B；
- Estimator在attachment_ref阶段运行，canonical不读取file bytes；
- request-only materializePromptAttachments在估算之后、streamText之前执行；
- attachment canonical保留mediaType，filename替换为`<filename>`，每个额外1024 tokens；
- trigger块或强制后缀超20k时，proactive跳过；manual以`compaction_media_requires_resend`完成；
- 不注入媒体移除提示后继续模型推理；
- UI提示重发更小或更少附件。

## Run terminal result生命周期

- terminal result持久化在`agent_run.terminal_result_code/detail`；
- phase固定为work_pending/work_in_progress/terminal_intent_persisted/terminal；
- terminal_intent_persisted时status仍running，公共查询result为空；
- intended status/code/detail只在intent phase存在；terminal时清空intended并写实际result；
- registry冻结全部runKind/status/code组合，unknown拒绝；数据库强制nullability、code<=80、detail<=240；
- detail默认null且只允许registry枚举诊断键；
- `convergeRunTerminal`只读取已持久intended，不接收Worker终态结果；其处理范围严格限定为workspace/session/run origin，不触碰其他Run；
- completed intent 要求本Run没有streaming/nonterminal Message且没有queued/running ToolExecution；违反即data invariant failure，事务回滚且Session不得idle；
- failed intent 将本Run streaming Assistant置failed；cancelled intent置cancelled；两者均将queued ToolExecution置cancelled、running ToolExecution置unknown；
- queued→cancelled表示未执行；running→unknown表示副作用可能已发生，保持既有诊断语义；两种实际转态均保留startedAt，并将completedAt固定写为convergence.updatedAt，不伪造或改写result/error；
- artifact状态变化的updatedRevision/updatedAt、Session revision、Run actual result/phase、intended清空与session_run_state idle在同一事务提交；
- persistence返回transitioned或already_converged和finalStatus；幂等重放必须核对ToolExecution completedAt，不能改写它；
- 所有convergence成功或一致重放均经同一应用层后置处理清除run prompt static cache；仅transitioned发布既有`agent.run.completed.v1`，不新增事件类型；
- 事件发布失败在DB提交后只记录错误，不回滚、不补发。当前内存SSE为best-effort，接受进程崩溃或发布异常造成永久漏事件的风险，本次不引入outbox；
- API cancel、enqueue failure、startup failure、Worker failure/cancel不得另行处理artifact，统一persistIntent→同一convergence；
- 已terminal只有artifact、Run、Session/run state均一致才幂等成功，矛盾状态拒绝；
- 最终 Assistant（无ToolCall/ToolExecution）由原子terminal完成动作写Assistant、response tokens和intent；可含replay/reasoning；user写`run_completed`、subtask写`subtask_completed`；
- Worker在流结束后根据recognizedCalls、visible文本和空响应计数选择入口：有ToolCall或未达空阈值时普通完成；无ToolCall且可见文本或已达空阈值时原子terminal完成；
- manual成功调用commitCompactionWithTerminalIntent原子写CompactionMessage、TextPart、Session root/head和`compaction_completed` intent；
- manual no-op/blocked/provider failure、user/subtask失败、取消、enqueue/API cancel/startup failure使用独立persistTerminalIntent后converge；
- API cancel、enqueue永久失败、startup recovery failure通过同一API本地intent+完整convergence事务；
- 已终态Run只允许完全相同的幂等收敛，不允许改写不同结果；
- startup不以Assistant/Tool/Compaction artifact推断intent；终态Assistant或手动compaction的原子成功产物不存在phase仍work_in_progress窗口（主动产物允许继续work_in_progress）；intent后崩溃通过同一convergence完成artifact/Run/Session收敛；工具完成等待下一模型步骤的work_in_progress继续原Run；
- `runNoticeText`仍只表示运行中notice；
- manual和普通user runId共用当前标签页pending-run registry；key区分workspace/session/runKind/runId；刷新后继续查询；
- record含schemaVersion=1和createdAt；非法记录静默删除；
- 只轮询当前workspace/session，其他合法记录保留；并发3条、FIFO分批；
- 网络/timeout/429/5xx保留重试；404/ownership/runKind mismatch提示一次后删除；
- workspace/session删除时清理相关key；
- user正常`run_completed`静默清理；failed/cancelled按code显示可行动i18n；
- 每个标签页独立展示一次，不跨标签页协调；
- terminal result只经Run状态接口读取，不混入timeline Message或实时事件；
- 不保存或展示Provider原始错误。

## 时间线、归档、回退和分叉

- timeline 展示当前 head 的完整可达祖先链，包括压缩前原文、compaction 摘要和压缩后消息；
- timeline 保持物理顺序，不按 S+B 模型顺序重排；retained tail 不复制，但作为原始历史自然可见；
- root 之前消息通过 `inCurrentOperationRange=false` 标记为只读；该标记不代表模型不可见；
- archive仍可包含tail并与Timeline可见历史重叠；
- move head/fork不越root，前端不得为 root 之前消息显示可执行入口，API仍必须服务端拒绝越界；
- context root 变化时 timeline delta 必须 reset 或完成等价边界更新；
- terminal result不是Message，不插入时间线。

## 数据库不可变与清理

- retainedFrom自引用FK `ON DELETE RESTRICT`；
- 同Workspace trigger；
- 非compaction null check；
- retainedFrom update拒绝；
- Workspace cleanup必须保持previous/replaces/retained图边原值，并通过逆拓扑删除满足FK；
- 删除顺序固定为FTS行→FTS map→client request→session_run_state→session model override→ToolExecution→MessagePart→Run→Session→Message逆拓扑→Attachment；
- ToolExecution必须先于MessagePart，Run与Session必须先于Message；
- 每轮只删没有剩余Message引用的节点，depth/id仅排序候选；
- 无候选但仍有节点即data invariant/cycle failure；
- foreign_keys=ON下replacement同depth、retained、首次和连续压缩图必须可删除。

Workspace删除的失败边界固定为：`convergeWorkspaceRunsForDeletion`在deletion intent和fence后逐Run完成DB收敛，任一Run intent/convergence的conflict或invariant failure立即停止，不drain、不物理删除；DB均成功但任一`cancelSessionAndWait`超时/异常，也停止且保留intent/fence。后续删除或启动重试只识别已terminal Run并重新drain，不能覆盖已有终态结果。所有Session lock按sessionId、Run按runId稳定排序，子任务包含在内。

若读取发现悬空、跨Workspace、无法抵达或循环，立即data invariant failure，不自愈。

## 可观测性

### 日志安全

允许按现有政策记录必要的sessionId、runId、planId、headMessageId、retainedFromMessageId和非敏感profileFingerprint。绝不记录用户文本、摘要、工具内容、文件、附件路径、replay密文、key/baseURL或凭证。

### 现行可验证信息（非结构化日志字段承诺）

- 压缩 Executor 的结果种类与原因、规划的 `expectedRevision`、成本判断及按配置执行的摘要请求次数，可在执行结果和局部测试中验证；它们不等于已实现的逐项结构化日志。
- 运行中 retry notice 仅提供重试次数、上限与等待秒数；通知普通失败、清理失败及已提交后的 fence 失效只写固定静态警告，不记录 Provider 原始错误、摘要或凭证。
- Run 终态以持久化的 status/code 和 convergence 结果为准；既有 `agent.run.completed.v1` 仅在首次 transitioned 时尽力发布。当前不单独发布 `compaction.source/plan/summary/commit` 结构化事件，也不承诺未实现的逐项结构化计数。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| Estimator偏差 | UTF-8固定公式、1.10系数、canonical+数值golden |
| proactive阻塞 | 可配置工作 deadline、可取消的指数退避、仅展示安全的重试进度 |
| 终态结果丢失 | 持久phase+intent、10秒terminal-control、startup convergence |
| pending记录陈旧 | version校验、永久stale删除、瞬时错误保留、FIFO并发3 |
| 读取撕裂 | 单一SQLite deferred读事务 |
| 多Provider语义漂移 | A/B来源冻结、SummaryInputBlock provider-neutral |
| 媒体被静默移除 | trigger媒体强制留B，不注入移除媒体的synthetic prompt |
| Provider不接受Assistant开头 | adapter能力+向前扩合法边界 |
| cleanup破坏不可变图 | 三边逆拓扑删除，不清空边界字段 |
| Workspace删除遗漏或误改Run | deletion intent/fence、稳定锁/排序、逐Run复用完整convergence、全部DB成功后再drain |
| SSE漏送或重复 | 首次transitioned才best-effort发布；重放不补发，接受无outbox漏送风险 |

## Run统一终态收敛与查询接口

工作：

- 实现work_pending→work_in_progress幂等开始写。
- 删除旧`AgentApiRunCompleteRequestSchema`、completeRun端点/API Client方法、`completeRunFromWorker`及包装层。
- 新增persistTerminalIntent原子helper/RPC和只读intent的完整convergence persistence helper。
- converge在一个持久化事务内严格按workspace/session/run origin收敛Message、ToolExecution、artifact updatedRevision/updatedAt、Session revision、Run结果/phase、intended清空和session_run_state idle。
- convergence persistence响应增加`kind: transitioned | already_converged`和finalStatus；已terminal重放同时校验artifact（含ToolExecution completedAt）、Session和run state。
- completed intent先验证本Run不存在streaming/nonterminal Message和queued/running ToolExecution；违反data invariant并回滚，不置idle。
- failed/cancelled分别收敛streaming Assistant，且queued ToolExecution→cancelled、running→unknown；不得碰其他Run。
- queued/running ToolExecution转态同一SQL事务写`completedAt=convergence.updatedAt`、status、updatedAt、updatedRevision；保留startedAt，不伪造或改写result/error，并补DB/DTO测试。
- 迁移`failMessageRunAndConverge`与`cancelRunAndConvergeInTransaction`的artifact语义到convergence persistence helper后删除旧路径，不保留重复权威。
- 完成普通Assistant与终态Assistant分离：普通入口不写intent；终态入口同一事务完成Assistant、response tokens和intent。
- 终态Assistant拒绝ToolCall/ToolExecution，可保留replay/reasoning；user/subtask分别固定成功码。
- 重构`runModelStep()`：流结束后先基于recognizedCalls、visible文本、空响应本地计数判定入口；前N-1空Assistant普通完成，第N次阈值完成原子终态。
- commitCompaction同一事务写CompactionMessage/TextPart、Session root/head和`compaction_completed` intent；响应丢失时严格幂等重放。
- manual无产物结果、user/subtask失败或取消、API取消、enqueue永久失败、startup recovery使用独立intent。
- Runner terminal loop共享10秒：intent最多3请求，convergence剩余预算最多3请求，固定250ms。
- 两RPC API Client policy均maxRetries:0，timeout裁剪剩余预算。
- 原子成功产物只需convergence，不占intent请求额度；startup按phase决策，intent phase只converge，不检查Assistant/Tool/Compaction artifact。
- work_in_progress工具已完成等待下一模型步骤的恢复测试。
- manual no-op/blocked/failure同样独立写intent。
- convergence连续失败保持原intended三元组，下一次startup继续converge；删除旧控制面结算失败码的registry、i18n和fixture项。
- 已terminal仅在artifact/Run/Session/run state全一致时幂等；不同结果或残留矛盾拒绝。
- 增加streaming failed/cancelled、queued/running、completed invariant、intent后崩溃、startup replacement+enqueue failure和跨Run范围隔离测试。
- 实现唯一`afterConvergeRunTerminal`应用层后置函数，统一覆盖Worker RPC、API cancel、enqueue failure、startup recovery和Workspace deletion本地逐Run收敛。
- 后置函数对transitioned/already_converged均清`runPromptStaticCache`；仅transitioned发布现有`agent.run.completed.v1`，事件发布异常只日志不回滚，重放不补发。
- 增加SSE首次一次性、响应丢失重放不重复、发布失败保持DB终态/cache失效，以及现有飞书插件/通知订阅的事件格式与无重复通知回归测试。
- 删除旧`cancelWorkspaceRunsAndConverge`直接SQL实现，新增Workspace deletion application编排器`convergeWorkspaceRunsForDeletion`：deletion intent→fence→sessionId稳定序handoff locks→runId稳定序逐Run本地persist/converge+后置处理→全部DB成功→逐Session drain→全部成功后cleanup。
- 每Run独立短事务；已有其他intent先converge原intent且不得覆盖；Run不变量失败时禁止drain/cleanup，drain失败保留intent，重试只重新drain已terminal Run。
- 覆盖user/manual/subtask、其他Workspace隔离、稳定排序、DB失败短路、drain失败重试及startup resume。
- 新增`GET /api/agent/sessions/:sessionId/runs/:runId`公共只读接口和ownership校验。
- 实现完整registry；Worker/API来源子集、unknown拒绝、detail默认null和枚举键限制。
- 空Session `/compact` 同步400，不创建Run。
- pending tools结果码。

完成：每条Run终态路径都有status+code，clientRequestId重放可查同一Run结果。

## 模式deadline与Manual

工作：

- deadline在source前创建并贯穿RPC/物化/规划/摘要/退避/CAS/收益/commit。
- proactive 15秒、零网络重试、CAS0重规划。
- manual 120秒、每logical call额外1次、CAS1重规划。
- CAS重规划不重置deadline。
- proactive计数覆盖整个attempt；manual覆盖整个Run；CAS不清零partition/logical/network。
- manual结果码映射，包括pending tools、media、conflict。
- Provider恰耗尽work deadline后仍进入独立terminal-control测试。

完成：业务无进展不误判技术失败，所有调用受剩余deadline控制。


## Recovery状态机

工作：

- standard/full各45秒；仅转full时启动新deadline。
- 只有standard业务无进展或standard步骤仍context-limit进入full。
- summary_input_limit立即失败。
- transient耗尽、permanent、cancelled不进full。
- trigger媒体禁止full。
- recovery CAS整个事件1次且不重置级别deadline。
- recovery计数按level；CAS不清零，standard转full才新建计数。
- 接近上限后CAS冲突重规划不得突破上限。
- user Run写media/recovery exhausted/conflict稳定code。

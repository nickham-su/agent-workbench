# 测试矩阵与验收标准

## 共享契约

- CompactionMessage接受string/null retainedFrom，拒绝缺字段、非completed、非单TextPart。
- 普通消息出现retainedFrom拒绝，其他现有宽约束fixture继续通过。
- commit/source/Run status DTO全部`additionalProperties:false`。
- source replay DTO不允许`Type.Any()`。
- ToolExecution共享及内部DTO严格含startedAt/completedAt；convergence后DTO `completedAt`精确等于请求updatedAt，不能由读侧重新计算。
- Run status接口只返回workspace/session/run/runKind/status/code/detail/updatedAt。

## Schema、Store与Workspace清理

- retained列、自引用FK `ON DELETE RESTRICT`、非compaction null check存在。
- 同Workspace insert/update trigger生效，retained更新被拒绝。
- schema semantics缺任一约束时判定非目标schema。
- `agent_run.execution_phase`、intended三元组、terminal result列和强制基本check生效。
- Run创建为`running/work_pending`；Worker真正开始后原子转为`running/work_in_progress`，重复开始幂等。
- `work_pending/work_in_progress`的intended与actual result全部为null。
- `terminal_intent_persisted`保持status=running，intended status/code完整，actual result为null。
- `terminal`清空intended，status为completed/failed/cancelled且actual code非空。
- intended/actual code长度1..80，detail为null或长度1..240。
- registry完整验证runKind/status/code；unknown、错误来源子集和未登记detail键拒绝。
- 已移除的旧控制面结算失败码不得出现在registry、契约、数据库fixture或i18n映射中。
- `persistTerminalIntent`相同intent重放成功，不同intent、非法phase或已terminal不同结果冲突。
- `convergeRunTerminal`只读取已持久intent且不接收Worker结果；Message/ToolExecution处理范围严格限定workspace/session/run origin。
- completed intent 遇本Run streaming/nonterminal Message或queued/running ToolExecution时data invariant failure；Run、Session revision、run state与artifact均不得部分更新或idle。
- failed intent：streaming Assistant→failed，queued ToolExecution→cancelled，running ToolExecution→unknown。
- cancelled intent：streaming Assistant→cancelled，queued ToolExecution→cancelled，running ToolExecution→unknown。
- queued→cancelled断言未执行；running→unknown断言副作用可能已发生。
- queued/running ToolExecution转态时，`completedAt=convergence.updatedAt`，保留startedAt且result/error原样；status/completedAt/updatedAt/updatedRevision必须同一事务。
- `AgentToolExecution`读侧DTO必须返回上述completedAt；queued/running转态的数据库行与DTO均断言准确。
- artifact状态变化的updatedRevision/updatedAt/completedAt、Session revision、Run actual result/phase、intended清空和session_run_state idle必须同一事务。
- 其他workspace/session/run的Message、ToolExecution、run state与revision不受影响。
- persistence convergence返回`kind=transitioned|already_converged`及finalStatus；已terminal且artifact（含completedAt）/Session/run state一致才为already_converged；不同终态或残留矛盾拒绝。
- intent后崩溃时startup调用同一convergence完成所有artifact、Run、Session收敛。
- API cancel、enqueue失败、startup失败、Worker失败/取消不得在convergence外重复处理artifact。
- Worker RPC、API cancel、enqueue failure、startup recovery和Workspace deletion本地逐Run收敛均调用同一after-convergence后置函数；首次和重放均清除run prompt static cache。
- 仅transitioned发布一次`agent.run.completed.v1`，响应丢失后重放为already_converged不重复发布；覆盖completed/failed/cancelled全部Run种类。
- SSE发布器抛错时Run仍终态、cache已清除、记录错误；重放不补发。断言现有内存best-effort语义，不引入outbox。
- 保持已有飞书插件/通知订阅回归测试：接收既有`agent.run.completed.v1`格式和finalStatus，且终态重放不产生第二次通知。
- 旧`AgentApiRunCompleteRequestSchema`、completeRun端点/API Client方法、`completeRunFromWorker`与包装层不存在。
- `markRunWorkInProgress`只允许work_pending→work_in_progress且重复幂等。
- `completeAssistantWithExecutions`完成非终态Assistant/ToolExecution且intent仍为null。
- `completeTerminalAssistantWithExecutions`在同一事务完成Assistant、response tokens和intent；拒绝ToolCall或ToolExecution；允许replay/reasoning。
- user terminal Assistant只接受`completed/run_completed`，subtask只接受`completed/subtask_completed`。
- 终态Assistant请求响应丢失后以相同Assistant/Parts、tokens、空executions和intent重放成功；任一差异conflict。
- compaction commit覆盖string/null、CAS、fence、非法链、跨Workspace、旧摘要/runtime/非completed、非连续后缀和幂等retainedFrom，并在同一事务写`compaction_completed` intent。
- compaction响应丢失后以相同坐标、摘要、retainedFrom和intent重放成功；任一差异conflict。
- fork/subtask共享祖先可成为retainedFrom，即使originSession不同。
- Workspace cleanup不更新previous/replaces/retained字段。
- Workspace cleanup固定顺序为FTS行→FTS map→client request→session_run_state→session model override→ToolExecution→MessagePart→Run→Session→Message逆拓扑→Attachment。
- `agent_tool_execution.call_part_id`启用`ON DELETE RESTRICT`时，错误地先删MessagePart必须触发FK失败；正确地先删ToolExecution后完整清理成功。
- Run trigger和Session head/root必须在Message删除前通过删除Run/Session解除。
- foreign_keys=ON下首次压缩后删除Workspace成功。
- foreign_keys=ON下连续压缩、retained跨旧摘要后删除Workspace成功。
- replacement连接相同depth Message时引用者仍先删除。
- previous/replaces/retained三类边混合时逆拓扑删除成功。
- depth/id只决定同批合法候选顺序，不作为正确性依据。
- 人工cycle导致data invariant failure且事务不部分提交。
- Workspace删除编排先写deletion intent和fence；按sessionId稳定序取得handoff locks，再按runId稳定序枚举当前active user/manual/subtask Runs。
- Workspace删除逐Run独立事务复用persist intent和完整convergence，断言不直接更新artifact；每个Run均经过cache/SSE统一后置处理，其他Workspace不受影响。
- 已terminal同结果Run幂等跳过；已有其他terminal intent先收敛原intent，不得被`cancelled/run_cancelled`覆盖。
- 任一Run persist/converge conflict或data invariant failure立即停止；后续Run、runtime drain和destructive cleanup均不得执行，deletion intent/fence保留。
- 所有Run数据库收敛成功后才按稳定Session顺序调用`cancelSessionAndWait`；drain失败不做cleanup、保留intent；重试识别已terminal Run、重新drain且不改terminal result。
- 首次删除、重试删除、startup resume均覆盖上述顺序；子任务Run不得漏掉。

## Compaction source一致快照

- 请求只接受workspaceId/sessionId/runId。
- Run ownership、active/running或受保护recovery规则校验。
- trigger和pending范围服务端派生，客户端无法覆盖。
- uiLocale固定null，one-shot内容locale-neutral。
- 单个`db.transaction()`读取坐标、Run、链、Parts、Executions、Replay、pending。
- 第二连接在事务期间推进Session时，单次response的head/revision/blocks仍对应同一快照。
- 实现只有单事务读取路径，没有第二套一致性算法。
- internal route校验token；public endpoint不泄露replay。

## Resolver与三层物化

- 生产链严格为`ResolvedContextBlock → PrimaryMaterializedBlock → Estimator → materializePromptAttachments → streamText`。
- `PrimaryMaterializedBlock`是主profile的provider-neutral、兼容replay已应用、附件展开前语义表示，fixture中的当前附件仍为`attachment_ref`。
- Estimator运行时不得调用附件存储、读取file bytes、临时URL或最终请求对象。
- `materializePromptAttachments()`只能在估算结束后、单次实际请求前执行。
- Plan、Estimator canonical和日志均不得保存附件bytes。
- 无摘要时与当前PromptContext来源等价。
- 首次：`A→B→C→S→D`输出`S→B→C→D`。
- 连续：`A→B→C→S1→D→E→S2`输出`S2→C→D→E`。
- retained无法抵达、循环、跨Workspace明确失败。
- User/System/Assistant原子块，Assistant多ToolCall+全部结果不可拆。
- 主profile空投影块成本0、不计进展、不可边界。
- current compaction计before/A，不可retain。
- Assistant首块默认非法；adapter显式支持时合法；否则向前扩User/System。
- Plan包含不含秘密的profileFingerprint及A/B来源ID，不保存candidate/primary wire message。
- fingerprint模型ID使用`providerModelId ?? model.id`。
- adapter identity来自provider.npm、实际调用路径和固定Provider API映射，不读取虚构profile.api。
- 初始流程为profile→fingerprint→source→materialize→plan。
- CAS后providerModelId改变时proactive跳过、manual/recovery `compaction_conflict`；相同才replan。

## 多Provider摘要输入

- 主模型profile为OpenAI Responses时，PrimaryMaterializedBlock保留兼容replay并用于成本。
- candidate摘要模型使用其他Provider时，SummaryInputBlock语义和A/B不变。
- SummaryInputBlock不含encryptedContent/providerOptions。
- 可见text、reasoning、tool call/result保留。
- A含replay-only Assistant且无可见内容时生成固定占位：

```text
[Prior assistant replay state omitted from summary input]
```

- candidate→primary只改变SDK转换和模型，不改变来源块、顺序和摘要语义。

## EstimatorV1 Golden

生产入口只能是：

```ts
estimatePrimaryMaterializedBlock(block: PrimaryMaterializedBlock): EstimatorEstimate
```

不提供裸`ModelMessage[]`、单条message、canonical对象或attachment bytes重载。每个fixture从真实`PrimaryMaterializedBlock`开始，同时断言其`messages`映射后的`EstimatorCanonicalMessage[]`、数组根canonical string、UTF-8 byte length、textTokens、fixedCosts分项和最终estimate。禁止直接把预制canonical对象作为唯一输入。

必须覆盖：

- system、user string、user text parts、attachment_ref；
- assistant string/text、reasoning、tool-call、empty assistant；
- tool message与`toolCallId/toolName/output.type/output.value`真实tool-result；
- OpenAI Responses text、reasoning、function_call三种replay part；
- reasoning密文占位与不同密文长度；
- 嵌套ToolCall input、多个attachment。

额外断言：

- 唯一canonical JSON根是整个`EstimatorCanonicalMessage[]`，所有golden均以`[`开始、以`]`结束；禁止逐message stringify后拼接；
- 一个来源Block映射为assistant+tool两条消息时，golden精确计入外层方括号与中间逗号；
- 该多消息Block固定断言`UTF-8 bytes=248`、`textTokens=83`、`fixedCosts=40`、`estimate=136`；
- 一个Block只对整个数组执行一次`ceil(bytes/3)`和一次最终`ceil(...*1.10)`，不得分别估算assistant/tool后相加；
- 两个Block的历史总成本等于两个`estimatePrimaryMaterializedBlock(block)`结果之和，不得合并多个Block后重新canonicalize或统一ceil；
- `attachment_ref`进入canonical时只保留白名单元数据，附件bytes不得出现；
- 对象key插入顺序不同canonical相同；
- 数组顺序保留；
- 字符串保持原Unicode，不做locale归一；
- `undefined/NaN/Infinity`明确失败；
- attachment filename始终`<filename>`、mediaType保留；
- message-level providerOptions、未知Provider options、OpenAI非白名单字段增删不改变canonical或cost；
- replay只从真实assistant text/reasoning/tool-call part提取；
- 当前真实part不含summaryIndex时不得从持久化envelope补造；
- 真实reasoning密文不进入canonical，只按`64+ceil(UTF8 bytes/4)`另计；
- `textTokens=ceil(UTF8ByteLength(canonical)/3)`；
- `estimate=ceil((textTokens+fixedCosts)*1.10)`；
- 同profileFingerprint/version/context结果完全一致。

## 20k、媒体与起点

- 恰好20000包含，20001停止。
- Assistant起点两种adapter能力均测试。
- 向前扩后超过20k标准blocked。
- trigger媒体块强制留B。
- trigger块自身或强制后缀超过20k：proactive跳过、manual媒体code、recovery媒体code。
- full检测trigger媒体直接失败，不生成继续推理请求。
- 不存在媒体移除synthetic prompt。
- 旧摘要大且新原文全可保留：proactive/manual no_prefix；无媒体的真实context-limit可full。

## 摘要分区与调用上限

- `finalLeafCount<=8`。
- `attemptedPartitionCount<=15`，失败内部节点也计数。
- `logicalProviderCallCount<=30`。
- 深度优先、先左后右、按块数量中点拆分确定性。
- 每partition candidate一次；candidate context-limit时同partition primary一次。
- 网络重试复用同logical call。
- proactive绝对网络请求不超过30。
- manual和每级recovery绝对网络请求不超过60。
- proactive计数作用域为整个attempt，manual为整个Run，recovery为每个level。
- CAS replan不清零partition/logical/network。
- standard转full才建立新level计数。
- 接近任一上限时发生CAS conflict，重规划仍不能突破上限。
- 创建第16 partition、第9叶或第31 logical call前失败。
- 单块primary仍超限返回summary_input_limit。
- Assistant/Tool永不拆；叶摘要顺序拼接；中间不落库。

## Work deadline、terminal-control与重试

使用fake clock、fake RPC和fake Provider，从调用source前开始计时。

### Proactive

- source/API事务/物化/规划/摘要/retry/CAS/收益/commit共同受15秒限制。
- 每logical call最多1次网络请求。
- deadline到达后不启动新RPC/call/退避，继续主模型。
- 永久控制面/安全错误向外失败。

### Manual

- 全流程120秒。
- 每logical call首次+1次瞬时重试，退避1秒且可取消。
- CAS重规划不重置120秒。
- deadline或重试耗尽写`compaction_provider_unavailable`。
- Provider恰好耗尽120秒work deadline时，仍启动独立terminal-control，不把intent/convergence塞进已耗尽work预算。

### Recovery

- standard从source前开始45秒；级内CAS重规划不重置。
- 只有转full时启动新的full 45秒。
- 每logical call首次+1次瞬时重试。
- transient耗尽不进full。

### Terminal-control

- 无持久业务产物的结果必须先`persistTerminalIntent`，成功后才能`convergeRunTerminal`。
- 两阶段共享同一个独立10秒绝对deadline，不计入work deadline。
- intent最多3个真实HTTP请求；intent成功后convergence使用剩余时间，最多3个真实HTTP请求。
- 最多是每阶段3次、合计6次，而不是两阶段合计3次；任何路径都不得超过10秒。
- 两个API Client policy均为`maxRetries:0`；只有Runner/专用terminal loop可重试。
- 每次RPC timeout裁剪为`min(配置timeout, terminal-control剩余时间)`；阶段内重试前固定退避250ms且退避也受剩余时间约束。
- fake transport必须按真实HTTP请求计数，覆盖intent第3次成功后convergence只使用剩余额度，以及intent成功、convergence第3次成功。
- intent相同重放与convergence相同重放最终只产生一个实际终态。
- 原子terminal Assistant和原子commitCompaction是work transaction，成功后不调用intent；首次convergence前新建10秒deadline、最多3个真实请求，响应丢失时按各自work RPC幂等重试。
- intent完全未写入而Worker崩溃时phase仍为`work_in_progress`；startup按安全恢复继续同一Run，无法安全恢复时写`run_startup_recovery_failed` intent再converge，禁止猜测原业务结果。
- terminal Assistant或compaction的原子产物+intent已提交后Worker崩溃，断言phase为`terminal_intent_persisted`，startup只converge，不prepare、不enqueue、不重跑模型、工具、摘要或commit。
- 工具已完成、正等待下一模型步骤的`work_in_progress`在startup继续同一Run；不得从最终Assistant、ToolExecution、CompactionMessage或其他artifact推导terminal intent。
- 有ToolCall的Assistant只能普通完成并继续；无ToolCall的可见文本终态使用原子terminal入口。
- 空响应阈值测试固定覆盖前N-1次普通完成且intent为空、第N次提交前根据本地计数选择原子terminal入口并写intent。
- manual committed使用原子commitCompaction；manual no-op、blocked和failure使用独立intent；至少覆盖`compaction_not_needed`的intent与收敛测试。
- convergence连续失败不会改写为其他terminal code；重启后继续收敛原intent。
- streaming Assistant 的failed与cancelled收敛分别测试；queued/running ToolExecution的cancelled/unknown收敛分别测试。
- startup replacement与enqueue失败均经persistIntent→同一convergence，并断言本Run artifact收敛、其他Run不变。
- completed intent遇任一非终态Message或queued/running ToolExecution必须data invariant failure且Session不idle。
- proactive内部skip不产生独立结果；manual/user/subtask均必须终态。

## CAS与profile变化

- proactive conflict不重规划。
- manual最多重规划1次，第二次`compaction_conflict`。
- recovery事件CAS总计1次。
- 重规划重新source/物化/摘要，不复用旧正文，且deadline不重置。
- CAS后先重新getExecutionProfile；fingerprint相同才source/replan。
- fingerprint变化不复用Plan；proactive跳过、manual/recovery均`compaction_conflict`。
- `providerModelId`从缺省变为显式或值改变时fingerprint变化测试。

## Per-Run terminal result与前端

- Worker终态Assistant/成功compaction原子写产物+intent；无产物Worker结果、API取消、enqueue永久失败、startup recovery均独立写intent，再通过同一convergence事务收敛artifact、revision、status+code与idle。
- 完整registry逐行做合法组合测试；Worker/API允许子集测试。
- 已终态相同结果幂等，不同结果拒绝。
- 空Session `/compact` HTTP 400且不创建Run。
- pending tools写`failed/compaction_pending_tools`。
- `/compact`返回顶层runId；clientRequestId重放返回同一runId。
- `GET /api/agent/sessions/:sessionId/runs/:runId?workspaceId=...`校验workspace/session ownership。
- `work_pending/work_in_progress/terminal_intent_persisted`公共响应均为running且code/detail为null；只有phase terminal返回稳定code，intended三元组永不泄露。
- manual、user、subtask全部码表与Run status映射准确。
- 普通send与multipart send捕获顶层runId，不再忽略响应。
- manual/user使用同一pending-run registry和轮询实现。
- sessionStorage key固定为`agent-workbench.agent.pending-run.v1/<workspaceId>/<sessionId>/<runKind>/<runId>`。
- `PendingRunStorageRecordV1`固定包含`schemaVersion:1`、workspaceId、sessionId、runId、runKind、createdAt；key与record必须一致。
- JSON损坏、schemaVersion错误、字段缺失或key/record不一致时直接删除，不显示提示。
- `restorePendingRuns({workspaceId, sessionId})`只轮询当前workspace/session；其他workspace/session合法记录保留且不轮询。
- 当前workspace/session确认删除时清理对应全部key。
- 404、ownership mismatch、response runKind mismatch显示一次固定通用提示后删除，不能无限重试。
- network、timeout、429、5xx保留记录并复用现有轮询退避。
- terminal展示或静默消费后删除；user `completed/run_completed`静默删除。
- 构造4条以上记录，断言按createdAt、再runId FIFO，最多并发3条，批次完成后继续。
- user `run_completed`不弹提示；failed/cancelled按code展示。
- 媒体重发、recovery exhausted、conflict显示可行动i18n。
- 终态每标签页展示至多一次并清除。
- 两个标签页可各自展示一次，不做跨标签页协调。
- timeline、snapshot和实时事件响应结构保持现状，terminal result仅从Run状态接口读取。
- code优先i18n；detail默认null，若非null只能是registry枚举键，且不含Provider原始错误或敏感上下文。

## Recovery状态机

- standard提交→重读→完整步骤成功。
- standard提交后仍context-limit→无媒体时full。
- standard no_prefix/no_progress/oversized/正常无可提交结果→无媒体时full。
- summary_input_limit立即失败，不进full。
- 媒体失败不进full。
- auth/permission/invalid/control/data invariant/cancelled不进full。
- transient耗尽不进full。
- full no_progress/input limit/仍超限写recovery_exhausted。
- 流建立、首chunk、部分文本后超限仍同一事件。

## 产品边界与日志

- timeline仍从root开始，tail不重新显示。
- archive可查tail；PromptContext可使用tail。
- move/fork不越root。
- terminal result不是Message。
- 日志无用户/摘要文本、工具内容、文件、密文、key/baseURL或凭证。
- 结构化日志含deadline、fingerprint、三种计数、成本、重试、CAS和媒体标记。

## 验收否决项

- Estimator生产入口不是`estimatePrimaryMaterializedBlock(block)`，直接接收裸ModelMessage/canonical/file bytes，或附件在估算前展开。
- Estimator直接canonicalize AI SDK ModelMessage、未知providerOptions影响成本、golden不是数组根、逐message估算，或跨Block合并后统一ceil。
- deadline未从source前启动或CAS重规划重置deadline。
- terminal-control不是intent→convergence、不是每阶段最多3次且共享10秒，API Client仍内部重试，或startup依赖artifact猜测终态。
- 成功终态Assistant或成功compaction未在同一事务写intent，存在产物提交但phase仍work_in_progress窗口。
- terminal Assistant携带ToolCall/ToolExecution，或空响应未在第N次提交前以本地阈值选择普通/原子terminal入口。
- 已移除的旧Run完成控制面或旧控制面结算失败码残留。
- `terminal_intent_persisted`泄露intended code、被重新enqueue，或工具完成后等待下一模型步骤的`work_in_progress`未继续同一Run。
- terminal result未归属agent_run或被混入会话运行态。
- terminal registry不完整、unknown可写、DB基本check不是强制。
- source存在第二套一致性算法或locale不是固定null。
- summary_input_limit进入full。
- full检测到trigger媒体后仍发起后续模型推理。
- 超过8叶/15partition/30logical call或网络绝对上限仍继续。
- CAS replan清零计数或standard/full错误共享/重置计数。
- Plan冻结跨Provider wire message或SummaryInput携带encrypted replay。
- Workspace cleanup顺序不是FTS行→FTS map→client request→session_run_state→session model override→ToolExecution→MessagePart→Run→Session→Message逆拓扑→Attachment，或ToolExecution晚于MessagePart。
- Workspace cleanup清空图字段或以depth排序代替逆拓扑正确性。
- pending-run未版本化、跨workspace/session误轮询、永久stale不删除、瞬时错误删除记录、并发超过3，或manual/user维护两套机制。
- fingerprint使用虚构api字段、忽略providerModelId或变化后返回旧码。
- converge仅收敛Run/session而未同事务收敛本Run origin artifact、artifact revision/timestamp和Session revision。
- completed intent存在非终态Message或queued/running ToolExecution仍把Session置idle，或failed/cancelled错误处理queued/running ToolExecution。
- queued/running ToolExecution经convergence转态时未同事务写`completedAt=updatedAt`，改写startedAt/result/error，或幂等重放刷新completedAt。
- terminal persistence不返回transitioned/already_converged与finalStatus，任何来源绕过统一cache/SSE后置处理，或already_converged重复发布完成事件。
- Workspace删除仍以旧批量SQL直接收敛artifact，未覆盖subtask/稳定锁与排序，在所有Run DB收敛前drain，或在drain失败/Run不变量失败后继续cleanup。
- fork/subtask、Assistant首块、CAS上限、旧摘要no_prefix等既有决策回退。

# 业务语义、术语与关键决策

## 术语

| 术语 | 定义 |
|---|---|
| 物理消息链 | 由 `previousMessageId` 连接的不可变 Message 祖先链 |
| context root | `agent_session.context_root_message_id`，模型解析坐标和用户结构操作边界；不是时间线可见性边界 |
| 当前摘要 S | 当前 context root 指向的 `CompactionMessage` |
| 摘要前缀 A | 本次由摘要模型压缩的有效来源前缀 |
| 保留尾部 B | 以原文继续发送给主模型的最近安全原子块 |
| ResolvedContextBlock | API resolver 输出的来源块，含 Message/Parts/Executions/replay |
| PrimaryMaterializedBlock | 按本 Run 主 ExecutionProfile 物化，用于20k、retained和成本 |
| SummaryInputBlock | 从冻结 A 来源生成的 provider-neutral 摘要语义块 |
| RetainableOriginalBlock | 对非空 PrimaryMaterializedBlock 的可保留原文筛选视图 |
| CompactionPlan | 固定快照、来源ID、A/B、profileFingerprint和成本的不可变计划 |
| attempted partition | 一次实际尝试摘要的连续 SummaryInputBlock 分区；内部节点也计数 |
| logical Provider call | 某 partition 对 candidate 或 primary 的一次逻辑调用；网络重试不新增 logical call |
| 完整模型步骤 | 一次主模型步骤从发起到正常完成、工具调用返回或终态错误 |

## 产品语义

### 模型顺序

```text
运行时静态 system
→ 当前摘要 S
→ retained tail B
→ S 提交后新增消息
```

静态 system 不属于 A/B。

### 用户时间线、归档和操作边界

- timeline 显示当前 head 沿 `previousMessageId` 可达的完整当前分支，按旧到新排列，包含压缩前原文、旧 compaction、当前 compaction 和后续消息；
- timeline 是展示投影，不按 ModelContext Resolver 的 S+B 顺序重排，也不因为 retained tail 被模型引用而复制消息；
- context root 之前的 timeline 消息只读；retained tail 虽可能进入模型私有上下文，仍不得获得 revert/fork 等结构操作权限；
- archive 仍是 context root 之前物理历史的搜索/读取投影，因此允许与 timeline 展示集合重叠并包含 tail；
- revert/fork 仍不得越过 context root；
- 模型上下文顺序与产品时间线顺序是不同投影。

若 Timeline DTO 需要返回边界标记，其语义必须是“是否位于 `contextRoot..head` 的当前操作区间”，不得命名或解释为模型可见性。建议字段为 `inCurrentOperationRange`；root 之前的 retained tail 该值为 `false`，但仍可能出现在模型上下文中。

## 安全原子块

- completed User：单条 Message 一块，包含文本和附件 Parts；
- completed System：单条 Message 一块；
- completed Assistant：Message、全部 ToolCall 和对应终态 ToolExecution 结果共同一块；
- replay-only Assistant 仍是一块；
- runtime、旧 compaction、非 completed、含 queued/running execution 的 Assistant 不作为可保留块。

Assistant 能否成为 B 首块由主 Provider adapter 显式声明 `assistant-after-system` 能力；默认不允许。不合法时向前扩到最近合法 User/System，扩展后超过20k则标准窗口不可用，不注入虚构承接消息。

主 profile 投影为空的物理块不计预算、不算有效进展、不能成为 retainedFrom，但可存在于物理闭区间。

## 关键决策

### 固定20k与EstimatorV1

固定20,000便于解释、复现和测试。生产入口只有`estimatePrimaryMaterializedBlock(block)`。PrimaryMaterializedBlock是兼容replay已应用、附件仍为`attachment_ref`的provider-neutral请求语义，不是最终file bytes消息。

每个Block把完整`EstimatorCanonicalMessage[]`作为一个数组根，方括号和逗号计入UTF-8成本；每Block只做一次文本ceil和1.10安全系数ceil，总历史成本为各Block estimate求和。

不持久化逐消息 token，因为目标模型、工具、附件和 replay 投影变化会使旧值失效。

### 三层物化，不冻结跨Provider wire message

Plan 冻结 `ResolvedContextBlock` 来源 ID、A/B 和主 profile fingerprint。

- `PrimaryMaterializedBlock` 在附件展开前决定20k、retained和压缩前后成本；实际请求随后才`materializePromptAttachments→streamText`；
- `SummaryInputBlock` 仅保留可见 text/reasoning/tool语义，不携带 encrypted replay/providerOptions；
- replay-only且无可见内容时生成固定安全占位；
- candidate 与 primary 摘要模型使用相同 provider-neutral 语义，切换模型不改变 A/B。

### 只保存retainedFrom

B 终点天然是 compaction 的 `previousMessageId`。不增加 `retainedToMessageId`，避免双重权威。

### retainedFrom属于CompactionMessage

该字段描述压缩消息的上下文重建规则，只对 compaction 有意义。数据库可同表存 nullable 列，但业务契约必须严格判别。

### 不复制tail、不移动context root

引用不可变原消息，避免复制 Parts/Executions/replay。context root 仍指向当前摘要，用于限定模型解析坐标和结构操作权限；timeline 独立展示完整当前分支，不以 context root 截断。

### 旧摘要不递归

retained 物理区间穿过旧摘要时跳过旧 compaction，不读取其 retainedFrom，也不再次发送旧摘要。

### Source快照唯一方案

API 在单个 `better-sqlite3 db.transaction()` deferred只读事务读取 Session坐标、Run、链、Parts、Executions、Replay和pending。禁止前后校验替代。

source请求只含workspace/session/run。trigger和pending范围服务端派生。locale本次固定为null/locale-neutral，未来locale authority另案设计。

### Deadline从source之前启动

work deadline 为 proactive 15秒、manual 120秒、recovery standard/full各45秒，覆盖source到commit尝试。级别内重规划不重置；standard转full才启动新的full 45秒。

无持久业务产物的结果使用独立 intent/convergence：两者共享独立10秒terminal-control预算，intent最多3个真实HTTP请求；成功后convergence使用剩余时间，最多3个；两阶段合计最多6个但总时长仍不超过10秒，退避固定250ms，两个API Client policy均`maxRetries:0`。

有持久成功产物时，事务内同步写 intent：无 ToolCall 的 user/subtask 终态 Assistant 同一事务完成 Assistant、response tokens 和 intent；manual `commitCompaction` 同一事务插入CompactionMessage/TextPart、更新Session root/head和`compaction_completed` intent。原子成功后只调用convergence；不允许产物已提交而phase仍为work_in_progress。

Run持久phase固定为work_pending→work_in_progress→terminal_intent_persisted→terminal。startup只按phase决策，不从Assistant、ToolExecution或CompactionMessage推断终态；intent存在时只converge。

converge是唯一终态artifact收敛权威：只读intended并在同一事务处理本Run origin范围。completed要求没有streaming/nonterminal Message和queued/running ToolExecution；failed/cancelled分别将streaming Assistant置failed/cancelled、queued ToolExecution置cancelled、running置unknown，同时更新artifact revision/timestamp、Session revision、Run与run state。queued/running变更时`completedAt`固定为本次convergence的`updatedAt`、保留`startedAt`、不填写或改变result/error。其他Run绝不受影响。

持久化convergence返回`{ kind: "transitioned" | "already_converged"; finalStatus }`。应用层将所有成功结果交给唯一后置函数：无论首次转态还是一致重放都清除`runPromptStaticCache.clear(runId)`；仅`transitioned`发布现有`agent.run.completed.v1`，范围保持为所有Run首次实际进入terminal，不增加事件类型。事件发布为best-effort：数据库事务已提交后发布失败只记录错误，不回滚、不补偿；一致重放不补发，避免重复。本次明确接受该内存SSE可能永久漏送的风险，不引入outbox。

Workspace删除不是独立的Run artifact收敛通道。唯一编排函数为`convergeWorkspaceRunsForDeletion`：持久deletion intent→设置Workspace deleting fence→按`sessionId`稳定序取得相关Session handoff locks→查询本Workspace全部当前active user/manual/subtask Runs→按`runId`稳定序逐Run在API本地复用persist intent与完整convergence，并逐Run经过同一应用层后置处理→全部数据库收敛成功后逐Session `runtime.cancelSessionAndWait/drain`→全部drain成功后执行destructive cleanup。每Run独立事务，绝不让SQLite事务跨越runtime网络等待。

删除编排遇到已terminal且收敛一致的Run幂等跳过；若Run已有其他terminal intent，先收敛原intent，成为terminal后再继续，不得覆盖为`run_cancelled`。任一Run的persist/converge冲突或data invariant failure立即停止，保留deletion intent，不得drain或删除数据；数据库收敛完成但drain失败同样保留intent，下次重试识别已terminal Run并再次drain，不改写terminal结果。其他Workspace绝不受影响。

### 分区与调用上限

固定：

```text
finalLeafCount <= 8
attemptedPartitionCount <= 15
logicalProviderCallCount <= 30
```

每partition最多candidate+primary；网络重试属于同一logical call。proactive网络请求绝对上限30；manual和每级recovery绝对上限60，且都受deadline约束。

计数作用域固定为 proactive整个attempt、manual整个Run、recovery每个level。CAS replan不清零partition/logical/network；只有standard转full才建立新的level计数。

### Run terminal result属于Run

不复用瞬态 `runNoticeText`，也不在 `session_run_state` 保存最近结果。`agent_run` 保存稳定 terminal result code；全局代码 registry 是 runKind/status/code 合法组合的业务权威，unknown code 拒绝，detail 默认null且仅允许登记的枚举诊断键。

新增按session/run查询的公共只读接口。manual `/compact` 与普通 user send 返回的runId使用同一个当前标签页pending-run registry；key包含workspace/session/runKind/runId，刷新后继续查询。普通成功静默清理，失败/取消按code显示一次；不做跨标签页协调。

记录schemaVersion固定为1；`restorePendingRuns()`只轮询当前workspace/session，网络错误保留，404/ownership/runKind mismatch提示一次后删除，workspace/session删除时清理，并发上限3且按FIFO分批。

### Fingerprint与CAS顺序

初始固定为`getExecutionProfile→fingerprint→getCompactionSource→materialize→plan`。模型ID使用`providerModelId ?? model.id`；adapter identity由provider.npm、实际调用路径和固定Provider API映射构造，不编造ExecutionProfile.api。CAS后重新取profile；fingerprint不同则proactive跳过、manual/recovery写`compaction_conflict`，相同才可source/replan。

### Recovery只对业务无进展进入full

standard以下结果可进入full：

- no_prefix；
- no_progress；
- blocked_oversized_tail；
- 标准方案无可提交结果但摘要能力正常；
- standard提交后完整主模型步骤仍context-limit。

`summary_input_limit` 立即失败，不进full，因为full输入只会更大。auth/permission/invalid/control/data invariant/cancel/transient耗尽都不进full。

### 当前trigger媒体不可移除

带图片/附件的trigger User块必须留B。块或强制后缀超过20k：proactive跳过、manual返回`compaction_media_requires_resend`、recovery返回`context_limit_media_requires_resend`。full也直接失败，不注入媒体移除提示后继续推理。

### Workspace清理遵守不可变边界

保留 retained self FK `ON DELETE RESTRICT`。目标schema清理顺序固定为FTS行→FTS map→client request→session_run_state→session model override→ToolExecution→MessagePart→Run→Session→Message逆拓扑→Attachment。ToolExecution必须先于MessagePart，Run/Session必须先于Message。三类图字段不可清空。

物理清理仅能发生在上述Workspace删除编排的所有Run数据库收敛和runtime drain均成功之后；deletion intent和fence覆盖整个等待与重试窗口，阻止新的Run进入。

## 不变量与决策表

| 条件 | 唯一结论 |
|---|---|
| B非空 | retainedFrom等于B第一来源Message ID |
| B为空 | retainedFrom=null |
| 所有新原文都可进入B | proactive/manual no_prefix |
| A只有旧摘要 | proactive/manual no_prefix |
| estimatedAfter>=before | proactive/manual不提交 |
| trigger媒体强制后缀>20k | proactive跳过；manual/recovery媒体失败 |
| standard业务无进展 | 无trigger媒体时进入full |
| summary_input_limit | 立即失败，不进full |
| 第16 partition/第9叶/第31 logical call | 创建前失败 |
| CAS conflict | Plan与摘要作废；按模式有限重规划且deadline不重置 |
| fingerprint变化 | proactive跳过；manual/recovery `compaction_conflict` |
| 用户取消 | cancelled；不提交、不降级 |

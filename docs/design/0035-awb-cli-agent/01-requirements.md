# 需求与业务边界

## 背景

外部 Agent 能执行命令，但现有 `awb` 仅提供登录及会话摘要查询。用户希望外部 Agent 在不打开 AWB 网页、不读取数据库、不取得 Worker 内部身份的情况下，调用已配置的 AWB Agent，继续已有上下文，知道任务是否仍在运行，读取消息并取回工作区产物。

本方案是薄客户端扩展，不将 AWB 改造成多租户工具平台。优先复用现有公开 API，用明确的 CLI 契约解决自动化调用问题，不为理论上的完全一致性新增数据库、后台服务或事件系统。

## 角色与对象

| 对象 | 业务含义与边界 |
|---|---|
| 调用者 | 外部 Agent 或人类，通过同一 CLI 操作；不得要求人类为每次业务调用做交互确认 |
| Workspace | 用户已有的远端工作区；所有资源命令显式指定，不猜当前本地目录对应哪个工作区 |
| Agent | 已配置的可调用 Agent；选择 Agent 不是修改其配置 |
| 主 session | 可接收用户消息、手动压缩和取消操作的会话；Fork 出来的主会话仍属于主 session |
| 子 session | AWB 内部子任务使用的会话；本次只允许已知 ID 的详情、消息和状态读取，不提供列表、创建、继续、单独取消 |
| Run | 一次发送或手动压缩的执行标识；保留为内部跟随锚点及发送输出，不提供独立查询命令 |
| 消息 | 当前可见分支上的消息；与工具执行事件、完整事件日志、文件系统快照不同 |
| 产物 | 工作区内的文件或目录；不是 AWB 任意内部存储路径，也不等同于所有工具 artifact |

## 需求

### R-DISCOVER：发现调用对象

- 列出已有工作区，展示 ID 与名称；不展示仓库 URL、凭证标识或远端绝对路径。
- 列出指定工作区 `user` 表面可用 Agent，展示 ID、名称、用途摘要，保留配置顺序。
- 未指定 Agent 时，选择当前列表第一个；继续已有 session 也如此，不沿用上次 Agent。
- “可用”仅指 scope 与工作区启用过滤通过，不保证模型、凭证或 Worker 已验证可运行。首个 Agent 配置错误时直接失败，不静默尝试后续 Agent。

### R-SESSIONS：主会话查询与已知会话详情

- 只列主 session；最近更新时间窗口必填，正整数 `s/m/h/d`，最多 90 天；状态支持 `idle/running/all`。
- 不增加全历史列表、父会话/直接子会话列表、递归任务树或后端分页需求。
- 保持摘要语义：窗口按更新时间；计数是该 session 原生累计已完成消息，不是窗口内增量，也不含 Fork 继承消息。
- 已知会话详情可读取主/子 session，不受上述列表窗口限制。
- 已裁决：列表默认 primary，保留弃用的 `--kind primary`；`--kind subtask/all` 本地退出 2、不联网并提示迁移，不忽略参数、不增加 legacy 能力、不改 API。此为有意收缩 CLI 行为，见[兼容性裁决](06-decisions-and-references.md#cli兼容性裁决)。

### R-SEND：发送与自动建会话

- 工作区必填，会话与 Agent 选填；不指定会话时创建主会话后发送。
- 接受提示词或图片，至少一个有效输入；支持纯文本、纯图片、混合，不隐式读取 stdin。
- 仅对主 session 发送；运行中冲突，不排队。
- 默认返回受理信息后退出，不等完整执行；`-f` 跟随本次 Run。
- 调用前完成可在本地发现的输入错误及无可用 Agent 检查，减少无用空会话。

### R-CREATE-FAILURE：接受不确定性，不自动重试副作用

- 创建请求失败或超时即调用失败，不重试、不继续发送；创建响应丢失时接受遗留空 session。
- 已创建成功、发送失败时，不重建；失败中保留经响应确认的 sessionID。
- 模型自行决定重试策略。CLI 不承诺自动建会话整链幂等、事务性或 exactly-once。
- 所有有副作用请求均不得自动重试，包括登录、创建、发送、取消、压缩。
- 既有发送/压缩请求 ID 由 CLI 每次调用生成，保留后端已有去重机制；不因此新增创建幂等 API，也不把网络失败说成“服务端没有执行”。

### R-MESSAGES：读取普通消息

- 主/子会话均支持，必须在 `--after` 与 `-n` 中恰选一个，按链顺序正序返回。
- 只输出[消息计数与投影](02-cli-contract.md#消息计数与投影)定义的普通消息；工具执行、系统、压缩及 runtime 消息不混入数量。
- `--after` 不包含锚点自身；锚点可为当前分支任意消息类型，不限于普通消息。
- `-n 1` 是最近一条普通消息，不保证是最近 Run 的成功回答；不足 N 条返回实际数量，空集合成功。
- 不因正文很长而静默截断；如果传输、调用工具或采集器截断，必须能从输出完整性标记/终态判断，不能把前缀当完整答案。

### R-FOLLOW：一次执行的有限跟随

- 发送跟随本次启动 Run；消息命令先捕获查询时 Run，再输出指定历史并跟随该 Run；压缩跟随本次压缩。
- 捕获无活动 Run 时，先对初始历史和可证明的来源 Run 做有界收尾；扩展追加的可信来源只取初始head本身，不跨过来源未知的较新user向前找旧Run。有来源时刷新最终内容、补齐同Run最终追加并重选；来源未知但历史范围稳定终结时正常成功，包括user-only/纯继承/空session。初始化期间出现无法证明归属关系的追加则 observation_failed、complete=false、退出 6，不丢掉新回答后输出旧user假成功，也不等待未来 Run。
- 固定目标，不因活动 Run 变化而切换；终态后补读最终消息再退出。
- `-f` 是消息级更新，不是逐 token 事件承诺；JSONL upsert 和人类终结正文规则见契约。
- 断线、等待超时、SIGINT 只停止 CLI，不发取消请求。终态失败/取消与监听失败必须使用不同的输出/退出语义。
- 正常追加、自动压缩/手动压缩可恢复最终消息；并发回退或替换导致目标离开当前可见分支时显式失败，不承诺旧分支或每个瞬时文本永久可恢复。

### R-STATUS：仅查询忙闲

- 主/子 session 均可查，只展示 `idle/running`，成功读取状态即退出成功。
- 不显示或要求最近 Run、终态原因、最后回答；`idle` 不表示最近一次成功。
- 不修改现有状态 API；内部跟随仍可读取其 activeRunId。

### R-CANCEL：主会话级联取消

- CLI 预查详情，拒绝子 session；不收紧原 API 对子会话的支持。
- 取消服务端处理时主 session 的当前执行及其活动后代，包含深层子任务。
- 不新增 expectedRunId；查询与取消之间可能切换 Run，不能承诺取消的是调用者此前看到的旧 Run。
- 不回滚文件、不删除历史，不将取消等同于外部进程副作用全部逆转。

### R-COMPACT：手动压缩上下文

- 工作区与主 session 必填，仅空闲时启动，冲突不排队。
- 默认受理后返回，支持 `-f`；无必要压缩时清晰表达跳过/未改变及原因。
- 保持后端实际语义：空会话报 `AGENT_COMPACTION_EMPTY`；多数无需压缩结果在 Run 终态体现，不要求即时化；去重不等于“本次无需压缩”。
- 原消息历史仍可读，工作区文件不因压缩而修改。

### R-DOWNLOAD：取回工作区资源

- 工作区、远端相对路径、本地输出文件路径均显式必填；目录复用现有自动 ZIP。
- CLI 做词法过滤，不接收任意远端绝对路径，不以 Content-Disposition 决定本地写入位置。
- 本地默认无覆盖，失败不发布半成品、不删除既有用户文件，仅清理本次拥有的临时文件。
- 不改变 API 既有规则：目录源文件累计 100 MiB、遇 `.git`/扫描软链整体失败、空目录不保留。
- 不为 CLI 收紧原 API，也不绕过既有校验；服务端 realpath/软链/竞态风险单独记录，不能宣称 CLI 过滤能够修复。

### R-HELP：简短统一与渐进帮助

- 资源加动作的短命令树，高频对象使用统一短别名；不混用 `--session` 和 `--session-id`。
- 所有层级支持 `--help/-h`；顶层概览、分组动作、具体命令参数/默认值/互斥/例子。
- 帮助本地完成，不读配置、不联网、不读业务输入、不执行业务校验和副作用；裸分组显示帮助。
- 错误输出本地编写的简短原因与对应帮助入口，不回显原始错误参数值。

### R-MACHINE 与 R-SECURITY：自动化与安全基础

- 支持人类文本与 `--json`；跟随时 JSONL，业务 stdout 与诊断 stderr 分离。
- 保留现有登录、安全 token 输入、Cookie 缓存、同源限制、手动重定向及续签保存约定。
- 不读取数据库、Worker 注入凭证、内部 token，不访问内部 Agent SSE，不读取 Agent 的 Provider 密钥。
- 不将提示词、图片、Cookie、响应错误正文、原始异常、远端绝对路径写入诊断；明确业务正文是调用者主动请求的输出，不能把安全日志约束误用成截断 Agent 回答。
- 人类输出中的用户可控元信息必须转义显示；消息正文保留正常换行但不得输出可执行 ANSI/终端控制序列。JSON/JSONL 解析后的正文保持原文，不套用人类显示转义。
- 输出失败必须携带阶段及“未发送/确认拒绝/已受理/结果未知”信息，便于模型正确行动。

## 明确不做

- 配置读写平台、模型覆盖、Agent 提示词/权限/MCP 修改。
- 子任务主动创建/继续、分叉、回退、审批、定时任务、通用工具直调。
- 独立 Run 查询命令、最近执行投影 API、完整会话枚举、直接子会话查询。
- 自动创建幂等 API、隐藏重试/排队、自动切 Agent、跨进程请求恢复数据库。
- 新事件服务、不可变消息日志、逐 token 历史、服务端下载安全改造或独立产物资源服务。

## 完成含义

- 已受理不等于执行成功；忙闲不是终态；最近消息不是可靠结果；CLI 中断不等于后台取消。
- 开发验收必须覆盖正常路径和未知结果路径；只证明 happy path 能跑通不能通过本方案验收。

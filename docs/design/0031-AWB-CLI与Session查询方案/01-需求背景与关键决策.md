# 需求背景与关键决策

[返回导航](00-文档导航.md)

## 背景与目标

AWB 已有 Agent Session、子任务和定时任务。用户希望通过独立 CLI 逐步获得系统查询和管理能力，再自行将这些能力组合为自动化流程。

首个交付能力是通用 Session 查询。每日总结只是讨论中的组合示例，不是需求中的业务类型、默认工作流或验收案例。API 不判断会话是否值得总结，也不排除任何特殊名称的会话。

### 产品目标

- 人和模型使用同一个 `awb` 入口，按需通过分层帮助发现功能。
- CLI 在 AWB 内置终端和 Worker bash 中可执行，也可供本地用户独立使用。
- 登录后使用用户级缓存，跨 Workspace 复用，不需要 Worker 代签或注入凭证。
- 常规 API 活动在阈值内保活，减少定期人工重新登录；长时间停用后仍自然过期。
- 查询任意显式指定 Workspace 中最近更新的主/子 Session，返回完整匹配结果和累计消息指标。
- 方案简单、确定、可验证，不以多租户或互联网服务标准增加基础设施。

## 用户已确定的关键决策

| 决策 | 内容 | 取舍原因 |
|---|---|---|
| CLI 优先 | 不增加模型专用查询工具 | 功能增多时依靠分层 `--help` 渐进披露，不常驻大量工具定义 |
| Node.js | CLI 使用 Node.js 技术栈 | 与现有 TypeScript/Node.js 项目相容 |
| 独立登录 | `awb login` 获取并缓存 Cookie | 人、脚本和 Agent 使用同一入口，不与 Worker 认证生命周期耦合 |
| 用户目录缓存 | 配置保存在用户级目录 | 内置终端与 Worker 默认同用户共享，无需每 Workspace 配置 |
| 不注入上下文 | 不要求注入 Session/Run/Workspace ID | Workspace 在命令中明确指定，CLI 可独立使用 |
| 复用现有认证 | 使用现有 Web Cookie 权限 | 不增加 scope、Run 绑定或受限凭证体系 |
| 阈值续签 | 普通剩余 6 小时、长会话剩余 7 天续签 | 避免 Web 轮询每次请求都生成 Cookie |
| 时间必填 | 唯一筛选是最近时间窗口，正且最多 90 天 | 保持一套时间逻辑，避免隐式默认和历史区间复杂性 |
| 全量返回 | 无分页、limit、cursor、`--all` | 单人环境下简化调用与完整性判断 |
| 统一展示 | 无 `--json`，只有可读文本 | 人和模型均能理解，减少双套输出逻辑 |
| 两个累计指标 | 用户消息数和 completed assistant 数 | 避免压缩后的 token 长度失真，保留历史工作量参考 |
| 指标不决策 | 不自动跳过短会话 | 筛选策略由调用者决定，不固化业务阈值 |

## 本方案建议固定的实施细节

以下是实现建议，不冒充用户已逐项指定的命令或字段名称；本目录其他文件统一按此基线展开。

- 包名 `@agent-workbench/cli`，目录 `packages/cli`，Node.js 22，TypeScript、commander、内置 fetch。
- 按初审裁决固定CommonJS单文件 `dist/cli.cjs`，避免依赖动态require导致的ESM产物运行失败；源码仍可使用import/export，不增加ESM适配层。
- 命令只有 `login` 与 `session list`；首版不增加 logout、profile、文件导出或管理写操作。
- `login --url` 必填，先health判断；仅认证开启时要求TTY隐藏输入或 `--token-stdin`。认证关闭时无TTY也可初始化，不读stdin；不支持token位置参数或 `--token`。
- URL 仅接受 HTTP(S) origin，不支持代理子路径、URL 用户口令、query 或 fragment；CLI 配置只保存一个 origin。
- 缓存位置固定为 `os.homedir()/.config/awb/config.json`，不引入独立 CLI 认证环境变量。
- CLI 时长支持正整数 `s/m/h/d`，无组合、小数或自然月；API 使用整数秒。
- 新增 `GET /api/agent/sessions/query`，与旧 metadata-only 列表分离。
- 时间窗口两端包含，服务端只获取一次当前时刻；排序 `updatedAt DESC, id BINARY DESC`。
- 当前状态缺失或损坏时报服务端数据错误，不静默伪造 idle。
- CLI 先处理响应续签缓存，再决定是否展示业务结果；多错误保留业务错误为主诊断。
- 缓存原子替换，不增加锁；接受并发 Cookie 覆盖带来的轻微有效期差异。

## 不在范围内

- `subtask fork` 扩展，原有定时任务功能及任何自动化业务 prompt。
- 业务用途标识、报告副本排除、短会话门槛、特殊名称过滤。
- `lastResponseTotalTokens`、Run/工具计数、期间增量、累计 token、Analytics 跨库关联、实时 tokenizer。
- 起止时间、历史区间、分页、游标、条数上限、多 profile、跨环境凭证同步。
- Worker 签发 Cookie、Run 凭证、权限范围、多用户授权、绝对会话期限、人工活跃检测。
- 文件输出功能、工具采集/归档上限改造、Worker 内部环境凭证隔离改造。

## 接受的限制

### 权限与共享

Cookie 权限与当前 Web 登录相同。显式 Workspace 是查询条件，不是授权边界。用户缓存由同一用户的各 Workspace 共用，文件权限不能隔离同用户任意命令。

### 活跃与过期

轮询仍算活跃，页面保持打开可能持续保活；阈值只减少续签次数。过期 Cookie 无法通过请求自行复活，需重新登录。不保存长期登录 token，所以长时间断用后的重新登录是预期行为。

### 计数与长度

累计计数不随压缩减少，但包含已回滚且物理保留的本会话记录。不包含 Fork 继承内容，也不等于当前模型分支长度、调用次数、任务成功数或文字长度。

### 全量与输出

90 天限制约束时间跨度，不严格约束匹配数量。API 返回全量，不静默限制条数。外层 bash 采集和 artifact 仍有硬上限，不能保证任何大小输出都完整进入模型。

## 开发前置与未决项

- 当前没有无法合理确定的阻碍性问题。
- 本方案固定了最小实现细节；若工程实施发现无法按此实现，应提交明确差异，而不是自行引入被排除机制。
- 源码仍可能由其他开发线更新，引用行号应结合符号核验；不得借本方案覆盖其他开发线变更。

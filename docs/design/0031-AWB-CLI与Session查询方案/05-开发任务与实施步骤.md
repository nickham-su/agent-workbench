# 开发任务与实施步骤

[返回导航](00-文档导航.md)｜[验收矩阵](06-验收标准与测试矩阵.md)

## 开发原则与依赖

- 仅实现本目录范围，不等待另一开发线的subtask fork，不修改定时任务或业务prompt。
- 先固定HTTP/CLI契约与边界测试，再接线；认证续签和查询服务可独立开发。
- CLI依赖已有login/health和新查询契约，Docker收尾依赖CLI构建。
- 不做数据库迁移或Agent schema升级；若实现认为必须新增字段，先解释原因并调整方案。
- 代码审查以契约、错误顺序和验收矩阵为准，不以功能“看起来能用”为唯一标准。

## 阶段：契约与测试骨架

### 任务

- 在shared新增通用Session query请求/响应schema和类型，并从公共入口导出。
- 定义严格请求字段、枚举、整数秒上限、DTO字段和错误code。
- 核验新路由`/api/agent/sessions/query`与既有`/:sessionId`路由静态路径优先级，不改变详情行为。
- 新读侧测试fixture包含Session/RunState/Message，不加载Parts、Run或Analytics。
- 保存现有tabs/continuable回归用例，特别保留“没有运行态/消息表也能读取metadata”的约束。

### 出口标准

- shared构建和类型检查通过。
- 契约中没有分页、JSON展示开关、token指标或业务用途字段。
- 请求重复/未知参数有明确测试，不能被Fastify剥离后放过。

## 阶段：主库通用查询

### 实施步骤

- 实现`session-activity-query.ts`原始URL解析和规范请求类型。
- 实现独立`SqliteSessionActivityQuery`，注入时钟便于确定性测试。
- 在只读事务中校验Workspace、捕获now一次，读取候选和状态，检查状态完整性，再做status筛选。
- 以同一窗口的候选CTE聚合原生completed消息，补零并映射DTO。
- 加数值/日期校验；固定排序和total，不加标题/head/标签过滤。
- 在composition增加窄query入口，更新service暴露、public dependencies类型和route schema。
- 新路由返回正常HTTP DTO，仍走现有普通鉴权。

### 出口标准

- 空会话、关闭主标签、未打开子标签均可匹配。
- 压缩前后、Fork继承、回滚、失败残片、跨Workspace的计数符合矩阵。
- 查询正文表/Analytics缺失不影响正常统计。
- 全量用例超过旧100条页上限仍全部返回；没有cursor或数量硬限。
- 原tabs/continuable单测与API回归通过。

## 阶段：现有Cookie阈值续签

### 实施步骤

- 抽取“验证并读取载荷”的helper，boolean验证函数保持对外兼容。
- 用已验证`exp-iat`识别24h/30d，仅标准窗口有续签策略；自定义TTL保持有效但不续签。
- 在普通auth成功路径设置请求级候选，不写全局状态，不设置新的认证协议。
- 在onSend根据候选与响应条件追加Set-Cookie，保留其他cookie，避免同名重复。
- 排除health/login/internal/WebSocket升级；验证错误响应续签规则和SSE首次头部规则。
- 属性与现有login保持一致，普通不Max-Age，long窗口完整30d。
- 复用现有auth fixture并新增阈值、兼容和hook集成测试，不读取真实认证配置。

### 出口标准

- 阈值相等/上下1ms以及过期边界都确定。
- Cookie本身可由现有验证函数验证，新普通Cookie未升为remember。
- auth关闭、内部认证及health无意外Set-Cookie。
- 前端无需刷新接口；既有401重登录路径仍工作。

## 阶段：CLI骨架、连接与登录

### 实施步骤

- 创建packages/cli workspace，显式声明commander直接依赖，以及TypeScript/tsx/esbuild/Node22类型所需清单并更新lockfile；不得依赖transitive包偶然存在。
- 固定esbuild `format=cjs/platform=node/target=node22/bundle=true`，产物 `dist/cli.cjs`，bin指向同名文件，源码可保留模块语法。
- 搭建bin入口、分层帮助、version、退出码、重复选项检测。
- config模块以home解析路径，校验一个origin及Cookie结构；测试路径通过模块依赖注入而非生产认证环境变量。
- 实现同目录临时文件原子替换及权限，失败清理不输出秘密。
- HTTP模块实现30秒完整请求超时、manual redirect、固定host-only无Domain且Path=/的单Cookie规则；Max-Age/Expires按鉴权文档处理，不实现通用jar。
- login先health；auth关闭即使无TTY也保存地址且不消费stdin。仅auth开启需读取token时校验TTY或token-stdin，remember固定true，不能前置因无TTY拒绝。
- 登录成功后保存，任何失败保留旧配置。
- stdin认证工具不把token位置参数纳入命令语法，不持久化长期token。

### 出口标准

- 不需要启动Worker即可登录测试API并缓存。
- help/version不读配置、不联网；auth开启且需token的非交互无输入立即失败；auth关闭的非交互初始化成功且不读取stdin。
- auth开/关、坏缓存、无权限、重定向、Secure和origin归一化用例通过。
- 请求/日志/输出仅出现测试生成的Cookie，不访问真实用户目录。

## 阶段：CLI查询与续签持久化

### 实施步骤

- 严格解析workspace/duration/kind/status，映射整数秒，不计算客户端窗口。
- 读取缓存后请求新接口；cookie=null允许请求。
- 完整接收body文本但暂不解析JSON；先校验并保存续签，再解析业务JSON/DTO，最后统一文本输出。login初次签发仍先验证登录响应再保存。
- 实现表头、固定多行字段、UTC时间、控制字符转义、总数和结束标记。
- 非2xx保持主错误，续签写失败增加诊断；2xx有效Cookie写失败即使DTO无效也退出7；保存成功后DTO无效退出6且不回滚Cookie。
- 用临时HTTP服务测试HTTP/传输边界、Cookie属性、非法Cookie与非法DTO组合，以及写失败/DTO失败优先序；拒绝不安全整数、不一致total及缺失字段。
- 测试关闭/打开认证配置变化；401不自动login、不删除原配置。

### 出口标准

- 一个命令全量返回，零匹配成功，无两套输出逻辑。
- 服务端窗口原样展示，不因CLI时区变化而改变筛选。
- 缓存只在login或收到新Cookie时写；不常规刷新同值文件。
- 计数只展示，不自动跳过任何名称或低计数Session。

## 阶段：工程门禁和安装

### 实施步骤

- 根build在shared构建后增加CLI，typecheck/test纳入CLI workspace。
- CLI测试用现有node:test/tsx风格；API新`.test.ts`和`.integration.test.ts`沿用当前扫描脚本。
- 完成CommonJS单文件 `dist/cli.cjs`；prune后将它移到脱离checkout及node_modules的独立Node22环境，清除NODE_PATH等回退，实际执行 `--help/--version`，不得用仓库内运行替代。
- 建议独立Node22容器仅复制cli.cjs且不挂载checkout、不安装CLI依赖，保存命令及输出证据；这才验证构建依赖闭包。
- Docker npm ci前复制CLI清单，runtime复制 `/opt/awb-cli/cli.cjs` 并建立 `/usr/local/bin/awb`。
- 验证dev用户、home卷挂载后仍能发现程序；不在home卷安装程序。
- 定义本地npm link方式及可诊断的prefix权限错误。
- 在内置终端login，再用真实Worker bash执行查询验证同用户配置共享，不读取或打印Cookie内容。

### 出口标准

- builder/runtime入口、用户权限、PATH通过，且独立Node22无checkout/node_modules环境的help/version均有成功证据；无ESM动态require失败。
- 复用home卷重建镜像后程序更新、登录缓存保留。
- 未修改Worker凭证注入、工具上限、subtask或scheduled-tasks。

## 阶段：综合验收与审查

### 建议执行门禁

下面是开发完成后应执行的命令，不是文档编写阶段已执行的记录：

```bash
npm run build
npm run typecheck
npm test -w packages/cli
npm run test:unit -w apps/api
npm run test:integration -w apps/api
npm run test:integration:worker -w apps/api
npm test -w apps/agent-worker
npm test
```

- 单测先验证纯解析、时钟边界和临时文件；集成再验证Fastify hook和真实HTTP；Docker/真实Worker最后验证安装。
- 测试认证数据全部临时生成，fixture/t.after清理；不复用用户缓存和真实运行数据库。
- 大工具输出只验证当前预览/artifact/采集边界，不以提高硬上限满足测试。
- 记录命令、环境、通过数和未执行项；没有执行的Docker或人工步骤不能写成通过。

## 审查检查点

- HTTP/API、CLI参数、时长上限、错误码、输出和缓存规则是否全部一致。
- 是否出现默默加分页、limit、默认时间、JSON、业务命名过滤或消息门槛。
- 是否把累积COUNT错误放到更新时间窗口内，或计算了Fork祖先而不是origin。
- 是否把新运行态读取混入旧metadata接口，导致旧fixture依赖RunState/Message。
- 是否在业务stdout输出前完成续签保存和DTO校验。
- 是否改变登录Cookie寿命/属性、误让health/internal续签，或加入长期token缓存。
- 是否确保命令结果完整而不误认为artifact一定包含任意大小的全部输出。
- 是否新增数据库字段/schema版本、权限体系、锁服务或另一开发线变更。

## 失败与回退

- CLI安装/缓存问题先修复本地配置和产物，不通过Worker内部token绕过。
- 发布期间Cookie helper对原验证接口保持兼容；旧客户端可以不消费续签但会按原期限过期。
- 新查询是增量路由，发生问题时不改旧tabs/continuable结果兜底，不用UI列表冒充通用全量查询。
- 本轮无数据库迁移，回退代码不需要重建Agent数据；Cookie格式保留v1。

# 鉴权续签与凭证缓存

[返回导航](00-文档导航.md)｜[CLI 与 API 契约](02-CLI与查询接口契约.md)

## 认证原则

- 复用现有 `/api/auth/login` 和 `awb_session` 签名 Cookie；不增加授权范围、会话表或新 token 协议。
- CLI 不读取浏览器缓存，不取得服务端签名密钥，不使用 Worker 内部认证头。
- 原始登录 token 仅用于一次登录请求，不落盘、不写日志、不放位置参数、环境认证回退或任务 prompt。
- Cookie 权限同当前 Web 登录，缓存全局共享并不构成 Workspace/Run 隔离。

## 登录与连接初始化状态机

本方案建议固定流程：

```text
校验 login 参数及 origin
 → 无 Cookie GET /api/health
 → 验证健康响应结构
 → authEnabled=false：生成 cookie=null 的配置
 → authEnabled=true：获取输入，POST /api/auth/login {token,remember:true}
 → 验证成功响应和 awb_session Cookie
 → 原子保存配置
 → 输出登录/连接初始化成功
```

### origin 规则

- 仅支持 `http:`、`https:`，必须有主机；允许非默认端口及 localhost/IP。
- 不支持 username/password、query、fragment 或非根 pathname；根 `/` 和无路径等价。
- 缓存 WHATWG URL 的规范 `origin`：scheme/host 规范化，默认端口归一化，不带末尾 `/`。
- 不支持反向代理子路径前缀，帮助文档明确要求服务 origin。
- HTTP 使用内置 fetch，禁止自动重定向。返回 3xx 为响应错误，不跟随或向另一个 origin 发送 Cookie。
- 普通查询只有缓存地址，不提供另一个 `--url`；更换服务器只能显式重新 login。

### 输入规则

- health确认authEnabled=false后，不检查TTY、不询问、不消费stdin、不发送原有Cookie、不调用login；无TTY且无stdin选项也正常保存cookie=null。
- 开启认证且无 `--token-stdin`：必须 stdin/stdout 处于可交互终端，隐藏 token 输入；提示写 stderr。
- 仅health确认authEnabled=true时，`--token-stdin`才要求stdin为非TTY并读取至EOF；接受UTF-8单行，去除一个末尾LF/CRLF，不trim其余内容，拒绝空输入、多行及token内容超过64 KiB（末尾换行不计）。用管道，不建议把秘密字面量写入shell命令历史。
- 仅health确认authEnabled=true且即将读取token时，非交互又无stdin选项才返回2；该检查不能先于health，也不尝试从环境、Worker或其他文件搜索登录token。
- token 输入被取消、登录401、网络/响应异常时不覆盖原配置。
- 使用现有 `{token,remember:true}`；CLI固定长窗口，不增加记住登录选项。
- 未通过会话Cookie结构检查的登录200不视为成功；没有目标Cookie、非法Secure配置均返回6且保留旧缓存。
- health与login之间认证配置改变造成响应错误时，明确失败，用户重新执行；不做隐式重试。

## Cookie 阈值续签

### 既有格式与兼容

现有 Cookie 为版本、载荷、HMAC 签名，载荷含 `iat/exp`。保持 `v1` 格式和当前验证能力。

| 识别窗口 `exp-iat` | 有效期 | 阈值 | 浏览器保存 |
|---|---:|---:|---|
| 恰好24小时毫秒数 | 24小时 | 剩余<=6小时 | 会话Cookie，无Max-Age |
| 恰好30天毫秒数 | 30天 | 剩余<=7天 | Max-Age=2592000秒 |

- 先使用既有校验验证签名、版本、时间，不能依据未验证payload决定续签。
- `exp <= now` 已过期，直接认证失败，不续签。
- 已验证载荷 `exp-iat` 为上述标准窗口时才识别续签类型。
- 对已有签名有效但窗口不是上述两种的 Cookie，保持当前认证结果，不续签；不拒绝已有自定义TTL测试Cookie、不改成30天。
- 达到阈值时新 `iat=本次认证时刻`、`exp=iat+原窗口`。未达到不发Set-Cookie。
- 等于阈值续签；大于阈值1毫秒不续；等于过期时刻不得续。
- 不设绝对最长存活期，持续业务请求可以长期保活。

### Hook 与响应范围

本方案建议在现有 auth guard 内只对已通过普通Cookie认证的请求建立续签候选，在统一 `onSend` 阶段附加响应头。

- 仅普通 `/api/` HTTP 路由；不覆盖静态资源或非API。
- 排除 `/api/health`、`/api/auth/login`、内部token路径（包括 analytics signal）和由自身机制认证的 WebSocket 升级。
- guard没有执行普通Cookie校验的请求不能得到候选；authEnabled=false不产生候选。
- **本方案建议固定：普通认证通过即算活跃，后续业务400/403/404/500也允许续签。**认证被拒绝的401没有候选，不续签；这符合“API鉴权通过后延长”的定义。
- HTTP 101升级不追加续签。SSE只在首次HTTP响应发送头时处理，不在流中续签。
- health只能报告认证状态，不能成为专门保活入口；高频正常业务轮询仍保活。
- `onSend`追加而不是覆盖其他Set-Cookie；若业务处理已显式设置同名Cookie，优先保留业务Cookie，不再追加第二个同名值。
- 所有既有Cookie属性保持：HttpOnly、SameSite=Lax、Path=/、Secure由当前配置控制；普通不增加Max-Age，长窗口重新设置完整30天Max-Age。
- 抽取已验证payload/窗口 helper，但保留现有 boolean 验证函数的兼容签名，避免修改health及其他调用方含义。

### 浏览器行为

- 浏览器接收Set-Cookie自动替换，前端不读取HttpOnly值，无需刷新接口或主动login。
- 并行请求在阈值附近可能同时续签，接受返回先后造成的轻微有效期覆盖；不增加会话锁或服务端活跃表。
- Web与CLI各自保存自己的Cookie，CLI续签不会替换浏览器的旧Cookie。
- 浏览器会话Cookie仍可能因关闭会话被清除；服务端重启且登录token不变不会主动失效；登录token变化使旧签名无效。

## 缓存实体

本方案建议固定 `os.homedir()/.config/awb/config.json`，不依赖cwd/Workspace、Worker注入或新增配置环境变量。

```typescript
interface CliConfigV1 {
  version: 1;
  apiOrigin: string;
  cookie: null | {
    name: "awb_session";
    value: string;
    secure: boolean;
  };
}
```

- 一个文件、一个连接，auth关闭时cookie=null。无profile、原始token、Workspace、Session或Run信息。
- Cookie value只保存值，HTTP发送 `Cookie: awb_session=<value>`；不把Path/Max-Age等Set-Cookie属性发回。
- CLI无需验证HMAC也不根据本地exp提前拒绝请求，避免关闭认证后旧Cookie造成客户端错误判断；服务端是认证权威。
- 必须解析单独的Set-Cookie头，使用Node22的`headers.getSetCookie()`，不得按逗号拆分Cookie。
- 只更新名为awb_session、结构正常且符合下列固定属性契约的Cookie；只接受当前请求origin直接返回的响应，不实现通用Cookie jar。忽略其他Cookie，同名多值或非法值返回响应错误，不能猜测。
- 缓存及响应Cookie值只接受现有 `v1.<base64url>.<base64url>` 外形，不允许空段、换行、分号或控制字符；这是HTTP输入结构检查，不验证签名。错误不可回显该值。
- 接收到Secure Cookie时必须HTTPS使用。HTTP登录返回Secure Cookie为配置错误，不缓存并提示使用HTTPS；普通HTTP请求不发送缓存中的Secure Cookie。
- 完整Cookie/Set-Cookie不进入诊断，响应原文不直接dump。

### 固定Cookie属性契约

本服务当前签发无Domain、Path=/的Cookie，CLI只支持此形式，不做子域匹配、路径匹配或客户端Cookie过期管理。

| 属性 | CLI接受/忽略规则 |
|---|---|
| Cookie名称 | 大小写敏感，只接收awb_session；其他名称忽略 |
| Domain | 必须不存在；即使与请求host相同、为空或有前导点也返回6，不扩展为domain Cookie |
| Path | 必须显式且恰好为 `/`；缺省或其他路径返回6 |
| Max-Age | 可缺省；出现时只接受本服务长窗口的十进制 `2592000`。0、负数、其他值或非法值返回6，不实现删除Cookie/任意TTL逻辑 |
| Expires | 本服务不发送；若出现返回6，不解析成另一套客户端到期/删除规则 |
| Secure | 记录是否出现，HTTPS发送规则不变，不忽略该标志 |
| HttpOnly、SameSite | 属于浏览器行为，CLI不保存、不据此调整发送；后端仍须保持HttpOnly与SameSite=Lax |
| 其他属性 | 忽略，不改变固定origin、host-only、Path=/或Secure规则 |

- 属性名大小写不敏感；已知属性重复为无效Cookie返回6，不能采用最后值覆盖。Max-Age、Path等值按上表校验。
- `headers.getSetCookie()`取得多条响应Cookie，各条独立解析；非目标Cookie的属性不参与上述校验，目标Cookie只能有一条。
- 缓存cookie没有Domain/Path/到期字段：接收时保证固定形式，发送只使用该文件的apiOrigin；不发送给其他origin，不在本地替代服务端exp验证。
- 任何属性拒绝发生在缓存写入前；2xx返回6、旧缓存不变。非2xx保持HTTP主错误，并补安全诊断。

### 读取、写入和共享

- 配置不存在或损坏：返回3，明确提示重新login；不能读取部分字段继续发送未知凭证。
- origin有效且cookie=null：正常发送无Cookie请求，不在本地强制阻断；auth打开时服务端401明确要求login。
- POSIX创建awb目录0700、临时及最终文件0600；只处理自己的awb目录，不修改HOME或父.config权限。
- 写入同目录唯一临时文件，设置权限、写完关闭后rename替换；不先删除旧文件，不把敏感值留在失败日志。
- 写失败尽力清理临时文件，旧配置可读且不被破坏；失败本身不能伪装成功。
- 非POSIX尽量使用当前用户可访问的文件属性，权限位不等价于Windows ACL；不把Linux chmod保证当作跨平台硬承诺。
- 不增加跨进程锁、CAS或守护进程。接受轻微Cookie并发覆盖；不要同时执行切换服务器的login和使用旧配置的命令，首版不保证该操作组合的选择顺序。
- 内置终端/Worker只有在相同用户、HOME和文件系统下共享；宿主机、独立容器、不同用户不会自动共享。
- 当前Docker /home/dev有卷，复用卷可保留配置；删除或换卷后重新login。

## 普通业务请求的续签处理顺序

下面顺序用于普通业务请求；login的初次Cookie不是续签，仍按前述登录流程先验证成功响应及Cookie，再原子保存新连接，失败不覆盖旧配置。

```text
发请求并完整接收body字节/文本（此时不解析业务JSON/DTO）
 → 识别HTTP主错误
 → 如有续签Cookie，校验并原子更新缓存（不论业务成功与否）
 → 解析业务JSON并校验DTO
 → 所有必需步骤成功后才打印成功结果
```

| 情况 | 处理 |
|---|---|
| 2xx且无续签 | 校验业务并输出 |
| 2xx且续签保存成功、DTO有效 | 保存后输出 |
| 2xx且有效续签保存失败、DTO有效或无效 | 返回7，不继续解析/校验业务，stdout无成功结果；DTO错误不改变缓存错误优先序 |
| 2xx且有效续签保存成功、JSON/DTO无效 | 返回6，已更新Cookie不回滚，stdout无成功结果 |
| 2xx且续签Cookie无效、DTO有效或无效 | 返回6，优先诊断Cookie，不写缓存、不继续业务校验 |
| 2xx无续签、JSON/DTO无效 | 返回6，不写缓存、不输出成功 |
| 401 | 返回4，不交互，不清除已缓存Cookie以便诊断；提示login |
| 非401业务错误+有效续签 | 先更新缓存，再返回业务错误6 |
| 业务错误+缓存更新错误 | 保持业务退出码，stderr同时说明缓存错误 |
| 网络/传输中断 | 返回5，不使用部分响应更新缓存 |
| 3xx | 返回6，不跟随，不更新缓存 |
| auth关闭且无Cookie | 正常请求，不要求login凭证 |

- CLI不自动重新登录、不自动重试，不保存长期token以续期。
- 缓存文件只在login或真正收到新的Cookie时写入；阈值外普通请求不重复写文件。
- 如果两个响应Cookie时间轻微倒退，接受其有效期差异；不能混用不同origin的配置与Cookie。

## 架构边界

```text
人类终端 / Worker bash
 → 独立 awb CLI
 → 现有公开登录 + 新通用查询 HTTP
 → shared contracts
 → public route / query application
 → 独立 SessionActivityQuery 读侧
 → 主 SQLite：Session + RunState + Message
```

- CLI不依赖API模块、AppContext、数据库、Worker API Client或内部鉴权。
- API继续拥有查询、数据一致性、Cookie验证和续签；CLI只做连接、参数、请求和可读展示。
- 新查询放Agent读侧，但不借用当前metadata-only的`SqliteSessionQuery.listSessions/getSession`来读取运行态。
- 单独增加窄读侧类与service入口，通过composition/routes类型接线；不让HTTP route直接拼SQL。
- 不改旧tabs/continuable DTO、参数、分页和标签可见性逻辑。不要向旧响应“顺便”加状态/计数。

## 数据实体：无新增数据库表

### Session

复用`agent_session`：id/workspace_id/title/kind/updated_at。更新时间是当前持久化Session元数据更新时间，不能改成消息时间、Run时间或人为活跃时间。

当前源码会在消息写回、工具结果、指针变更、自动标题等路径更新；手动标题不更新updated_at。查询只消费现有语义，不顺带改标题或生命周期行为。

### RunState

复用`session_run_state`的(workspace_id,session_id)和status。正常Session创建时应有对应RunState。缺失或非法状态是数据一致性错误，不作为idle恢复，不需要读取Run表解释执行阶段。

### Message

复用`agent_message`的workspace_id/origin_session_id/type/status。统计原生累计已提交user及completed assistant，不读取Parts正文、Provider replay、附件或有效上下文链。

### 本地配置

仅新增CLI用户目录中的`CliConfigV1`文件，字段与生命周期见鉴权文档。无服务端凭证表、profile表、统计缓存表或新字段。

## 批量查询实施骨架

在普通`deferred`只读事务内：

- 验证Workspace存在。
- 取得一次now，计算固定窗口。
- 批量选择Workspace/时间/kind候选，LEFT JOIN RunState；验证全部候选状态有效，再按请求status筛选。
- 批量聚合最终候选的Message类型，合并计数，缺消息补0。
- 验证安全整数和日期，构建DTO；total取items.length。

不逐Session调用详情API、不逐Session解析上下文。状态无效必须被检查，不应因为INNER JOIN或status筛选被悄悄漏掉。

以下为聚合示意，参数应绑定，不拼接用户输入：

```sql
WITH candidates AS (
  SELECT s.id
  FROM agent_session s
  JOIN session_run_state r
    ON r.workspace_id = s.workspace_id AND r.session_id = s.id
  WHERE s.workspace_id = @workspaceId
    AND s.updated_at >= @updatedFrom AND s.updated_at <= @updatedTo
    AND (@kind = 'all' OR s.kind = @kind)
    AND (@status = 'all' OR r.status = @status)
)
SELECT
  m.origin_session_id AS sessionId,
  SUM(CASE WHEN m.type = 'user' THEN 1 ELSE 0 END) AS userMessageCount,
  SUM(CASE WHEN m.type = 'assistant' THEN 1 ELSE 0 END)
    AS completedAssistantMessageCount
FROM agent_message m
JOIN candidates c ON c.id = m.origin_session_id
WHERE m.workspace_id = @workspaceId
  AND m.status = 'completed'
  AND m.type IN ('user', 'assistant')
GROUP BY m.origin_session_id;
```

- 该聚合之前必须完成上述LEFT JOIN状态完整性检查。
- 元数据/状态与消息聚合是分开的固定数量查询，避免多明细表JOIN导致乘法重复计数。
- 用候选CTE而不是把大量ID拼进IN参数，避免无分页结果量受SQL占位符数量限制。
- 事务只读一致性是本次查询的正常数据库用法，不建设跨调用快照或会话锁。
- 没有消息的候选仍保留；不要用消息INNER JOIN把空会话排除。
- 别拿`head.depth`、当前context root长度、共享祖先数量替代原生COUNT。

### 索引与复杂度

可复用现有：

- Session `(workspace_id,updated_at DESC)`。
- RunState `(workspace_id,session_id)`主键。
- Message `(origin_session_id,updated_revision)`。

累计计数需要扫描对应候选的历史消息记录，不承诺恒定时间。先采用这些索引和批量聚合，首版不加统计表、Analytics或额外性能架构；若实测发现瓶颈再以证据提出优化。

不提升Agent schema版本，不触发Agent域重建；本轮没有新增数据库实体需求。

## CLI技术栈和构建

- Node.js22，与当前Docker基线一致；TypeScript源码可使用import/export，运行产物固定为CommonJS，不由源码模块语法推断bundle格式。
- commander负责分层命令，但单值重复参数需额外校验。
- 内置fetch负责HTTP，AbortController覆盖请求与完整body读取，避免收到headers后无限等待。
- CLI可以type-only导入shared DTO，运行时对明确响应字段做轻量校验；不能因引用shared根入口把API/数据库或整个模型SDK运行链带进CLI。
- 固定esbuild `platform=node`、`target=node22`、`format=cjs`、`bundle=true`，生成 `dist/cli.cjs`，保留一次 `#!/usr/bin/env node`；bundle commander及必要CLI依赖，Node内置模块由原生require加载，不增加ESM动态require适配。
- package声明 `bin: { "awb": "dist/cli.cjs" }` 和build/typecheck/test脚本；不包含better-sqlite3/node-pty/API实现。
- CLI必须显式声明commander直接依赖，以及esbuild、TypeScript、tsx、Node22类型等所需构建/测试依赖并更新lockfile；不得依赖其他workspace偶然带入的transitive包。具体版本实施时选定并验证，不将未实测版本写成已验证。
- 构建出口必须将单个cli.cjs移到脱离checkout/node_modules的独立Node22环境，在无NODE_PATH回退且无用户配置时分别执行 `--help/--version` 成功；仅在仓库目录执行不算独立产物通过。
- 新workspace自动被根`packages/*`识别，但根build/typecheck/test以及Docker清单复制必须显式接入CLI。
- 单元测试使用既有node:test/tsx风格，真实请求使用临时HTTP服务，配置文件用测试临时目录，不读取真实用户缓存。

## 安装与部署

### Docker

- builder阶段在npm ci前复制CLI package清单，确保workspace lockfile一致。
- packages源码COPY后随根build构建CLI；npm prune后单文件仍可运行。
- runtime复制bundle到 `/opt/awb-cli/cli.cjs`，创建 `/usr/local/bin/awb` 入口并设置执行权限；入口指向该CommonJS文件。
- 入口可为符号链接指向带shebang的文件；路径及文件对dev用户可读可执行。
- 不把程序放/home/dev，避免home卷遮蔽镜像内容或镜像更新。
- 保持既有HOME、home卷和用户；不改变Worker环境注入，也不把Cookie构建进镜像。
- 验收必须实际在内置终端和Worker`bash -lc 'awb --help'`中发现入口，而不只是直接node执行成功。

### 本地开发

本方案建议从仓库根执行：

```bash
npm run build -w packages/shared
npm run build -w packages/cli
npm link -w packages/cli
awb --help
```

- 使用用户可写的npm全局prefix；无权限时明确诊断，不要求自动sudo。
- link指向当前checkout的构建产物，源码修改后重新build。
- 本地安装不是每Workspace安装，也不在Worker启动时安装。
- 本地与Docker分别login，不声称宿主机缓存自动进入容器。

## 现有工具输出完整性边界

| 层次 | 当前默认 | 说明 |
|---|---:|---|
| Worker普通工具预览 | 8,000字符，预览3,000字符 | 超过后写Workspace artifact，预览截断正常，不是命令失败 |
| 文本artifact | 200,000字符 | 超出只保存前缀加truncated，不能找回其余 |
| bash采集 | stdout+stderr合计512 KiB | 超限尝试终止进程树，未采集内容丢失 |
| read单次 | 约50 KiB，最多2,000行 | 可分页；单行超过2,000字符尾部不可按行offset续读 |

- artifact为`.awb/agent/artifacts/by_tool_execution/<id>.txt`，保存渲染后的工具文本，不是原始字节流。
- bash可返回completed工具结果但`outputLimitExceeded=true`，不能只看ToolExecution状态认定完整。
- CLI统一多行紧凑模板，不把完整结果塞进单行JSON；普通多行归档可通过read分段阅读。
- API始终全量，CLI不增加隐式条数截断或分页。stdout之外的上游硬限制不会被artifact补救。
- 调用者需观察工具超限标识、归档尾部truncated及文本最后结果标记；不把前缀当完整列表。
- 本方案建议在正常完整输出末尾加固定`查询结束：已输出 N 个 Session。`，与total一致，便于发现截断。标记不是保证硬上限外的数据可恢复，也不是第二种输出。
- 不改Worker输出上限、artifact保存和read接口；本次不增加outfile功能。大输出的链路边界测试是验证现状，不承诺任意大小完整输出。

## 独立已知风险

当前bash继承Worker整个环境，存在内部控制凭证继承路径。本方案不使用该能力作为认证来源，也不把修复纳入CLI前置或偷偷修改Worker。后续应单独评估，不能将用户缓存误称为同用户进程不可读取的秘密沙箱。
